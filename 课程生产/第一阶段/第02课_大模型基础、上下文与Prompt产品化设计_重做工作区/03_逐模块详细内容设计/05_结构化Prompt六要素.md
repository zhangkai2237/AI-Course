## 一、本模块在课程中的作用

模块04已经确定“要什么结果、需要什么信息”。本模块解决：

> 怎样把零散的业务要求组织成一段模型能够执行、团队能够检查、后续能够拆分和维护的Prompt？

本模块不把Prompt当作“说服AI的咒语”，而把它当作一份面向模型的任务说明。

### 六要素的使用原则

- 六要素是检查清单，不是每次必须等长填写的表格；
- 任务越简单，需要显式说明的内容可能越少；
- 任务越专业、风险越高、输出越结构化，越需要把关键信息写清楚；
- Prompt长度不是质量指标；
- Prompt只是产品方案的一部分，不替代数据、流程、评测和人工确认。

### 课堂讲解控制

本文件为老师备课提供了每个要素的示例、错误和提醒，但课堂7分钟讲解时，每个要素只讲“解决什么问题＋销售案例中的一个对应项”。详细错误和补充说明只在学员出现相应问题时使用，不能逐段照读。

---

## 二、教学目标与验收方式

### 1. 教学目标

学员完成本模块后应能：

- 说出结构化Prompt六类信息；
- 判断一段Prompt缺少哪些关键内容；
- 将模块04的输出和上下文组织成Prompt V0.2；
- 解释每一段Prompt解决什么问题；
- 避免只堆角色、形容词和格式要求。

### 2. 模块验收标准

学员的Prompt不按文采评分，只检查：

1. 任务是否明确；
2. 输入材料是否有清楚边界；
3. 规则是否对应真实风险；
4. 输出是否可检查；
5. 缺失信息是否有处理方式；
6. 是否存在没有用途的冗余要求。

## 四、六要素详细设计

### 4.1 角色与能力

#### 回答的问题

> 希望模型以什么专业视角、能力边界和工作责任处理任务？

#### 销售拜访助手示例

```text
你是销售拜访记录整理助手，负责根据给定材料提取客户明确表达的信息，
并整理为便于销售检查和录入CRM的结构化结果。
```

#### 作用

- 指定处理视角；
- 明确主要责任；
- 限制任务范围。

#### 常见错误

```text
你是世界顶级、经验丰富、洞察一切、极度专业的销售大师……
```

问题：堆叠形容词，但没有说明具体任务、信息依据和责任边界。

#### 教师提醒

角色不是所有Prompt中最重要的部分，也不是越资深越好。对于明确的提取任务，任务、输入、规则和输出通常比夸张角色更重要。

### 4.2 任务目标

#### 回答的问题

> 模型这一次必须完成什么，交付给谁，用于什么后续动作？

#### 示例

```text
请根据本次拜访转写，提取客户核心诉求、明确异议和双方确认的下一步行动，
供销售本人检查后录入CRM。
```

#### 作用

- 限制任务范围；
- 避免模型自由发挥成泛泛总结；
- 把输出连接到真实使用场景。

#### 常见错误

- “全面深入分析”；
- “整理得专业一些”；
- 同时要求摘要、商机预测、主管辅导、客户邮件和报价建议。

修正原则：一段Prompt优先完成一个清晰任务闭环。

### 4.3 业务背景与输入材料

#### 回答的问题

> 模型需要依据哪些事实、背景和变量完成任务？

#### 示例结构

```text
【业务背景】
当前处于方案沟通阶段。本次输出由一线销售在拜访结束后检查。

【客户与商机信息】
{{customer_profile}}
{{opportunity_stage}}

【本次拜访转写】
{{visit_transcript}}
```

#### 作用

- 让模型知道材料属于什么场景；
- 明确事实依据；
- 为后续参数化留下清楚变量。

#### 常见错误

- 把所有历史资料全部放入；
- 不标明材料类型和边界；
- 把教师写的示例内容误当作真实输入；
- 没有区分销售发言与客户发言。

#### 教师提醒

上下文不是只有用户输入。系统带入的客户资料、商机阶段和业务规则也属于模型本次处理所依据的信息。

### 4.4 规则与约束

#### 回答的问题

> 有哪些必须遵循的业务规则、风险边界和缺失信息处理方式？

#### 示例

```text
1. 只依据提供的材料整理，不把推测写成客户事实；
2. 客户诉求和异议尽量附对应原话或证据片段；
3. 没有明确负责人或时间时填写“待确认”，不得自行补充；
4. 区分客户明确表达、销售判断和AI建议；
5. 忽略与当前任务无关的寒暄内容。
```

#### 作用

- 把业务风险转成模型行为要求；
- 明确什么不能做；
- 规定信息缺失时如何处理。

#### 常见错误

- 使用“保证100%准确”“绝对不能出错”等无法执行和验证的口号；
- 规则之间互相冲突；
- 为了显得严谨，增加大量与当前任务无关的限制；
- 只说“不要幻觉”，没有说明事实依据和缺失处理。

### 4.5 输出格式与验收标准

#### 回答的问题

> 最终结果必须长什么样，包含什么，怎样判断可继续使用？

#### 示例

```text
请按以下结构输出：

1. 客户核心诉求
   - 诉求：
   - 证据原话：
   - 状态：明确 / 待确认

2. 客户异议
   - 异议：
   - 针对对象：
   - 证据原话：

3. 下一步行动
   - 事项：
   - 责任人：
   - 截止时间：
   - 状态：已确认 / 待确认
```

#### 作用

- 降低结果结构波动；
- 方便人工检查；
- 为后续写入系统或继续处理打基础。

#### 常见错误

- 只规定Markdown或JSON，没有规定字段含义；
- 字段很多，但没有业务用途；
- 强行要求JSON，却没有后续系统解析需求；
- 规定格式却不说明内容准确性要求。

#### 教师提醒

格式不是越技术化越专业。选择表格、列表、Markdown或JSON，要看结果的后续使用方式。

### 4.6 示例与迭代要求

#### 回答的问题

> 模型需要通过什么样例理解边界？输出前后是否需要检查或补问？

#### 可以包含的内容

- 一条合格输出示例；
- 一条不可接受的反例；
- 字段映射示例；
- 信息不足时先列出待确认项；
- 输出前检查事实是否有依据；
- 对高风险任务先返回草稿供人工确认。

#### 销售案例的轻量示例

```text
如果转写中只出现“后续再约技术同学聊一下”，但没有责任人和时间，
应输出：
事项：安排技术沟通
责任人：待确认
截止时间：待确认
```

#### 常见错误

- 示例与规则冲突；
- 给了一个例子后，误以为模型会自动覆盖所有边界；
- 要求模型无限自我反思、保证正确；
- 把多个独立任务塞进“迭代要求”。

#### 教师提醒

简单任务可以不提供示例。示例主要用于容易歧义、格式严格或边界难以只用规则说明的任务。

## 五、三分钟逐层补全示范（61—64分钟）

### V0：模糊任务

```text
帮我整理一下这次销售拜访。
```

问题：对象、任务、材料、规则、输出均不明确。

### V1：只有任务

```text
请提取本次拜访中的客户诉求、异议和下一步行动。
```

改善：知道要找什么；仍不知道依据材料、缺失处理和输出结构。

### V2：加入材料与规则

```text
请根据【本次拜访转写】提取客户诉求、异议和下一步行动。
只依据转写中的明确内容；没有负责人或时间时标记“待确认”。
```

改善：有事实边界和缺失处理；仍不方便检查和录入。

### V3：加入结构与验收

增加：

- 每项结论附证据原话；
- 行动项包含事项、责任人、时间和状态；
- 区分客户明确表达和AI建议。

改善：结果开始具备业务可用性。

### 示范结论

不是因为Prompt从一行变成了十行，所以结果更好；而是因为任务、事实来源、规则和输出标准逐步清楚了。

## 六、两人结对微练习（64—67分钟）

### 练习材料

使用模块04已填写的目标输出与上下文，不新增完整拜访原文。

### 分工

- 学员A：把内容整理成结构化Prompt；
- 学员B：按六要素检查缺失、冲突和冗余；
- 90秒后交换角色，完成一次修正。

### 检查表

| 检查项 | 有/无 | 是否需要修改 |
|---|---|---|
| 角色与能力是否简洁且有用 |  |  |
| 任务目标是否唯一、明确 |  |  |
| 输入材料是否有边界 |  |  |
| 规则是否对应真实风险 |  |  |
| 输出是否可验收 |  |  |
| 示例或迭代要求是否必要 |  |  |

### 老师巡场只看三类问题

1. 角色很长，任务仍然不清楚；
2. 规则写了很多，但没有事实依据和缺失处理；
3. 输出结构完整，却不能支持销售后续动作。

## 七、结构化Prompt参考骨架

```text
【角色与能力】
你是________，负责________。

【任务目标】
请根据________，完成________，结果用于________。

【业务背景与输入材料】
业务背景：________
输入1：{{________}}
输入2：{{________}}

【规则与约束】
1. ________
2. ________
3. 信息不足时________

【输出格式与验收标准】
请输出________，至少包含________。
每项结果需要满足________。

【示例与迭代要求】
示例：________
输出前请检查：________
```

这是一份备课和练习骨架，不应直接成为所有业务的万能模板。

## 八、67—68分钟校准与休息前收口

### 三个高频错误

1. **角色替代任务**：写了“资深专家”，却没定义要完成什么；
2. **格式替代标准**：规定表格或JSON，却没说明事实要求；
3. **长度替代质量**：不断增加要求，但无法解释每一段解决什么风险。

### 收口句

> 现在我们已经有了一段专业Prompt，但它仍然要求每个销售都理解并填写这些内容。休息之后，我们要做产品经理最关键的一步：哪些内容应该藏在产品内部，哪些才应该交给用户？
