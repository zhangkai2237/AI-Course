# Prompt产品化设计单｜课堂版

> 场景：销售拜访记录助手  
> 使用方式：模块04完成V0.1，模块05完成V0.2关键骨架，模块06完成V0.3，模块07—08测试和修正。

## V0.1：目标输出、验收与上下文

### 1. 用户与使用时点

本课统一假设：

> 一线销售在拜访结束后10分钟内检查AI草稿，录入CRM并准备下一步跟进。

### 2. 目标输出与验收

老师已示范第一项，请补充至少一项。

| 目标输出 | 怎样算合格 | 高风险错误 |
|---|---|---|
| 客户核心诉求 | 只写客户明确表达的诉求，关键结论能返回原文 | 把销售推测写成客户诉求 |
|  |  |  |
|  |  |  |

### 3. 上下文清单

从候选信息中选择至少3项，并说明用途。

候选信息：

- 本次拜访转写；
- 说话人标签；
- 客户基本资料；
- 当前商机阶段；
- CRM字段定义；
- 缺失信息处理规则；
- 公司全部历史资料；
- 与本次任务无关的过往聊天；
- 产品方案说明。

| 信息 | 事实/背景/规则 | 支持哪项输出 | 必需/按需/暂不需要 |
|---|---|---|---|
|  |  |  |  |
|  |  |  |  |
|  |  |  |  |

## V0.2：结构化Prompt关键骨架

> 不要求课堂从头写完整Prompt。至少补全任务目标、一条关键规则和一项输出标准。

### 角色与能力

你是销售拜访记录整理助手，负责________。

### 任务目标

请根据________，完成________，结果用于________。

### 输入材料

- 客户背景：________；
- CRM字段：________；
- 拜访转写：________。

### 规则与约束

1. ________；
2. ________；
3. 信息不足时________。

### 输出格式与验收标准

- 输出字段：________；
- 关键结论需要________；
- 行动项必须包含________。

### 同伴检查

- [ ] 任务是否具体？
- [ ] 每条规则是否对应真实风险？
- [ ] 输出是否可以检查？
- [ ] 是否存在无用途的形容词或要求？

## V0.3：从Prompt到产品

### A. 信息怎样进入产品

至少填写：

- 2项产品固定；
- 1项用户提供；
- 2项系统获取。

| 信息或规则 | 产品固定/用户提供/系统获取 | 产品承载或交互方式 |
|---|---|---|
|  |  |  |
|  |  |  |
|  |  |  |
|  |  |  |
|  |  |  |
|  |  |  |

至少删除一项原本想让用户填写、但系统可以自动获取的信息：

> 我删除的手工输入是________，改为由________自动获取，并允许用户________。

### B. 结果怎样检查和确认

至少设计1项“执行前必须确认”。同一项信息可以由系统获取，同时在使用或写入前要求用户确认。

| 输出字段或后续动作 | 主要风险 | 普通展示/建议检查/必须确认 | 证据与交互方式 |
|---|---|---|---|
