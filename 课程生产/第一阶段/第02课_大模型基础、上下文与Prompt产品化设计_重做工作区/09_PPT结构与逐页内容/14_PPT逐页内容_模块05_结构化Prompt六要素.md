## 一、本模块设计原则

1. 六要素是本课程整理的产品检查框架，不是行业唯一标准；
2. 不要求背CRISPE缩写，也不要求每项等长写满；
3. 每一项只讲“回答什么问题、案例对应什么、缺失会怎样”；
4. 输入材料与规则分开；输出格式与验收标准分开；
5. 示例使用通用状态例子，不提前泄露模块07案例答案；
6. 基准版只完成V0.2关键骨架，充分互动版才补齐完整骨架。

## 第24页｜六要素是一张检查表，不是咒语

### 页面标题

> 六要素：检查任务说明有没有漏掉重要信息

### 页面上屏文字

```text
01  角色与能力
模型承担什么职责？

02  任务目标
这次必须完成什么？

03  业务背景与输入材料
依据哪些事实完成？

04  规则与约束
哪些边界必须遵守？

05  输出格式与验收标准
结果怎样组织、怎样算可用？

06  示例与迭代要求
是否需要示例、检查或补问？
```

底部标注：

```text
本课程基于参考框架重新整理｜不是固定语法｜不要求全部写满
```

### 版式与视觉

- 六张编号卡排成2×3；
- 01—02使用任务色，03—04使用上下文与规则色，05—06使用结果色；
- 底部来源属性必须可见；
- 不在投屏页展示CRISPE英文全称。

### 动画与讲课动作

六张卡按“任务→依据与边界→结果”三组出现。老师说明：判断是否保留某一段，只问它解决了什么歧义、信息缺口、风险或输出问题。

### 时间与来源

- 时间：53:00—55:00；
- 来源：K7，A2录音P571—P595、课件113、118—119页，T3课程重组。

## 第25页｜角色限定职责，任务决定完成什么

### 页面标题

> 角色不能替代任务，形容词也不能替代责任

### 页面上屏文字

#### 角色对比

```text
不建议
你是全世界最顶级、最专业、最聪明的销售专家

更具体
你是销售拜访记录整理助手，
负责依据给定材料生成供销售检查的CRM草稿
```

#### 任务对比

```text
不够
请专业地分析一下

更具体
根据本次拜访转写，整理客户诉求、异议、行动项和待确认信息，
供销售检查并录入CRM
```

底部：

```text
角色回答“承担什么职责”
任务回答“这次完成什么、结果用于什么”
```

### 版式与互动

- 左侧角色，右侧任务；每侧上方反例、下方改进；
- 提问：“如果只能先补一项，夸张角色和明确任务，哪一个更重要？”；
- 学员回答后高亮“任务目标”。

### 时间与来源

- 时间：55:00—57:00；
- 来源：K7＋CASE。

## 第26页｜输入提供事实，规则规定边界

### 页面标题

> 输入材料告诉模型“依据什么”，规则告诉模型“不能越过什么”

### 页面上屏文字

| 业务背景与输入材料 | 规则与约束 |
|---|---|
| 客户与商机基本信息 | 只依据提供材料 |
| 本次拜访转写 | 不把推测写成事实 |
| CRM字段说明 | 缺失信息标记待确认 |
| 当前产品方案 | 高风险结论附证据 |
| 特殊备注 | 不生成成交概率 |

底部边界：

```text
广义上下文可以包含规则；
为了方便检查，本课在Prompt结构中把规则单独列出。
```

### 版式与视觉

- 左侧画成“材料文件夹”，右侧画成“业务护栏”；
- 中间用“事实依据”与“行为边界”区分；
- 不展示模块07具体数字、日期或标准答案。

### 讲课动作

指出两个常见问题：只写“参考附件”但不说明用途；只写“不要幻觉”但不说明缺失时怎么办。

### 时间与来源

- 时间：57:00—59:30；
- 来源：K7、T3。

## 第27页｜输出结构不等于验收，示例也不是保证

### 页面标题

> 结果“长什么样”和“能不能用”，要分别定义

### 页面上屏文字

#### 上半部

| 输出格式 | 验收标准 |
|---|---|
| 表格或CRM字段 | 关键事实有证据 |
| 固定字段顺序 | 缺失信息明确标记 |
| 确定性状态标签 | 行动项包含人、事、时间、状态 |

#### 下半部

```text
示例可以帮助理解状态和字段

已确认：客户明确同意先进行小范围验证
待确认：后续是否扩大范围，仍需内部讨论

但一个示例不能覆盖所有情况，也不能替代测试
```

### 版式与视觉

- 上半部左右对比；
- 下半部使用一条不含案例数字的通用状态示例；
- “示例≠保证”作为右下角结论标签。

### 时间与来源

- 时间：59:30—62:00；
- 来源：K7＋本课程验收设计。

## 第28页｜从V0到V3，增加的是可检查要求

### 页面标题

> Prompt变好，不是因为更长，而是因为每次修改都解决一个问题

### 页面上屏文字

```text
V0  帮我整理一下这次销售拜访
问题：任务、材料、规则和输出都不清楚

V1  提取客户诉求、异议和下一步行动
增加：明确任务

V2  根据转写提取；只依据明确内容；缺失标待确认
增加：输入材料、事实边界、缺失处理

V3  关键结论附证据；行动项包含人、事、时间和状态
增加：输出字段与验收标准
```

底部：

```text
每一项新增要求，都应该对应一个具体问题。
```

### 版式与动画

- 使用四层阶梯或四列版本卡；
- 每次只高亮新增内容，旧内容保持浅色；
- V3出现后回看四类问题如何逐步被解决。

### 互动

追问：“从V0开始，如果只能先增加一项，你会先加什么？”接受“先明确任务”及有合理依据的回答。

### 时间与来源

- 时间：62:00—64:00；
- 来源：K5—K7＋CASE。

## 第29页｜完成V0.2关键骨架

### 页面标题

> 课堂练习：补全结构化Prompt关键骨架

### 页面上屏文字

```text
请基于V0.1补全

① 任务目标
② 1条关键规则
③ 1项输出验收标准

同伴只检查一处最重要缺口

时间：4分钟
```

底部互查：

```text
任务是否具体？
规则是否对应真实风险？
输出是否可以检查？
```

右侧提示：

```text
基准版：V0.2关键骨架
充分互动版：补齐输入、缺失处理、输出结构和检查，形成完整骨架
```

### 版式与互动流程

- 左侧设计单局部，右侧任务和倒计时；
- 个人填写2分30秒，同伴检查45秒，老师收集一组关键段落45秒；
- 不要求朗读完整Prompt；
- 老师只校准角色替代任务、格式替代验收、规则无法执行三类问题。

- 时间：64:00—68:00；
