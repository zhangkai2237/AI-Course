# 08 五条测试与Bad Case

“能够回答一条问题”不代表产品可靠。测试需要换表达、问边界问题并制造冲突。

## 每条测试记录什么

- 用户问题；
- 预期路径；
- 预期依据；
- 实际检索片段；
- 最终回答；
- 问题归因；
- 修改与复测。

## 五种测试

### T1 直接命中

验证当前规则中的明确事实能否被找到。

### T2 同义表达

用户不使用文档原词时，是否仍能找到正确内容。

### T3 适用范围

检查模型是否保留区域、商家类型等条件，并避免扩大结论。

### T4 无答案/实时事实

知识库没有门店实时数据时，是否进入正确路径或明确拒绝编造。

### T5 版本冲突

旧版进入知识库后，系统是否会找到失效规则；发生冲突时是否能够按产品策略处理。

## 四类Bad Case

| 类型 | 表现 |
|---|---|
| 没找到 | 正确知识存在但没有召回 |
| 找错了 | 召回旧版、无关或不适用内容 |
| 资料冲突 | 同时找到两个不同结论 |
| 找对但答错 | 依据正确，模型仍遗漏或编造 |

## 四步排查

```text
先看路由
→ 再看正确知识是否存在
→ 再看实际检索片段
→ 最后看模型如何使用依据
```

不要一看到答案错了就直接改Prompt。如果正确知识没有被检索回来，修改回答语气不能解决问题。
