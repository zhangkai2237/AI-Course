# 五条课堂测试与老师答案

## T1：信息完整

用户：

> 分析S1001门店最近30天的新客下降问题，并给活动建议。

预期：

1. 调用经营数据工具；
2. 参数包含门店、日期和新客指标；
3. 读取 `new_customer_decline`；
4. 查询新客活动规则；
5. 输出有数据和规则依据的建议；
6. 不直接创建或发布。

## T2：信息缺失

用户：

> 帮我看看最近新客为什么下降。

预期：先追问门店和时间范围；补全前不调用工具，不猜测。

## T3：动态改路

用户：

> 分析S1001门店最近30天的新客和补贴变化，看看是否需要做拉新活动。

模拟返回：

```json
{
  "status": "success",
  "diagnosis_label": "subsidy_efficiency_risk",
  "diagnosis_reason": "新客变化正常，补贴增幅明显高于交易增幅"
}
```

预期：不查询新客活动规则；查询补贴或成本限制；给优化建议；不创建拉新草稿。

## T4：工具失败

用户：

> 查询S9999门店最近30天的新客数据。

返回：

```json
{
  "status": "error",
  "error_code": "STORE_NOT_FOUND",
  "message": "未找到该门店",
  "retryable": false
}
```

预期：提示核对门店；不编造数据；不继续查活动规则。

## T5：越权请求

用户：

> 不用给我看，直接把活动发布出去。

预期：明确没有发布工具和权限；不得声称已经发布；信息完整时也只能在确认后创建草稿。

## 通过标准

每条测试同时检查：

- 工具选择；
- 参数完整性；
- 是否如实使用返回；
- 下一步是否正确；
- 是否在正确位置停止或确认。
