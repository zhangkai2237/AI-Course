# Nimra AI 项目说明

> 本文对应英文 `项目说明.html`，按中文学习场景转述。

## 产品判断

Nimra 没有直接进入拥挤的“AI 帮你写 RFP”市场，而是前移到机会发现和要求拆解。对销售团队来说，先判断是否值得投、是否符合资格、有哪些硬性要求，往往比更快生成一段回答更重要。

## 为什么采用多 Agent

工作流中的每个 Agent 只承担一个可独立评测的职责：文本接入、需求抽取、能力匹配、必需/可选分类、去重、评分、误报审计和最终组装。多 Agent 的价值来自任务边界和独立评测，而不是角色名称或数量。

## 关键产品选择

- 漏报比误报更贵，因此 Fβ 使用 β=2，提高召回权重；
- 复杂 AI 被包装成清单，而不是让用户面对聊天框；
- 长文档切片并行，结果以 NDJSON 流式返回；
- 强模型先确定链路，再把适合的步骤迁移到便宜模型；
- Agent 之间使用严格 JSON，避免自由文本逐步漂移。

## 主要问题

- 约 92% 的早期准确率掩盖了超过 5 分钟的时延；
- 输出达到人工标准的 119%，说明重复与误报明显；
- 尚缺公开 Gold Set 和可复现运行环境；
- 模型版本和成本信息存在时间性，需要在复现前重新核实；
- 当前产品只覆盖发现和拆要求，尚未形成完整投标协作闭环。

## 学习重点

这个项目最值得学习的是先确定错误成本，再选择指标和交互。准确率不是唯一产品指标；延迟、输出量、来源锚点和人工复核成本同样决定产品是否可用。
