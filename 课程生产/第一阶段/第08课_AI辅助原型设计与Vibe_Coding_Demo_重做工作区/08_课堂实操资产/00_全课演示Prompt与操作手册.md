# 第八课全课演示Prompt与操作手册

> 课程：AI辅助原型设计与Vibe Coding Demo  
> 总时长：120分钟  
> 使用工具：Codex桌面端＋本地浏览器  
> 文档用途：讲师现场演示时，只需按本文顺序操作和复制Prompt，不再到六个部分分别寻找提示词。  
> 正式需求基线：第七课《商品对比工具PRD》V1.0教学定稿。

---

## 一、演示总路线

```text
宽泛Prompt生成错误Demo
→ 对照PRD审查问题
→ 提取任务、页面和流程
→ 生成低保真原型
→ 补齐页面状态与可演示界面
→ 生成可运行Demo
→ 用局部Prompt修复问题
→ 按固定用例验收与交接
```

全课共使用10组Prompt，其中P0为课前检查，P1—P9为课堂演示。需要Codex先给方案、等待确认的环节，本文已拆成“A轮分析”和“B轮执行”，不要一次性让它边猜边写。

## 四、第一部分：为什么不能直接生成最终Demo（约12分钟）

### P1：用宽泛Prompt制造错误Demo

#### 教学目的

不是教大家写一个更长的Prompt，而是让学员看到：即使输入了PRD，AI仍可能自行补全设计空白。

#### 现场操作

1. 为了结果稳定，优先打开课前准备好的错误Demo；
2. 如需现场生成，粘贴P1；
3. 生成位置必须是`demo-wrong/index.html`，不要覆盖正式Demo；
4. 打开页面，只演示，不修改；
5. 让学员先人工找错并填写问题清单。

#### Prompt

```text
请阅读项目中的商品对比工具PRD，生成一个完整、专业、适合移动端展示的商品对比工具Demo。

要求功能完整、交互流畅、视觉效果好，可以直接用于课堂演示。

请将结果生成到：
课程生产/第一阶段/第08课_AI辅助原型设计与Vibe_Coding_Demo_重做工作区/demo-wrong/index.html
```

#### 预期观察

学员重点检查：是否出现AI推荐、是否允许第5个商品、是否混淆SPU与SKU、是否虚构到手价、是否补齐缺失参数、是否遗漏冲突来源与异常状态。

### P8：局部修复——缺失参数被自动补齐

```text
当前问题：标准化CSV中缺失的参数在demo/index.html对比页被显示为推测值。
```
