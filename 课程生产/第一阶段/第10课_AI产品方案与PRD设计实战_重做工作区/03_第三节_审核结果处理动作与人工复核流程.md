# 第三节：审核结果、处理动作与人工复核流程

第二节结束时，我们已经确定了智能审核产品中的能力分工：

```text
规则负责检查明确问题
大模型负责理解复杂语义
RAG负责提供当前审核依据
人工负责处理高风险和不确定问题
```

这一节只解决一个很具体的问题：

> 规则、大模型和RAG都完成工作以后，产品应该给用户一个什么结果，用户下一步做什么？

## 一、从多个能力的原始结果开始

运营人员提交了一段文案：

> 这款产品是目前最值得购买的理财产品，预计年化收益可达20%，收益稳定，完全不用担心亏损。

系统运行完规则、RAG和大模型以后，可能得到三组结果。

### 1. 规则检查结果

```text
命中片段：“最值得购买”
规则类型：绝对化表达召回规则

命中片段：“完全不用担心亏损”
规则类型：收益保证类高风险规则
```

### 2. RAG检索结果

```text
依据一：
金融营销内容审核规则V3，第12条
不得使用缺乏事实依据的绝对化比较表达。

依据二：
金融营销内容审核规则V3，第18条
不得明示或暗示保证本金和收益。

依据三：
收益数据使用规范V2，第7条
展示收益数据时需注明数据来源和统计周期。
```

### 3. 大模型语义审核结果

```text
风险一：
“预计年化收益可达20%”没有说明数据来源和统计周期。

风险二：
“收益稳定”可能让用户误认为收益不受市场波动影响。

风险三：
“完全不用担心亏损”存在风险隐瞒和收益保证问题。
```

这些仍然是系统内部结果。如果直接全部展示，用户可能看到重复问题、大段规则原文和多个不一致的建议，但仍然不知道整篇内容下一步应该怎么处理。

## 二、多个风险结果的合并

结果合并主要解决三个问题：

1. 相同风险不重复展示；
2. 不同来源的证据继续保留；
3. 每个风险都对应具体处理建议。

规则和大模型都识别到“完全不用担心亏损”时，不应该展示成两个完全独立的问题，而应该合并成：

```text
风险片段：完全不用担心亏损
风险类型：收益保证与风险隐瞒
风险等级：高
识别来源：确定性规则＋大模型语义审核
审核依据：金融营销内容审核规则V3，第18条
修改建议：删除保证性表达，并补充必要的风险提示
```

“最值得购买”和“年化收益可达20%”不是同一个问题，应该分别保留。

| 风险片段 | 风险类型 | 识别来源 |
|---|---|---|
| 最值得购买 | 绝对化表达 | 规则＋大模型 |
| 年化收益可达20% | 数据依据不足 | 大模型＋RAG |
| 收益稳定 | 收益误导 | 大模型 |
| 不用担心亏损 | 收益保证与风险隐瞒 | 规则＋大模型＋RAG |

一条正式风险结果至少需要包含：

```text
风险片段
风险类型
风险等级
判断原因
审核依据
识别来源
修改建议
是否需要人工复核
```

这也是AI产品PRD的一个典型要求：PRD不只写“页面展示审核结果”，还要定义机器结果由哪些结构化字段组成。

## 三、单条风险与整体审核结果

一篇内容可能包含多个风险项。产品除了展示每个风险，还需要给整篇内容一个整体处理结果。

第一版可以设计四类主要结果。

### 结果一：机器预审通过

适用于没有发现需要阻断的风险，审核依据完整，规则和模型结果没有明显冲突，且内容属于当前产品支持范围的情况。

```text
机器预审结果：通过
未发现需要阻断的风险
```

机器预审通过不代表内容已经自动发布，也不代表机器承担最终合规责任。

### 结果二：建议修改

适用于存在低风险或提示性问题，但不要求强制驳回的情况。

```text
机器预审结果：建议修改
发现2项提示性问题
```

用户可以查看建议、修改后重新审核，或保留原文并申请人工确认。

### 结果三：退回修改

适用于发现明确且可通过修改解决的问题。

```text
机器预审结果：退回修改
当前内容存在3项需要修改的问题
```

用户修改后形成新内容版本，再次进入机器审核。

### 结果四：转人工复核

适用于存在高风险问题、模型无法稳定判断、审核依据不足、规则冲突或需要责任人完成最终判断的情况。

```text
机器预审结果：待人工复核
转人工原因：存在收益保证类高风险表达
```

## 四、风险结果与处理动作

风险等级必须对应明确的产品动作。

| 审核情况 | 整体结果 | 下一步动作 |
|---|---|---|
| 未发现风险 | 机器预审通过 | 进入现有后续流程 |
| 只有低风险问题 | 建议修改 | 用户确认或修改 |
| 存在明确中风险问题 | 退回修改 | 修改后重新审核 |
| 存在高风险问题 | 待人工复核 | 进入人工审核队列 |
| 机器无法确定 | 待人工复核 | 由人工判断 |
| 审核依据不足或冲突 | 待人工复核 | 由人工或规则运营处理 |

如果PRD只写“系统输出高、中、低风险”，研发仍然不知道高风险是否直接驳回，中风险是否允许用户忽略，以及哪些风险必须人工处理。

因此，PRD需要同时写清风险等级、对应的处理规则和用户下一步可以执行的操作。

## 五、运营人员看到的审核结果

运营人员不需要查看所有技术节点的原始日志。他们真正关心：

1. 整体结果是什么；
2. 哪些内容有问题；
3. 为什么有问题；
4. 应该怎么修改；
5. 下一步做什么。

审核结果可以按以下结构展示。

### 整体结果

```text
当前结果：待人工复核
整体风险等级：高
发现风险：4项
审核时间：2026年8月19日 14:32
```

### 原文风险标记

> 这款产品是目前【最值得购买】的理财产品，预计【年化收益可达20%】，【收益稳定】，完全【不用担心亏损】。

### 单个风险详情

```text
问题片段：完全不用担心亏损
风险类型：收益保证与风险隐瞒

判断原因：
该表达可能使用户误认为产品不存在本金损失风险。

审核依据：
金融营销内容审核规则V3，第18条。

修改建议：
删除保证性表达，并补充明确的风险提示。
```

页面根据整体结果展示相应的下一步操作，例如修改内容、申请人工确认、修改并重新提交，或查看人工复核进度。

这里的重点不是页面设计，而是AI结果必须被翻译成用户能看懂、能够继续行动的产品结果。

## 六、运营修改后的重新审核流程

假设运营人员把原文修改为：

> 根据公司历史数据统计，截至2026年6月，该产品过去一年收益率为8%。历史表现不代表未来收益，实际结果可能受到市场波动影响。

修改后不能直接沿用上一版审核结果。流程应该是：

```text
原始内容V1
→ 机器审核
→ 退回修改
→ 运营修改
→ 形成内容V2
→ 重新进行机器审核
```

因为修改可能解决原来的风险，也可能产生新风险。AI修改建议只能帮助用户修改，不能自动认为修改后的内容已经通过。

## 七、人工复核的触发条件

不是所有机器结果都适合直接退回运营修改。

例如：

> 本产品是为追求稳健收益的投资者设计的。

规则可能认为“稳健收益”命中收益风险词，而大模型认为“追求稳健收益”描述的是用户目标，不一定等于承诺产品收益稳定。RAG找到的规则则说明，可以描述目标用户的风险偏好，但不得暗示产品保证实现相应收益。

这时不应该强行选择一个结论，而应该：

```text
标记存在判断分歧
→ 展示规则、模型和知识依据
→ 转人工复核
```

人工复核主要处理：

- 上下文歧义；
- 规则和模型冲突；
- 依据不完整；
- 高风险内容；
- 需要业务责任人判断的例外。

## 八、人工审核需要的信息与动作

人工审核人员不应该重新从零开始读全文。系统应该展示：

- 当前待审核文案；
- 机器整体结果；
- 风险片段；
- 规则命中情况；
- 大模型判断；
- RAG找到的依据；
- 转人工原因；
- 运营已经修改过的版本。

人工可以执行四类主要动作。

### 1. 复核通过

适用于机器误判、当前语境不构成实际风险、已有充分业务依据或内容满足当前规则的情况。机器认为高风险但人工选择通过时，需要记录原因。

### 2. 驳回修改

人工应该指出需要修改的片段、问题类型、修改原因和修改后是否需要再次人工审核。

### 3. 调整机器结果

人工可以调整风险类型和风险等级，但调整结果需要记录原因，不能只覆盖原始机器结果。

### 4. 升级处理

普通审核人员无法决定时，可以升级给高级审核人员、法务、合规负责人或业务负责人。第一版不一定实现复杂多级审批，但不应该强迫当前审核人员给出超出权限的结论。

## 九、人工结果回到产品流程

人工复核通过时：

```text
待人工复核
→ 人工复核通过
→ 返回运营人员
```

人工驳回修改时：

```text
待人工复核
→ 人工驳回修改
→ 返回运营人员
→ 运营修改
→ 形成新版本
→ 重新机器审核
```

人工升级处理时：

```text
待人工复核
→ 升级处理中
→ 指定责任人继续处理
```

人工结果应该记录人工最终结论、调整后的风险类型和等级、处理原因、修改建议、处理人和处理时间。这些记录可以在后续用于评测、规则补充和模型优化。

## 十、完整案例的产品流程

### 第一步：运营提交V1

```text
这款产品是目前最值得购买的理财产品，
预计年化收益可达20%，收益稳定，
完全不用担心亏损。
```

### 第二步：系统识别风险

规则、大模型和RAG共同发现绝对化表达、收益数据依据不足、收益误导、收益保证和风险隐瞒四项问题。

### 第三步：系统合并结果

```text
整体风险等级：高
风险数量：4
处理建议：转人工复核
```

文案涉及金融收益保证和风险隐瞒，属于需要人工承担最终判断责任的高风险内容。

### 第四步：人工复核

```text
人工复核结果：驳回修改

复核意见：
删除绝对化和保证性表达；
补充收益数据来源、统计周期和风险提示；
修改后需要重新提交审核。
```

### 第五步：运营生成V2

> 根据公司历史数据统计，截至2026年6月，该产品过去一年收益率为8%。历史表现不代表未来收益，实际结果可能受到市场波动影响。

### 第六步：重新审核

系统重新运行规则、RAG和大模型审核。如果未发现需要阻断的问题，则将V2标记为机器预审通过。

完整流程是：

```text
运营提交V1
→ 机器发现风险
→ 转人工复核
→ 人工驳回修改
→ 运营生成V2
→ 重新机器审核
→ 机器预审通过
→ 运营进入原有后续流程
```

## 十一、人工调整、内容版本与机器失败记录

人工复核不是把机器结果直接覆盖掉。为了在出现问题时还原当时的决策过程，第一版至少需要保留四条底线。

### 1. 机器原始结果和人工最终结果同时保留

例如：

```text
机器原始结果：高风险，建议转人工
人工最终结果：复核通过
```

系统不能只保存“通过”，否则以后无法判断是机器漏判，还是人工覆盖机器结果后出现了问题。

### 2. 人工修改机器结果时必须记录原因

至少在以下情况中要求填写原因：

- 机器高风险被人工改为通过；
- 机器通过被人工改为驳回；
- 风险类型发生修改；
- 风险等级发生修改。

最小记录包括：

```text
机器原始结果
人工最终结果
修改原因
操作人
操作时间
```

### 3. 内容发生实质修改后必须重新审核

```text
内容V1
→ 审核通过

运营修改正文
→ 生成内容V2
→ 原审核结果不再适用
→ 重新审核
```

每次审核至少需要绑定当时的内容版本、规则版本和模型/Prompt版本，避免新内容继续沿用旧结果。

### 4. 机器审核失败不得默认通过

如果出现规则服务失败、RAG无法提供依据、模型调用超时或输出格式错误，处理应该是：

```text
机器审核未完成
→ 保留已经产生的结果
→ 允许安全重试
→ 再次失败时转人工
```

统一原则是：

> 没有完成审核，不等于审核没有问题。

## 十二、将审核处理流程写进PRD

这一节最终需要在PRD中写清三项内容。

### 1. 审核结果结构

包括整体审核结果、整体风险等级、风险项列表，以及每个风险的片段、类型、理由、依据、建议和是否需要人工复核。

### 2. 结果与处理动作的映射

```text
没有风险
→ 机器预审通过

低风险
→ 建议修改

明确可修改问题
→ 退回修改

高风险、不确定或依据冲突
→ 转人工复核
```

### 3. 人工复核流程

包括什么条件触发人工复核，人工需要查看哪些机器结果，可以执行哪些动作，人工结果如何返回运营，以及内容修改后是否需要重新审核。

### 4. 最小决策追溯要求

包括机器原始结果、人工最终结果、人工调整原因、内容与AI版本，以及机器审核失败后的重试和转人工要求。

## 十三、本节需要真正理解的内容

第二节解决的是：

> 每种能力负责发现什么问题。

第三节解决的是：

> 问题被发现以后，产品怎样让用户继续完成任务。

两节连起来就是：

```text
规则、大模型和RAG发现风险
→ 系统合并风险
→ 形成整体审核结果
→ 映射为具体处理动作
→ 运营修改或人工复核
→ 修改后重新审核
```

机器在第一版中负责识别风险、解释风险、给出修改建议并把任务送入正确流程，但不替代人工承担最终合规责任，也不自动发布内容。

本节完成以后，我们得到AI产品PRD中的四项内容：

1. 结构化审核结果；
2. 审核结果与产品动作的映射；
3. 运营修改和人工复核的完整流程；
4. 机器与人工结果、版本和失败处理的最小追溯要求。

下一节将继续回答：

> 这么多能力里，第一版究竟做到哪里，哪些必须进入MVP，哪些应该暂时不做。
