## 一、本模块PPT设计原则

1. 只建立支持产品判断的最低必要生成心智模型；
2. 使用“逐步预测后续Token”作为简化表述，不冒充完整技术原理；
3. 不把大模型讲成固定答案库、数据库查询或纯随机拼字；
4. 概率图只用于教学示意，不伪装成真实模型内部概率；
5. Temperature只讲发散程度，不讲成正确率按钮；
6. 区分“结果不同”和“事实错误”；
7. 最后一页只建立测试意识，不提前讲完整评测体系；
8. 不展开Transformer、Attention、预训练过程和采样算法。

### 本模块视觉系统

- 当前上下文：深蓝色容器；
- 候选Token：3—5个浅色卡片；
- 被选Token：青绿色高亮；
- 风险或错误：低饱和橙红；
- 每页沿用同一套“上下文→候选→选择→继续”视觉语言；
- 概率数字必须标注“教学示意”。

## 第7页｜大模型不是固定答案库

### 页面标题

> 大模型生成答案，不是简单地“找到一条现成答案”

### 页面上屏文字

#### 左侧：两种常见误解

```text
像搜索引擎
从已有内容中找到一条相关结果

像数据库
根据明确条件返回已有记录
```

#### 右侧：本课采用的简化理解

```text
大模型
根据当前上下文，
逐步预测接下来更可能出现的Token，
并连续生成结果。
```

底部小字：

```text
这是支持产品判断的最低必要心智模型，不是完整技术原理。
```

### 版式结构

- 左侧约42%：搜索引擎、数据库两张卡；
- 中间使用“≠简单等同”连接；
- 右侧约58%：大模型逐步生成卡；
- 右侧卡片内部用短Token流作为视觉，不放完整长句。

### 视觉重点

- 搜索和数据库不是“错误技术”，只是不能简单等同于大模型开放生成；
- 避免使用红叉把搜索、数据库描述成落后或无价值；
- “当前上下文”“逐步预测”“Token”使用主强调色。

### 动画顺序

1. 搜索引擎卡出现；
2. 数据库卡出现；
3. 中间“不简单等同”出现；
4. 大模型简化理解出现；
5. 底部边界说明出现。

### 停留时间

约2分钟。

### 讲课动作

老师说明三点：

1. 大模型产品可以和搜索、数据库结合；
2. 但开放生成不是简单复制一条现成答案；
3. 后面所有产品判断都基于这个简化心智模型。

避免讲：

- 大模型完全没有理解；
- 大模型只是高级搜索；
- 大模型永远不使用外部知识。

### 老师备注来源（不投屏）

```text
知识依据：K1｜A1录音P481—P490、P499—P526｜A1课件14—15页
```

### 对应讲义

- 学生版模块02“一、排除三种不完整理解”；
- 老师版模块02“大模型不是固定答案库”。

## 第8页｜它怎样一步一步生成？

### 页面标题

> 大模型怎样一步一步生成答案？

### 页面上屏文字

```text
当前上下文
“为了备战周末马拉松，
下班后我准备去公园……”

        ↓

计算多个后续Token的可能性

        ↓

按生成策略选出一个Token

        ↓

把新Token加入上下文

        ↓

继续生成
```

右下角主结论：

```text
每生成一步，后续判断的上下文也随之变化。
```

### 版式结构

- 页面中央使用横向或环形五步流程；
- 顶部显示当前上下文短句；
- 中间展示3—5个候选Token卡片；
- 被选中的Token进入下一轮上下文；
- 右下角保留结论卡。

### 建议视觉演示

第一轮：

```text
上下文……去公园 → 跑步／散步／见朋友
```

选择“跑步”后：

```text
上下文……去公园跑步 → 训练／放松／五公里
```

页面中的“跑步／散步／见朋友”是为了便于理解而合并展示的候选后续，可能包含一个或多个Token；不把它们标成单个Token，也不标真实概率。

### 动画顺序

1. 当前上下文出现；
2. 候选Token出现；
3. 一个Token高亮；
4. 高亮Token移动到上下文尾部；
5. 第二轮候选出现；
6. 结论出现。

不建议使用复杂路径动画，保证在线共享屏幕稳定。

### 停留时间

约2分30秒。

### 讲课动作

老师使用“一步一步续写”的口语解释，不讲矩阵和模型层：

> 模型不是先把整段答案想好，再逐字显示。它会在当前上下文下不断决定下一步，刚刚生成的内容又会影响后面。

### 老师备注来源（不投屏）

```text
知识依据：K1｜A1录音P481—P526
```

### 对应讲义

- 学生版模块02“二、什么是逐步生成”；
- 老师版模块02“续写演示”。

## 第9页｜加一句背景，后续为什么会变？

### 页面标题

> 只增加一句背景，后续为什么会变化？

### 页面上屏文字

#### 左侧

```text
下班后，
我准备去公园……

可能续写
散步｜跑步｜看花｜见朋友
```

#### 右侧

```text
为了备战周末马拉松，
下班后我准备去公园……

可能续写
跑步｜训练｜完成五公里
```

底部主结论：

```text
上下文会改变后续候选的可能性。
相关背景能引导结果，错误或冲突背景也可能误导结果。
```

### 版式结构

- 左右两列使用完全相同的版式；
- 新增的“备战周末马拉松”使用高亮底色；
- 候选词使用小标签；
- 右侧与训练相关的词视觉权重更高，但不显示虚构精确概率。

### 互动方式

先只展示两段未完成句子，提问：

```text
请各说一个你觉得最可能出现的后续。
```

收集2—3个答案后，再展示候选词和结论。

### 动画顺序

1. 左右两段前文出现；
2. 学员续写；
3. 左右候选标签出现；
4. 新增背景高亮；
5. 底部结论出现。

### 停留时间

约2分30秒。

### 讲课动作

老师从语言例子转到产品：

> 在销售助手中，客户背景、商机阶段、字段定义和事实规则，同样会改变模型接下来的生成。但不是信息越多越好，下一模块会专门讨论应该给什么。

### 老师备注来源（不投屏）

```text
知识依据：K1、K4｜A1生成逻辑＋本课程产品转译
```

### 对应讲义

- 学生版模块02“三、为什么前文会改变结果”；
- 老师版模块02“上下文改变续写”。

## 第10页｜一个位置通常有多个合理后续

### 页面标题

> 一个位置，通常不只有一个合理后续

### 页面上屏文字

```text
当前上下文
“下班后，我准备去公园……”
```

候选示意：

| 候选后续（可含多个Token） | 可能性示意 |
|---|---:|
| 散步 | 34% |
| 跑步 | 29% |
| 见朋友 | 18% |
| 拍照片 | 11% |
| 其他 | 8% |

页面角标：

```text
候选短语和数字仅为教学示意，
不是某个模型的真实Token切分或内部概率。
```

底部结论：

```text
开放任务往往存在多个合理生成路径。
```

### 版式结构

- 左侧约40%：当前上下文；
- 右侧约60%：横向概率条；
- 条形使用同一色系深浅；
- 不用饼图，方便比较候选；
- 教学示意角标必须始终可见。

### 动画顺序

1. 当前上下文出现；
2. 五个候选条同时出现；
3. 最高候选轻微高亮；
4. 底部结论出现。

### 停留时间

约2分30秒。

### 讲课动作

老师强调：

- 图中短语是对多条可能生成路径的可读化简化，不等于单个Token；
- 候选不只有一个；
- 最高可能不等于必然被选择；
- 第一步不同，会改变后面的上下文；
- “可能不同”不等于“每次一定不同”。

不要展开Top-k、Top-p、logits或采样公式。

### 老师备注来源（不投屏）

```text
知识依据：K2｜A1录音P499—P532｜A1课件14—15页
```

### 对应讲义

- 学生版模块02“四、为什么同一句Prompt可能不同”；
- 老师版模块02“候选Token与概率”。

## 第11页｜Temperature影响发散，不是正确率按钮

### 页面标题

> Temperature影响发散程度，不是“正确率按钮”

### 页面上屏文字

#### 中央滑杆

```text
较低                                      较高
更集中、更保守                更多样、更发散
```

#### 下方四个边界

```text
不等于：越低越正确

不等于：设为0后所有平台绝对一致

不能：补充模型没有拿到的知识

不能：代替任务定义和业务规则
```

### 版式结构

- 页面上半部：一条从低到高的Temperature滑杆；
- 左端候选词较集中，右端候选词更多样；
- 页面下半部：四张“不等于／不能”边界卡；
- “正确率按钮”使用低饱和风险色划掉。

### 视觉示意

可用同一个任务展示：

```text
任务：写一句产品宣传语

较低：表达更接近常见稳妥句式
较高：表达方式更多样
```

不要使用事实提取任务暗示提高Temperature会带来“更好创意且同样准确”。

### 动画顺序

1. 滑杆出现；
2. 左端“集中”出现；
3. 右端“发散”出现；
4. 四个边界同时出现。

### 停留时间

约2分30秒。

### 讲课动作

老师只讲直觉：

> Temperature可以影响选择更集中还是更发散，但它不是事实正确率的开关。任务不清楚、材料缺失、规则错误时，调低Temperature并不会把问题自动修好。

### 老师备注来源（不投屏）

```text
知识依据：K2｜A1录音P517—P532｜A1课件14—15页
```

### 对应讲义

- 学生版模块02“五、Temperature是什么”；
- 老师版模块02“Temperature直观解释”。

## 第12页｜结果不同，不等于发生幻觉

### 页面标题

> 结果不同，与结果错误，是两件事

### 页面上屏文字

#### 左侧：可能只是合理差异

```text
任务
为销售助手写一句宣传语

结果A
拜访结束，关键信息自动成稿

结果B
让每次客户沟通，都留下可跟进的记录

判断
表达不同，但都可能合理
```

#### 右侧：更需要警惕的错误

```text
编造材料中不存在的事实

把未知内容说成确定事实

与给定材料发生冲突

生成无法验证的引用、数据或承诺
```

底部：

```text
先问“是否与任务和证据冲突”，
不要只因为两次答案不同就称为幻觉。
```

### 版式结构

- 左右两栏；
- 左栏使用两张同权重输出卡；
- 右栏使用四个风险标签；
- 中间放“不同 ≠ 错误”的大号符号。

### 互动方式

老师展示左侧两条宣传语，提问：

```text
它们不同，是否说明其中一条一定是幻觉？
```

学员回答后再出现右侧错误标准。

### 动画顺序

1. 任务与结果A、B出现；
2. 学员判断；
3. “不同≠错误”出现；
4. 右侧四类风险出现；
5. 底部检查句出现。

### 停留时间

约2分30秒。

### 讲课动作

老师强调：

- 创意任务允许多样；
- 事实提取、日期、金额和承诺不允许随意变化；
- 后续案例会用证据和确定性状态判断业务错误。

### 老师备注来源（不投屏）

```text
知识依据：K2、K15边界｜A1能力局限＋本课程产品转译
```

### 对应讲义

- 学生版模块02“六、结果不同是不是幻觉”；
- 老师版模块02“差异与错误的区分”。

## 第13页｜一次Demo为什么不能证明稳定？

### 页面标题

> 一次Demo成功，只能证明“这一次可以”

### 页面上屏文字

#### 左侧

```text
一次输入
一次运行
一条满意结果

只能说明
这一次得到了可接受输出
```

#### 右侧

```text
产品上线前还要观察

不同用户表达
不同材料质量
多次运行结果
高风险字段
失败后怎样处理
```

底部主结论：

```text
Prompt可以降低部分错误，
但不能把生成模型变成绝对规则系统。
```

页面右下角小字：

```text
本课只建立测试意识，完整评测方法留到后续课程。
```

### 版式结构

- 左侧使用一个单点Demo卡；
- 右侧从一个点扩展为五类测试场景；
- 中间使用放大镜或扩展箭头；
- 底部结论独立横条。

### 动画顺序

1. 左侧“一次Demo”出现；
2. “只能说明这一次”出现；
3. 右侧五类观察点逐项出现；
4. 底部结论出现；
5. 后续课程边界小字出现。

### 停留时间

约3分30秒。

### 讲课动作

老师结合不同任务说明：

- 营销创意可以接受多样；
- 文章改写表达可变，但事实不能变；
- 客户事实、金额、日期和承诺需要严格证据和确认。

收口并过渡：

> 既然结果取决于模型这一次获得了什么信息，接下来就要理解Token和上下文窗口：一次任务到底能装多少，又应该装什么。

### 老师备注来源（不投屏）

```text
知识依据：K2、K13边界｜本课程产品转译
```

### 对应讲义

- 学生版模块02“七、产品含义”；
- 老师版模块02“产品经理必须形成的三个判断”。
