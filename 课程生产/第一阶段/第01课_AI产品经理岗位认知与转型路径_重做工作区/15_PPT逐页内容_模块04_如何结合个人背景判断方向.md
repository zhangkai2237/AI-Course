## 一、本模块PPT设计原则

1. 本模块不做性格测试，也不根据职业名称直接推荐方向；
2. 先盘点真实经历，再形成方向假设，最后用真实JD验证；
3. 六类资产不是官方能力模型，也不要求六项均衡；
4. 不使用雷达图和1—10分自评，防止制造虚假的精确感；
5. 每项资产都要落到具体事件，不接受只有能力标签的表达；
6. 优先方向和备选方向都只能称为“待验证假设”；
7. 平台和解决方案相关判断继续标记“待真实JD验证”；
8. 第36、37页只演示推导过程，不建立职业与方向的固定映射；
9. 第38页留出完整3分钟填写，老师不继续讲新知识；
10. 不使用真实公司Logo、内部项目或讲师当前身份为案例背书。

### 六类资产视觉系统

| 资产 | 建议图标 | 页面短标签 | 核心判断 |
|---|---|---|---|
| 行业 | 建筑／行业网络 | 懂行业 | 能否讲清行业角色、规则和约束 |
| 用户 | 人物／观察 | 懂用户 | 是否长期服务、观察并影响过一类用户 |
| 业务 | 流程箭头 | 懂业务 | 能否讲清流程、指标和关键异常 |
| 产品 | 原型／功能模块 | 做产品 | 是否承担过问题、方案、上线和复盘责任 |
| 数据与技术协作 | 数据节点／接口 | 能协作 | 是否与数据、研发等共同解决过复杂问题 |
| 客户与项目交付 | 握手／里程碑 | 能交付 | 是否参与过方案、试点、实施、验收和采用 |

六类卡片使用同等视觉权重，不表达排序，也不暗示每个人都要拥有六项强证据。

## 第31页｜先别问哪个最热门

### 页面标题

> 选方向，先别问“哪个最热门”

### 页面上屏文字

#### 左侧：常见但无效的问题

```text
哪个方向最热门？
哪个方向薪资最高？
别人都在学什么？
```

左侧加一个浅灰色“×”，不展示任何市场结论。

#### 右侧：本节要解决的问题

```text
我过去有哪些真实证据？
这些证据在哪类岗位中更有价值？
我还需要用什么信息验证？
```

#### 页面底部判断链路

```text
过去经历 → 可证明资产 → 方向假设 → 真实JD验证 → 学习与项目行动
```

链路上方增加小标签：

```text
今天先完成V0.1
```

### 版式结构

- 页面上半部分左右对比；
- 左侧问题使用低饱和灰色，右侧问题使用主色；
- 底部使用一条贯穿全页的五步链路；
- “方向假设”使用虚线框，突出它不是最终结论。

### 动画顺序

1. 左侧三个常见问题出现；
2. 点击后出现“×”；
3. 右侧三个有效问题依次出现；
4. 底部判断链路从左到右展开；
5. 最后出现“今天先完成V0.1”。

### 讲课动作

老师先问：

> 如果一个方向很热门，但你目前没有任何相关证据，它一定是你转型成本最低的方向吗？

停顿后说明：

> 我们不是让大家永远留在过去，而是先找到第一块踏板。今天形成的只是一个可以被验证、也允许被修改的方向假设。

```text
知识依据：ZH02人岗匹配＋YH01 JD分析｜判断链路为本课程教学重组
```

### 对应讲义

## 第33页｜前三类资产：你理解什么

### 页面标题

> 前三类资产：你真正理解谁、什么行业、哪条业务

### 页面上屏文字

#### 行业资产

```text
不是：在某个行业待过几年
而是：能讲清角色、规则、流程、风险与约束
证据：能解释总部、区域和门店怎样完成一次活动
```

#### 用户资产

```text
不是：我自己也是这类用户
而是：长期观察、访谈或服务，并依据反馈做过改变
证据：根据访谈和留存数据调整过新用户引导
```

#### 业务资产

```text
不是：我做过电商、销售或客服
而是：能讲清流程、角色、指标和关键异常
证据：能拆解履约流程并定位问题环节
```

页面底部：

```text
“待过、用过、做过”只是经历名称；能讲清具体问题，才可能成为资产
```

### 版式结构

- 使用三栏证据卡；
- 每栏固定三层：“不是／而是／证据示例”；
- “不是”使用灰色，“而是”使用主色；
- 证据示例使用浅色底板，控制为两行以内。

### 动画顺序

1. 行业资产完整出现；
2. 用户资产完整出现；
3. 业务资产完整出现；
4. 最后显示页面底部结论。

### 讲课动作

每类控制在40—50秒。老师不要求学员当场完整回答，只让他们在纸上给自己最强的一项做标记。

提醒：所有例子均为教学示例，不暗示例子中的职业自动适合某一AI方向。

### 老师备注来源（不投屏）

```text
教学工具：T3｜案例均为CASE｜行业经验迁移依据ZH08第76—94段
```

### 对应讲义

- 第三部分“3.1 行业资产—3.3 业务资产”；
- 第七部分六类资产讲解的前三项。

## 第34页｜后三类资产：你真正做过什么

### 页面标题

> 后三类资产：你真正负责、协作和交付过什么

### 页面上屏文字

#### 产品资产

```text
不是：职位名称叫产品经理
而是：承担过问题定义、方案、推进、上线与复盘
证据：从访谈和数据发现问题，推动上线并迭代
```

#### 数据与技术协作资产

```text
不是：经常和研发沟通
而是：共同处理过指标、系统、接口、权限或异常
证据：梳理系统边界，并用日志定位异常
```

#### 客户与项目交付资产

```text
不是：沟通能力很好
而是：做过访谈、方案、试点、实施、验收或采用复盘
证据：完成流程访谈、培训和验收，并控制需求范围
```

页面底部：

```text
能力标签不能证明匹配，具体责任和行为才可以
```

### 版式结构

- 与第33页完全同版式，形成对照；
- 三栏宽度一致；
- 对“职位名称”“经常沟通”“能力很好”三个模糊表达加删除线或灰色弱化；
- 例子只显示关键事实，不放完整项目故事。

### 动画顺序

1. 产品资产；
2. 数据与技术协作资产；
3. 客户与项目交付资产；
4. 底部结论。

### 讲课动作

老师强调：

> 数据与技术协作不等于一定会写代码；客户交付也不等于一定面对外部付费客户。关键是有没有清晰的责任、协作边界和完成标准。

### 老师备注来源（不投屏）

```text
教学工具：T3｜案例均为CASE｜不得由职业名称直接推导岗位方向
```

### 对应讲义

- 第三部分“3.4 产品资产—3.6 客户与项目交付资产”；

## 第35页｜不要给自己打分

### 页面标题

> 不给自己打1—10分，先判断证据等级

### 页面上屏文字

#### 三级证据

```text
强｜承担关键责任，能讲清行动、取舍和结果
中｜深度参与并理解过程，但不是关键负责人
弱｜只有学习、体验、观察、兴趣或自我评价
```

#### 一条证据的基本结构

```text
场景 → 责任 → 行动 → 结果
```

#### 课堂判断题

```text
“我沟通能力强，适合做AI解决方案。”

这属于强、中还是弱证据？还缺什么？
```

### 第二阶段参考分析

学员回答后再出现：

```text
当前只能算弱证据
缺少｜具体场景、本人责任、关键行动、可观察结果
```

随后显示改写示例：

```text
负责三家企业客户系统上线，完成访谈、方案确认、培训与验收；
遇到超范围需求时推动确认二期边界，首期按时上线。
```

底部提醒：

```text
没有数字可以如实写验收、上线、异常解决或决策结果；不要编造数据
```

### 版式结构

- 页面上半部使用三级阶梯，但不表达“人人都必须走到强”；
- 下半部左侧放判断题，右侧互动后揭示缺失信息；
- 改写示例使用独立证据卡；
- 底部使用醒目但克制的真实性提醒。

### 动画顺序

1. 强、中、弱三级证据出现；
2. “场景—责任—行动—结果”展开；
3. 展示判断题并暂停；
4. 邀请一名学员回答；
5. 揭示“弱证据”和缺失项；
6. 展示改写示例和真实性提醒。

### 讲课动作

老师不要只公布答案，要追问：

1. 发生在哪个具体项目？
2. 他本人负责什么？
3. 做过什么关键动作？
4. 最后怎样判断完成或有效？

收口：

> 我们不是被“沟通能力强”说服，而是被具体行为和责任说服。

### 老师备注来源（不投屏）

```text
教学工具：T3三级证据法｜案例为CASE｜不代表解决方案方向已验证
```

### 对应讲义

- 第四部分“三级证据法”；
- 第七部分“61:00—64:00｜用三级证据排除主观判断”。

```text
不是“后台产品＝To B”
而是流程、权限和技术协作证据，使To B更值得优先验证
```

### 版式结构

- 左侧45%为资产证据卡，右侧45%为方向假设卡；

- 右上角保留明显倒计时区域；
- 不放任何参考答案；
- 底部四条规则始终可见。

### 动画顺序

1. 完整模板一次出现；
2. 老师讲完填写要求后启动3分钟倒计时；
3. 剩余60秒时，仅口头提醒，不增加新内容；
4. 时间到后出现“V0.1已完成”。

### 讲课动作

老师只讲以下说明，然后停止讲授：

> 每类资产最多写一条最强证据，没有就如实写弱，不需要凑满。
>
> 优先方向写一个，备选方向写一个。依据必须来自上面的证据，不能只写“我感兴趣”或“听说岗位多”。
>
> 最大缺口只写一个。我们先看清最关键的问题，不列一张让自己焦虑的清单。
>
> 最后把判断压缩成一条定位句：我已有哪两项关键证据、优先验证什么方向、下一步补什么缺口。写不完整也没有关系，先形成V0.1。

3分钟内老师巡视，不逐个点评，不打断填写。

### 时间到后的收口

```text
V0.1：基于自我盘点形成
V0.2：结合现场追问与反馈修正
V1.0：分析真实JD后再次验证
```

老师口述：

> 这不是最终职业结论。后面的现场分析会帮助几位同学形成V0.2；课后再用真实JD检查，形成V1.0。

## 三、正式PPT制作提示

### 1. 页面密度

- 第31、32页属于框架页，尽量保持留白；
- 第33—35页文字较多，正式制作时通过逐步动画控制阅读顺序；
- 第36、37页复用同一模板，方便学员比较；
- 第38页优先保证模板可读，不添加装饰性插图。

### 2. 互动控制

- 第35页必须先让学员判断，再出现参考分析；
- 第36、37页必须先展示证据，再揭示方向；
- 第38页启动倒计时后不再讲新知识；
- 互动答案不追求唯一标签，重点是证据和待验证信息。

### 3. 教学口径

正式PPT和老师讲解中统一使用以下表达：

```text
优先验证方向
备选验证方向
方向假设
强／中／弱证据
最大缺口
V0.1／V0.2／V1.0
```

避免使用：

```text
最适合你的方向
你天生适合
转型成功率
就业保证
热门赛道
六边形能力评分
```
