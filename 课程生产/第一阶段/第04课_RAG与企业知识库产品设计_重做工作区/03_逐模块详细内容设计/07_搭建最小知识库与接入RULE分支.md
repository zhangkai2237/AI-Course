# 07 搭建最小知识库与接入RULE分支（83-105分钟）

## 教学目标

完成从文档上传、分段观察、检索测试到接入上一课Workflow的最小操作闭环。

## 操作原则

- 操作目标固定，按钮名称不固定；
- 老师必须课前按当前平台重新走通；
- 不要求每位学员注册成功；
- 不上传真实公司材料；
- 不在课堂调复杂参数。

## 操作前展示最终目标

```text
开始
→ 意图分类
→ 条件分支
   ├─ RULE → 知识检索 → RAG回答 → 结束
   ├─ DATA → 安全提示 → 结束
   ├─ COMPLAINT → 转人工提示 → 结束
   └─ OTHER → 追问 → 结束
```

只修改`RULE`分支，其他路径保持上一课版本。

## 步骤一：创建教学知识库

命名建议：

`商家活动规则知识库_课堂版`

说明：

- 这是教学虚构知识库；
- 只回答商家规则问题；
- 不包含订单、GMV、补贴消耗等实时数据；
- 不包含真实公司材料。

## 步骤二：导入三份文档

先导入：

- 《新客立减活动规则V2》；
- 《活动违规与申诉说明》。

旧版本V1可以有两种教学方式：

1. 一开始就导入，用于观察冲突；
2. 先完成正常测试，再导入V1制造Bad Case。

推荐第二种，更容易看到“新增一份错误知识如何改变结果”。

## 步骤三：检查解析与分段

老师至少现场打开两个片段，带学员检查：

- 标题是否保留；
- 时间和条件是否在同一片段；
- 适用范围是否丢失；
- 申诉说明是否与活动时间混在一起；
- 文档版本是否能被识别或通过元数据补充。

如果平台只提供自动分段：

- 不展开算法；
- 记录一个不理想片段；
- 说明生产环境需要人工抽查或更细的解析策略。

## 步骤四：先做知识库检索测试

在接入Workflow前，先问：

> “新客活动到什么时候还能报名？”

只观察检索结果：

- 是否返回V2；
- 返回了哪个片段；
- 片段是否包含报名截止时间；
- 是否包含适用范围；
- 是否有无关结果。

这里故意不急着看生成答案，让学员形成“检索与生成分开验收”的习惯。

## 步骤五：接入`RULE`分支

根据当前平台选择同类能力：

- 知识检索节点；
- 在模型节点中绑定知识库；
- 应用/智能体的知识配置。

产品逻辑保持一致：

```text
RULE问题
→ 用用户原问题检索指定知识库
→ 把候选片段传给回答节点
→ 按回答规则生成
```

## 步骤六：配置最小回答规则

示例逻辑，不要求逐字照抄：

```text
你负责回答商家活动规则问题。

仅依据提供的知识片段回答，不得使用常识补充平台规则。
回答必须保留日期、适用范围和前提条件。

如果片段中没有足够依据：
明确说明“当前知识库未找到可靠答案”，并建议联系人工确认。

如果片段包含不同版本且无法确认当前有效版本：
明确提示“检索到的规则存在版本冲突”，列出冲突点，不自行选择。

输出：
1. 简洁答案
2. 适用条件
3. 依据文档/版本
```

## 步骤七：运行一条正常问题

展示三层结果：

1. Workflow进入了`RULE`；
2. 检索返回了正确片段；
3. 最终回答保留了时间、范围和依据。

任何一层失败，都记录而不是现场反复乱改。

## 平台异常备用方案

如果网络或账号失败：

- 展示预先准备的分段截图；
- 发放纸面“检索返回卡”；
- 学员从3个候选片段中选依据；
- 手工完成增强Prompt和最终回答；
- 仍然能够达成本课产品目标。

## 安全说明

- 禁止上传工作中的内部材料；
- 禁止使用含个人信息、账户信息或商业秘密的文档；
- 平台的数据使用条款和企业权限需由实际组织评估；
- 课堂知识库不代表可直接上线。
