# 第八课第二部分讲义：从 PRD 提取用户任务、页面和流程

> 建议时长：18 分钟  
> 本部分目标：把第七课的正式 PRD 转换成生成原型与 Demo 之前的“结构蓝图”。

## 一、承接第一部分：生成 Demo 前还缺什么

第一部分已经看到：即使 PRD 正确，AI 直接生成的 Demo 仍可能擅自增加功能、做错规则或遗漏状态。

问题不只是 Prompt 不够长，而是 PRD 与 Demo 之间还缺少一层产品设计判断：

```text
用户要完成什么任务
→ 需要哪些页面或界面载体
→ 用户怎样完成一条完整流程
```

本部分先完成这三层转译，不生成 HTML，也不讨论视觉风格。

核心句：

> PRD 定义产品规则，Demo 蓝图定义用户如何完成任务。

---

## 二、第一步：先找用户任务，不要先列页面

如果直接从 PRD 标题推导页面，很容易把文档章节机械地做成页面。正确的起点是用户目标。

商品对比工具的核心用户目标是：

> 用户已经形成 2 至 4 个候选手机，希望快速识别关键差异，减少反复切换页面，并继续完成购买决策。

围绕这个目标，可以拆出八个子任务：

1. 选择具体 SKU；
2. 确认已选商品和数量；
3. 进入商品对比；
4. 查看核心参数差异；
5. 切换“只看差异”或“全部参数”；
6. 理解价格条件、参数缺失和参数冲突；
7. 删除或替换商品；
8. 返回商品详情继续决策。

这里要特别注意：

- “浏览参数表”只是页面行为，不是完整用户任务；
- “AI 推荐最合适的手机”不属于一期范围；
- 页面必须能追溯到一个真实用户任务，否则就要检查它是否多余。

---

## 三、第二步：从任务推导必要页面

两小时课堂不做完整电商 App，只保留支撑核心流程的三个界面。

| 界面 | 支持的任务 | 必须表达的内容 |
|---|---|---|
| 商品选择页 | 选择具体 SKU、加入对比 | SKU、加入状态、类目与数量规则 |
| 底部对比栏 | 确认已选商品、进入对比 | 已选商品、当前数量、删除入口、进入条件 |
| 商品对比页 | 查看差异并继续决策 | 核心参数、全部参数、只看差异、价格条件、缺失与冲突 |

参数反馈、删除确认和超限提示可以通过页面内提示、弹窗或浮层完成，不必为了每一种状态新增独立页面。

判断页面是否必要，可以追问：

1. 它服务于哪个用户任务？
2. 用户从哪里进入？
3. 完成操作后去哪里？
4. 删除这个页面后，核心任务还能否完成？

核心句：

> 页面不是 PRD 章节的可视化，而是用户完成任务的载体。

---

## 四、第三步：把页面连成完整流程

主流程如下：

```text
选择具体 SKU
→ 加入对比
→ 查看底部对比栏
→ 继续选择候选商品
→ 进入商品对比页
→ 查看核心参数差异
→ 切换“只看差异”或“全部参数”
→ 删除、替换或返回继续浏览
```

流程不能只覆盖顺利完成的理想路径，还要补充最关键的分支：

| 场景 | 页面反馈 | 用户下一步 |
|---|---|---|
| 只选择 1 个商品 | 暂不能开始对比，提示至少再选 1 个 | 继续选择 |
| 已选择 4 个商品 | 阻止加入第 5 个，并说明上限 | 删除或替换 |
| 加入跨三级类目商品 | 说明一期不支持跨类目 | 取消或清空后重选 |
| 删除一个商品 | 更新数量与进入条件 | 继续选择或对比 |
| 返回商品列表或详情 | 保留本地临时选择 | 继续浏览 |

检查一条流程时，至少回答五个问题：

- 用户从哪里进入；
- 用户怎样完成目标；
- 成功后去哪里；
- 失败时怎样恢复；
- 中途返回后，已完成的操作是否保留。

## 五、课堂演示：让 Codex 先生成 Demo 蓝图

这一轮明确不让 Codex 写代码。先让它读取第七课的正式产物，提取任务、页面和流程，再由产品经理检查。

### Prompt 示例

```text
请读取当前项目中的以下正式材料：

1. 商品对比工具最终 PRD；
2. 产品决策记录；
3. 第七课产品决策摘要；
4. 商品样例数据。

本轮不要生成 HTML、代码或视觉稿，只完成 Demo 生成前的结构梳理。

请输出：

1. 核心用户目标；
2. 用户为完成目标需要执行的子任务；
3. 支持这些任务所必需的页面或界面载体；
4. 一条完整的核心用户流程；
5. 数量不足、达到上限、跨类目、删除商品等关键分支；
6. 当前材料中仍然缺少的交互决策。

要求：

- 每个页面必须能够追溯到具体用户任务；
- 不得添加 PRD 没有确认的功能；
- 无法从材料中确定的内容标记为“待产品经理确认”；
- 区分正式产品决策与 AI 提出的交互建议；
- 不讨论视觉风格和技术实现；
- 不生成代码，也不要修改项目文件。

请使用以下结构输出：

A. 核心用户目标
B. 用户任务清单
C. 任务—页面映射表
D. 主流程与关键分支
E. 待确认交互决策
```

### 产品经理如何检查 AI 的结果

不要因为输出结构完整就直接接受。重点检查：

1. 是否遗漏“选择具体 SKU”等已确认规则；
2. 是否把 AI 推荐、登录或云端保存偷偷加入页面；
3. 是否每个页面都能追溯到用户任务；
4. 是否有入口、返回路径和失败恢复；
5. 是否把待确认问题写成了既定方案。

如果 AI 给出多个交互方案，产品经理需要完成取舍并记录决策，不能让 AI 默认选择。

## 六、本部分课堂产出

本部分形成三项可继续使用的输入：

1. 《用户任务与页面清单》；
2. 《核心用户流程》；
3. 《待确认交互决策》。

这三项内容确认后，下一部分才进入页面信息架构和低保真结构验证。

过渡串词：

> 现在我们还没有画页面，但已经知道用户要完成什么、需要经过哪些界面，以及流程在哪里可能中断。下一步再把这些任务和规则放到页面结构中，检查信息应该出现在哪里、用户能不能顺利完成操作。
