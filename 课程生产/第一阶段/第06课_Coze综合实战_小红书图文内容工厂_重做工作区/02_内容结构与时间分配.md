# 第06课内容结构与时间分配

> 基准时长：180分钟，含7分钟休息  
> 互动充分版：190—200分钟  
> 课堂形态：纯Coze实操，不讲独立产品化

## 一、课程目标

在同一个小红书项目中完成Prompt、Workflow、RAG和Agent四次升级，让学员能操作、能测试、能解释四种能力的关系和边界。

## 二、180分钟安排

| 时间 | 模块 | 学员核心操作 | 课堂产物 |
|---|---|---|---|
| 0—10 | 01 最终效果与环境检查 | 运行老师最终版；复制四个模板；检查模型与额度 | 环境检查通过 |
| 10—30 | 02 Prompt主实操 | 完成Start→LLM→End；配置结构化Prompt；运行两条测试 | P0文案生成器 |
| 30—38 | Prompt迁移挑战 | 将Prompt改为差评回复生成器 | P0挑战版 |
| 38—75 | 03 Workflow主实操 | 增加输入检查、角度、正文、图片脚本、图片、审核节点 | P1图文Workflow |
| 75—83 | Workflow迁移挑战 | 修改下游节点，输出60秒短视频口播稿 | P1挑战版 |
| 83—90 | 休息 | 保存版本；老师检查后续知识库和Agent模板 | — |
| 90—115 | 04 个人语气RAG主实操 | 导入本人历史文字；检索样本；提取语气卡；隔离历史事实 | P2语气RAG Workflow |
| 115—123 | RAG边界测试 | 测试历史事实不迁移、跨体裁输出、无命中与防抄句 | P2测试记录 |
| 123—155 | 05 Agent主实操 | 配置Agent目标、工具、调用条件、确认与停止；运行五条测试 | P3内容策划Agent |
| 155—163 | Agent迁移挑战 | 改造成新品上市内容策划Agent | P3挑战版 |
| 163—175 | 06 四版本统一测试 | 同一请求分别运行四版，填写能力对照 | 四版本测试记录 |
| 175—180 | 07 总结与课后任务 | 保存、命名、提交链接；确定自己的迁移方向 | 四份产物＋作业 |

## 三、课堂节奏规则

每个主实操模块都必须包含：

1. 2—3分钟最终效果演示；
2. 3分钟说明本轮新增能力；
3. 12—25分钟学员配置；
4. 5—8分钟正常与边界测试；
5. 2分钟记录本轮结论；
6. 8分钟迁移挑战。

## 四、主项目升级路线

```text
P0 Prompt
Start → LLM → End

P1 Workflow
Start → 输入检查 → 内容角度 → 标题正文 → 图片脚本
→ 图片生成/图片Prompt → 内容审核 → End

P2 个人语气RAG Workflow
Start → 输入检查 → 形成语气检索问题 → 检索历史表达样本
→ 提取抽象语气卡 → 内容角度 → 按语气生成 → 图片 → 事实与语气审核 → End

P3 Agent
用户目标 → 检查信息 → 按需搜索/查知识
→ 调用P2 Workflow → 展示结果 → 确认后保存草稿 → Stop
```

## 五、课堂统一输入

```text
topic：为什么学会Prompt还不等于会做AI产品
audience：1—3年经验、希望转向AI产品的产品经理
goal：引发收藏、评论或课程咨询
source_material：Prompt只解决模型如何理解已有信息；真实产品还涉及流程、知识、工具、风险和验证
tone：真实、克制、有方法，不制造焦虑
image_style：简洁编辑感、米白背景、蓝绿色点缀
```

## 六、统一产出格式

- 5个标题；
- 1篇小红书正文；
- 3—5个标签；
- 1句封面文案；
- 3张内页脚本；
- 1组图片提示词或实际图片；
- 事实依据；
- 风险与需人工确认项。

## 八、完成标准

### P0

- 输入完整时可以生成结构化内容；
- 输入不足时暴露Prompt-only的边界；
- 输出不存在未提供的真实经历。

### P1

- 必要变量能够传递；
- 缺信息时走停止分支；
- 正常路径产生正文和图片相关输出；
- 能查看每个节点的输入和输出。

### P2

- 历史文字样本解析正常；
- 能看到实际检索片段并生成抽象语气卡；
- 历史原文不直接进入写作节点；
- 新内容事实只来自本次source_material；
- 非小红书样本也能迁移语气，但输出仍符合小红书体裁。

### P3

- 信息不足时先追问；
- 完整材料时不重复搜索；
- 需要生产内容时调用P2 Workflow；
- 保存草稿前确认；
- 无发布工具时不声称已经发布。

## 九、课堂边界

- 不搭独立前端；
- 不调用Coze API；
- 不做用户登录与支付；
- 不接真实小红书账号；
- 不自动发布；
- 不使用真实公司和客户数据；
- 不讲MCP和Multi-Agent；
- 不要求学员写代码。
