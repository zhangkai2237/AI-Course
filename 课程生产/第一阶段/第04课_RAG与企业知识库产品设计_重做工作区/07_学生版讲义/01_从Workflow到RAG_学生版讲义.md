# 01 从Workflow到RAG

上一课搭建了四路商家咨询Workflow：

```text
用户问题
→ 意图分类
  ├─ RULE：规则问题
  ├─ DATA：实时数据问题
  ├─ COMPLAINT：投诉与高风险问题
  └─ OTHER：信息不足或其他问题
```

当时`RULE`分支只能读取一张固定规则卡。如果规则变成大量文档并持续更新，会出现：

1. 全部塞进Prompt，占用大量上下文；
2. 同一规则被复制到多个地方，更新容易遗漏；
3. 回答出错时，不知道使用了哪份资料；
4. 新旧版本可能同时存在；
5. 不同用户可能拥有不同访问权限。

本课将`RULE`升级为：

```text
RULE
→ 检索商家规则知识库
→ 找到与问题相关的知识片段
→ 基于依据回答
→ 显示来源或进入兜底
```

其他路径仍然保留：

- 实时数据查询业务系统；
- 投诉和赔付进入人工；
- 信息不足先追问。
