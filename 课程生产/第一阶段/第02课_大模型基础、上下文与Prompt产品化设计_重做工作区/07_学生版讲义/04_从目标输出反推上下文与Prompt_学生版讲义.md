# 模块04：从目标输出反推上下文与Prompt

> 课堂时间：40—53分钟基准版；充分互动时约15—16分钟  
> 本模块任务：先定义结果和必要信息，再开始写Prompt  
> 课堂产出：目标输出、验收标准和上下文清单V0.1

## 一、为什么不要直接从Prompt开始

下面这段话看起来很长：

> 你是一位非常资深、非常专业、逻辑严密、洞察敏锐、表达清晰的销售专家。请认真、全面、深入地分析下面的内容，输出一份高质量、专业、有价值、让人满意的销售拜访总结。

但它仍然没有说清：

- 结果给谁使用；
- 在什么时点使用；
- 需要哪些具体内容；
- 什么事实不能推测；
- 缺失信息怎样处理；
- 输出怎样才算合格；
- 结果之后进入什么动作。

“专业、深入、高质量”是形容词，不是可检查的产品要求。

因此：

> Prompt不是产品设计的起点，清楚的用户任务和目标输出才是起点。

## 二、正确的设计顺序

设计时可以按照：

谁在什么时点使用  
→ 需要什么目标输出  
→ 怎样判断输出可用  
→ 模型需要哪些信息  
→ 最后设计Prompt和处理流程

这里的“输出—输入—处理”是产品设计顺序，不是系统运行顺序。

## 三、先固定首要用户

同一段拜访录音，交给不同用户，结果重点会不同：

| 使用者 | 主要目的 | 关注内容 |
|---|---|---|
| 一线销售 | 检查并推进下一步 | 诉求、异议、行动项 |
| 销售主管 | 判断风险并辅导销售 | 商机阶段、缺口、风险 |
| 客户 | 确认双方共识 | 结论、双方行动和时间 |
| CRM系统 | 形成结构化记录 | 固定字段、状态和证据 |

如果一个Prompt同时服务所有人，容易出现：

- 输出内容太多；
- 内外部信息混在一起；
- 字段与阅读体验冲突；
- 任务无法验收。

本课统一假设：

> 一线销售在拜访结束后10分钟内检查AI草稿，录入CRM并准备下一步跟进。

这句话已经包含：

- 用户：一线销售；
- 时点：拜访结束后10分钟内；
- 任务：检查事实并录入CRM；
- 下一步：准备跟进。

## 四、目标输出和输出格式不是一回事

### 目标输出

目标输出回答：

> AI最终需要交付哪些具体内容？

例如：

- 客户核心诉求；
- 客户明确表达的异议；
- 试点范围与状态；
- 下一步行动；
- 待确认信息。

### 输出格式

输出格式回答：

> 结果以什么形式呈现？

例如：

- 表格；
- JSON；
- 分段文本；
- 卡片；
- CRM字段。

“用表格输出”不能替代业务定义。一个格式整齐的表格，也可能充满错误事实。

## 五、什么是验收标准

验收标准回答：

> 我们怎样判断结果可以使用？

销售拜访助手可以包括：

- 重要结论能在转写中找到依据；
- 客户事实、销售判断和AI建议分开；
- 负责人或时间不明确时标记待确认；
- 不自行补充预算、决策人和采购时间；
- 行动项能支持销售创建后续任务；
- 高风险结论能够返回原文核对。

对比：

| 不可验收的要求 | 更可验收的要求 |
|---|---|
| 结果要专业 | 每条行动项有人、事、时间和状态 |
| 内容要准确 | 关键事实附原文证据 |
| 分析要全面 | 至少覆盖诉求、异议、行动项和待确认 |
| 不要幻觉 | 不把推测写成事实，缺失时标记待确认 |

## 六、从输出反推上下文

定义输出后，再问：

> 模型为了完成这一项输出，需要得到什么信息？

| 目标输出 | 必要上下文 | 用途 |
|---|---|---|
| 客户核心诉求 | 本次拜访转写 | 判断客户明确表达了什么 |
| 关键原话 | 带说话人标签的转写 | 避免混淆销售和客户 |
| 主要异议 | 转写＋讨论的产品方案 | 理解客户反对的对象 |
| 下一步行动 | 转写 | 找到双方明确承诺 |
| CRM字段 | 字段定义 | 让结果进入后续流程 |
| 待确认信息 | 缺失信息规则 | 防止模型自行补齐 |

## 七、上下文可以分成三类

### 1. 事实材料

告诉模型发生了什么：

- 本次转写；
- 客户资料；
- 订单或商机数据；
- 原始文档。

### 2. 任务背景

告诉模型结果给谁用、在什么时点使用：

- 目标用户；
- 工作阶段；
- 结果用途；
- 下一步动作。

### 3. 业务规则

告诉模型哪些边界不能越过：

- 不得把推测写成事实；
- 缺失信息标待确认；
- 哪些字段必须有证据；
- 哪些内容必须人工确认。

## 八、必要、按需和暂不需要

上下文不是越多越好，可以分为：

### 必要

缺少后会明显影响当前核心输出。

### 按需

只在某些子任务或特定情况使用。

### 暂不需要

与当前任务没有直接关系，或存在噪声、冲突、权限风险。

判断方法：

> 如果删除这项信息，哪一项目标输出会明显变差？

如果回答不出来，先不要默认提供。

## 九、课堂练习：完成V0.1

打开课堂版设计单。

### 基准版

1. 使用老师给定的用户和使用时点；
2. 在示例基础上补充1项目标输出和验收标准；
3. 从候选信息中选择至少3项上下文；
4. 标明事实、背景或规则，以及必要、按需或暂不需要。

### 充分互动版

在基准版基础上：

- 再补充1项目标输出；
- 把用户改为销售主管或客户，观察输出怎样变化；
- 分享一项由默认全部提供改为按需提供的信息。

## 十、常见误区

### 同时服务所有用户

先选一个首要用户，其他用户可以成为独立任务。

### 目标输出仍然是“专业总结”

继续追问：具体有哪些字段？怎样检查？结果之后做什么？

### 把AI建议当成客户事实

客户事实、销售判断和AI建议需要分开。

### 所有资料都标为必须

每项资料必须对应某个输出或规则，否则先删除或改为按需。

### 还没定义结果就开始画页面

页面字段应该来自任务和输出。先完成V0.1，再进入产品交互。

## 十一、先记住

1. 写Prompt前先定义谁在什么时点使用结果；
2. 目标输出、输出格式和验收标准是三个不同问题；
3. 每项上下文都应服务某个输出或规则；
4. 信息更多不等于上下文更好；
5. V0.1只完成输出、验收和上下文，不提前画完整产品。
