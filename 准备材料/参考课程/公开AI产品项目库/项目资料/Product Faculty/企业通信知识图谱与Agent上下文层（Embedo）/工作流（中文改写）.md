# Embedo / Ambito 工作流（中文改写）

> 本文对应 `工作流.png` 的中文流程。

## 写入侧

1. **信息进入**：会议、邮件、Slack/Teams 和日历事件通过 Webhook 或连接器进入。
2. **统一标准化**：转换为统一事件格式，保存租户、用户、时间和来源权限。
3. **按来源路由**：针对会议、邮件和聊天执行不同预处理。
4. **重要性分类**：Haiku 判断是否包含值得保留的组织信号，并分类主题。
5. **实体提取**：Sonnet 提取决策、承诺、行动项、开放问题和相关人员。
6. **低置信度升级**：复杂或低置信度结果升级到更强模型或人工。
7. **向量化与存储**：实体写入 PostgreSQL/pgvector，原始材料留在对象存储。
8. **项目聚类**：将相关实体自动组成项目和关系图谱。
9. **风险检测**：识别无人负责、长期停滞或可能失约的承诺。
10. **被动提醒**：通过 Slack 等渠道向授权用户发送提醒。

## 读取侧

1. 人类从仪表盘或 Ask Ambito 发起查询，或 Agent 通过 MCP 请求上下文；
2. 系统验证租户、用户身份和 OAuth 范围；
3. 在检索阶段按权限过滤实体和来源；
4. Haiku/Sonnet 理解查询并检索相关结构化上下文；
5. 生成带来源的综合结果；
6. 仪表盘展示信号，MCP 返回最小必要上下文；
7. 记录访问、纠错和用户反馈。

## 硬性边界

- 未授权实体不得进入模型上下文；
- Agent 不直接获得整段原始沟通；
- 权限和 Schema 失败立即阻断，不做概率性容错；
- 来源片段必须与提取结论保持可验证关系。
