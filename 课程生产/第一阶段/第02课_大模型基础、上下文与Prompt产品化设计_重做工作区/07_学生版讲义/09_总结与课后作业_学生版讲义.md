# 模块09：总结与课后作业

> 课堂时间：114—117分钟；117—120分钟为机动和答疑  
> 本模块任务：用四个结论收束课程，并明确课后V1.0作业

## 一、整节课只带走四个结论

### 结论1：大模型是生成，不是固定查询

大模型依据当前上下文逐步生成后续Token。同一输入可能产生不同结果，一次Demo不能证明稳定。

### 结论2：上下文是有限的任务工作区

用户输入、内部指令、历史对话和补充材料都会进入或影响本次上下文。产品经理要选择必要、可靠、结构清楚的信息，而不是无差别堆料。

### 结论3：好Prompt来自清楚的产品定义

先定义谁在什么时点需要什么结果、怎样算可用，再反推输入、规则和输出。Prompt不是脱离需求的文案技巧。

### 结论4：Prompt产品化是让产品承担复杂度

固定要求由产品承载，变化信息通过字段收集，已有信息自动获取，高风险结果由用户确认。

## 三、课后作业

从自己的真实工作中选择一个适合文本类大模型辅助的具体场景。

优先选择：

- 已存在明确人工流程；
- 有比较清楚的输入材料；
- 知道结果交给谁；
- 能找到脱敏样例或构造虚构样例；
- 一次任务可在几分钟到几十分钟内完成。

不建议：

- 做一个万能企业Agent；
- 用AI提升公司效率；
- 做一个全能客服；
- 同时包含十几个流程的大型平台；
- 必须使用敏感数据才能完成的题目。

## 四、可选场景

- 用户访谈记录整理；
- 客服对话问题归因；
- 需求反馈分类；
- 营销文案草稿；
- 合同要点提取；
- 周报信息汇总；
- 招聘面试记录整理；
- 项目风险和行动项提取。

示例不代表场景天然适合大模型，仍需说明用户、输入、输出和风险。

## 五、V1.0提交结构

打开课后作业模板：

> [05_Prompt产品化设计单_课后作业版.md](../06_课堂练习与作业材料/05_Prompt产品化设计单_课后作业版.md)

需要完成：

### 1. 场景

- 目标用户；
- 使用时点；
- 当前人工任务；
- AI结果后的下一步动作。

### 2. 目标输出和验收

至少定义2项目标输出，并说明：

- 怎样算合格；
- 有什么高风险错误。

### 3. 上下文清单

至少列出3类必要信息，并说明：

- 事实、背景还是规则；
- 支持哪项输出；
- 必需还是按需。

### 4. 结构化Prompt

按实际需要填写：

- 角色与能力；
- 任务目标；
- 背景和输入；
- 规则与约束；
- 输出格式与验收；
- 示例和检查。

不要求为了形式完整而强行写满。

### 5. 产品化拆分

先区分信息供给：

- 产品固定；
- 用户提供；
- 系统获取；
- 对应的产品承载或交互。

再单独设计风险处理：

- 普通展示；
- 建议检查；
- 执行前必须确认；
- 对应的证据、权限和确认动作。

### 6. 一次测试

使用一条脱敏、公开或虚构样例：

- 保存输入；
- 保存Prompt；
- 保存输出；
- 记录模型名称和日期。

### 7. 一条Bad Case

- 具体哪里不满意；
- 原始证据是什么；
- 首先属于哪类问题；
- 下一次最小修改是什么。

### 8. 技术边界

判断是否已经涉及：

- 企业私有或最新知识；
- 多步骤和条件分支；
- 外部系统动作；
- 上游数据错误；
- 模型能力不足。

本次不要求设计RAG、Workflow或Agent。

## 六、作业分级

### A. 必做版

零基础学员和第一次完成本模板的学员，只要求提交：

- 具体场景；
- 2项目标输出与验收标准；
- 3类必要上下文；
- 结构化Prompt关键骨架；
- 信息供给拆分；
- 至少1项高风险结果的处理方式；
- 1条样例测试；
- 1条Bad Case和最小修改。

### B. 进阶版

在必做版基础上增加：

- 完整Prompt骨架；
- 补齐主要风险字段的证据、权限和确认交互；
- 第二轮复测；
- Prompt以外的技术边界判断。

第一次作业以完成必做版为合格，不要求为了显得复杂而强行加入RAG、Workflow或Agent。

## 七、必做版最低验收标准

- [ ] 场景具体到谁在什么时点完成什么任务；
- [ ] 至少2项目标输出和可检查标准；
- [ ] 至少3类必要上下文；
- [ ] Prompt要求对应任务、风险或输出；
- [ ] 区分产品固定、用户提供和系统获取；
- [ ] 至少为1项高风险结果设计建议检查或必须确认；
- [ ] 至少运行1条样例；
- [ ] 至少找到1条Bad Case；
- [ ] 提出具体修正动作；
- [ ] 不提交敏感数据、个人隐私或公司机密。

## 八、典型不合格情况

- 只有一段从网上复制的Prompt；
- 选题是万能助手，没有具体用户和任务；
- 输出标准只有专业、准确、高质量；
- 把所有资料全部放进上下文，无法说明用途；
- 只展示一次满意结果，没有Bad Case；
- 产品仍要求用户每次填写完整Prompt；
- 使用未经脱敏的真实客户或公司数据。

## 九、完全零基础替代任务

如果没有正式工作场景，可以选择：

1. 公开访谈或公开视频字幕整理；
2. 公开产品测评的优缺点提取；
3. 虚构用户反馈分类；
4. 个人学习笔记和行动计划提取；
5. 使用课堂虚构材料，但重新设计不同目标输出。

最低完成：

- 一个明确用户和时点；
- 两项输出及验收标准；
- 一版结构化Prompt；
- 产品固定、用户提供和系统获取各至少一项；
- 至少选择1项高风险结果，说明应建议检查还是必须确认；
- 一条Bad Case及修改。

## 十、数据安全要求

不要提交：

- 真实客户姓名、电话和联系方式；
- 员工隐私；
- 未公开合同和价格；
- 公司内部账号、密钥或权限信息；
- 未经授权的业务数据；
- 其他无法确认使用权限的材料。

无法脱敏时，构造结构相同的虚构样例，并明确标注虚构。

## 十一、选题收窄句式

如果题目太大，用一句话重新描述：

> ________在________时，需要AI帮助完成________，结果用于________。

例如：

不清楚：

> 用AI提升客服效率。

更具体：

> 客服主管在每日复盘时，需要AI把当天脱敏对话按既有问题标签分类，结果用于确定次日重点培训问题。
