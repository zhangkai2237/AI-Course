## 一、本模块PPT设计原则

1. Token只讲基本单位、容量和成本意识，不做固定汉字换算；
2. 明确不同模型的Tokenizer可能不同；
3. 上下文窗口讲“本次任务有限工作区”，不等同永久记忆、训练知识或数据库；
4. 同时讲容量问题与质量问题；
5. 第18页先练习后讲评，学生屏幕不出现老师答案；
6. 讲评标准是“材料服务哪项目标输出”，不是争论唯一分类。

## 第14页｜Token是模型处理信息的基本单位

### 页面标题

> Token：模型处理和生成信息的基本单位

### 页面上屏文字

```text
自然语言
      ↓  Tokenizer
Token序列
      ↓
模型处理与生成
```

右侧边界：

```text
Token不固定等于……

× 一个汉字
× 一个中文词
× 一个英文单词
× 固定长度字符

不同模型的切分方式可能不同
```

### 版式结构

- 左侧55%：一句短文本被切成若干Token块；
- 右侧45%：四个“不固定等于”和一个结论；
- Token块使用相邻但不同深浅颜色，避免让人误以为按字固定切分。

### 视觉示例

使用同一句中英混合短文本：

```text
AI产品经理正在整理meeting notes。
```

页面只表达“会被切成Token序列”，不手工声称某个模型必然如何切分。若正式PPT展示真实切分，必须标明模型或Tokenizer名称和日期。

### 动画顺序

1. 自然语言出现；
2. Token块依次出现；
3. 右侧四个“不固定等于”出现；
4. “不同模型可能不同”最后高亮。

### 停留时间与讲课动作

约3分钟。老师只回答：Token是什么、为什么不能固定换算、为什么产品经理需要知道。

### 老师备注来源（不投屏）

```text
知识依据：K3｜A1录音P265—P298｜A1课件9—10页
```

## 第15页｜一次调用中，哪些内容都会占空间？

### 页面标题

> 用户只输入一句话，不代表模型只看到一句话

### 页面上屏文字

```text
一次调用可能包含

产品内部指令
用户本次输入
历史对话
上传文档
系统补充的业务材料
检索到的知识片段
本次输出预算
```

底部结论：

```text
界面上看不到的内容，也可能占用本次Token空间。
```

### 版式结构

- 使用一个有容量上限的“上下文容器”；
- 六类输入从左侧依次进入容器；
- 输出预算在容器右侧预留区域显示；
- 避免把输入和输出画成完全相同的技术实现，只表达总预算与产品约束。

### 动画顺序

1. 空容器出现；
2. 内部指令、用户输入、历史、文档、业务材料和知识片段依次进入；
3. 输出预算区域出现；
4. 底部结论出现。

### 停留时间与讲课动作

约2分30秒。老师补充：长Prompt、长历史和无关资料既可能占空间，也可能增加调用成本；具体计价留到后续课程。

### 老师备注来源（不投屏）

```text
知识依据：K3、K4｜A1录音P265—P340
```

## 第16页｜上下文窗口是本次任务的有限工作区

### 页面标题

> 上下文窗口：模型完成本次任务时可使用的有限工作区

### 页面上屏文字

| 容易混淆的概念 | 本课怎样区分 |
|---|---|
| 上下文窗口 | 一次调用可容纳输入与输出Token的有限空间；具体上限依模型和接口而异 |
| 永久记忆 | 产品是否保存、何时重新提供，是另一件事 |
| 模型已有知识 | 训练中学到的能力和知识，不等于本次材料 |
| 产品数据库 | 数据存在系统里，不代表本次已经给模型 |

底部大字：

```text
系统里有 ≠ 模型这一次看到了
```

### 版式结构

- 上半部用“有限工作区”容器图；
- 下半部使用四行对比；
- “系统里有≠本次看到”使用全页最强强调色。

### 动画顺序

1. 上下文窗口定义出现；
2. 四个概念逐行出现；
3. 底部结论出现。

### 停留时间与讲课动作

约3分钟。先区分“窗口”与“实际上下文”：窗口更接近本次调用的容量边界，实际上下文是本次真正放进去的内容。再用CRM举例：客户资料在CRM中，只有产品查询、筛选并放入本次上下文，模型才可能依据它回答。

### 老师备注来源（不投屏）

```text
知识依据：K4｜A1录音P301—P340｜本课程产品转译
```

## 第17页｜能放进去，不等于应该放进去

### 页面标题

> 上下文问题有两类：容量不够，和信息不好

### 页面上屏文字

#### 左侧：容量问题

```text
超过限制后，可能出现

无法提交
内容截断
早期信息被移除
输出空间不足
系统先摘要或压缩
```

#### 右侧：质量问题

```text
没有超限，也可能因为……

无关信息太多
多个版本冲突
重要事实埋得太深
材料没有来源和时间
任务本身过于复杂
```

底部主结论：

```text
上下文窗口回答“最多能装多少”
上下文设计回答“当前应该装什么”
```

### 版式结构

- 左侧用“溢出的容器”；
- 右侧用“未装满但混乱的容器”；
- 底部两句话形成对照。

### 动画顺序

1. 容量问题出现；
2. 质量问题出现；
3. 底部两个问题出现。

### 停留时间与讲课动作

约3分钟。必须说明具体截断和报错行为依模型与产品实现而异，不能讲成所有平台统一行为。

### 老师备注来源（不投屏）

```text
知识依据：K4｜A1课件9—10页｜T2产品转译
```

## 第18页｜Token与上下文分类练习

### 页面标题

> 课堂练习：这五类材料，本次应该怎样提供？

### 页面上屏文字

```text
任务
销售拜访结束后，AI生成一份供销售检查的CRM草稿

请将材料分为
本次必须提供｜视任务按需提供｜本次暂不需要

每项写一句理由
```

五张材料卡：

```text
① 本次拜访转写，含说话人标签
② 客户基本资料和当前商机阶段
③ 本次讨论的产品方案说明
④ 客户过去三年的全部CRM记录
⑤ 公司所有产品、制度和培训资料
```

底部：

```text
判断提示：删除这项信息，哪一项目标输出会明显变差？
时间：3分钟
```

### 版式结构

- 顶部：任务背景；
- 中部：三列分类区，五张材料卡可通过动画或现场批注移动；
- 底部：判断提示＋倒计时；
- 不在学生屏幕显示老师参考分类。

### 互动方式

1. 学员在材料表中独立填写2分钟；
2. 同桌或聊天区分享一项最有争议的材料；
3. 老师用1分钟只讲判断原则。

### 讲评原则

- 本次转写通常必须；
- 其他材料要根据目标输出、相关性、版本、权限判断；
- “全部CRM”和“公司所有资料”不应默认全部提供；
- 完整参考答案只在老师材料中。

### 老师备注来源（不投屏）

```text
材料：../06_课堂练习与作业材料/02_Token与上下文分类练习.md
老师答案：../06_课堂练习与作业材料/02A_Token与上下文分类练习_老师参考答案.md
```
