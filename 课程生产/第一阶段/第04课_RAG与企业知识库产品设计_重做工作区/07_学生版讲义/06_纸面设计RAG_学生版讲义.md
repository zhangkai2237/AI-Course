# 06 先纸面设计，再打开平台

平台不会自动替产品经理定义业务边界。搭建前先完成四项设计。

## 一、业务目标

用一句话说明：

> 当什么用户问什么问题时，从哪个知识源找到什么依据，以什么形式回答；没有依据时怎么办。

## 二、知识来源

确认：

- 哪些文档是权威材料；
- 谁负责；
- 当前有效版本；
- 适用范围；
- 谁可以访问；
- 怎样更新和下线。

## 三、RULE升级路径

```text
RULE
→ 指定知识库
→ 检索候选片段
→ 判断依据状态
   ├─ 可靠依据 → 基于依据回答
   ├─ 没有依据 → 明确未找到
   └─ 资料冲突 → 提示冲突并人工确认
```

## 四、回答规则

至少包含：

1. 只根据检索片段回答；
2. 保留日期、范围和前提；
3. 没有依据或存在冲突时不自行推断。

## 五、纸面设计自检

- [ ] 没有把实时数据放进知识库
- [ ] 有当前有效版本
- [ ] 有无答案策略
- [ ] 有冲突处理
- [ ] 有依据或来源
- [ ] 保留DATA、COMPLAINT和OTHER路径
