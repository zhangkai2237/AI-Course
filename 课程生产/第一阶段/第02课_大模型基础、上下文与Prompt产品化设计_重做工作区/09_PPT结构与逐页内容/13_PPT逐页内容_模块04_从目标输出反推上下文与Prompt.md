## 一、本模块PPT设计原则

1. 不从Prompt模板开始，先固定用户、时点、目标输出和验收；
2. 明确“输出—输入—处理”是产品设计顺序，不是系统运行顺序；
3. 目标输出、输出格式和验收标准必须分开；
4. 每项上下文都要说明支持哪项输出或规则；
5. 基准版练习使用老师给定的用户、时点和第一项示例；
6. 第23页只完成V0.1，不提前写完整Prompt或画完整页面；
7. 学员填写时间优先，老师不能用讲解挤占练习。

## 第19页｜很长的Prompt，也可能没有产品定义

### 页面标题

> Prompt写得很长，为什么还是不能验收？

### 页面上屏文字

中央展示：

```text
你是一位非常资深、非常专业、逻辑严密、洞察敏锐、
表达清晰的销售专家。请认真、全面、深入地分析下面的内容，
输出一份高质量、专业、有价值、让人满意的销售拜访总结。
```

点击后出现三个追问：

```text
给谁使用？

具体交付什么？

怎样判断可用？
```

底部主结论：

```text
“专业、深入、高质量”是形容词，
不是可检查的产品要求。
```

### 版式结构

- 第一屏让长Prompt占据页面中央，制造“看起来很专业”的感觉；
- 第二屏将大量形容词变成浅灰，只保留三个缺口问题；
- 底部结论使用强对比横条。

### 互动方式

提问：

```text
这段Prompt已经很长了，你仍然无法检查什么？
```

收集1—2个答案后再显示三个追问。

### 停留时间与讲课动作

约2分钟。收口：Prompt不是产品设计起点，清楚的用户任务和目标输出才是起点。

### 老师备注来源（不投屏）

```text
知识依据：K5、K6｜A2录音P520—P553｜教学反例
```

## 第20页｜先结果，再信息，最后处理

### 页面标题

> 写Prompt之前，先按这个顺序思考

### 页面上屏文字

```text
01  谁在什么时点使用？
        ↓
02  需要什么目标输出？
        ↓
03  怎样判断输出可用？
        ↓
04  模型需要哪些信息？
        ↓
05  最后设计Prompt和处理流程
```

页面角标：

```text
这是产品设计顺序，不是系统运行顺序。
```

### 版式结构

- 使用五步横向或阶梯流程；
- 第1—4步使用同一主色；
- 第5步使用不同颜色，表示Prompt是后置设计结果；
- 角标固定在右上角。

### 动画顺序

五步依次出现；最后单独高亮“Prompt和处理流程”。

### 停留时间与讲课动作

约2分钟。老师用一句销售案例串联：销售拜访后检查CRM草稿，需要客户诉求、异议、行动项和待确认信息，因此才知道要提供转写、字段和规则。

### 老师备注来源（不投屏）

```text
知识依据：K6｜A2录音P520—P553｜A2课件100—103页
```

## 第21页｜先固定一个首要用户和使用时点

### 页面标题

> 同一段拜访录音，给不同人，目标输出会不同

### 页面上屏文字

| 使用者 | 主要目的 | 更关注什么 |
|---|---|---|
| 一线销售 | 检查事实并推进跟进 | 诉求、异议、行动项 |
| 销售主管 | 判断风险并辅导 | 阶段、缺口、风险 |
| 客户 | 确认双方共识 | 结论、双方行动和时间 |
| CRM系统 | 形成结构化记录 | 字段、状态和证据 |

本课统一假设：

```text
一线销售在拜访结束后10分钟内，
检查AI草稿、录入CRM，并准备下一步跟进。
```

### 版式结构

- 上半部：四张角色卡或四行精简表；
- 下半部：四条路径收敛到本课统一假设；
- “一线销售、10分钟内、检查、录入、跟进”分词高亮。

### 动画顺序

1. 四类用户同时出现；
2. 点击后出现各自关注；
3. 其他三类淡化；
4. 本课统一假设出现。

### 停留时间与讲课动作

约2分钟。强调先选首要用户并不意味着其他用户没有价值，而是避免一个Prompt同时承担四个不同任务。

### 老师备注来源（不投屏）

```text
知识依据：K6｜CASE｜本课程统一课堂假设
```

## 第22页｜目标输出、格式和验收不是一回事

### 页面标题

> “要什么、怎么放、怎样算合格”是三个问题

### 页面上屏文字

以“下一步行动”为例：

| 概念 | 回答的问题 | 示例 |
|---|---|---|
| 目标输出 | AI要交付什么内容？ | 下一步行动 |
| 输出格式 | 结果怎样呈现？ | CRM字段或表格 |
| 验收标准 | 怎样判断可以使用？ | 事项、负责人、时间、状态齐全；缺失标待确认 |

反例：

```text
“用表格输出”只能规定格式，
不能保证表格里的事实正确。
```

### 版式结构

- 使用三列概念卡或三行对比表；
- 同一“下一步行动”案例贯穿三行；
- 右侧可放一张结构整齐但缺负责人和日期的错误表格；
- 反例结论放在底部。

### 动画顺序

1. 目标输出出现；
2. 输出格式出现；
3. 验收标准出现；
4. 错误表格出现；
5. 反例结论出现。

### 停留时间与讲课动作

约3分钟。老师对比：

```text
不够：结果要专业、准确、全面
更可验收：关键事实有证据；未知标待确认；行动项具备人、事、时间、状态
```

### 老师备注来源（不投屏）

```text
知识依据：K6｜A2输入—输出产品视角＋T3课程整理
```

## 第23页｜完成V0.1

### 页面标题

> 课堂练习：从目标输出反推必要上下文

### 页面上屏文字

```text
已给定
用户：一线销售
时点：拜访结束后10分钟内
第一项目标输出：客户核心诉求

请完成
① 补充1项目标输出＋验收标准
② 从候选信息中选择至少3项上下文
③ 标明：事实／背景／规则
④ 标明：必需／按需／暂不需要
⑤ 写清它支持哪项目标输出

时间：4分钟
```

右侧候选信息：

```text
本次拜访转写
说话人标签
客户基本资料
当前商机阶段
CRM字段定义
缺失信息处理规则
公司全部历史资料
无关过往聊天
产品方案说明
```

底部提醒：

```text
如果删除这项信息，哪一项目标输出会明显变差？
```

### 版式结构

- 左侧60%：V0.1填写任务；
- 右侧40%：候选信息卡；
- 右上角4分钟倒计时；
- 可以展示课堂设计单局部截图，但不显示参考答案。

### 互动流程

1. 个人填写2分30秒；
2. 两人互看45秒；
3. 老师抽1人分享一项目标输出或一项“暂不需要”；
4. 老师只纠正一个最典型问题。

### 基准版验收

- 至少2项目标输出（含老师示例）；
- 至少3项上下文；
- 每项上下文能说清用途；
- 不要求画页面，不要求写完整Prompt。

### 充分互动版

- 再补1项目标输出；
- 或把用户改为销售主管，观察输出怎样变化；
- 增加2—3分钟，后续时间整体顺延。
