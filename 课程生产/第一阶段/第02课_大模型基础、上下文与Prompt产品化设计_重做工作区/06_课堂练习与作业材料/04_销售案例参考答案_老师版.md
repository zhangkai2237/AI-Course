# 销售拜访记录助手｜老师参考答案

> 仅供老师备课和讲评，不发给学员。案例全部为教学虚构。

## 一、第一轮问题清单

| 第一轮结果 | 问题 | 原文依据 |
|---|---|---|
| 计划8家试点 | 把可能方案写成确定事实 | 当天只确认按5家准备 |
| 试点后采购并全量推广 | 把销售推测写成客户承诺 | 客户明确说试点不等于采购承诺 |
| 预计6月底上线 | 把希望和提问写成计划 | 客户说当天不能承诺 |
| 两周完成对接 | 丢失前提，变成正式工期 | 未看接口文档，不是承诺 |
| 预算不是主要问题 | 自行弱化商务风险 | 预算较紧且金额未确认 |
| 下一步无负责人和日期 | 无法创建任务 | 原文有具体负责人和时间 |
| 未体现数据与隐私风险 | 漏掉关键异议 | 部署、日志和外部传输需评审 |
| 未列待确认信息 | 关键事实仍然缺失 | 预算、决策人和采购时间未确认 |

## 二、优先修改方向

每组最多修改3条，优先选择：

1. 区分已确认、讨论中和待确认；
2. 不把销售提问、推测或方案方估计写成客户承诺；
3. 关键结论附证据；
4. 预算、决策人和时间未确认时单独列出；
5. 行动项包含事项、负责人、时间和状态。

不接受“必须输出5家试点”这类写死案例答案的修改。

## 三、结构化Prompt参考

### 角色

你是销售拜访记录整理助手，负责依据材料生成便于销售检查和录入CRM的草稿。

### 任务

整理客户核心诉求、试点范围、主要异议、合作意向、行动项和待确认信息。

### 规则

1. 只依据输入材料；
2. 区分已确认、讨论中和待确认；
3. 客户主动纠正的内容优先；
4. 关键结论附证据；
5. 未确认的预算、决策人和时间标记待确认；
6. 行动项包含事项、负责人、时间和状态；
7. 不生成成交概率和采购建议。

### 输出

按CRM字段输出，每个关键结论包含内容、状态和证据；行动项使用表格；最后列出待确认信息。

### 试点和合作意向

| 内容 | 状态 | 证据 |
|---|---|---|

|---|---|---|---|

- 最终部署方式；
- 正式数据接入工期。

## 五、产品化参考

| 内容 | 分类 | 承载方式 |
|---|---|---|
| 助手角色、任务边界 | 固定项 | 内部Prompt或流程 |
| CRM字段和事实规则 | 固定项 | 字段配置和校验 |
| 本次重点字段、特殊备注 | 用户变量 | 多选和短文本 |
| 转写、客户资料、商机阶段 | 自动获取 | 系统带入并可修正 |
| 日期、金额、责任人和承诺 | 人工确认 | 高亮证据，逐项确认 |
| 写入CRM | 人工触发 | 确认后点击写入 |

- 不把教学示意冒充真实模型输出；
- 正式上课前用实际模型结果替换第一轮和第二轮截图。
