# 商品对比工具 PRD（历史版本）

> 文档版本：V1.0｜文档状态：评审稿｜产品阶段：MVP → 增强版｜更新时间：2026-08-09  
> 适用端：Web、H5、App｜产品负责人：待定｜设计/研发/测试/数据：待定

## 0. 文档说明

### 0.1 需求来源

电商平台希望建设商品对比工具，帮助用户在多个候选商品之间快速理解关键差异、降低信息搜集与记忆成本，并更快完成购买决策。

### 0.2 前置假设

- 平台拥有商品、SKU、价格、促销、库存、履约、评价与类目属性等基础数据。
- 首期优先覆盖参数相对标准化、比较诉求强的同一叶子类目，如手机、电脑、家电、数码设备等。
- 商品详情页、搜索/列表页、收藏或购物车可提供对比入口。
- 用户既可能未登录，也可能已登录；未登录状态使用本地会话保存，登录后支持跨端同步。
- 本文中的目标值是首版建议基线，立项后应结合平台现状、流量规模和历史漏斗校准。

### 0.3 名词定义

| 名词 | 定义 |
|---|---|
| SPU | 标准商品单元，用于表达同一商品模型或款型。 |
| SKU | 库存量单位，通常由颜色、规格、容量等销售属性组合形成。 |
| 对比池 | 用户当前待比较的候选商品集合。 |
| 对比页 | 以统一结构并列展示候选商品及其差异的页面。 |
| 比较属性 | 可用于商品横向比较的标准化字段，如重量、屏幕尺寸、能效等级。 |
| 销售属性 | 影响具体购买与库存的规格属性，如颜色、容量、套装。 |
| 差异项 | 候选商品在同一比较属性上的取值不完全相同。 |
| 缺失项 | 某商品在指定比较属性上没有有效值。 |

## 1. 项目概述

### 1.1 背景与问题

用户在高考虑度商品的购买过程中，往往需要反复打开详情页、手工记录参数、切换规格并核对价格。现有详情页以单商品转化为中心，缺少跨商品的一致信息结构，导致以下问题：

- 信息分散：价格、规格、服务与评价散落在不同模块或页面。
- 口径不一：同类属性存在命名、单位与枚举差异，难以直接比较。
- 认知负担高：用户需要记住前一商品的信息，再与当前商品进行心算比较。
- 差异不突出：大量相同参数遮蔽真正影响决策的少数差异。
- 决策链路长：用户在多个页面之间往返，容易退出、延迟购买或转向外部平台。

### 1.2 产品定位

商品对比工具是站内的“候选收敛与决策辅助层”。它不替代搜索、推荐或详情页，而是连接“发现候选商品”和“选择具体 SKU 并下单”两个阶段，通过结构化并列展示、差异高亮和购买信息同步，帮助用户从多个候选快速收敛到一个可购买选项。

### 1.3 产品原则

- 真实优先：所有结论可回溯到平台商品数据，不生成无法验证的事实。
- 差异优先：默认突出影响决策的不同点，同时保留查看全部信息的能力。
- 口径统一：先标准化属性名、单位和枚举，再进行横向展示。
- 决策闭环：比较结果必须能顺畅衔接选规格、领优惠、加购或立即购买。
- 控制复杂度：首期只解决高频、可标准化的同类商品比较，不追求全品类万能比较。

## 2. 目标与成功指标

### 2.1 业务目标

1. 缩短有比较需求用户从进入候选商品到作出购买动作的时间。
2. 提高比较场景的加购率、立即购买点击率和最终支付转化率。
3. 降低因信息不透明产生的详情页往返、退出和购买后不符合预期。
4. 沉淀类目级标准比较属性，为搜索、导购和推荐复用。

### 2.2 用户目标

- 快速看懂候选商品“哪里不同”。
- 明确价格、优惠、库存和服务差异。
- 根据自己的关注点筛掉不合适的候选。
- 在有依据的情况下选择规格并完成购买。

### 2.3 北极星指标

**有效对比决策率** = 进入对比页后 30 分钟内，对任一被比较商品发生“加购、立即购买或收藏”行为的去重用户数 ÷ 对比页有效访问用户数。

有效访问需满足：页面成功加载且停留 ≥ 5 秒，或发生属性展开、差异筛选、商品切换等有效交互。

### 2.4 核心指标与建议目标

| 指标 | 定义 | MVP 建议目标 |
|---|---|---|
| 对比功能使用率 | 看到对比入口的用户中，至少添加 2 个商品的比例 | ≥ 5% |
| 对比页到购买意向转化率 | 对比页访问后 30 分钟内加购或立即购买的比例 | 相比匹配对照组提升 ≥ 8% |
| 决策时长 | 首次添加对比至首次购买意向动作的中位时长 | 相比基线下降 ≥ 15% |
| 差异查看使用率 | 使用“仅看差异”的对比页用户占比 | ≥ 25% |
| 对比页退出率 | 无有效交互直接退出的访问占比 | ≤ 35% |
| 属性有效覆盖率 | 核心比较属性中存在有效值的商品占比 | ≥ 95% |
| 价格新鲜度 | 展示价格与结算可用价格一致的请求占比 | ≥ 99.5% |

### 2.5 护栏指标

- 商品详情页到支付的整体转化率不得显著下降。
- 对比功能导致的页面性能劣化：列表/详情页 LCP 增量 ≤ 100ms；对比页 LCP P75 ≤ 2.5s。
- 对比相关价格投诉率、参数错误反馈率和取消/退款率不得高于同类目基线。
- 商家曝光不得被不可解释地系统性倾斜；排序和推荐必须可解释、可审计。

### 2.6 非目标

- 首期不支持跨大类商品的自由比较，例如手机与平板并列比较。
- 首期不替用户自动下单，也不承诺“唯一最佳商品”。
- 首期不抓取或展示站外价格、站外评价与未经授权的数据。
- 首期不建设复杂的自然语言对话导购；AI 总结属于后续增强能力。
- 首期不覆盖非标准品、服务型商品、拍卖、预售规则极复杂的商品。

## 3. 用户与核心场景

### 3.1 目标用户

| 用户类型 | 主要特征 | 核心诉求 |
|---|---|---|
| 参数型用户 | 熟悉品类，关注性能、规格和可量化参数 | 快速识别参数差异与性价比 |
| 价格敏感型用户 | 预算明确，关注到手价、优惠和长期成本 | 看清真实价格、权益与成本差异 |
| 低认知用户 | 不熟悉专业术语，容易被大量参数淹没 | 获得易懂解释和关键差异摘要 |
| 谨慎决策用户 | 重视评价、售后、品牌与风险 | 综合比较口碑、服务和履约确定性 |

### 3.2 核心用户故事

- 作为浏览列表的用户，我希望勾选多个感兴趣的商品并立即比较，以免逐个打开详情页。
- 作为详情页用户，我希望把当前商品加入对比，并看到可直接添加的同类候选。
- 作为预算有限的用户，我希望比较实时到手价、优惠和服务，而不是只比较标价。
- 作为不懂参数的用户，我希望看到关键参数的通俗解释和差异意义。
- 作为已登录用户，我希望稍后或换设备后继续查看我的对比结果。
- 作为已经做出决定的用户，我希望直接选择规格、加购或购买，不再回到起点。

### 3.3 典型任务流

发现候选商品 → 加入对比池 → 凑齐至少 2 个商品 → 打开对比页 → 仅看差异/查看重点维度 → 替换或移除候选 → 选择目标商品与 SKU → 加购或立即购买。

## 4. 产品范围与版本规划

### 4.1 MVP 范围（P0）

- 搜索/列表页与商品详情页添加、取消对比。
- 底部或侧边对比浮层，展示对比池状态。
- 同一叶子类目 2–4 个 SPU 并列比较。
- 商品基础信息、实时价格、促销摘要、库存状态、核心参数、服务与评价摘要。
- “仅看差异”、属性分组、缺失值说明、固定商品头部。
- 商品移除、替换、清空、分享链接。
- 选择 SKU、加购、立即购买与详情页跳转。
- 未登录会话保存；登录用户服务端保存最近对比记录。
- 埋点、监控、配置后台与基础数据质量机制。

### 4.2 增强版（P1）

- 用户自定义关注维度与属性置顶。
- 同类推荐候选和“补充一个常见对比商品”。
- 价格趋势、能耗/耗材等长期成本信息。
- 评价主题对比、优缺点摘要及证据回溯。
- 基于用户偏好的解释型推荐结论。
- 对比结果收藏、命名、跨端管理。

### 4.3 探索版（P2）

- 自然语言提问与多轮决策辅助。
- 多模态差异说明，如尺寸示意、外观并排、场景适配。
- 经严格规则定义的跨子类比较。
- 家庭成员协同选择、投票和评论。

## 5. 信息架构与入口

### 5.1 入口设计

| 页面 | 入口形式 | 默认文案 | 关键行为 |
|---|---|---|---|
| 搜索/类目列表 | 商品卡片复选框或图标 | 加入对比 | 加入当前商品；显示已选状态 |
| 商品详情页 | 购买区次级按钮 | 加入对比 | 加入当前 SPU，并提示继续选同类商品 |
| 收藏页 | 批量操作 | 对比所选 | 选择 2–4 个同类商品后进入对比页 |
| 购物车 | 商品操作区次级入口 | 对比同类 | 仅对满足条件的商品开放 |
| 对比历史 | 个人中心入口 | 我的对比 | 恢复、分享或删除历史对比 |

### 5.2 对比浮层

- 添加第 1 个商品后出现，不强制打断当前浏览。
- 展示商品缩略图、简称、当前数量、剩余名额和“开始对比”按钮。
- 数量不足 2 个时按钮置灰，并提示“再添加 1 件即可对比”。
- 支持移除单个、清空全部、收起/展开。
- 用户离开当前页面后，浮层状态在同一会话中保留。
- 移动端采用底部抽屉；桌面端采用底部横条或右侧抽屉，避免遮挡购买主按钮。

### 5.3 对比页结构

1. 顶部导航：返回、标题、保存/分享、清空。
2. 商品头部区：图片、标题、品牌、当前 SKU、价格、库存、主行动按钮。
3. 决策工具条：仅看差异、隐藏空项、属性搜索、分组导航。
4. 关键结论区：MVP 展示规则生成的关键差异标签；P1 可加入解释型总结。
5. 属性比较区：按“核心信息—性能/规格—体验—服务—评价”分组。
6. 底部或吸顶行动区：查看详情、加入购物车、立即购买。

## 6. 详细功能需求

### 6.1 添加商品到对比池（FR-01）

**触发条件**

- 商品属于已开放对比的叶子类目。
- 商品处于可展示状态；下架商品仅可在历史对比中以失效态展示。

**处理规则**

1. 用户点击“加入对比”。
2. 系统校验类目、重复商品、对比数量上限与商品有效性。
3. 校验通过后加入对比池，入口更新为“已加入”，浮层展示最新状态。
4. 校验不通过时使用明确提示，不静默失败。

**边界规则**

- MVP 最少 2 个、最多 4 个 SPU。
- 同一 SPU 不重复加入；若 SKU 不同，默认保留同一 SPU 并在对比页切换 SKU。
- 首个商品确定对比类目。加入不同叶子类目时，提示“仅支持同类商品对比”，并提供“替换当前对比”选项。
- 达到 4 个后再添加时，弹出替换面板，由用户选择要移除的商品。
- 商品数据加载失败时不得先展示成功态；重试后仍失败则提示稍后再试。

### 6.2 管理对比池（FR-02）

- 支持查看、移除单个、清空全部和恢复最近一次误清空。
- 清空属于低风险可逆操作，执行后提供 5 秒撤销提示。
- 被移除商品不自动补位；系统可在空位展示“添加同类商品”。
- 同一会话中的新增、删除和顺序调整实时同步到所有已打开的同域页面。
- 登录时将本地对比池与云端最近一次对比合并；冲突时以当前活跃会话为主，超出上限要求用户选择。

### 6.3 对比页加载与商品头部（FR-03）

- 页面必须先渲染骨架屏，分阶段加载商品基础信息、价格库存和参数。
- 商品列顺序与对比池一致；桌面端支持拖拽排序，移动端支持“调整顺序”。
- 每列展示：主图、短标题、品牌、关键标签、当前 SKU、实时价、优惠摘要、库存/配送摘要、评价分与评价量。
- 商品名称最多展示 2 行，可展开查看完整名称。
- 价格应标注口径，如“券后预计”“会员价”“起售价”；无法计算到手价时不得伪装为确定价格。
- 价格或库存请求失败时，对应区域显示“暂时无法获取”，参数区仍可用。
- 头部随页面滚动保持可见；窄屏一次突出 2 列，其余列横向滑动，并固定属性名称列。

### 6.4 SKU 选择与价格联动（FR-04）

- 默认优先使用用户从详情页加入时选择的 SKU；否则使用可售默认 SKU。
- 用户可在每个商品列中切换核心销售属性。
- SKU 变化后，价格、促销、库存、配送承诺、主图和购买按钮必须联动刷新。
- 刷新期间只锁定当前商品列，其他商品仍可操作。
- 若选中 SKU 无货，按钮切换为“到货提醒”或“查看其他规格”，不得继续立即购买。
- 分享链接可携带 SKU 标识；若该 SKU 失效，页面回退到可售默认 SKU 并明确提示。

### 6.5 属性分组与展示（FR-05）

**默认分组**

- 基础信息：品牌、型号、上市时间、适用人群/场景。
- 价格权益：标价、预计到手价、促销、赠品、分期、会员权益。
- 核心规格：由类目配置的 5–10 个首屏关键属性。
- 性能与体验：性能、尺寸、重量、材质、续航、噪音等类目属性。
- 服务履约：库存、配送、安装、保修、退换政策。
- 用户口碑：评分、评价数、好评率与结构化评价标签。

**展示规则**

- 属性顺序由类目模板配置，核心属性优先；不按数据库字段顺序直接展示。
- 每行显示标准属性名、必要的解释图标和各商品取值。
- 同一属性统一单位和精度，例如毫米与厘米转换后再比较。
- 布尔值使用“支持/不支持/未知”，不得将未知显示为不支持。
- 多值属性按标准枚举顺序展示，长文本折叠并可展开。
- 属性缺失显示“暂无数据”，并支持反馈纠错。

### 6.6 仅看差异与差异高亮（FR-06）

- 默认展示全部核心属性；用户可切换“仅看差异”。
- 差异判断基于标准化后的值，而非原始文本字符串。
- 数值型属性换算为同单位后比较；允许配置容差，避免舍入误差形成伪差异。
- 枚举型属性以标准枚举 ID 比较；集合型属性比较集合差异。
- 某商品缺失、其他商品有值时计为差异，但使用“数据缺失”样式，不将缺失解释为能力较弱。
- 差异高亮使用背景或标记，不只依赖颜色；支持辅助技术读取“此项存在差异”。
- 当所有可见属性均相同时，展示“当前筛选下未发现差异”，并提供恢复全部属性。

### 6.7 关键差异摘要（FR-07）

MVP 使用确定性规则生成，不使用开放式生成模型：

- 从类目核心属性中选择差异显著且数据完整的 3–5 项。
- 优先级 = 类目业务权重 × 用户关注权重（若有）× 差异显著度 × 数据置信度。
- 输出事实型标签，例如“重量轻 180g”“保修多 1 年”“预计到手价低 300 元”。
- 不输出无法由属性直接证明的绝对判断，如“性能最好”“最值得买”。
- 点击摘要定位到对应属性行，并展示数据来源/更新时间。
- 当可用数据不足时隐藏摘要区，不用低质量内容填充。

P1 可加入偏好驱动的推荐，但必须说明适用条件与依据，例如“如果更重视便携，可优先考虑 A；依据：重量更轻、续航相近”。

### 6.8 属性解释与决策辅助（FR-08）

- 专业属性旁提供解释入口，内容包括定义、对使用体验的影响和常见选择建议。
- 解释由类目运营配置或审核后发布，不直接使用商家营销文案。
- 对“越高越好”“越低越好”不做通用假设，仅在类目模板明确配置时展示方向性提示。
- 对可能存在权衡的属性，使用中性描述，例如高刷新率可能带来更流畅体验，也可能影响续航。
- P1 支持用户选择关注点，如“预算、性能、便携、售后”，然后重排属性与摘要，不改变原始事实。

### 6.9 商品替换与推荐候选（FR-09）

- 用户可点击商品列的“替换”，进入同叶子类目候选面板。
- MVP 候选来源：最近浏览、收藏、同搜索结果和平台常见同类商品。
- 候选卡需展示价格区间、核心差异标签和是否已在对比池。
- 排序不得仅以商业出价决定；如含广告商品，必须明确标识且不混入自然比较结论。
- 替换后保留当前列位置，并重新计算差异与摘要。

### 6.10 购买闭环（FR-10）

- 每个商品提供“查看详情”“加入购物车”“立即购买”三个动作，主次层级由平台策略统一。
- 未选择必选销售属性时，点击购买动作先打开 SKU 选择器。
- 加购成功后展示规格、数量和购物车入口；不自动离开对比页。
- 立即购买进入确认订单流程；返回时保留对比页状态。
- 价格、库存或促销在点击后发生变化时，必须二次确认并展示变化内容。
- 对比页购买动作沿用平台已有风控、限购、实名、区域限制与售后规则。

### 6.11 保存、历史与分享（FR-11）

- 未登录用户：本地保存 7 天或直到用户清除站点数据。
- 登录用户：服务端保存最近 20 组对比，每组最多 4 个商品，默认保留 90 天。
- 用户可删除历史记录；删除后服务端按隐私策略处理，不再用于个性化展示。
- 分享生成短链，携带商品 ID、SKU（可选）、排序和可公开的筛选状态，不携带用户身份、优惠券明细等敏感信息。
- 接收方打开后重新获取实时价格、库存和促销，并提示“价格与库存以当前页面为准”。
- 商品失效时保留占位与名称，提示已下架，并推荐替换；全部失效时引导重新选择。

### 6.12 反馈与纠错（FR-12）

- 属性解释、商品参数和价格区域提供“信息有误”入口。
- 用户可选择问题类型：参数错误、价格不一致、缺少信息、商品不是同类、其他。
- 提交时自动携带商品 ID、属性 ID、页面版本、展示值和时间，不要求用户重复填写。
- 提交成功后生成反馈编号；高风险问题（价格、合规参数）进入优先队列。
- 反馈处理结果可选站内通知用户；后台需支持定位来源字段和责任方。

## 7. 业务规则

### 7.1 可比性规则

- 默认只允许同一叶子类目商品加入同一对比组。
- 类目运营可配置“可互比类目组”，但必须共享核心属性模板且通过数据质量验收。
- 套装与单品、全新与二手、国内版与海外版默认不可直接比较；若开放，必须显著标注商品形态差异。
- 商家自定义属性只有映射到平台标准属性后才可进入差异计算。

### 7.2 属性标准化

- 属性模型包含：标准属性 ID、名称、数据类型、单位、精度、枚举、是否核心、展示顺序、差异算法、容差、解释内容、数据来源和置信度。
- 单位转换只适用于同量纲数据；无法可靠转换的值保留原文但不参与数值差异排序。
- 异常值必须经过范围校验；明显越界时降级为“待核实”，不参与关键摘要。
- 多来源冲突时遵循平台主数据 > 品牌认证数据 > 商家结构化数据 > 文本抽取数据的建议优先级，最终由平台治理策略确认。

### 7.3 价格与优惠口径

- 展示价格必须标注适用条件、有效期和用户资格。
- 个性化优惠只对当前用户可见，不写入公开分享快照。
- 无法确定优惠组合时展示“可用优惠”而非虚构到手价。
- 价格对比默认使用当前可选 SKU 的同口径价格；起售价只能与起售价比较，并明确标识。

### 7.4 评价口径

- 评分、评价量和好评率需标明统计周期与有效评价规则。
- 不同类目或不同评价规则的数据不得直接形成高低结论。
- 评价摘要必须可回溯到足够数量的有效评价；样本不足时提示“评价样本较少”。

## 8. 页面状态与异常处理

| 状态 | 页面表现 | 用户可执行动作 |
|---|---|---|
| 首次空状态 | 说明对比价值，展示如何添加商品 | 去搜索、查看推荐类目 |
| 仅 1 件商品 | 展示当前商品和空位 | 添加同类商品、返回继续浏览 |
| 正常 2–4 件 | 展示完整对比 | 筛选、替换、购买、分享 |
| 部分数据失败 | 保留已成功模块，失败区域提示 | 重试、继续查看其他信息 |
| 商品下架 | 商品列灰化并标记失效 | 替换、移除、查看相似商品 |
| 全部无货 | 保留参数比较，不展示可购买假象 | 到货提醒、替换商品 |
| 分享链接过期 | 解释失效原因 | 恢复仍有效商品、重新选择 |
| 网络离线 | 展示最近缓存并标记更新时间 | 重试；禁止使用过期价格购买 |
| 无可比属性 | 说明当前商品数据不足 | 查看详情、反馈、替换商品 |

## 9. 交互与视觉要求

### 9.1 桌面端

- 属性名列固定，商品列等宽；4 件商品时仍需保证核心信息可读。
- 商品头部吸顶，横向滚动时保持属性名与当前商品标题可见。
- 分组支持折叠；当前分组在侧边或顶部导航中高亮。
- hover 可补充解释，但所有关键信息必须能通过点击和键盘获得。

### 9.2 移动端

- 默认同时展示 2 个商品列，通过横向滑动查看其他商品。
- 属性名保持固定或在每行顶部重复，避免用户丢失上下文。
- 底部主操作区避免遮挡内容；与系统安全区适配。
- 重要筛选采用底部面板，操作后即时生效并保留滚动位置。

### 9.3 无障碍

- 支持键盘完成添加、移除、切换筛选、展开和购买。
- 焦点顺序与视觉顺序一致；动态更新使用合适的读屏提示。
- 差异、库存和优劣提示不得仅依赖红绿颜色。
- 文本与背景对比度满足 WCAG 2.1 AA；触控目标建议不小于 44×44px。
- 商品图片包含替代文本，表格/网格具备正确语义和表头关联。

### 9.4 文案原则

- 事实与建议分开表达；避免“完胜”“闭眼买”等绝对化营销语言。
- 缺失数据写“暂无数据/待核实”，不写“无”。
- 价格写清条件，如“预计券后”“需会员”“指定地区可用”。
- 错误提示说明原因并给出下一步，例如“最多比较 4 件，请先替换一件”。

## 10. 数据与系统设计要求

### 10.1 核心数据对象

| 对象 | 关键字段 |
|---|---|
| CompareSession | session_id、user_id、category_id、product_ids、sku_ids、排序、筛选、来源、创建/更新时间 |
| ProductSnapshot | product_id、标题、图片、品牌、状态、类目、数据版本、更新时间 |
| OfferSnapshot | sku_id、价格类型、金额、促销条件、库存、区域、配送承诺、更新时间 |
| AttributeSchema | category_id、attribute_id、名称、类型、单位、精度、枚举、权重、分组、顺序、差异规则 |
| AttributeValue | product_id/sku_id、attribute_id、原始值、标准值、来源、置信度、更新时间 |
| CompareShare | share_id、商品与 SKU、排序、筛选、过期时间、创建渠道，不含用户敏感信息 |

### 10.2 接口能力

- 对比资格校验：批量返回商品可比性、类目与不可比原因。
- 对比聚合接口：一次返回基础信息、标准属性和版本号；价格库存可独立高频刷新。
- 对比会话接口：创建、更新、读取、删除与登录合并。
- 分享接口：创建匿名快照、解析快照、校验失效商品。
- 配置接口：按类目下发属性分组、顺序、核心权重、单位与解释。
- 反馈接口：记录问题类型、上下文与处理状态。

### 10.3 一致性与时效性

- 商品参数可按数据版本缓存；价格、促销和库存必须按平台现有实时策略获取。
- 下单前必须由交易系统重新校验价格、库存、限购和资格；对比页数据不得作为交易凭证。
- 对比聚合返回各模块独立更新时间；前端不得用旧参数时间冒充价格更新时间。
- 客户端收到商品状态变化时，及时刷新对应列并重新计算摘要。

### 10.4 性能与可用性

- 对比页首屏核心内容接口 P95 ≤ 800ms，完整属性接口 P95 ≤ 1.5s（不含弱网传输）。
- 对比页 LCP P75 ≤ 2.5s，交互响应 INP P75 ≤ 200ms，CLS P75 ≤ 0.1。
- 服务可用性目标 ≥ 99.95%；价格/库存子服务失败时支持模块级降级。
- 属性行采用分组懒加载或虚拟化，避免长列表阻塞主线程。
- 分享页应具备防爬、限流和缓存策略；公开页面不得泄露个性化信息。

### 10.5 安全、隐私与合规

- 最小化收集对比行为数据；明确数据用途、保留期与删除机制。
- 分享链接使用不可枚举标识，并过滤用户 ID、地址、会员等级、专属券等信息。
- 所有输入和商家内容进行 XSS、注入与恶意链接防护。
- 商业推广、广告候选与自然结果明确区分；关键排序规则可审计。
- 参数与推荐文案遵循广告、消费者权益、价格展示和行业合规要求。

### 11.3 漏斗与分析看板

入口曝光 → 加入第 1 件 → 加入第 2 件 → 打开对比页 → 使用决策工具 → 加购/立即购买 → 提交订单 → 支付成功。

看板需按端、入口、类目、新老用户、商品数量、价格带、实验组拆分，并监控：漏斗转化、决策时长、退出率、属性缺失率、接口错误率、分享回流和购买后退款/退货。

### 11.4 归因规则

- 主归因窗口：对比页有效访问后 30 分钟内首次发生的购买意向动作。
- 支付归因窗口：对比页有效访问后 7 天内购买被比较商品的订单。
- 同一订单命中多个对比会话时，归因到最近一次有效会话。
- 同时保留直接转化和辅助转化口径，避免夸大对比工具贡献。

## 12. 实验设计

### 12.1 MVP 上线实验

- 实验对象：已开放类目的合格流量，以用户 ID 或匿名设备 ID 稳定分桶。
- 对照组：无对比入口或保持现有体验。
- 实验组：开放对比入口、浮层与对比页。
- 主指标：有效对比决策率、支付转化率、决策时长。
- 护栏：详情页转化、页面性能、退出率、退款率、参数/价格投诉率。
- 建议至少覆盖完整购买周期和周内波动；样本量由历史基线、最小可检测效应与统计功效计算。

### 12.2 后续实验方向

- 默认全部属性 vs 默认核心属性。
- 差异高亮样式与“仅看差异”默认状态。
- 对比上限 3 件 vs 4 件。
- 规则摘要有/无、摘要条数和位置。
- 购买按钮常驻 vs 随商品头部吸顶。

## 13. 运营与配置后台

- 类目开关：按端、渠道、用户比例开放或关闭。
- 属性模板：分组、顺序、核心属性、解释、单位、精度、容差和权重。
- 可比类目组：配置跨叶子类目互比范围并记录审批历史。
- 质量看板：属性覆盖率、异常值、来源冲突、反馈量和修复时效。
- 文案与推荐位：支持版本、预览、灰度和回滚。
- 紧急能力：单类目、单属性、单商品或全局熔断；价格异常时可独立关闭价格比较。
- 权限：产品配置、类目运营、数据治理、审核发布分权，并保留操作日志。

## 14. 验收标准

### 14.1 P0 功能验收

- Given 用户在开放类目列表页，When 添加第 1 件商品，Then 对比浮层出现且提示再添加 1 件。
- Given 对比池已有 1 件商品，When 添加同叶子类目第 2 件，Then 可进入对比页并保持商品顺序。
- Given 对比池已有其他类目商品，When 添加不可比商品，Then 明确提示不可比原因且原对比池不被静默清空。
- Given 对比池已有 4 件商品，When 添加第 5 件，Then 展示替换选择，用户取消后数据不变。
- Given 用户开启“仅看差异”，When 两商品标准值一致，Then 该属性隐藏；标准值不同则保留并标记。
- Given 某商品属性缺失，When 其他商品有值，Then 显示“暂无数据”并标记为缺失，不显示为“不支持”。
- Given 用户切换 SKU，When 接口成功，Then 当前列的图片、价格、促销、库存和购买状态同步刷新。
- Given 用户点击立即购买，When SKU 未完整选择，Then 先完成规格选择，不进入错误订单。
- Given 分享接收方打开链接，When价格已变化，Then 展示当前实时价格及更新时间，不展示分享者专属优惠。
- Given 价格接口失败，When 参数接口正常，Then 参数对比仍可用且价格区域支持重试。

### 14.2 数据质量验收

- 试点类目核心属性有效覆盖率 ≥ 95%。
- 数值属性单位转换正确率 ≥ 99.9%，枚举映射正确率 ≥ 99.5%。
- 抽样对比中不存在将“未知”误判为“不支持”的 P0 问题。
- 关键差异摘要 100% 可定位到对应属性和值。
- 价格、库存进入交易前均由交易系统二次校验。

### 14.3 性能与兼容验收

- 达成 10.4 中的性能指标，并完成弱网、超长标题、4 商品、长属性值压力测试。
- 覆盖平台支持的主流浏览器、iOS/Android 最低版本与常见屏幕尺寸。
- 完成键盘、读屏、缩放 200%、高对比度和色觉障碍检查。
- 单模块故障可降级，不造成整页白屏或错误购买。

### 14.4 上线阻断条件

- 价格或优惠出现系统性错误。
- 商品间属性错位、单位换算错误或核心属性覆盖率未达标。
- 分享链接泄露个性化或身份信息。
- 下单商品/SKU 与用户所选不一致。
- 关键性能、稳定性或无障碍要求未达到平台上线红线。

## 15. 测试重点

### 15.1 功能测试

- 从所有入口添加、取消、重复添加、跨类目添加、超过上限、清空和撤销。
- 2/3/4 件商品的展示、排序、替换和横向滚动。
- 全部相同、全部不同、部分缺失、异常值、多单位、多枚举属性。
- SKU 有货/无货/失效、促销变化、价格变化、配送区域变化。
- 登录前后合并、多端同步、历史恢复、分享打开与分享失效。

### 15.2 异常与安全测试

- 慢请求、超时、部分接口失败、重复提交、断网重连和缓存过期。
- 商品下架、类目迁移、属性模板升级、数据版本不一致。
- 分享 ID 枚举、越权读取、XSS、参数篡改、重放和限流。
- 商家标题或属性含特殊字符、超长文本、HTML 和恶意脚本。

### 15.3 数据校验

- 与商品详情、购物车和订单确认页交叉核对价格、SKU、库存和参数。
- 按类目抽样人工复核差异判断与关键摘要。
- 监控缺失率、异常率、冲突率随版本变化，防止模板更新造成回归。

## 16. 上线计划

### 16.1 阶段安排

1. **准备期**：选定 2–3 个高比较意图类目；完成属性模板、数据治理、原型和技术评审。
2. **内测期**：员工与白名单流量，验证准确性、稳定性、异常降级和反馈闭环。
3. **灰度期**：1% → 5% → 20% → 50%，每阶段至少观察一个完整高峰周期。
4. **全量期**：护栏指标稳定且实验达到预设门槛后全量；类目逐批扩展。

### 16.2 灰度准入

- P0/P1 缺陷清零，P2 缺陷具备可接受规避方案。
- 核心属性覆盖、价格一致性、性能、可用性和隐私审计通过。
- 客服、类目运营和数据治理已获得问题定位手册与责任人列表。
- 监控、告警、熔断、回滚开关均已演练。

### 16.3 回滚策略

- 前端入口、对比页、关键差异摘要、价格模块均可独立关闭。
- 关闭入口后保留已有分享页的安全降级，避免直接报错。
- 配置与属性模板支持版本回滚；服务端保持至少一个稳定版本兼容。

## 17. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 属性口径不一致 | 形成错误差异，损害信任 | 建立标准属性模型、单位转换、置信度与人工抽检 |
| 价格与促销不实时 | 投诉或购买落差 | 独立刷新、标注条件、下单前二次校验、异常熔断 |
| 信息过载 | 用户仍难以决策 | 核心属性优先、仅看差异、分组折叠、摘要定位 |
| 推荐偏置 | 商家公平与合规风险 | 事实与建议分离、广告标识、规则审计、可解释依据 |
| 入口干扰主链路 | 详情转化下降 | 次级入口、渐进式浮层、A/B 实验与护栏监控 |
| 移动端宽度受限 | 阅读困难、错列 | 固定属性名、双列视窗、吸顶标题、设备专项测试 |
| 数据缺失较多 | 工具价值下降 | 类目准入门槛、缺失监控、反馈闭环、分批开放 |
| 分享泄露隐私 | 安全与合规事故 | 匿名快照、字段白名单、不可枚举 ID、过期与删除机制 |

## 18. 依赖项与职责建议

- 商品中心：SPU/SKU、类目、标题、图片、状态。
- 属性与数据治理：标准属性、映射、单位、质量监控、纠错闭环。
- 营销与价格：实时价格、优惠条件、会员资格、赠品。
- 库存与履约：区域库存、配送时效、安装与服务。
- 交易系统：SKU 校验、加购、立即购买与订单归因。
- 评价系统：有效评价、评分、标签与内容合规。
- 用户与存储：登录态、跨端同步、历史记录和隐私删除。
- 推荐/搜索：同类候选、最近浏览、常见比较商品。
- 数据平台：埋点、实验分桶、指标看板和异常告警。
- 客服与运营：问题受理、内容审核、类目配置和上线值守。

## 19. 待决策事项
