## 一、课程定位

本课解决的不是“怎样创建一个Agent按钮”，而是：

> 当任务的下一步会受到当前信息和工具返回结果影响时，产品经理如何让模型在目标、工具、权限和停止条件内选择下一步，并为参数缺失、工具失败和高风险操作设计明确路径。

与前后课程的增量关系：

- 第02课：一次模型调用与Prompt；
- 第03课：产品经理提前规定的Workflow；
- 第04课：RAG提供企业知识依据；
- **第05课：模型受控选择工具，并根据工具结果决定是否继续；**
- 第06课：综合判断是否值得使用Agent以及MVP做到哪里。

## 四、本课程教学重组

以下内容是基于来源重新组织的教学工具，不是参考课程逐字原话：

1. **Agent最小循环**
   - 目标 → 判断缺少什么 → 选择行动 → 调用工具 → 观察结果 → 继续/停止。
2. **工具十字段**
   - 名称、用途、使用条件、输入、类型、必填、返回、异常、权限、确认。
3. **工具风险分级**
   - 自动执行、确认后执行、审批后执行、禁止自动执行。
4. **四类异常**
   - 信息不足、工具失败、权限/风险异常、判断失控。
5. **五条最小测试**
   - 正常调用、缺少参数、动态改路、工具失败、写入前确认。
6. **单Agent优先原则**
   - 一个Agent加多个工具能够稳定完成时，不为了“高级感”拆成Multi-Agent。

## 五、教学案例

### 商家经营助理

案例完全虚构，使用固定模拟数据。

三项工具：

```text
query_store_metrics
search_activity_rules
create_campaign_draft
```

经营数据返回值包含：

- 指标值；
- 环比变化；
- 数据完整性；
- 教学诊断标签；
- 诊断依据。

Agent根据标签选择下一步，不让模型自由发明经营阈值。

## 六、本课明确不讲

- Function Calling代码实现和协议字段细节；
- 真实数据库和生产接口接入；
- 长期记忆工程；
- ReAct、规划算法和思维链推导；
- MCP Server安装开发；
- A2A协议；
- Multi-Agent搭建与复杂通信；
- Computer Use和浏览器自主操作；
- 完整Agent评测指标体系；
- 企业级审计和完整权限架构。

## 七、来源风险与纠偏

1. 录音转写中的`防尘扩`、`方程calling`等统一按上下文理解为`Function Calling`。
2. 参考课中“Agent是终端唯一形态”等趋势判断不作为本课确定事实。
3. 工具风险分级属于课程教学框架，不能声称为统一行业标准。
4. MCP具体平台、数量、安装入口会变化，只固定概念和产品判断。
5. 原课中的酒店、出行和真实平台案例不作为本课主案例。
6. 平台演示的按钮和套餐必须开课前实测。

## 八、结论

本课核心知识有充分原文支撑。Function Calling、Agent与Workflow差异、工具执行循环和MCP由知乎技术先修课直接覆盖；Agent能力、关键确认与Multi-Agent由亚慧Agent课覆盖；目标、边界和人工接管由知乎正课第19课补强。

课程新增的价值不在于制造新技术结论，而是把来源内容重组为初级产品经理可以直接使用的工具设计、风险确认、异常处理和测试产物。
