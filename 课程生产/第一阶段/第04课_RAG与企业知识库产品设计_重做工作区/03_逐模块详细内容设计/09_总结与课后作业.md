# 09 总结与课后作业（119-125分钟）

## 教学目标

帮助学员把零散知识收束为一条可迁移的产品设计路径，并明确课后作业的验收标准。

## 一张图复盘

```text
先判断：是不是知识型问题？
  ├─ 实时事实 → 业务系统/API
  ├─ 高风险争议 → 人工/受控流程
  └─ 内部知识 → RAG

RAG设计：
知识来源与治理
→ 解析与分块
→ 检索与重排
→ 增强Prompt与生成
→ 引用/无答案/冲突处理
→ 测试与反馈
```

## 本课六个结论

1. RAG是“先检索、后生成”，不是让模型重新训练一次；
2. RAG适合企业内部、需要更新、需要依据的知识；
3. 实时订单和经营事实必须查询业务系统；
4. 知识质量、版本和权限是产品问题，不只是技术问题；
5. RAG只能缓解幻觉，不能保证答案正确；
6. 测试时必须分开看检索结果和最终回答。

## 产品经理在RAG项目中的工作

产品经理需要推动：

- 定义用户问题和业务边界；
- 选择知识源并确认权威性；
- 协调知识负责人和更新机制；
- 定义版本、范围和权限；
- 设计正常、无答案、冲突和人工路径；
- 准备测试样本；
- 根据Bad Case判断先改哪一层；
- 与算法、后端、数据、运营和安全团队协作。

产品经理不需要独立完成：

- Embedding模型开发；
- 向量数据库底层实现；
- OCR与文档解析算法；
- 大规模检索性能优化。

## 课后作业

### 任务

在自己的工作或熟悉领域中，选择一个“基于知识回答”的场景，完成《RAG知识库产品设计V1.0》。

### 必交内容

1. 用户与业务问题；
2. 为什么适合RAG；
3. 哪些问题不由RAG处理；
4. 至少3类知识来源；
5. 每类知识的治理六字段；
6. 离线建库和在线问答流程图；
7. 无答案、冲突和权限策略；
8. 5条测试问题：
   - 3条正常命中；
   - 1条无答案；
   - 1条边界或冲突；
9. 如果能使用平台：
   - 至少上传2份脱敏或公开文档；
   - 截图一条检索结果；
   - 记录一个Bad Case及修改；
10. 如果不能使用平台：
   - 用纸面检索卡模拟同样过程。

## 作业验收标准

| 维度 | 通过标准 |
|---|---|
| 场景合理 | 答案来自相对稳定或可更新知识，而不是实时交易事实 |
| 来源清楚 | 能说明知识从哪里来、谁负责 |
| 边界清楚 | 明确RAG、业务系统和人工各自负责什么 |
| 链路完整 | 包含建库、检索、生成和失败处理 |
| 治理可执行 | 有版本、范围、权限和更新机制 |
| 测试有效 | 不只测试“能答”，还覆盖无答案和冲突 |
| 安全合规 | 不上传公司敏感信息和个人数据 |

## 零基础降级要求

完全零基础学员只需完成：

- 1个明确场景；
- 2类知识来源；
- 1张RAG流程图；
- 3条测试，其中必须有1条无答案；
- 不要求完成平台搭建。

降级的是工具操作，不降低对场景边界和知识来源的要求。

## 与下一课衔接

下一课学习Agent与工具调用：

- Workflow：产品预先规定主要路径；
- RAG：为知识型问题提供依据；
- Agent：模型在目标约束下决定是否以及如何调用知识或工具。

下一课不会重新讲RAG基础，而是把RAG作为Agent可使用的一项受控能力。
