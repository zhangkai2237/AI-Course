# Nimra AI 产品需求文档（中文改写）

> 来源：英文 `原始PRD.xlsx` 与 `原始PRD.csv`。本文保留原方案逻辑，并按中文 PRD 结构重组。

## 1. 产品定义

Nimra AI 是面向销售、投标和资助申请团队的 RFP 发现与需求拆解工具。系统从公开来源发现机会，或接收用户上传的招标文件，将长文档转换为带来源位置的结构化要求清单。

## 2. 市场与问题

政府、非营利和企业采购中的 RFP 数量受预算和经济周期影响，但大量寻找、阅读和整理工作仍依靠人工。现有 Loopio、Responsive、Qorus Docs、Inventive.AI 等产品更多聚焦回复和知识库管理，前置的机会发现与资格判断仍有空间。

## 3. 用户与商业模式

- 用户：销售、销售工程师、提案撰写者、资助申请者；
- 场景：机会搜索、资格判断、要求拆解和响应准备；
- 商业模式设想：低价订阅，订阅期内提供持续搜索和文档处理；
- 产品体验：用搜索、上传和清单代替开放式聊天。

## 4. 产品目标

- 提高潜在 RFP 的发现效率；
- 尽可能不漏掉资格、截止日期和强制要求；
- 让每项要求能够定位到原文；
- 将 40—200 页文件转成可执行清单；
- 在长文档场景控制延迟、重复和输出膨胀。

## 5. MVP 范围

### 当前范围

- 搜索或上传 RFP；
- PDF/TXT 解析与长文档切片；
- 机会、资格、范围和截止日期提取；
- 必需/可选分类；
- 行动项/信息项分类；
- 去重、置信度和人工复核标记；
- 来源锚点与交互式清单；
- 结果存储与流式返回。

### 延后范围

- 自动填写整份 RFP；
- 记住企业历史回答；
- 分析历史中标内容并提出写作建议；
- 大规模开源模型替换和复杂协作功能。

## 6. 核心功能

### F1 RFP 发现与接入

使用爬虫、来源 API 和适配器发现公开机会；用户也可以直接上传 PDF 或 TXT。

### F2 文档解析与分片

清理文本，按章节和语义切片，并行处理长文档。保留页码、标题或字符范围，供最终引用。

### F3 需求抽取与分类

抽取资格、截止日期、交付要求、技术和商务条款，并标记必需/可选、行动项/信息项。

### F4 去重和能力匹配

合并同义或重复要求，并可将要求与销售方产品材料进行匹配，帮助快速判断适配性。

### F5 评分与人工复核

为每项要求提供置信度。低置信度、潜在误报或冲突项进入复核队列，不能静默删除。

### F6 清单与来源

生成可勾选清单，每项包含类型、责任动作、原文位置和状态。处理过程中用流式 NDJSON 持续返回可用结果。

## 7. 多 Agent 方案

- Bones：文档接入与文本提取；
- Brule：需求抽取；
- Dr. Rockzo：要求与销售能力匹配；
- Shakalu：必需/可选分类；
- Heiter：语义去重；
- Robby：评分与复核标记；
- Dr. Cox：误报审计；
- Riviera：组装清单和来源锚点。

主要 Agent 使用 Claude Sonnet，部分低复杂度步骤使用 Haiku。长期计划是抽象模型连接层，评估 Qwen、Llama 等开源模型。

## 8. 数据与系统

- 存储：Postgres；
- 向量检索：pgvector；
- 向量能力：Voyage AI；
- Agent 间协议：严格 JSON；
- 长文档策略：切片、并行和流式输出；
- 用户反馈：记录错误标签、漏项和修改，进入评测集。

## 9. 评测

人工标注 Gold Cases，使用召回加权的 Fβ 指标，β=2。除准确率外，还要测：

- 强制要求召回率；
- 必需/可选分类准确性；
- 重复率和输出膨胀；
- 来源锚点准确性；
- 端到端和首批结果延迟；
- Token 成本；
- 新版本对既有 Gold Case 的回归影响。

公开材料记录的早期结果约为 92% 准确率，但 20 页文件处理超过 5 分钟，输出量达到人工标准的 119%。这两项必须作为上线前阻断问题。

## 10. 风险与边界

- RFP 格式和行业差异造成长尾；
- 高召回策略会增加人工复核；
- 多 Agent 链路可能累积延迟和成本；
- 去重过强可能误删真实要求；
- 来源锚点错误会破坏用户信任；
- 产品不能在没有证据时声称用户具备投标资格。
