# 03 从人工SOP到流程（20—35分钟）

## 案例背景

虚构的“邻里增长平台”服务本地商家。商家运营每天收到大量咨询，目前人工处理方式是：先读问题、判断类型，再查规则、查系统、转人工或追问。团队希望用AI降低重复分流成本，但第一版不允许模型编造实时数据，也不允许自动承诺退款赔偿。

## 先定义输出

每次处理必须输出五项：

1. `issue_type`：RULE / DATA / COMPLAINT / OTHER；
2. `handling_method`：回答规则 / 查询系统 / 转人工 / 追问；
3. `reference_reply`：给用户看的参考话术；
4. `need_human`：true / false；
5. `reason`：为什么走这条路径，供内部检查。

## 再定义输入

本课只保留一个必填输入：`user_query`，即商家原始问题。课堂规则卡作为固定材料写入规则分支。真实产品后续还可能需要商家ID、门店ID、渠道、历史对话等，但本课不加入。

## 把人工SOP翻译成四条路径

1. 阅读 `user_query`；
2. 判断四类意图；
3. 根据标签进入对应分支；
4. 每条分支产生安全输出；
5. 汇总到结束节点。

## 为什么先画图再开平台

平台只能帮助执行逻辑，不能替产品经理决定：分几类、哪些能自动答、哪些必须人工、成功标准是什么。逻辑没画清楚时直接拖节点，常见结果是画布很复杂但业务边界不清。

## 课堂追问

- “昨天门店GMV是多少？”为什么不能直接让模型回答？
- “平台乱扣费，我要投诉。”为什么转人工不是AI失败？
- “活动怎么回事？”为什么不应该强行归为规则咨询？
