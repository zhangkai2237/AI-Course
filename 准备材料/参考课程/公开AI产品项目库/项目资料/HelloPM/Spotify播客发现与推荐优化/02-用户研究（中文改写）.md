# 第二阶段：Spotify用户研究

> 根据同目录《02-用户研究.pdf》中文改写。

## 1. 研究方法

通过5次访谈和问卷研究播客听众怎样发现、选择和消费内容。

## 2. 主要发现

### 发现发生在外部

用户通过Instagram、YouTube片段、朋友和热门事件找到播客，再到Spotify播放。Spotify被当成播放终点而不是发现起点。

### 选择依赖情境

- 通勤需要与路程匹配的长度；
- 锻炼时更适合短新闻；
- 深度学习需要长内容；
- 放松时更重视情绪与关系感。

### 可信度来自主持人和嘉宾

知识型用户会先判断嘉宾背景和主持人质量，再决定是否投入时间。单纯热度不足以建立信任。

### 前三个搜索结果非常关键

如果候选不能在前几项命中用户意图，用户会离开搜索或回到外部平台。

### 长内容需要导航

用户希望看到章节、时间戳和主题，以便跳到关心部分。

## 3. 两类代表用户

### 好奇探索者

通过社交短片发现内容，重视情绪、话题和嘉宾关系，希望低成本尝试。

### 知识型用户

把播客当学习材料，重视专业性、深度、时效和职业阶段。

## 4. 最终问题

Spotify缺少按意图、心情、场景和可信度组织播客的机制，导致用户发现困难、搜索退出，并把平台固定为消费工具。

## 5. 设计约束

- 新用户不能依赖历史行为；
- 推荐必须支持时长和场景；
- 用户需要知道为什么推荐；
- 热门不等于适合；
- 片段、章节和可信度都应服务于更快开始播放。

+## 6. 研究对产品的具体要求

| 研究发现 | 设计要求 |
|---|---|
| 外部短片是主要入口 | 将试听片段带回Spotify |
| 通勤和运动影响时长 | 支持场景与时长筛选 |
| 嘉宾背景影响信任 | 展示可核验资料 |
| 前三项不相关就退出 | 提高顶部结果准确性 |
| 长节目难导航 | 提供章节与时间戳 |
| 用户把Spotify当音乐App | 给播客独立而清楚的入口 |

## 7. 用户任务表达

用户不是在寻找“一个播客”，而是在完成更具体的任务：

- 通勤40分钟了解行业新闻；
- 锻炼时听10分钟快讯；
- 周末深度理解一个主题；
- 找到熟悉艺人参加的访谈；
- 判断一位嘉宾是否值得投入一小时。

推荐系统需要理解任务，而不只是内容标签。

## 8. 研究局限

- 样本不大；
- 受访者可能偏重知识和长内容；
- “前三个结果”需要行为数据验证；
- 用户说喜欢短片，不代表会因此完成长节目；
- 音乐与播客兴趣的迁移仍是假设。
