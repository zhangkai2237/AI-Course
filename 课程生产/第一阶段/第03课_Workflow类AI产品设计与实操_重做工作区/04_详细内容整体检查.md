# 第03课详细内容整体检查

## 检查结论

九个模块已经形成完整闭环，可以进入讲义生产。课程不再重复旧第三课的“产品形态分类”，增量明确：从第02课的一次Prompt进入多节点、分支和测试。

## 逐项检查

| 检查项 | 结果 | 修正 |
|---|---|---|
| 与第02课衔接 | 通过 | 开场直接对比“一次调用”和“多路径”，不重讲六要素 |
| 零基础可理解 | 通过 | 先纸面V0.1，再单路V0.2，最后四路V0.3 |
| 来源可追溯 | 通过 | Workflow、意图路由、最小闭环、实时数据和人工兜底均有原文锚点 |
| 案例真实性 | 通过 | 有业务背景、角色、约束和失败路径；同时明确为教学虚构 |
| 操作难度 | 通过 | 只使用开始、LLM、条件、固定输出、结束和日志 |
| 与RAG边界 | 通过 | RULE只读固定规则卡，不讲知识库；明确下一课替换点 |
| 风险边界 | 通过 | DATA不编数，COMPLAINT不承诺，OTHER不强猜 |
| 时间 | 可执行 | 基准120分钟；跟做和讨论可自然延长至125—130分钟 |
| 可离线授课 | 通过 | 纸面练习、完整Prompt和参考流程均可脱离平台完成 |

## 必须保留的设计

1. 纸面流程图先于工具操作；
2. `DATA`和`COMPLAINT`使用确定性安全输出；
3. 五条测试中必须包含模糊输入与高风险输入；
4. 故意制造“分类输出多了说明导致分支失败”的Bad Case；
5. 课尾明确RAG只接替规则材料获取，不把两课混在一起。

## 不进入本课的内容

循环、子工作流、API、数据库、RAG、Agent、置信度阈值、线上监控和复杂评测全部不进入正式讲授。它们可以在答疑中只说明后续课程位置，不能现场扩展搭建。
