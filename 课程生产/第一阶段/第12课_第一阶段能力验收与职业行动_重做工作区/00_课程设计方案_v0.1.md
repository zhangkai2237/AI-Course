# 第12课｜从零散技能到完整AI产品：阶段能力验收与职业行动

> 文档用途：第12课整体课程设计方案。  
> 当前版本：v0.1，待逐节讨论确认后，再展开完整讲义与PPT。  
> 建议时长：180分钟，包含10分钟课间休息。  
> 课程性质：第一阶段收尾课、能力验收课、第二阶段项目启动课。  

---

## 一、课程定位

### 1. 这节课不是什么

第12课不是：

- 按照第1课到第11课重新复述一遍知识点；
- 再讲一次AI产品经理有哪些岗位方向；
- 把老师提供的完整PRD包装成学员自己的项目成果；
- 依靠行业趋势、职业口号和情绪鼓励制造结课感；
- 在最后一课继续堆叠大量新知识。

### 2. 这节课要解决什么

第一阶段已经让学员分别接触了AI场景判断、Prompt、Workflow、RAG、Agent、需求分析、PRD、原型、Demo、评测、模型选型、成本和ROI。

但这些能力目前仍然分散在不同课程和不同练习中。第12课需要帮助学员完成三次连接：

1. 把分散知识连接成一条完整的AI产品工作链路；
2. 把课堂练习连接成可以被检查的能力证据；
3. 把第一阶段的学习结果连接到个人职业方向和第二阶段项目。

### 3. 一句话课程目标

> 通过一次陌生AI产品需求的综合判断，帮助学员验收第一阶段能力，看清距离完整项目的差距，并形成下一阶段的项目与职业行动计划。

### 4. 本课回答五个问题

1. 面对一个新的AI产品需求，我能不能独立完成基本判断？
2. 前11课的知识如何组成一条完整的AI产品工作链路？
3. 什么样的AI项目才能成为可信的作品集证据？
4. 学完第一阶段后，我原来的职业方向判断是否需要修正？
5. 第二阶段应该完成什么项目，补齐什么能力？

## 二、贯穿全课的主案例

### 1. 案例名称

**项目会议决策与任务跟进助手**

### 2. 业务背景

一家拥有多个并行项目的企业，每周召开大量项目会议。会议结束后，项目经理需要人工整理：

- 本次会议形成了哪些明确结论；
- 哪些问题仍然存在分歧；
- 产生了哪些待办任务；
- 每项任务的负责人和截止时间；
- 哪些结论与历史会议或项目制度存在冲突；
- 哪些任务需要同步到项目管理系统。

目前主要问题是：

- 一场60分钟会议，整理纪要通常需要30—40分钟；
- 讨论内容很多，但真正的结论和待办经常遗漏；
- 负责人、截止时间和验收要求表述不完整；
- 新结论可能与历史决策冲突；
- 人工录入任务系统容易延迟或出错；
- 部分会议内容涉及未公开产品和客户信息，存在数据安全要求。

业务方希望建设一个AI助手：上传会议转写文本后，自动提取会议结论、分歧和行动项，结合历史项目资料检查冲突，并在人工确认后同步到任务系统。

### 3. 案例为什么适合作为结课验收

这个案例能够覆盖第一阶段的主要能力，但不会直接复刻以前的课堂项目：

| 第一阶段能力 | 在案例中的对应问题 |
|---|---|
| 场景判断 | 会议整理是否真值得用AI解决，价值在哪里 |
| Prompt与上下文 | 如何定义输入、任务、约束和结构化输出 |
| Workflow | 转写、提取、校验、确认和同步如何组成流程 |
| RAG | 如何检索历史决策、制度和项目资料 |
| Agent与工具调用 | 是否允许自动创建任务，在哪一步必须人工确认 |
| MVP | 第一期先解决纪要整理，还是同时解决冲突检查和任务同步 |
| PRD | 如何写清楚用户、流程、输入输出、异常和验收标准 |
| 原型与Demo | 需要设计哪些页面、状态和确认动作 |
| 评测与Bad Case | 如何判断结论、负责人、截止时间是否提取正确 |
| 模型选型 | 如何平衡长文本能力、准确率、速度、安全和成本 |
| ROI | 节省的整理时间和降低的遗漏损失能否覆盖系统成本 |

### 4. 案例使用边界

- 本课不要求学员现场写完完整PRD；
- 不要求现场搭建可运行系统；
- 不追求唯一标准答案；
- 重点检查学员能否识别关键决策、风险和验证方法；
- 案例结束后必须回到通用能力，不把整节课变成另一堂项目实战课。

## 四、各部分详细规划

## 开场：说明本课的验收任务（0—10分钟）

### 教学目的

- 让学员知道今天不是知识回放；
- 建立“用一个陌生需求检查学习成果”的课堂预期；
- 明确整节课的三个最终产出。

### 核心内容

教师先展示两个问题：

1. 如果现在给你一个从未见过的AI产品需求，你知道应该问哪些问题吗？
2. 如果面试官问你“为什么这样设计”，你能不能用产品、AI、评测和商业证据回答？

随后说明本课的验收标准：

> 第一阶段不是要求学员记住所有概念，而是要求面对一个新需求时，知道应该依次做出哪些判断。

### 本课最终带走的成果

1. AI产品决策全景图；
2. 完整项目差距清单；
3. 第二阶段项目与职业行动卡。

---

## 第一节：陌生AI产品需求的综合判断（10—45分钟）

### 教学目的

在教师提示答案之前，检查学员能否主动调用前11课所学内容。

### 课堂任务

围绕“项目会议决策与任务跟进助手”，要求学员完成八项判断：

1. 谁是核心用户，当前问题究竟是什么；
2. 为什么需要AI，哪些问题不需要AI；
3. AI、规则和人工分别负责什么；
4. 应该采用Prompt、Workflow、RAG还是Agent；
5. MVP第一期应该做什么、不做什么；
6. 系统最可能出现哪些错误；
7. 应该如何评测，达到什么条件才允许上线；
8. 模型、安全、成本和ROI需要检查什么。

### 教学方式

- 5分钟：教师发放案例材料并说明背景；
- 12分钟：学员独立填写，避免一开始被他人答案影响；
- 10分钟：3—4人小组对比方案，找出分歧；
- 8分钟：抽取两组说明最关键的三个决策。

### 学员产出

**《AI产品决策全景图V0.1》**

这张表不要求写成长篇文档，只要求每一个关键判断都有简洁结论和依据。

### 观察重点

教师不急着判断工具名称是否选对，重点观察：

- 是否先从用户问题出发；
- 是否把“大模型能生成”误认为“产品应该自动执行”；
- 是否考虑知识来源、错误风险和人工确认；
- 是否能够主动缩小MVP；
- 是否提出可执行的评测方法；
- 是否把模型能力、成本与业务价值放在一起判断。

---

## 第二节：第一阶段能力地图与案例复盘（45—70分钟）

### 教学目的

把第一节的分散答案重新组织成一条完整的AI产品工作链路，让学员看见自己真正掌握的能力结构。

### 复盘主线

教师不按照课程编号回顾，而是按照五个工作阶段复盘：

| 工作阶段 | 关键问题 | 对应课程能力 |
|---|---|---|
| 发现与判断问题 | 谁的问题、是否值得解决、AI是否适合介入 | 岗位认知、场景判断、需求分析 |
| 设计AI解决方案 | 规则、Prompt、Workflow、RAG、Agent如何分工 | 大模型基础与四类产品能力 |
| 定义产品与MVP | 产品流程、功能范围、输入输出和人机协作怎么设计 | PRD、MVP、原型与Demo |
| 验证效果与风险 | 系统是否有效、哪里会错、如何持续改进 | 评测集、指标、Bad Case |
| 判断落地与价值 | 模型能否稳定使用、成本是否合理、项目是否值得做 | 模型选型、部署约束、Token成本、ROI |

### 教师复盘的重点结论

完整的AI产品判断不是选择一个技术名词，而是形成一条证据链：

> 真实问题 → AI介入理由 → 产品与人机方案 → MVP → 效果验证 → 成本与价值 → 迭代。

### 学员产出

学员根据复盘修改第一节答案，形成：

**《AI产品决策全景图V1.0》**

### 与前课的边界

- 不重新解释Prompt、RAG、Workflow和Agent的基本概念；
- 不重新教学如何写PRD、做评测或计算ROI；
- 只说明这些能力在完整项目中何时出现、如何互相影响。

## 第三节：完整AI项目的成果标准与差距诊断（80—120分钟）

### 教学目的

让学员区分“听过课程、做过局部练习”和“拥有一个可以证明能力的完整项目”。

### 1. 完整项目需要形成七类证据

| 项目证据 | 需要证明什么 |
|---|---|
| 用户与场景证据 | 问题真实存在，并值得解决 |
| 产品判断与需求分析 | 为什么使用AI，目标和范围是否合理 |
| 正式PRD | 产品流程、功能、规则、异常和验收是否清楚 |
| AI方案与系统流程 | Prompt、Workflow、RAG、Agent、规则和人工如何协作 |
| 原型或可运行Demo | 方案能否被体验、演示和验证 |
| 评测结果与Bad Case | AI效果是否达到要求，问题如何被发现和改进 |
| 模型、成本、ROI与迭代记录 | 产品是否具备真实落地和持续运营的可能 |

### 2. 盘点第一阶段已经拥有的材料

学员不是“什么都没有”，已经接触或完成过：

- Prompt与结构化输出练习；
- Workflow设计与测试；
- RAG知识库方案；
- Agent受控工具调用方案；
- Coze综合实践；
- AI辅助需求分析和PRD；
- 原型与Vibe Coding Demo；
- 评测集、指标与Bad Case分析；
- 智能审核项目完整PRD参考稿；
- 模型选型、成本与ROI判断。

### 3. 明确当前缺少的内容

大多数学员尚未亲自完成：

- 一个由自己选择并持续推进的统一项目；
- 一套前后口径完全一致的项目材料；
- 基于真实用户、业务数据或访谈的需求证据；
- 自己完成并可以演示的Demo；
- 真实评测结果和多轮迭代记录；
- 能够在面试中完整讲述的项目故事。

### 4. 正确使用第10课智能审核项目

第10课的完整PRD是：

- 学习完整AI PRD结构的参考样本；
- 检查项目材料完整度的教学案例；
- 第二阶段项目设计时可以借鉴的方法模板。

它不是所有学员已经独立完成的作品，也不能直接写进每个人的简历。

### 课堂练习

让学员选择自己最想继续完善的一个课堂案例，按照七类证据标记：

- 已经完成；
- 接触过但需要重做；
- 完全缺失；
- 需要真实用户或外部条件支持。

### 学员产出

**《完整AI项目差距清单》**

---

## 第四节：第一阶段后的职业方向校准（120—150分钟）

### 教学目的

不重复第1课的岗位分类，而是根据11节课中的真实学习体验，重新校准当时的方向假设。

### 校准依据

学员回看第1课的“个人方向初步判断卡”，再用以下证据检查：

1. 哪类任务自己理解得最快；
2. 哪类课堂产出完成得最好；
3. 更喜欢研究用户和业务，还是设计系统与AI能力；
4. 更喜欢标准化产品，还是企业项目和解决方案；
5. 面对评测、成本、技术限制时是否愿意继续深入；
6. 当前能力能够支持目标岗位中的哪些要求；
7. 最大的证据缺口能否通过一个完整项目补齐。

### 职业部分的核心结论

第1课形成的是职业方向假设；第12课做的是基于学习证据的第一次修正。

本节不承诺一次选出唯一方向，而是形成：

- 一个优先验证方向；
- 一个备选方向；
- 三项已有证据；
- 三项关键缺口；
- 下一步需要分析的真实JD；
- 一个能够补齐主要证据的项目方向。

### 学员产出

**《职业能力校准卡V1.0》**

### 与第1课的边界

- 不重讲AI产品岗位分类；
- 不重讲零基础转型路径；
- 不泛讲行业前景和薪资；
- 只根据第一阶段产生的新证据修正原有判断。

---

## 第五节：第二阶段项目任务与行动计划（150—175分钟）

### 教学目的

让第一阶段不以“听完课程”结束，而以“明确下一项完整任务”结束。

### 第二阶段核心任务

> 独立完成一个能够被体验、被验证、被讲清楚的AI产品项目。

### 项目必须包含的交付物

1. 项目背景与用户问题；
2. 需求证据和AI介入判断；
3. 产品方案与正式PRD；
4. AI能力分工和系统流程；
5. 原型或可运行Demo；
6. 评测集、评测结果和Bad Case；
7. 模型选型、成本和ROI方案；
8. 至少一次基于测试结果的迭代；
9. 项目展示材料和面试讲述版本。

### 项目选择标准

项目不追求看起来宏大，优先满足：

- 有明确用户和高频问题；
- 能找到或合理构造测试材料；
- 能在有限时间内完成核心闭环；
- AI能力在项目中不可替代，但不承担所有工作；
- 能够做出原型或Demo；
- 能够形成可量化的评测和价值判断；
- 与个人目标岗位存在关联。

### 项目任务书V0.1

课堂内只要求完成：

- 项目暂定名称；
- 目标用户与核心问题；
- 为什么选择它；
- 希望证明的三项能力；
- 当前已经拥有的材料；
- 最大的三个未知问题；
- 第一周需要完成的验证动作。

### 学员产出

**《第二阶段项目任务书V0.1》**

---

## 五、课程收尾设计（175—180分钟）

### 不使用的收尾方式

- 不用长篇行业趋势制造兴奋感；
- 不说“学完以后已经具备独立负责所有AI项目的能力”；
- 不用大段职业口号替代下一步行动；
- 不再增加新的概念和方法。

### 最终回收三个结论

1. **第一阶段完成了什么**  
   从只会体验AI工具，走到了能够对AI产品做出基本判断。

2. **第一阶段还没有完成什么**  
   还没有形成一个由自己端到端完成、可以被验证和展示的完整项目。

3. **第二阶段要完成什么**  
   把第一阶段的判断方法变成一个属于自己的完整AI产品证据链。

### 建议结束语

> 第一阶段真正重要的，不是你记住了多少AI名词，而是面对一个新问题时，你开始知道应该问谁的问题、为什么需要AI、方案应该怎样分工、怎样验证效果，以及这件事是否值得做。下一阶段，我们要把这些判断变成一个能够被体验、被验证、也能够由你自己讲清楚的完整项目。

## 六、课程材料规划

本课后续只生产必要材料，控制文件数量：

1. **完整授课讲义**：所有章节持续写入同一个Markdown文件；
2. **正式PPT**：以内容页为主，减少纯过渡页；
3. **课堂学习单**：整合三张表，不拆成多个零散文件；
4. **教师使用的案例参考答案**：供复盘和时间控制使用。

### PPT结构原则

- 每个章节标题明确写出该节讲授内容；
- 标题负责说明结构，不直接替代正文结论；
- 章节编号和名称必须足够醒目；
- 减少只有一句话的过渡页；
- 关键案例、判断表、能力地图和项目证据链必须在PPT中完整呈现；
- 同一套案例贯穿前两节，第三节以后回到学员个人项目；
- 预计32—38页，不追求页数，优先保证只看PPT也能理解课程主线。
