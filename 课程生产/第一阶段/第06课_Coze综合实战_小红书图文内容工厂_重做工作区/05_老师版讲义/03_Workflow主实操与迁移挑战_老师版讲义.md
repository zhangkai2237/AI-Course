# 模块03：Workflow主实操与迁移挑战——老师版讲义

> 时间：38—83分钟  
> 主实操：37分钟  
> 迁移挑战：8分钟  
> 产物：P1小红书图文Workflow＋60秒口播挑战版

## 一、老师先理解

Workflow不是把一个LLM节点外面多画几条线，而是把可预先确定的生产步骤拆开，使每一步有明确输入、输出、错误位置和是否继续的条件。

本轮仍然会用到Prompt：内容策划、标题正文、图片脚本和审核节点都有自己的Prompt。正确关系是：

> Prompt定义一个节点怎么做；Workflow定义多个节点按什么顺序协作。

本轮的核心不在搭多少节点，而在让学员亲自经历：单节点调试、变量传递、缺信息分支和局部修改。

## 二、开场建议讲法

“P0有一个典型问题：角度不对、正文缺失、图片不匹配时，我们只看到最终结果，不知道应该改哪里。如果把所有要求继续堆进一个Prompt，短期能补洞，长期会越来越难维护。

现在把内容生产当成一个真实SOP：先检查原料，再定角度，再写正文，再做图片脚本，最后审核。步骤可以提前确定，所以先用Workflow，而不是Agent。”

## 三、屏幕/板书：目标流程

```text
Start
→ 必要输入检查
→ 内容角度与大纲
→ 标题与正文
→ 图片脚本
→ 图片生成 / 图片Prompt
→ 内容审核
→ End
```

请学员先不要操作，老师逐节点说一句职责。强调一个节点最好有一个主要职责。

## 四、屏幕操作一：Start与输入检查

P1沿用P0输入，并增加：

- `image_style`：例如简洁编辑感、米白背景、蓝绿色点缀；
- `page_count`：课堂默认3。

增加条件节点或平台当前提供的等价判断能力：

```text
topic为空 OR audience为空 OR source_material为空
→ 返回“请补充缺失信息”

其余情况
→ 进入内容角度与大纲
```

### 建议讲法

“P0里我们只能在Prompt中请求模型别编造；P1把关键规则变成确定性分支。只要必要素材为空，后面的生成节点就不运行。这是从语言要求变成系统控制。”

### 检查结果

让学员临时清空source_material运行一次。正确结果不是文案质量差，而是根本不进入内容生成路径。

## 五、屏幕操作二：内容角度与大纲节点

该节点只做策划，不写完整正文。

建议Prompt：

```text
你是一名知识型内容策划。

请根据主题、受众、目标和事实素材，形成内容策划方案。

主题：{{topic}}
受众：{{audience}}
目标：{{goal}}
事实素材：{{source_material}}

只输出：
1. 受众当前最可能遇到的问题；
2. 一个主要内容切入角度；
3. 一个核心观点；
4. “问题—误区—方法—行动”的四段式大纲；
5. 希望读者采取的行动。

不得写完整正文，不得补充素材中没有的个人经历和效果数字。
```

### 学员动作

先单独运行本节点，查看输入中是否真的包含topic、audience、goal和source_material，再看输出是否只停留在策划层。

## 六、屏幕操作三：标题与正文节点

输入必须同时包含：

- Start中的原始事实和风格；
- 上一节点产生的受众问题、核心观点和大纲。

建议Prompt：

```text
你是一名小红书知识内容编辑。

请严格依据原始素材和策划大纲生成内容。

【原始事实】
{{source_material}}

【目标受众】
{{audience}}

【内容目标】
{{goal}}

【表达风格】
{{tone}}

【策划大纲】
{{outline}}

输出：
1. 5个不过度夸张的标题；
2. 1篇结构清楚的正文；
3. 1句不超过18字的封面文案；
4. 3—5个标签。

不得添加原始事实和大纲中不存在的经历、公司、数据和结果承诺。
```

### 纠偏

如果正文完全没有使用大纲，让学员查看节点运行输入。最常见原因不是模型能力，而是上游输出未绑定。

## 七、屏幕操作四：图片脚本节点

输入：选定标题、正文、image_style和page_count。

建议Prompt：

```text
请将以下小红书正文转成图文脚本。

正文：{{body}}
图片风格：{{image_style}}
内页数量：{{page_count}}

输出：
1. 封面：主文案、辅助文案、画面主体、版式；
2. 每张内页：页标题、3个以内要点、画面建议、排版建议；
3. 每张图片对应的生成提示词。

要求：
- 页数与page_count一致；
- 单页文字适合移动端阅读；
- 图片内容与正文顺序一致；
- 不出现未经提供的品牌Logo、人物身份和效果数字。
```

### 图片两条路线

如果课堂账户的图片生成节点稳定：将图片Prompt传入图片生成能力。

如果权限、模型或额度不稳定：直接把结构化图片Prompt作为节点输出，并用老师预生成图片进入审核。老师要明确告诉学员，学习目标是“流程产生了正确的图片输入”，不是比赛谁现场出图更快。

## 八、屏幕操作五：内容审核节点

审核节点不能只输出“整体不错”。建议固定检查项：

```text
请依据原始事实，对正文和图片脚本进行审核。

原始事实：{{source_material}}
正文：{{body}}
图片脚本：{{image_script}}

逐项输出：
1. 事实是否都能在原始素材中找到依据；
2. 是否存在夸张承诺或焦虑营销；
3. 标题、正文和图片是否一致；
4. 单页文字是否过长；
5. 必须人工修改的内容；
6. review_status：pass或revise。

只要存在无法确认的个人经历、公司信息、数字或效果承诺，review_status必须为revise。
```

### 老师先理解

LLM审核不能等同于最终风控。它只是流程内的一次自动检查，正式发布前仍需人工确认。

## 九、单节点调试顺序

要求全班按固定顺序调试：

1. 内容角度；
2. 标题正文；
3. 图片脚本；
4. 内容审核；
5. 完整流程。

每完成一个节点，都要打开运行记录回答：

- 它实际收到了什么？
- 它实际返回了什么？
- 下一个节点引用的是哪个字段？

### 建议讲法

“做Workflow时，最终答案只是最后一张成绩单。真正的排错证据在每个节点的输入和输出里。”

## 十、三条课堂测试

### W1：正常路径

使用统一输入，检查所有节点按顺序运行，End返回标题、正文、标签、封面、内页、图片或图片Prompt、审核结果。

### W2：缺素材路径

删除source_material。预期进入补充信息分支，后续生成节点不运行。

### W3：页数冲突Bad Case

将page_count设为5，但故意让图片节点的Prompt仍写死“输出3张内页”。

让学员定位：

- Start收到的是5；
- 图片脚本输出只有3；
- 问题发生在图片脚本节点；
- 应让节点遵循page_count，而不是在总Prompt里到处补“5页”。

## 十一、迁移挑战：60秒短视频口播稿

复制P1，不从空白开始。保留输入检查、内容角度和审核，替换下游输出：

```text
标题正文节点 → 60秒口播脚本
图片脚本节点 → 镜头脚本
图片生成节点 → 画面提示/B-roll建议
```

新输出要求：

- 0—3秒：开头钩子；
- 3—48秒：问题、误区和方法；
- 48—60秒：总结与行动；
- 每段对应镜头、字幕重点和风险提示。

### 迁移讲解

“迁移不是换一个Prompt就算完成，也不是重新搭一遍。我们保留仍然稳定的上游流程，只替换与新内容形态有关的下游节点。”

## 十二、常见故障

### 节点有输出，下游却为空

检查下游绑定的是否为本次运行字段；字段改名后要同步更新引用。

### 条件分支始终走错

先查看Start中的原始值，注意空字符串、空格和未传值在平台中可能表现不同。课堂可先使用最简单的“为空/不为空”判断。

### 完整流程耗时过长

暂停图片实际生成，改走图片Prompt路线；其他节点仍可完整验证。

### 审核永远pass

给正文故意加入一个素材中不存在的结果数字，检查审核规则是否真正工作。

## 十三、最低完成线与认知记录

最低完成线：

- 正常路径到达End；
- 缺素材路径停止；
- 至少检查三个节点的真实输入输出；
- 能定位页数冲突发生在哪个节点；
- 理解短视频挑战如何复用上游流程。

学员填写：

> Workflow把可预先确定的任务拆成可重复、可观察和可局部修改的步骤；当下一步需要根据开放状态动态选择时，它可能需要Agent或更复杂的分支，而不是无限增加固定节点。

## 十四、休息与转场

83—90分钟休息。老师利用休息时间确认知识库已经解析、P2模板可访问，并打开备用知识片段截图。

休息后说：

“P1的流程已经稳定，但表达仍然像通用编辑。下一轮不让RAG补充历史事实，而是检索老师过去写过的内容，抽象出个人语气，再用本次事实生成新的小红书。”
