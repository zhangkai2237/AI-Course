## 一、本模块设计原则

1. 第0课判断场景价值，第2课验证怎样让模型稳定完成任务；
2. 第一轮结果明确标注“教学构造”，不冒充真实模型输出；
3. 学员先找错，第41页才逐步揭示参考答案；
4. 每条Bad Case必须对应原文证据和验收标准；
5. Prompt最多修改3处，修改通用规则，不写死案例数字；
6. 第二轮必须使用真实模型输出并标注模型、日期、输入和设置；
7. 最后回到信息供给与风险处理两个维度。

## 第36页｜同一个案例，两节课训练目标不同

### 页面标题

> 第0课问“值不值得做”，第2课问“怎样把它做稳定”

### 页面上屏文字

| 第0课 | 第2课 |
|---|---|
| 场景是否值得做 | 假设决定验证，模型怎样完成任务 |
| AI可以承担哪些环节 | 需要哪些上下文和规则 |
| 人与AI怎样分工 | 信息怎样进入、结果怎样确认 |
| 形成初步方案 | 测试Prompt并做最小修改 |

底部链路：

```text
基线结果 → 证据找错 → 最小修改 → 第二轮验收 → 修正产品流程
```

### 版式与时间

- 左右对比＋底部流程；
- 84:00—85:00；
- 不重新讨论场景价值。

本次只整理：

```text

```

本次不做：

```text
成交预测｜自动报价｜完整方案｜自动写入CRM
```

### 版式与时间

- 85:00—87:00；

## 第38页｜90秒证据扫描

### 页面标题

> 先扫描高风险证据，不从头逐字朗读

### 页面上屏文字

```text
打开完整转写，重点圈出

② 确认、可能、暂定、不承诺
③ 客户主动纠正的语句
④ 负责人和下一步行动
```

页面右侧只显示扫描方法，不摘录能够直接揭示答案的原文：

```text

F  事实或明确确认
U  不确定、待确认或附带条件
A  行动项
R  风险或限制
```

### 版式与材料

- 左指令和倒计时，右扫描标记方法；
- 学员同步查看完整材料；
- 材料：`../06_课堂练习与作业材料/03_销售案例背景与转写_学员版.md`；

## 第40页｜证据化找错

### 页面标题

> “感觉不准确”不够，必须写清四件事

### 页面上屏文字

```text
1  结果写了什么？
2  具体问题是什么？
3  原文证据是什么？
4  违反了哪条验收标准？

至少完成3条｜时间3分钟
```

反例与合格表达使用一个不对应本案例答案的通用示例：

```text
不合格：太笼统、不够专业、感觉有问题

合格：结果遗漏了输入材料中明确给出的截止时间；
原文包含具体日期；违反“行动项必须包含截止时间”。
```

### 版式与互动

- 左四步结构，右反例/合格例；
- 设计单四列表格局部放大；
- 学员填写，老师不提前提示具体错误；
- 91:00—94:00。

## 第41页｜第一轮参考讲评

### 页面标题

> 语言通顺，仍然可能发生这些业务错误

### 页面上屏文字

按点击逐条揭示：

| 结果表述 | 问题 | 原文依据 |
|---|---|---|
| 计划8家试点 | 把可能方案写成确定事实 | 当天只确认按5家准备 |
| 试点后采购并全量推广 | 把销售推测写成客户承诺 | 客户明确否认采购承诺 |
| 预计6月底上线 | 把希望写成确定计划 | 客户说今天不能承诺 |
| 两周完成对接 | 丢失条件，变成正式工期 | 未看接口文档，不是承诺 |
| 预算不是主要问题 | 自行弱化商务风险 | 预算较紧且金额未确认 |
| 下一步没有负责人和日期 | 无法创建后续任务 | 原文有明确负责人和时间 |
| 未体现数据和隐私风险 | 遗漏关键异议 | 外部传输、部署和日志需评审 |
| 未列待确认信息 | 看似完整，事实仍有缺口 | 预算、决策人和采购时间未确认 |

底部：

```text
AI产品验收不能只看“读起来像不像好答案”。
```

### 版式与时间

- 每次只揭示一行，同时高亮原文；
- 屏幕可排成左右各4行；课堂根据学员答案重点讲4—5条，其余作为完整答案保留；
- 94:00—97:00。

## 第42页｜最多修改3处

### 页面标题

> 根据Bad Case做最小修改，不从头重写

### 页面上屏文字

```text
每组选最重要的1—3条问题

Bad Case
      ↓
优先检查Prompt哪一部分？
      ↓
写一条可迁移的修改
```

对比：

```text
不建议：必须输出5家试点

更通用：区分已确认、讨论中和待确认；
可能方案不能改写为确定事实
```

底部任务：

```text
最多修改3处｜时间3分钟
```

### 版式与时间

- 左问题—修改映射，右写死答案vs通用规则；
- 97:00—100:00；
- 老师巡场只检查是否一条修改对应一个问题。

## 第43页｜第二轮真实输出

### 页面标题

> 第二轮真实输出：改完以后，发生了什么？

### 页面上屏文字

```text
【正式PPT待补真实模型输出】

模型：________
生成日期：________
完整Prompt：见课堂材料／演讲者备注
可见设置：________
输出是否节选：是／否
```

屏幕只高亮：

```text
改善了什么？
仍然有什么问题？
是否出现新的Bad Case？
```

### 版式与使用底线

- 左第一轮问题摘要，右第二轮真实输出；
- 改善用绿色，剩余问题用橙色；
- 不润色后冒充原始输出；
- 未生成真实结果前不制作伪聊天截图；
- 100:00—103:00。

## 第44页｜第二轮验收＋产品流程三句话

### 页面标题

> 一次改善之后，还要完成验收和产品流程

### 页面上屏文字

#### 左侧：第二轮验收

```text
□ 确定性状态是否正确
□ 是否把讨论、推测或条件估计写成承诺
□ 关键事实是否完整且可核对
□ 行动项是否支持后续执行
□ 缺失信息是否明确处理
□ 高风险内容是否进入确认流程
```

#### 右侧：产品流程三句话

```text
1 用户进入页面后，系统已经准备________
2 用户仍需填写、选择或确认________
3 必须确认后才能写入CRM的是________
```

底部：

```text
一次结果改善 ≠ 系统已经稳定 ≠ 可以取消人工确认
```

### 版式与互动

- 左验收、右三句话；
- 学员填写3分钟，老师讲评2分钟；
- 信息供给使用蓝色，风险处理使用橙色；
- 103:00—108:00。
