# 营销内容智能审核项目·第二次课

## 审核体系、方案选择与多场景迁移

建议总时长180分钟。课程由原项目第四节、第五节和扩展后的第七节组成：先把业务要求拆成可执行的审核点，再决定规则、模型与人工怎样分工，最后用合同审核作为母案例，完整展开客服质检、招聘信息、发票报销和金融营销四个迁移案例。

本课不重讲模型原理，也不把跨行业案例做成课堂分组练习。四个场景均由教师按完整项目逻辑讲解，学员重点观察同一套产品方法在不同业务中的变化与不变。

## 一、整堂课的目标

完成本课后，学员应当能够：

1. 把“内容要准确、合规”拆成检查对象、适用条件、依据、判断、例外和处理；
2. 区分审核要求与执行方式，说明规则、模型、业务资料和人工各自承担什么；
3. 判断何时适合使用组合方案，何时简单办法已经足够；
4. 从合同审核案例中提取一套判断型AI产品的迁移框架；
5. 看懂客服质检、招聘信息、发票报销和金融营销四类产品的输入、流程、边界与人工承接。

# 开场：今天解决两个先后关系（00—10分钟）

## 教师开场

上一次课，我们已经理解了营销内容为什么需要审核，也看过事前自检、事中审核和事后巡检三个业务环节。今天不急着继续画页面，而是补上两个决定产品质量的先后关系。

第一个先后关系是：先把业务要求说清楚，再决定使用什么技术。业务只说“价格要准确”，研发还不知道检查哪一个价格、在什么条件下适用、缺资料怎么办。

第二个先后关系是：先理解人工怎样工作，再把方法迁移到其他行业。迁移不是把“营销文案”替换成“合同”或“发票”，而是在新场景里重新完成一次业务判断。

板书：

```text
业务要求 → 审核点 → 能力分工 → 可运行流程 → 场景迁移
```

## 开场提问

> 如果业务只说“帮我做一个AI审核”，你最先需要追问什么？

教师可把回答归入四类：审核什么、依据什么、结果给谁、出错怎么办。不要在开场展开模型选型，告诉学员这些问题会在前两节逐步回答。

# 第四节：审核体系——把业务要求拆成具体审核点（10—55分钟）

## 本节任务

用检查对象、适用条件、依据、判断、例外和处理六个要素，把业务经验整理成可实现、可确认、可测试的审核点。

## 1. 为什么“内容准确”还不能直接实现（10—16分钟）

教师讲述：

小林是一名审核人员。研发问：“系统主要审什么？”小林回答：“商品功能要准确，价格和赠品条件要完整。”这句话对人有方向感，对系统却不够具体。

- 商品功能准确，是只核对数字，还是判断数字描述的对象？
- 价格完整，是每篇文案都要列出全部优惠，还是只说明当前价格的适用条件？
- 赠品名额用完后，是沿用活动开始时的规则，还是使用新的权益状态？
- 缺少活动资料时，系统应当提示问题，还是停止对应判断？

因此，本课所说的审核点不是一句笼统规则，而是一项可以被执行和确认的检查任务。

```text
审核点 = 检查对象 + 适用条件 + 业务依据 + 判断方式 + 例外分支 + 处理动作
```

这六项分别服务不同参与者：业务负责人确认要求，产品经理定义流程，研发理解输入输出，测试人员准备正常、问题和边界样例，审核人员知道最终由谁处理。

## 2. 先把本案的检查范围分层（16—22分钟）

净小伴P1案例首版先聚焦五类任务：

| 检查类别 | 本案需要回答的问题 | 主要材料与负责人 |
| --- | --- | --- |
| 商品事实与功能对象 | 65℃和12000Pa分别描述什么，是否符合当前商品资料 | 商品资料；产品负责人 |
| 价格与适用条件 | 1799元怎样成立，资格与用券条件是否交代完整 | 活动方案；活动负责人 |
| 赠品条件与当前权益 | 赠送对象、支付条件、限量以及当前是否仍然有效 | 赠品规则与权益状态；活动负责人 |
| 承诺的支持范围 | “全面避障”“次日到达”等表达是否超出材料支持范围 | 商品与履约资料；相应负责人 |
| 上下文与资料完整性 | 缺SKU、活动、有效版本或使用状态时，哪些判断无法继续 | 任务和资料记录；提交人与负责人 |

教师强调两点：

第一，分类只是范围地图，真正进入实现还要继续拆成单个审核点。第二，资料中存在某项内容，不代表每篇文案都必须写到。文案没有宣传赠品时，赠品检查应当是不适用，而不是缺失。

## 3. 审核点R01：温度与功能对象一致性（22—30分钟）

原句：“65℃热水直接拖地。”

| 要素 | 定义 |
| --- | --- |
| 检查对象 | 温度被用于描述哪个功能，是否与当前商品资料一致 |
| 适用条件 | 当前P1文案出现温度数值及相关功能表达 |
| 所需材料 | 完整文案、绑定SKU、有效商品资料F-PROD-01 |
| 判断方式 | 先理解温度对应的动作与对象，再与商品资料比较 |
| 例外分支 | 没有温度表达则不适用；对象不清或资料冲突则待确认 |
| 处理动作 | 作者修改，产品负责人确认商品事实，审核人员复核 |

教师逐条比较：

| 表达 | 预期判断 |
| --- | --- |
| 65℃热水直接拖地 | 功能对象与材料不一致，需要修改 |
| 基站支持65℃热水洗拖布 | 当前商品资料能够支持 |
| 65℃热水深度清洁 | 对象不清，需要结合全文；仍不清楚时交人工 |
| 基站支持热水洗拖布 | 没有温度值，本项温度检查不适用 |

教师强调：如果样例只有错误句，团队很容易把要求误解为“看到65℃就提示”。一条完整审核点至少需要正常、问题、不适用和待确认四类样例。

## 4. 审核点R02：宣传价格与适用条件一致性（30—38分钟）

原句：“本次活动到手1799元，人人同价。”

2399减400再减200等于1799，只能说明某条优惠路径在数值上成立。文案是否成立，还要看新会员资格、两类券的领取与使用条件，以及“人人同价”是否扩大了适用范围。

| 要素 | 定义 |
| --- | --- |
| 检查对象 | 宣传金额及其适用人群、优惠条件是否符合绑定活动 |
| 适用条件 | 文案出现当前商品与活动的价格主张 |
| 所需材料 | 完整文案、商品、活动、适用时间、有效活动方案F-PROMO-01 |
| 判断方式 | 核对金额路径，识别资格与条件，再判断是否遗漏或扩大范围 |
| 例外分支 | 无价格表达则不强行补价；缺有效活动资料则无法完整确认 |
| 处理动作 | 作者补充或修改，活动负责人确认条件，审核人员复核 |

三种表达对照：

1. “1799元，人人同价”：条件缺失且扩大适用范围。
2. “领券到手1799元”：仍缺少新会员资格和两类券条件。
3. “活动期内，新会员领取并使用400元活动券及200元专享券后1799元”：主要条件已经说明，再结合全文和有效活动核对。

第三种不是唯一标准句式。系统要核对的是语义和条件关系，而不是强制作者复制模板。

## 5. 审核点R03：赠品条件与当前权益（38—45分钟）

文案写：“下单就送宠物清洁包。”给定活动实际要求包括指定商品、支付成功、系统确认前200名、每单一份、赠完即止。

这条审核点除了活动开始时的规则，还需要当前权益状态。名额用完以后，初始规则依然存在，但已不能支持“现在下单仍然赠送”的承诺。

| 要素 | 定义 |
| --- | --- |
| 检查对象 | 当前商品与活动中的赠品主张 |
| 适用条件 | 文案宣传清洁包或同义权益 |
| 所需材料 | F-GIFT-01、当前权益状态、商品活动关联、内容使用状态 |
| 判断方式 | 核对赠送对象、支付条件、名额、每单数量和当前状态 |
| 例外分支 | 当前状态未知时只能核对初始规则，不能宣称仍有名额 |
| 处理动作 | 作者修改，活动负责人确认权益，审核与内容负责人完成复核和更新 |

教师强调：同一条审核点可以复用于自检、正式审核和巡检，但输入会变化。巡检比发布前审核多出“本次变化”“受影响对象”和“内容是否仍在使用”。

## 6. 审核结果不能只分“有风险”和“没风险”（45—51分钟）

| 结果状态 | 示例 | 下一步 |
| --- | --- | --- |
| 未发现该项问题 | 功能对象与当前资料一致 | 保留判断范围，不扩大成整篇通过 |
| 与材料不一致 | 把基站洗拖布温度写成直接拖地 | 作者修改或负责人确认新材料 |
| 表达缺少条件 | 1799元没有说明资格与用券条件 | 补充条件后复核 |
| 信息不足 | 缺活动资料、对象不清或状态未知 | 标明缺项与责任人 |
| 本项不适用 | 文案没有任何赠品主张 | 不要求补写无关内容 |
| 执行未完成 | 调用超时、文件无法读取、结果不可用 | 重试或转人工，不能显示为通过 |

教师讲述：最后一行尤其重要。业务判断和技术执行是两层状态。系统没做完检查，不等于没有发现问题。

## 7. 本节收束（51—55分钟）

教师总结：

审核点解决的是“究竟查什么”。它把业务经验转成团队共同理解的工作单元。三个审核点的结构相同，但材料、适用条件和责任人不同。

板书：

```text
先定义审核点，再谈模型和工作流
```

过渡：接下来回答“怎样查”。同一条审核点可以由程序、模型和人工共同完成，不必把整条任务交给单一能力。

# 第五节：方案选择——规则、模型与人工怎样分工（65—110分钟）

## 本节任务

比较四类候选方案，沿三个审核点完成能力分工，并把交接、冲突、失败和人工责任设计清楚。

## 1. 审核要求与执行方式是两层设计（65—70分钟）

第四节定义“查什么”，第五节决定“怎样查”。

本项目中的混合审核，是把规则与程序校验、大模型的语义判断、业务材料和人工复核按任务组合，共同完成审核。

- 程序适合取得指定材料、检查适用时间、执行金额计算、校验引用和状态；
- 模型适合理解自由表达中的对象、主张、条件和上下文；
- 业务负责人提供并确认商品、活动、履约和权益事实；
- 人工审核负责处理争议、作出正式结论并承接后续处置。

三个业务环节回答“什么时候发生”，混合审核回答“任务怎样分工”。两者不是同一维度。

## 2. 为什么不直接把全文交给模型（70—77分钟）

| 候选方案 | 能改善什么 | 需要验证的限制 |
| --- | --- | --- |
| 整理材料与清单，继续人工审核 | 减少找材料和漏项 | 逐句理解与比对仍由人完成 |
| 以规则程序为主 | 稳定执行明确条件、时间、金额和材料校验 | 自由表达与条件关系维护成本高 |
| 以模型为主 | 理解多种说法，辅助识别与解释 | 可能漏条件、误读对象或错误引用 |
| 规则、模型与人工组合 | 分别承担明确校验、语义理解与责任确认 | 交接更复杂，必须验证整体是否省力 |

教师讲述：组合方案不是天然更高级。若核心问题只是材料分散，先把材料管理做好可能更有效。选择方案要看输入特点、稳定性要求、维护成本、人工责任和纠错成本。

## 3. 三条审核点怎样分配能力（77—91分钟）

### 3.1 65℃：程序取材料，模型理解对象，人工确认争议

程序根据SKU取得当前商品资料并校验版本；模型判断“65℃”描述的是直接拖地、基站洗拖布，还是对象不清；返回结果必须能定位原句和对应材料。

若对象仍不清，产品负责人确认商品事实，审核人员决定如何处理。只搜索数字无法完成这项判断。

### 3.2 1799元：金额计算与条件理解分开

程序计算优惠路径并检查活动时间；模型识别文案中的价格、人群、领券条件及其语义范围。条件写在前文时，要结合全文判断，不能只检查价格所在句。

即使金额计算正确，只要资格条件缺失，问题仍然存在。相反，模型提取错金额时，后面的计算再准确也没有意义。

### 3.3 赠品巡检：程序选范围，模型识别当前承诺，人工确认处置

活动负责人先确认赠品名额用完以及生效范围；程序按商品、活动和使用状态筛选内容；模型判断文本是否仍在作当前赠送承诺；内容负责人决定更新、说明或暂停。

首版不让模型推测剩余名额，也不因出现“清洁包”关键词就自动下架内容。

### 3.4 分工总表

| 工作 | 首版安排 | 原因 |
| --- | --- | --- |
| 取得指定材料、检查时间、计算金额、校验引用 | 程序 | 步骤明确，结果便于核对 |
| 理解功能对象、条件范围、赠品承诺和上下文 | 模型辅助 | 自由表达存在多种说法 |
| 确认业务事实、处理争议、正式审核与内容处置 | 业务负责人和审核人员 | 涉及权限、事实与责任 |

## 4. 混合审核真正难在交接（91—102分钟）

### 原文与材料要能核对

模型返回原文中不存在的句子，不能作为问题定位；引用来自其他活动，也不能支持本次判断。定位或引用校验失败时，状态应当是待核实或执行异常。

### 事实缺失不能靠常识补齐

没有库存、地址和下单时间，就不能用“通常能够次日到达”支持当前履约承诺。两份适用材料冲突时，也不能让模型自行选择语气更肯定的一份。

### 多路结论需要合并，不是简单投票

金额计算成立、资格条件缺失，这两条结果并不冲突，最终应保留条件问题。若两路对同一事实给出不同判断，则带上原句、材料、判断路径和负责人进入人工确认。

### 执行失败不能变成未发现问题

某一项超时或返回不可用，就标记该项未可靠完成。其他检查可以保留，但总结果不能把失败项悄悄算作通过。

### 每个结果都要有下一步

修改交给作者，材料争议交给业务负责人，正式结论交给审核人员，技术失败进入重试或人工处理。没有承接人的提示，只是把识别成本转移成新的待办堆积。

## 5. 模型选择应围绕具体任务验证（102—107分钟）

不要只比较模型能否写出流畅点评。至少围绕以下任务准备样本：

- 功能对象是否识别正确；
- 价格资格与条件是否漏掉；
- 原句定位是否准确；
- 引用材料是否属于本任务；
- 不确定时是否能够停下并交人工；
- 处理一条有效问题需要多少人工时间；
- 时延和调用成本是否适合当前环节。

教师强调：组合本身不保证效果。若某项用更简单的办法就能稳定完成，应当调整分工。

## 6. 本节收束（107—110分钟）

教师总结：

```text
规则负责确定动作
模型负责理解表达
材料提供业务事实
人工承担确认与处置
```

真正的产品设计不止是把四者画成方框，而是把输入、输出、校验、失败和责任交接说清楚。

# 第七节：从合同审核到多个判断型AI产品（120—175分钟）

## 本节任务

合同审核是母案例。教师先完整还原项目逻辑，再依次讲解客服会话质检、招聘信息审核、发票与报销审核、金融营销材料审核。四个迁移场景都是正式案例，不作为分组练习。

## 1. 合同审核母案例（120—137分钟）

### 1.1 先收窄项目边界

不做“AI法务”或完整法律咨询，而是面向企业内部业务人员和法务人员，为常规业务合同提供初步检查、问题定位和修改建议。复杂争议、重大风险与最终决定仍由专业人员负责。

### 1.2 先理解人工工作

| 人工审核对象 | 需要回答的问题 |
| --- | --- |
| 合同主体 | 和谁签约，信息是否完整，对方企业是否存在异常 |
| 合同条款 | 付款、交付、验收、违约和权利义务是否清楚 |
| 规范引用 | 引用内容是否准确、是否仍然适用 |
| 履约方式 | 时间、付款、验收与责任是否能够实际执行 |
| 周边风险 | 历史履约、企业异常、内部关系和业务风险 |

### 1.3 从输出反推输入

最终输出不能只有“有风险”或总分，而要包含问题条款、问题类型、关注原因、业务影响、修改建议和人工待确认项。

因此输入也不能只有合同正文，还需要本次审核重点、企业合同规则、对方企业信息和交易背景。

### 1.4 先验证基础能力

选择脱敏合同快速测试，重点看能否定位真实条款、发现明显矛盾、给出可理解建议、避免把正常商业安排一律判成风险、避免编造内容，并在不确定时交给人工。

模型可以先完成覆盖较广的初步检查，但不能替代熟悉公司业务和谈判背景的法务负责人。

### 1.5 拆成并行工作流

```text
合同与审核要求
      ↓
文件解析与类型确认
      ↓
条款审核 / 规范引用检查 / 签约主体与企业风险查询
      ↓
问题合并、去重与分级
      ↓
审核意见和修改建议
      ↓
法务确认
```

边界包括：非合同文件、无法读取、缺签约主体、企业名称查不到、外部接口失败、多路重复和结论冲突。每一种都要有明确状态和下一步。

### 1.6 企业内部连接形成特殊价值

合同交付条款可连接ERP订单、库存、生产排期、资金计划、历史履约和供应商名录。通用工具可能判断“30天交付”条款形式正常，企业系统却能发现产能和物料无法支持。这就是内部AI产品的差异：不仅理解文本，还理解这家企业当前能不能做到。

## 2. 十一项迁移框架（137—143分钟）

| 步骤 | 核心问题 |
| --- | --- |
| 1 业务问题 | 企业为什么现在需要解决它 |
| 2 首版小场景 | 从大业务中先选择哪一段 |
| 3 人工工序 | 人原来按什么顺序完成 |
| 4 最终输出 | 用户需要看见什么并采取什么动作 |
| 5 输入来源 | 判断需要哪些文件、数据和上下文 |
| 6 快速验证 | 当前模型是否具备基础能力 |
| 7 并行拆分 | 哪些工作适合分开执行 |
| 8 边界分支 | 缺项、失败、冲突和版本变化怎样处理 |
| 9 结果合并 | 多路结果怎样去重、分级并交给人 |
| 10 企业连接 | 接入哪些内部系统才能形成特殊价值 |
| 11 运行验证 | 用什么结果决定继续、修改或缩小范围 |

## 3. 案例一：客服会话质检（143—151分钟）

业务问题：售后对话数量大，主管只能抽查少量会话，错误承诺、未核对订单、前后口径不一致和推诿难以及时发现。

首版范围：售后退款会话质检，不做完整客服管理系统。

示例对话：

> 客户：退款什么时候能到账？  
> 客服：肯定今天到账，您放心。  
> 客户：昨天另一个客服说需要三个工作日。  
> 客服：反正系统已经处理了，具体您自己等着吧。

| 产品要素 | 设计 |
| --- | --- |
| 输入 | 会话内容、角色、订单与退款状态、当前服务政策、质检规则 |
| 并行任务 | 流程规则检查、多轮语义判断、订单与政策核对 |
| 输出 | 问题位置、问题类型、等级、整改建议和待确认项 |
| 边界 | 转写失败、角色混淆、订单接口无返回、否定句误报、客服申诉 |
| 人工承接 | 质检主管复核，客服确认或申诉，进入培训和规则改进 |
| 企业连接 | CRM、订单、工单、知识库、投诉和培训系统 |

教师收束：质检产品的完成点不是打分，而是问题被确认、申诉、整改和复训。

## 4. 案例二：招聘信息审核（151—158分钟）

业务问题：企业发布的岗位多，岗位事实、薪酬范围、必填信息和限制性表达难以统一管理。

首版范围：企业岗位正式发布前的信息审核。

案例文本：“高薪招聘运营经理，月入2万元起。限男性，30岁以下，本地户口。无经验也可以，面试通过即可入职。需先参加公司指定培训，培训费用可以办理分期。”

| 产品要素 | 设计 |
| --- | --- |
| 输入 | 招聘文案、企业信息、岗位编制、薪酬范围、有效期、发布渠道要求 |
| 人工工序 | 查企业、查岗位、查薪资、查必填项、查限制条件 |
| 并行任务 | 文案与必填项、企业与发布账号、岗位资料一致性 |
| 输出 | 缺项、问题位置、类型、修改要求和是否转人工 |
| 边界 | 企业或岗位无法确认、资料冲突、薪酬范围不清、疑似异常引流 |
| 人工承接 | 招聘运营、HR业务负责人，必要时转相关专业人员 |
| 企业连接 | 招聘系统、企业名录、岗位编制、薪酬系统和投诉记录 |

教师强调：模型能识别文本表达，但“该岗位是否真实存在、薪酬是否经过批准”必须依赖企业内部事实。

## 5. 案例三：发票与报销审核（158—165分钟）

业务问题：财务人员需要反复核票、核科目、查预算、查合同和查审批流程，材料分散且异常组合难以发现。

首版范围：员工费用报销的初步审核，不自动付款。

案例：技术部门员工提交一张周末产生的高额休闲服务发票，备注为客户招待；金额在个人权限内，但OA中没有对应招待申请，部门预算接近用完。

| 产品要素 | 设计 |
| --- | --- |
| 输入 | 发票、报销单、员工与部门、预算、合同、OA申请和费用制度 |
| 人工工序 | 验票、核科目、核金额、查人员、查预算、查审批 |
| 并行任务 | 票据验真、政策核对、预算检查、合同与审批核对 |
| 输出 | 可继续、待补材料、退回、等待预算或转人工复核 |
| 边界 | 票据接口失败、科目与业务矛盾、重复报销、多路结论冲突 |
| 人工承接 | 员工补材料，直属负责人说明业务，财务作出最终处理 |
| 企业连接 | 财务、OA、预算、合同和付款系统 |

教师强调：金额在权限内不等于业务合理；发票真实也不等于报销成立。多个判断需要合并，但系统不应跳过人工确认直接付款。

## 6. 案例四：金融营销材料审核（165—172分钟）

业务问题：宣传内容需要与正式产品材料、风险提示、目标人群和渠道要求保持一致，版本变化会影响大量在用内容。

首版范围：一类理财产品宣传材料发布前审核，并保留材料变化后的复查入口。

案例文本：“稳健理财，年化收益6%。本金安全，无需承担市场风险。历史表现优秀，适合所有投资者。”

| 产品要素 | 设计 |
| --- | --- |
| 输入 | 宣传材料、正式产品文件、风险提示、目标人群、渠道和有效版本 |
| 人工工序 | 查宣传表达、查产品事实、查风险披露、查适用人群、查版本 |
| 并行任务 | 明确表达检查、产品事实核对、风险披露完整性、渠道适配 |
| 输出 | 问题位置、缺失信息、等级、修改要求和人工结论 |
| 边界 | 产品材料冲突、适用人群不清、版本失效、系统结论冲突 |
| 人工承接 | 内容作者修改，产品与合规负责人确认，发布人员执行 |
| 企业连接 | 产品中心、合规系统、客户分层、渠道发布和版本管理 |

教师强调：这类高风险业务中，AI适合辅助定位、比对和提醒，最终判断与发布责任必须明确到人。本案例用于产品设计教学，不给出具体专业结论。

## 7. 五个案例放在一起看（172—175分钟）

| 场景 | 被判断对象 | 关键业务材料 | 最终人工角色 | 企业连接形成的价值 |
| --- | --- | --- | --- | --- |
| 合同审核 | 合同条款 | 模板、制度、交易背景、对方企业信息 | 法务 | 发现真实履约与交易风险 |
| 客服质检 | 多轮会话 | 服务政策、订单与客户状态 | 质检主管 | 把问题接入申诉、整改与培训 |
| 招聘审核 | 岗位文案 | 岗位编制、薪酬与企业信息 | HR负责人 | 判断岗位与承诺是否真实 |
| 报销审核 | 票据和报销单 | 预算、OA、合同和费用制度 | 财务 | 组合判断真实性、合理性和流程完整性 |
| 金融营销 | 宣传材料 | 产品文件、风险提示、目标人群与渠道 | 产品与合规负责人 | 管理适用人群、版本和发布链路 |

不变的是方法：业务问题、人工工序、输出输入、能力验证、流程、边界、人工和企业连接。变化的是判断对象、业务事实、责任角色与自动化边界。

# 全课收束（175—180分钟）

今天三部分形成一条完整路线：

```text
第四节：把业务要求拆成审核点
第五节：把审核点分配给程序、模型、材料和人工
第七节：把这套方法重新应用到多个业务场景
```

教师结束语：

AI产品经理的专业性，不体现在能否快速生成一个看起来完整的方案，而体现在能否把判断任务定义清楚、把能力边界分配合理、把失败和人工责任接住，并在不同业务中重新完成一次完整判断。

## 教师备课补充

- 第四节重点是“任务定义”，不要提前陷入模型和工作流细节；
- 第五节重点是“选择与交接”，不要把组合方案讲成固定答案；
- 第七节的四个迁移场景全部由教师讲解，不安排分组练习；
- 跨行业案例用于产品设计教学，不替代法律、财务、人力或金融专业意见；
- 时间不足时，合同与客服必须完整讲，招聘、报销和金融可各压缩到5分钟，但不要改成学员练习；
- 课堂Demo可用于展示材料、审核点和结果状态，但本课不要求新增系统功能。
