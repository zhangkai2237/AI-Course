# 第05课《Agent与受控工具调用》内容结构与时间分配

> 基准时长：约138分钟，含5分钟短休息。  
> 紧凑版：125-130分钟，压缩讨论与MCP/Multi-Agent扩展。  
> 互动充分版：140-150分钟。

## 一、一句话目标

帮助零基础产品经理理解Agent如何根据当前状态选择工具，并完成一份包含工具参数、权限确认、异常处理、停止条件和人工接管的受控Agent方案。

## 二、学员最终产出

一份《Agent受控执行设计与测试表》，包含：

- 用户和Agent目标；
- 三项可用工具；
- 工具输入、输出与异常；
- 自动、确认、审批和禁止执行分级；
- 参数不足、工具失败、无权限和结果冲突路径；
- 完成、停止和人工接管条件；
- 五条测试及预期结果；
- 是否需要MCP和Multi-Agent的判断。

## 四、紧凑版压缩规则

如果必须接近125分钟：

- 模块一和模块二共压缩5分钟；
- 三条动态路径只展开两条；
- 纸面互查由4分钟压缩为2分钟；
- Coze测试三、四使用预制结果，不等待现场完整运行；
- MCP与Multi-Agent合计控制在6分钟；
- 不删除写入前确认和工具失败测试。

## 五、互动充分版加时位置

允许增加时间：

- Workflow与Agent判断讨论：3-5分钟；
- 工具描述互改：5分钟；
- 纸面设计分享：5-8分钟；
- Coze失败排查：5分钟；
- MCP/Multi-Agent问答：3分钟。

即使超时，也必须保留：

1. 模型提出调用，应用系统真正执行；
2. 参数和权限必须先校验；
3. 写入类动作执行前确认；
4. 工具失败不得编造；
5. Agent必须有停止和人工接管条件；
6. 至少一次观察动态结果改变下一步。

## 六、贯穿案例与模拟数据

### 三个工具

```text
query_store_metrics
search_activity_rules
create_campaign_draft
```

### 三种动态路径

1. 新客下降：查经营数据 → 查新客活动规则 → 生成方案 → 确认后创建草稿；
2. 补贴异常：查经营数据 → 查补贴规则 → 输出优化建议 → 不创建新活动；
3. 数据不足：查经营数据 → 追问是否扩大时间范围 → 用户补充后继续或停止。

### 经营工具固定返回字段

```text
metric_values
period_change
data_completeness
diagnosis_label
diagnosis_reason
```

诊断标签由模拟工具按教学规则返回，Agent不自由定义“下降多少算异常”。

## 七、五条课堂测试

| 编号 | 输入类型 | 测试目的 |
|---|---|---|
| T1 | 信息完整且新客下降 | 是否正确查询数据、规则并生成建议 |
| T2 | 缺少门店和日期 | 是否追问必要参数而不是编造 |
| T3 | 补贴异常但新客正常 | 是否改变路径、不调用新客活动工具 |
| T4 | 门店不存在或接口超时 | 是否说明失败、停止或安全重试 |
| T5 | 用户要求直接发布 | 是否区分草稿与发布，并在写入前确认 |

## 八、平台与备课策略

- 老师提前配置，不在课堂从空白开始搭复杂Agent；
- 三个工具使用教学模拟数据；
- 学员重点观察工具选择、参数、返回、继续/停止和确认；
- 课前保存五条完整运行结果；
- 准备无网络版工具返回卡和Agent运行状态图；
- 学员无账号时仍可完成纸面设计和测试判断。

## 九、课程边界

- 本课不要求学员开发API或数据库；
- 不要求现场安装MCP；
- 不要求搭Multi-Agent；
- 不展开长期记忆和复杂规划；
- 不把Agent描述成比Workflow更高级；
- 不把平台演示成功当成产品可上线；
- 不连接真实公司系统和真实经营数据。

## 十、与后续课程的接口

- 第06课：判断这个商家经营场景第一版是否真的需要Agent；
- 第07课：把Agent目标、工具、权限和状态写进PRD；
- 第09课：系统设计Agent工具成功率、任务完成率和Bad Case；
- 第10课：扩展权限最小化、审计、确认、回滚和人机协作；
- 第二阶段：有真实需要的小组再实践MCP或Multi-Agent。
