# 第四阶段：Claude提示模板库PRD

> 根据同目录《04-最终PRD.pdf》中文重写。文中的增长目标和资源估算均为作者设定的方案目标，并非Anthropic官方承诺。

## 1. 产品名称

Claude Prompt Template Library（Claude提示模板库）

## 2. 背景

新用户经常不知道怎样组织提示，导致输出不符合任务、反复重写和切换其他工具。研究中5/5访谈对象提到提示结构问题，问卷中约80%的受访者也报告类似困难。

## 3. 产品目标

### 用户目标

帮助用户在第一次尝试时构造更完整的提示，减少试错与额度浪费。

### 业务目标

提高新用户激活、30日留存和免费转付费机会，降低因输出失败导致的竞争产品切换。

## 4.目标结果

作者设定的假设目标：

- 新用户首会话模板采用率40%；
- 模板用户第一次提示成功率70%；
- 30日留存提升20%；
- 竞争工具切换率降低25%。

## 5. 目标用户

### 学生与研究者

需要调试、研究、解释和写作，但担心浪费免费额度。

### 专业和技术用户

需要文档、代码、调试和复杂任务支持，希望减少重复补充上下文。

## 6. MVP范围

### 范围内

- 15个精选模板；
- 代码与调试、研究、写作、文档、学习5个类别；
- 类别浏览和搜索；
- 填空式自定义；
- 完整提示预览；
- 直接发送或继续编辑；
- 1—5星评价；
- 请求新模板；
- 热门和最近使用。

### 范围外

- 根据历史自动生成模板；
- 社区公开模板；
- 语音转模板；
- 输入时实时建议；
- IDE扩展；
- 多语言模板；
- 自动个性化推荐。

## 7. 用户流程

```text
空白会话页
→ 点击“试用模板”
→ 浏览类别
→ 选择模板
→ 填写最多三个关键字段
→ 预览完整提示
→ 编辑或直接发送
→ 获得Claude输出
→ 评价模板或提交新需求
```

## 8. 主要用户故事

- 作为学生，我希望使用调试模板，避免浪费有限消息；
- 作为新用户，我希望看到优秀示例，理解怎样与Claude沟通；
- 作为研究者，我希望按类别快速找到结构；
- 作为高频用户，我希望评价模板并推动改进；
- 作为专业用户，我希望申请缺少的任务模板。

## 9. 验收标准

- 空白对话页5秒内可发现模板入口；
- 用户两次点击内进入目标类别；
- 字段具有明确标签和示例；
- 一分钟内完成填写并发送；
- 生成提示进入普通聊天流程且无异常；
- 结果出现后可选评价；
- 移动端触控区域和排版可用。

## 10. 指标

### 核心指标

- 首会话模板采用率；
- 第一次提示成功率；
- 达到满意输出前的平均重写次数。

### 护栏指标

- 模板放弃率；
- 模板使用耗时与空白输入耗时；
- 模板满意度；
- 使用模板后仍切换工具的比例。

### 事件埋点

- template_library_opened；
- template_category_viewed；
- template_selected；
- template_customized；
- template_sent；
- template_abandoned；
- template_rated；
- template_requested。

## 11. 边界情况

- 没有匹配模板：保持空白输入并提供申请入口；
- 中途切换模板：返回列表，不自动保存不完整输入；
- 上次内容误带入：默认清空，可主动复用；
- 提示过长：显示字符数并允许缩短；
- 移动端拥挤：字段纵向排列，类别可折叠；
- 模板输出仍不佳：收集评价，暂停低质量模板。

## 12. 依赖与资源假设

- 模板内容存储；
- 分析和A/B实验能力；
- Web与移动端适配；
- 产品、设计、前端、后端、内容和QA资源；
- 模板质量测试和更新机制。

## 13. 上线计划

1. 第1周：目标与利益相关方对齐；
2. 第1—3周：设计、流程和原型；
3. 第4—8周：开发；
4. 第9周：测试；
5. 第10周：向20%用户Beta发布；
6. 第10—13周：观察数据并迭代；
7. 第14周：满足条件后扩大发布。

## 14. 主要风险

- 模板覆盖不足；
- 模板本身不能改善模型输出；
- 自定义步骤比空白输入更慢；
- 用户找不到入口；
- 模板过时或质量下降；
- 用户误认为模板能保证事实正确。

## 15. 上线后的迭代原则

- 每两周根据使用和请求更新模板；
- 低采用模板先检查入口和任务匹配；
- 低成功率模板重写结构和输出约束；
- 高放弃模板减少字段；
- 数据不能区分问题时，补充访谈和可用性测试。
