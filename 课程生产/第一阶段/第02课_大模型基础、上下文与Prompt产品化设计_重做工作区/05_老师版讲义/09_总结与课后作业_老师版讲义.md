# 模块09老师版讲义：总结与课后作业

> 授课时间：114—117分钟，共3分钟  
> 117—120分钟：机动和集中答疑  
> 教学任务：用四句话收束课程，布置一份完整作业并说明最低验收标准  
> 学员产出：《Prompt产品化设计单》V1.0

---

## 一、老师先理解

### 1. 这个模块只做三件事

1. 把整节课收束成四个可复述结论；
2. 说明课后只交一份完整产物；
3. 让学员知道作业怎样才算合格。

本模块不增加新知识，也不重新解释Token、六要素、RAG或Agent。

### 2. 为什么作业只有一份

本课已经形成多个中间产物：

- 目标输出和验收标准；
- 上下文清单；
- 结构化Prompt；
- 产品化拆分；
- 测试结果和Bad Case；
- 边界判断。

如果把它们拆成多份作业，学员容易机械填表，看不到完整链路。因此课后只提交一份《Prompt产品化设计单》V1.0，所有内容都是同一场景的不同部分。

### 3. 三分钟怎样控制

- 114—115分钟：四个结论；
- 115—116分钟：作业任务和选题；
- 116—117分钟：最低标准和零基础替代；
- 117分钟后：只做机动或答疑。

详细模板已经写入讲义，课堂不要逐项朗读。

## 二、逐分钟上课讲法

### 114:00—115:00 四句话回顾整节课

#### 【屏幕】

1. 大模型是生成，不是固定查询；
2. 上下文是有限的任务工作区；
3. 好Prompt来自清楚的产品定义；
4. Prompt产品化是让产品承担复杂度。

#### 【建议讲法】

> 第一，大模型依据当前上下文逐步生成后续Token，因此同一个输入可能得到不同结果。一次Demo正确，不代表产品已经稳定。

> 第二，上下文是有限的任务工作区。用户输入、内部指令、历史对话和补充材料都会占用它。产品经理要选择必要、可靠、结构清楚的信息，而不是无差别堆料。

> 第三，好Prompt来自清楚的产品定义。先说明谁在什么时点需要什么结果、怎样才算可用，再反推输入、规则和输出。Prompt不是脱离需求的文案技巧。

> 第四，Prompt产品化就是让产品承担复杂度。固定要求由产品维护，变化信息通过字段收集，已有信息自动获取，高风险结果由用户确认。

#### 【课堂控制】

四条讲完立即进入作业，不重新举例，不邀请多人复述。若时间充足，只让全班一起说出四个短句。

---

### 115:00—116:00 说明课后作业

#### 【口头精简版】

> 课后请从自己的工作中找一个具体文本任务，完成一份Prompt产品化设计单。说清用户、输出、验收、上下文和结构化Prompt，再把内容拆成固定项、用户填写项和系统自动获取项。

> 至少运行一条脱敏或虚构样例，找到一条Bad Case并提出最小修改。没有工作场景的同学可以使用公开材料或虚构反馈，但不要照抄今天的销售案例答案。

#### 【选题边界】

优先选择：

- 已存在明确人工流程；
- 有比较清楚的输入材料；
- 知道结果交给谁使用；
- 能拿到脱敏样例或构造虚构样例；
- 一次任务可在几分钟到几十分钟内完成。

不建议选择：

- 万能企业Agent；
- 用AI提升公司效率；
- 全能客服；
- 同时包含十几个流程的平台；
- 必须使用公司敏感数据才能完成的题目。

#### 【可选示例】

- 用户访谈记录整理；
- 客服对话问题归因；
- 需求反馈分类；
- 营销文案草稿；
- 合同要点提取；
- 周报信息汇总；
- 招聘面试记录整理；
- 项目风险和行动项提取。

示例不是标准答案，学员仍需说清用户、时点、输入和结果。

---

### 116:00—117:00 最低标准与零基础替代

#### 【屏幕：最低标准】

1. 一个具体场景；
2. 至少2项目标输出及验收标准；
3. 至少3类必要上下文；
4. 一版结构化Prompt；
5. 信息供给方式与风险处理的拆分；
6. 至少运行1条样例；
7. 找到1条Bad Case并提出具体修改；
8. 不提交敏感数据。

#### 【建议讲法】

> 作业不是比谁的Prompt最长，也不是比谁用了更多技术名词。合格的关键是：场景具体，输出可以检查，Prompt要求有用途，产品分工合理，并且真的测试过一次。

> 完全零基础或没有工作场景的同学，可以使用公开访谈、公开视频字幕、公开产品测评、虚构用户反馈或个人学习笔记。最低完成两项输出、一版Prompt、三类产品化拆分和一条Bad Case。

> 详细模板和验收标准已经放进讲义。不要提交真实客户、员工、公司机密或个人隐私。

#### 【结束语】

> 今天到这里。最后三分钟用于集中答疑；如果没有问题，请先在模板里写下自己的作业选题，避免下课后又把题目选得过大。

## 三、课后作业详细说明

### 1. 作业任务

从真实工作中选择一个适合文本类大模型辅助的具体场景，完成《Prompt产品化设计单》V1.0。

选题最好满足：

- 有明确的目标用户；
- 有清楚的使用时点；
- 有现成的人工任务；
- 有可描述的输入材料；
- 有结果之后的下一步动作；
- 能够使用脱敏或虚构样例测试。

### 2. 作业结构

#### 第一部分：场景

填写：

1. 场景名称；
2. 目标用户；
3. 使用时点；
4. 当前人工任务；
5. AI结果之后的下一步动作。

#### 【老师批改时检查】

- “运营人员”是否太宽泛；
- “提高效率”是否缺少具体任务；
- 是否能用一句话说成“谁在什么时候，用AI完成什么”；
- AI输出之后是否存在真实下一步。

#### 第二部分：目标输出与验收

| 目标输出 | 怎样算合格 | 高风险错误 |
|---|---|---|
|  |  |  |
|  |  |  |

至少填写2项。

不合格写法：

- 输出一份专业报告；
- 结果准确、完整、高质量；
- 让用户满意。

合格写法示例：

- 每条行动项包含事项、负责人、截止时间和状态；
- 用户反馈分类必须来自给定标签，不确定时标为待确认；
- 合同金额和日期必须附原文证据。

#### 第三部分：上下文清单

| 信息 | 事实/背景/规则 | 支持哪项输出 | 必需/按需 |
|---|---|---|---|
|  |  |  |  |
|  |  |  |  |
|  |  |  |  |

至少列出3类必要上下文。每项必须能回答“它支持哪项输出”，不能只是堆材料。

#### 第四部分：结构化Prompt

根据场景填写：

- 角色与能力；
- 任务目标；
- 业务背景和输入材料；
- 规则与约束；
- 输出格式与验收标准；
- 示例与迭代要求。

不要求为了形式完整而强行写满六项，但每一部分应有明确用途。

#### 第五部分：产品化拆分

##### A. 信息供给

| 信息或规则 | 产品固定/用户提供/系统获取 | 产品承载或交互方式 |
|---|---|---|
|  |  |  |
|  |  |  |
|  |  |  |

##### B. 风险处理

必做版至少填写1项；进阶版补齐主要风险字段和后续动作。

| 输出字段或后续动作 | 主要风险 | 普通展示/建议检查/必须确认 | 证据、权限和交互方式 |
|---|---|---|---|
|  |  |  |  |
|  |  |  |  |

老师重点检查：

- 用户是否仍要复制完整Prompt；
- 系统已有信息是否仍要求用户手填；
- 固定业务规则是否交给每位用户记忆；
- 高风险结果是否单独设计了证据、权限和确认方式；
- 是否错误地把“必须确认”当成第四种信息来源。

#### 第六部分：一次测试和Bad Case

必须完成：

1. 使用一条脱敏或虚构样例运行Prompt；
2. 保存输入、Prompt和输出；
3. 找到至少一条不满意结果；
4. 判断首先属于任务、上下文、规则、输出，还是超出单次Prompt；
5. 提出下一次最小修改。

本次不要求建立正式评测集，但不能只展示一条满意结果。

#### 第七部分：技术边界判断

完成一句话：

> 当前问题主要能否用Prompt和上下文解决？是否已经涉及私有知识、多步骤流程或外部系统动作？

不要求设计RAG、Workflow或Agent。

## 四、作业分级与验收标准

### 必做版

第一次完成模板或零基础学员只要求：具体场景、输出与验收、上下文、Prompt关键骨架、信息供给拆分、至少1项高风险结果处理、一次样例测试和一条Bad Case。

### 进阶版

在必做版基础上增加：完整Prompt骨架、主要风险字段的证据、权限和确认交互、第二轮复测及技术边界判断。

第一次作业以必做版完成为合格，不强制所有学员提交进阶版。

### 合格必须满足

- [ ] 场景具体到谁在什么时点完成什么任务；
- [ ] 至少2项目标输出和可检查标准；
- [ ] 至少3类必要上下文；
- [ ] Prompt主要要求能对应任务、风险或输出；
- [ ] 区分产品固定、用户提供和系统获取；
- [ ] 至少为1项高风险结果设计建议检查或必须确认；
- [ ] 至少运行1条样例并找到1条Bad Case；
- [ ] 提出一个具体修正动作；
- [ ] 不提交真实敏感数据、隐私或公司机密。

### 典型不合格情况

- 只有一段从网上复制的Prompt；
- 选题是万能助手，没有具体用户和任务；
- 输出标准只有“专业、准确、高质量”；
- 把所有资料都塞进上下文，无法说明用途；
- 只展示一次满意结果，没有Bad Case；
- 产品仍要求用户每次填写完整Prompt；
- 使用未经脱敏的客户、员工或公司数据。

### 建议的反馈方式

老师批改时优先给三类反馈：

1. 最需要收窄的场景是什么；
2. 最需要变得可检查的验收标准是什么；
3. 下一次最值得验证的一处修改是什么。

不要一次列出十几处问题，否则初学者难以完成第二版。

## 五、完全零基础学员替代任务

### 1. 适用对象

- 当前没有正式工作场景；
- 无法接触可脱敏的业务材料；
- 对所在行业流程不了解；
- 第一次尝试结构化Prompt。

### 2. 可选任务

1. 公开访谈或公开视频字幕整理；
2. 公开产品测评的优缺点提取；
3. 虚构用户反馈分类；
4. 个人学习笔记整理和行动计划提取；
5. 使用模块07的虚构材料，但重新设计不同目标输出。

### 3. 最低要求

- 一个明确使用者和时点；
- 两项输出及验收标准；
- 一版结构化Prompt；
- 产品固定、用户提供和系统获取各至少一项；
- 至少选择1项高风险结果，说明应建议检查还是必须确认；
- 一条Bad Case及修改。

不要求画完整界面。

### 4. 不建议的做法

- 直接复制销售案例参考答案；
- 让模型代写整份作业而不检查；
- 为了显得复杂，主动加入RAG、Agent和MCP名词；
- 用虚构场景时不标注虚构。

## 六、117—120分钟答疑建议

### 优先回答

- 作业选题是否过大；
- 某项输出如何写成可验收标准；
- 某类信息属于固定、用户还是自动获取；
- Bad Case首先从哪里排查；
- 如何脱敏或构造虚构样例。

### 暂不展开

- RAG和Agent详细架构；
- 模型选型横向评测；
- 完整技术实现；
- 就业和面试问题；
- 与本节作业无关的复杂项目咨询。

如果无人提问，让学员当场写下：

> 我的目标用户是____，在____时点，需要AI帮助完成____。

老师随机看2—3个题目，帮助学员把过大的选题收窄。

## 八、老师课后复盘

记录：

- 学员是否能区分输出格式和验收标准；
- 哪个Prompt要素最容易被写成空话；
- 学员是否仍倾向把所有信息塞进上下文；
- 学员能否把Prompt拆成产品字段和自动获取项；
- 案例三轮是否在24分钟内完成；
- 哪类Bad Case最难判断；
- 作业选题是否普遍过大；
- 下一版需要删减或补充什么。

## 九、老师必须记住

1. 总结只讲四句话，不增加新知识；
2. 课后只交一份完整设计单；
3. 作业必须包含一次真实测试和一条Bad Case；
4. 零基础学员可以使用公开或虚构材料；
5. 不要求本次设计RAG、Workflow或Agent；
6. 必须强调脱敏、隐私和公司机密；
7. 117分钟后只做机动和答疑。
