# 07 升级四路V0.3（78—102分钟）

## 目标结构

`开始 → 分类LLM → 条件分支 → 四种处理 → 结束`

## 分类Prompt

```text
你是商家咨询分类器。请根据用户问题，只判断它属于以下一个标签：

RULE：询问平台规则、活动规则、经营规范或政策。
DATA：需要查询实时订单、GMV、结算、门店状态等业务系统数据。
COMPLAINT：投诉、扣费争议、退款赔付、威胁曝光或其他高风险表达。
OTHER：信息不足、意图模糊，或不属于以上三类。

规则：
1. 只输出一个大写标签，不要解释，不要标点。
2. 涉及投诉、扣费、退款赔付时优先输出 COMPLAINT。
3. 需要实时数值或状态时输出 DATA。
4. 无法确定时输出 OTHER，不要猜测。

示例：
“满减能和会员券一起用吗？” → RULE
“昨天门店GMV是多少？” → DATA
“平台乱扣费，我要投诉。” → COMPLAINT
“活动怎么回事？” → OTHER

用户问题：{{user_query}}
```

## 条件分支

条件应使用分类节点输出 `issue_type`，并处理可能的空格：如果平台支持结构化输出，优先使用枚举；否则至少在Prompt中限制只输出标签，并检查是否需要 `trim`。

## 四条分支

### RULE

课堂虚构规则卡：

- 平台满减与平台新客券不可叠加；
- 商家券是否可叠加，以活动配置页明确标识为准；
- 规则卡未覆盖时，不得猜测，提示核实当前有效规则。

输出格式：结论 → 课堂依据 → 不确定性提示。

### DATA

使用确定性固定输出：

> 该问题需要查询业务系统中的实时数据。本课堂版本未连接订单或经营系统，因此不会生成具体数值；正式产品应在校验权限后查询。

### COMPLAINT

使用确定性固定输出：

> 已识别为投诉或高风险咨询。系统将保留原始问题并转交人工处理；当前不自动承诺退款、赔偿或处理结果。

### OTHER

输出一个澄清问题，例如：

> 为了准确处理，请补充你想了解的具体活动名称，以及你关心的是参与条件、叠加规则还是生效时间？

## 为什么关键分支使用固定话术

投诉和实时数据属于硬边界。此处用确定性节点而不是继续让模型自由生成，是在用产品结构约束风险。
