# 第00课学员版讲义（新版49页PPT对应版）

## 课程名称

开班典礼、课程学习地图、AI时代背景与第一次AI场景分析

## 本课学习目标

学完本课，你应该能够：

1. 理解课程的初心、三阶段学习路径和课程约定；
2. 分清AI、机器学习、深度学习、NLP、AIGC和大模型的基本关系；
3. 理解近几年生成式AI为什么快速发展；
4. 用完整方法分析“销售拜访记录助手”；
5. 在自己工作中找到一个真实AI Case。

---

## 一、这门课为什么存在

很多产品经理学习AI时会遇到两种困难。

一种是技术概念太多。模型、训练、微调、向量、召回、RAG和Agent都能听到，但不知道它们和产品需求、PRD、交互和项目决策有什么关系。

另一种是学了很多AI工具。可以生成文档、原型和Demo，但还不会回答：为什么要做这个产品？用户的真实问题是什么？AI真的比普通方案更合适吗？效果怎么验证？出错后怎么处理？

这门课想建立的是一条产品经理可以使用的完整路径：

> 理解产品经理需要的AI技术，但始终从用户问题、产品方案、效果验证和业务落地出发。

### AI产品经理不等于AI工具产品经理

AI工具可以帮助我们研究、写作、生成原型、搭建Demo和提高个人效率。这些能力非常重要，但AI产品经理还需要：

- 找到值得解决的真实问题；
- 判断是否真的需要AI；
- 设计AI、规则、工具和人之间的分工；
- 评估AI输出是否可以使用；
- 处理风险、成本、上线和持续运营。

“会用AI工具”和“会做AI产品”并不冲突。工具是帮助我们表达和验证的手段，产品判断决定工具应该用在哪里。

## 二、三阶段学习路径

### 第一阶段：系统学习

目标是建立AI产品完整地图，理解大模型、Prompt、Workflow、RAG、Agent、MCP、交互、评测、Bad Case、成本和ROI。

不是要求背住所有名词，而是要知道：

- 它在解决什么问题；
- 它和其他概念是什么关系；
- 什么时候适合使用；
- 应该怎样写进产品方案。

### 第二阶段：项目实践

目标是把知识变成可展示的产出。学员通过公共项目走通0到1，再选择与自己背景和目标岗位匹配的方向项目。

每个人的项目不完全一样，这样全班可以看到不同行业、不同流程和不同Bad Case。但小组学习不等于所有人共交一份作业，每个人仍需要完成自己的项目产出。

### 第三阶段：求职转化

目标是让市场能看懂和相信你的能力。内容包括目标岗位、定向简历、项目表达、作品集、面试追问和投递复盘。

项目必须真实标注。没有上线就不写上线，没有真实数据就写测试结果或待验证假设，不把团队成果全部写成个人贡献。

三个阶段分别回答：你懂不懂？你做没做？你讲得清吗？

## 三、课程约定与学习方式

AI发展很快，课程中的工具、案例和部分课次顺序可能调整。但课程的核心能力主线和已承诺交付应该保持稳定。

课程内容会尽量通过来源追溯、实际验证、版本说明和公开勘误保证质量。如果你发现问题，可以提供证据和反例，但不建议只以“某个博主这样说”作为结论。

学习应该完成一个闭环：

1. 课前带着真实问题；
2. 课中跟随案例和模板完成第一版；
3. 课后换成自己的工作场景；
4. 接受老师和同学的反馈；
5. 修改并保留修改原因。

## 四、AI时代的基本背景

### 1. AI不是最近几年才出现

AI已经发展了70多年。早期研究者就已经开始研究如何让机器表现出智能。随后经历了规则系统、机器学习、深度学习、预训练模型和大模型等阶段。

过去的AI大多藏在产品后台，例如搜索、推荐、广告、地图和风控。普通用户会使用这些产品，但很少直接与AI对话。

2022年以后，普通用户开始通过自然语言直接使用AI，让AI生成文字、图片、音频、视频和代码。因此，最近几年爆发的是生成式AI的大众化，而不是AI这个概念突然出现。

### 2. AI、机器学习、NLP和AIGC不是同一层概念

可以从三个维度理解。

#### AI想实现什么

AI，即人工智能，是一个大范围，目标是让机器表现出感知、理解、推理、决策或行动等能力。

推荐系统猜测你喜欢的内容，地图预测到达时间，风控判断交易是否异常，大模型生成文字和代码，都属于AI。

#### AI通过什么实现

机器学习是实现AI的重要方法。传统软件通常由人编写规则，机器执行规则。机器学习则从大量数据中学习规律，然后预测新结果。

深度学习是机器学习中的一类方法。为了方便初学者理解，可以先记住下面的包含关系：

```text
人工智能 AI
└── 机器学习 ML
    └── 深度学习 DL
        └── 大模型与生成模型
```

#### AI在处理什么问题

- NLP，自然语言处理：处理文字和语言，如分类、摘要、翻译和问答。
- CV，计算机视觉：识别和理解图片、视频。
- ASR，自动语音识别：把人说的话转成文字。
- TTS，语音合成：把文字转成机器语音。
- 推荐与预测：根据数据猜测用户偏好、风险或未来结果。

一句话总结：

> AI是目标，机器学习是方法，NLP是问题领域，AIGC是能力和应用形态。

### 3. AIGC是什么

AIGC可以理解为由AI生成内容。内容可以是文字、图片、音频、视频、代码或结构化数据。

| 输入 | AI输出 | 类型 |
|---|---|---|
| 用户评论 | 判断是正面还是负面 | 识别或分类 |
| 用户评论 | 生成评论总结 | AIGC |
| 商品图片 | 判断是否违规 | 识别或审核 |
| 商品描述 | 生成宣传图片 | AIGC |

AIGC不等于所有AI。一个产品也可以同时使用识别、预测、检索和生成能力。

### 4. 大模型、LLM和ChatGPT的关系

大模型通常指通过大规模数据预训练、能够适应多种任务的基础模型。

LLM即大语言模型，主要处理文字和语言。多模态模型则能同时处理文字、图片、声音或视频。

ChatGPT是一个产品，GPT是模型家族。可以把模型理解成发动机，但一辆可以上路的车还需要方向盘、车身、刹车、导航和安全系统。同样，AI产品还需要知识、工具、流程、权限、交互和评测。

### 5. 最近几年的快速发展

- 2017年：Transformer成为大模型的重要技术基础。
- 2018—2021年：预训练模型发展，一个基础模型开始适应多个任务。
- 2022年：生成式AI进入大众市场，普通用户开始使用自然语言直接操作AI。
- 2023年：大模型和多模态能力发展，更多企业开始尝试业务应用。
- 2024年：长上下文和工具调用能力继续增强。
- 2025年至今：推理模型和Agent系统成为重要方向。

整体趋势可以理解为：

```text
识别信息
→ 生成内容
→ 分析问题
→ 调用工具
→ 执行任务
```

### 6. AI产品不只是一个聊天框

传统产品通常是用户点击功能，系统执行固定规则，返回相对确定的结果。

AI产品可能是用户表达一个目标，AI理解任务，获取知识和数据，必要时调用工具，然后生成或执行，最后由用户确认结果。

因为AI输出可能不确定，产品还要设计错误提示、原文引用、结果修改、失败重试、人工确认和权限管理。

## 五、案例精讲：销售拜访记录助手

### 1. 案例背景

本案例是一个教学假设。销售或BD拜访客户后，需要把客户诉求、现有解决方案、主要异议、合作意向、下一步计划、负责人和跟进时间录入CRM。

CRM是客户关系管理系统，可以理解为企业用来记录客户资料、销售进展和待办任务的系统。

现实中可能出现：

- 拜访结束后没有时间记录；
- 整理内容依赖销售个人回忆；
- CRM内容过于简单；
- 客户的关键异议和后续任务被遗漏。

### 2. 确认问题

先不要问AI能做什么，而是确认：

- 目标用户：经常拜访客户的销售和BD；
- 使用场景：线下拜访或电话沟通后录入CRM；
- 现有方式：手写笔记、录音、聊天记录和个人回忆；
- 核心问题：整理耗时，关键信息容易遗漏。

这些只是初步假设。真正项目中需要通过访谈、观察和数据验证，不能因为听起来合理就当作事实。

### 3. 拆解流程

完整流程可以拆成：

```text
拜访前准备
→ 进行客户沟通
→ 记录沟通内容
→ 整理关键信息
→ 填写CRM
→ 创建后续任务
→ 持续跟进客户
```

适合AI优先介入的环节包括：

- 录音转文字；
- 提取客户诉求、异议和合作意向；
- 总结沟通结论；
- 生成CRM记录草稿；
- 生成待办事项。

需要人工保留的环节包括：

- 判断客户的真实合作意愿；
- 确认承诺、报价和重要事实；
- 决定下一步销售策略；
- 检查后正式写入CRM。

### 4. 设计人机分工

```text
销售完成客户拜访
→ AI将录音转成文字
→ AI提取诉求、异议、意向和行动项
→ AI生成结构化记录草稿
→ 销售查看原文、检查和修改
→ 确认后写入CRM并创建后续任务
```

输出示例：

```text
客户核心诉求：
希望减少门店活动配置的操作时间。

主要异议：
担心新系统培训成本过高。

合作意向：
愿意小范围试用，但暂不愿意全量采购。

下一步行动：
1. 周五前发送试用方案——负责人：销售A
2. 下周安排产品演示——负责人：产品B
```

AI负责降低信息整理和录入成本，销售负责确认事实和商业决策。

### 5. 识别风险并设计兜底

AI可能：

- 把不同说话人的内容混在一起；
- 没有正确识别行业术语、产品名、金额或日期；
- 把销售建议误认为客户承诺；
- 遗漏负责人和截止时间；
- 生成对话中根本没有出现的信息；
- 把敏感客户信息发送到不合规系统。

对于低风险的摘要问题，可以允许销售编辑。对于金额、日期、承诺和合作意向，应该展示原文并要求人工确认。对于敏感数据，还需要权限、数据隔离和合规审查。

### 6. 验证产品价值

#### 效率指标

- 每次拜访后的平均记录时间；
- CRM录入完成时间；
- 销售使用助手的频率。

#### 质量指标

- CRM关键字段完整率；
- 行动项遗漏率；
- 销售修改AI结果的比例；
- 关键信息提取准确率。

#### 业务指标

- 客户跟进任务按时完成率；
- 有效客户信息沉淀率；
- 长期观察客户转化率是否改善。

“生成一份摘要”只是产品输出，“销售更快完成记录，并减少客户信息和行动项遗漏”才是产品价值。

### 7. 案例复盘公式

> 完整AI产品方案 = 用户问题 + AI任务 + 人机分工 + 错误兜底 + 验证指标。

## 六、课后作业：找到你工作中的AI Case

### 作业目标

回到自己的工作场景，找到一个可能使用AI解决的真实问题。

不要从“我们能不能做一个AI助手”或“我也想做一个Agent”开始。请从下面的问题开始：

> 谁在什么情况下，反复遇到了什么问题？

### 作业模板

```text
1. Case名称：

2. 目标用户：
谁会使用这个产品？

3. 使用场景：
用户在什么时候遇到问题？

4. 当前问题：
用户现在怎么做？
最耗时、最困难或最容易出错的地方是什么？

5. AI承担的任务：
AI接收什么输入？
AI具体处理什么？
AI输出什么结果？

6. 人机分工：
哪些步骤交给AI？
哪些步骤必须由人确认或决策？

7. 风险与兜底：
AI最可能犯什么错？
产品怎样发现并处理这个错误？

8. 验证指标：
至少写一个效率指标和一个质量指标。
```

### 提交要求

- 案例必须尽量来自你真实接触过的工作场景；
- 不要求完成全套PRD或页面原型；
- 优先把问题、流程、人机分工、风险和验证说清楚；
- 不知道的信息标注“待验证”，不要把假设当作事实；
- 建议控制在1—2页。

### 作业自检

1. 我能否说清楚谁遇到了问题？
2. 这个问题是否真实发生？
3. AI承担的任务是否足够具体？
4. 我是否设计了人工确认和错误处理？
5. 我是否知道怎么判断它有没有价值？

## 七、本课总结

1. AI是目标，机器学习是方法，NLP是问题领域，AIGC是能力和应用形态。
2. 模型不等于产品，AI产品还需要知识、工具、流程、权限、交互和评测。
3. 分析AI Case时，需要同时考虑用户问题、AI任务、人机分工、风险兜底和验证指标。
4. 一个好的第一次作业不必大而创新，但必须尽量真实、具体、可以验证。
