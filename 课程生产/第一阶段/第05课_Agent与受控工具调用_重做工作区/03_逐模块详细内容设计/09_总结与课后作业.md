# 模块九：课程总结与课后作业

## 一、模块定位

- 建议课堂时长：2 分钟
- 对应总课时：136—138 分钟
- 作用：收束认知，明确课后产出

如果课堂互动较多，本模块可以只口头总结并展示作业页，不再展开新知识。

## 二、四句话总结

### 1. Agent 不是“更会聊天”

Agent 的关键是围绕目标判断下一步，并通过工具影响外部系统或任务状态。

### 2. 工具不是越多越好

工具名称、用途、输入、输出、权限和失败处理都需要被清楚定义。

### 3. 能执行就必须能受控

高风险动作需要确认或审批；工具失败、信息不足和越权请求都要有停止与接管方案。

### 4. 先跑通单 Agent 最小闭环

MCP 和 Multi-Agent 是后续扩展选项，不是每个产品都必须采用的起点。

## 三、课堂即时产出 V0.1

学员在纸面练习中已经完成一份 Agent 方案草稿，至少包含：

- 用户与目标；
- 必要输入；
- 2—4 个工具；
- 正常路径；
- 确认点；
- 异常和停止条件。

这份 V0.1 是课后作业的起点，不需要重新选题。

## 四、课后作业：完成自己的 Agent 产品设计 V1.0

### 作业任务

从自己的工作或生活场景中选择一个真实问题，完成一份“受控 Agent 产品设计”。

### 必交内容

#### 1. 场景与用户

- 谁遇到了什么问题；
- 当前流程为什么不够好；
- 为什么需要 Agent，而不是普通对话或固定 Workflow。

#### 2. 任务目标

用一句可判断是否完成的话描述目标。

不合格示例：

> 帮助用户提升效率。

合格示例：

> 根据销售人员提交的客户信息和本次拜访记录，补全 CRM 草稿中的指定字段，并将无法确认的字段标记出来交给销售人员复核。

#### 3. 工具设计

设计 2—4 个必要工具，每个工具写清：

- 工具名称；
- 使用场景；
- 输入参数；
- 返回结果；
- 权限与限制；
- 失败时怎么办。

#### 4. 运行路径

画出或写出：

> 接收目标 → 补全信息 → 判断下一步 → 调用工具 → 读取结果 → 继续或停止

同时标明哪些步骤固定、哪些步骤由 Agent 动态判断。

#### 5. 风险与控制

至少写清：

- 一个需要用户确认的动作；
- 一个必须拒绝或转人工的动作；
- 一个工具失败后的处理方式；
- 任务停止条件。

#### 6. 五条测试用例

至少覆盖：

1. 正常完成；
2. 信息缺失；
3. 模糊或冲突指令；
4. 工具失败；
5. 高风险或越权请求。

每条测试需写“预期行为”，不能只写用户问题。

#### 7. 技术形态判断

回答两个问题：

- 当前方案是否真的需要 MCP？为什么？
- 当前方案是否真的需要 Multi-Agent？为什么？

不要求实际搭建 MCP 或 Multi-Agent。

## 五、作业评价标准

| 评价项 | 核心问题 |
|---|---|
| 场景真实性 | 是否来自具体任务，而不是泛泛而谈 |
| Agent 必要性 | 路径是否存在需要动态判断的部分 |
| 工具清晰度 | 工具职责和输入输出是否明确 |
| 可控性 | 是否设计确认、权限、异常与停止 |
| 可测试性 | 是否能通过测试用例判断方案好坏 |
| 复杂度控制 | 是否避免无必要的工具和多 Agent |

## 六、隐私要求

- 不提交公司真实客户信息；
- 不提交内部账号、Token、密钥或接口地址；
- 业务数据必须脱敏或使用模拟数据；
- 不把受限材料直接上传到公共模型或课堂平台。

## 七、与下一课的连接

下一课会进一步讨论场景判断与 MVP：

> 面对一个业务问题，什么时候应该做 Agent，什么时候用 Workflow、RAG 或普通 AI 功能就够了；又该如何确定第一版产品边界。

因此，本次作业最重要的不是把方案做复杂，而是留下清楚的判断依据，供下一课继续评审。
