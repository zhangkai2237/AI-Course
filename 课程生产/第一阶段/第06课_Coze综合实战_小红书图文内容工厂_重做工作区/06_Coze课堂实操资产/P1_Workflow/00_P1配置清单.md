# P1小红书图文Workflow｜Coze配置清单

## 实测信息

```text
Coze空间：
搭建人：
最后实测日期：
指定模型：
图片节点/模型：
是否全量通过：
备用截图路径：
```

## 一、项目目标

把P0中的单次生成拆成固定内容生产SOP，并实现：

- 必要输入缺失时停止；
- 每一步可以单独查看输入输出；
- 图片生成不可用时输出图片Prompt；
- 最终返回自动审核状态，但保留人工确认。

## 二、目标画布

```text
Start
→ IF_必要输入检查
   ├─ 缺失 → End_补充信息
   └─ 完整 → LLM_内容角度与大纲
             → LLM_标题与正文
             → LLM_图片脚本
             → 图片生成（可选）/ 图片Prompt备用
             → LLM_内容审核
             → End_完整结果
```

## 三、Start输入

| 名称 | 类型 | 必填 | 示例 |
|---|---|---:|---|
| `topic` | String | 是 | 为什么学会Prompt还不等于会做AI产品 |
| `audience` | String | 是 | 1—3年经验、希望转向AI方向的产品经理 |
| `goal` | String | 是 | 引发收藏、评论或课程咨询 |
| `source_material` | String/Long Text | 是 | 允许使用的事实观点 |
| `tone` | String | 否 | 真实、克制、有方法 |
| `image_style` | String | 否 | 简洁编辑感、米白背景、蓝绿色点缀 |
| `page_count` | Integer | 否 | 3 |

## 四、输入检查

节点名称：`IF_必要输入检查`

缺失条件：

```text
topic为空 OR audience为空 OR source_material为空
```

缺失分支固定返回：

```text
status：need_more_information
message：请补充主题、目标受众和事实素材后再生成。
```

完整分支进入 `LLM_内容角度与大纲`。

## 五、生成节点与Prompt文件

| 节点 | Prompt文件 | 主要输出 |
|---|---|---|
| `LLM_内容角度与大纲` | `01_内容角度与大纲Prompt.txt` | `content_plan` |
| `LLM_标题与正文` | `02_标题与正文Prompt.txt` | `copy_package` |
| `LLM_图片脚本` | `03_图片脚本Prompt.txt` | `image_script` |
| `LLM_内容审核` | `04_内容审核Prompt.txt` | `review_result` |

首次搭建可先让四个节点各输出一个String，跑通后再按当前Coze的结构化输出能力拆字段。

## 七、图片路线

### 优先路线

将图片脚本中的每张图片Prompt传给已实测可用的图片生成节点，并把图片URL或图片对象返回End。

### 课堂备用路线

如果图片权限、额度或模型不稳定：不执行图片生成，直接返回 `image_script` 中的图片Prompt。老师使用预生成图片展示最终效果。

不允许因为图片节点失败而判定整个Workflow学习失败。

## 八、End输出

正常分支：

| 字段 | 来源 |
|---|---|
| `status` | 固定值 `completed_need_human_review` |
| `copy_package` | `LLM_标题与正文.copy_package` |
| `image_script` | `LLM_图片脚本.image_script` |
| `images` | 图片节点输出，可选 |
| `review_result` | `LLM_内容审核.review_result` |

缺失分支：

| 字段 | 值 |
|---|---|
| `status` | `need_more_information` |
| `message` | 请补充主题、目标受众和事实素材后再生成 |

## 九、调试顺序

1. 单独运行内容角度节点；
2. 检查标题正文节点是否收到content_plan；
3. 检查图片脚本是否遵循page_count；
4. 给正文加入一个虚构数字，检查审核能否识别；
5. 跑完整正常路径；
6. 清空source_material，跑缺失路径。
