# 第01课《AI产品经理岗位认知与转型路径》知识点来源溯源表

> 文档状态：来源主表（已按当前教学决策校准）  
> 当前阶段：01来源主表校准完成；02、03待依据本表逐项复核  
> 本课定位：帮助学员看懂AI产品经理在做什么，认识主要岗位方向，并结合个人背景形成第一个可验证的转型方向。

---

## 一、本课只回答三个问题

1. AI产品经理到底是什么工作？
2. AI产品岗位为什么会有不同方向？
3. 我的背景更适合优先验证哪个方向？

本课最终产出不是完整职业规划，而是一张“个人方向初步判断卡”：

- 我的既有背景；
- 可以迁移的经验资产；
- 优先验证的AI产品方向；
- 一个备选方向；
- 做出这一判断的依据；
- 当前最明显的能力缺口；
- 需要继续分析的真实JD；
- 下一步验证动作。

个人定位句是对方向判断卡的压缩表达，不是简历包装，也不构成岗位适配或录用承诺。

## 五、教师必须掌握的原材料内容

### 5.1 AI产品经理的工作链路

来源：亚慧01第590—672段。

教师需要理解的完整逻辑：

1. **先定义业务和用户问题**：AI不是需求本身，不能因为有模型就寻找一个勉强可以使用的场景。
2. **准备验证材料**：通过真实问题、数据或评测集，建立判断AI能力是否满足场景的依据。
3. **验证技术可行性**：模型偶尔能答对不代表达到产品上线标准，要在承诺方案之前完成验证。
4. **设计产品与人机关系**：明确用户输入什么、AI处理什么、人在哪些环节判断、错误时怎样兜底。
5. **定义验收标准**：明确什么叫正确、可用、稳定，以及哪些错误不能接受。
6. **上线后收集Bad Case**：持续收集错误、遗漏、不一致和用户不满意的案例。
7. **推动持续优化**：与业务、算法、研发、数据和运营一起判断问题来自产品、数据、模型还是流程。

本课讲到“知道这七件事存在”即可。评测集、指标和Bad Case方法分别放到后续课程。

### 5.2 产品经理真正不可替代的工作

来源：知乎02录音第536—550段。

教师需要理解：

- 写PRD只是表达方案的手段，不是产品经理的最终价值。
- AI可以降低资料整理、文档撰写和原型生成的成本。
- 产品经理仍然要判断：问题值不值得解决、服务谁、为什么现在做、采用什么方案、怎样衡量结果。
- 因此，“AI工具使用能力”是工作效率的一部分，不等同于“AI产品经理岗位能力”。

### 5.3 To B AI产品经理的工作重点

来源：知乎08第148—202段。

教师需要理解：

- 从企业原有业务流程开始，而不是从Agent、RAG等技术名词开始。
- 使用者、购买者、决策者和反对者可能是不同的人。
- 要判断AI插入哪个流程节点、改变什么决策或劳动方式。
- 要说明能减少多少成本、时间和错误，或者提升什么业务结果。
- 要处理权限、安全、数据边界、私有化和系统连接。
- 产品交付后，还要看客户是否采用、是否真正产生价值。

### 5.4 To C AI产品经理的工作重点

来源：知乎18第136—180段、第308—330段。

教师需要理解：

- 从具体用户和具体场景出发，避免只描述宽泛人群。
- 判断用户真正缺少的是时间、信息、决策支持、情感、娱乐还是交易帮助。
- AI能力只有与用户缺少的价值匹配，才可能形成产品机会。
- MVP要尽快让用户感受到核心价值，Aha Moment比功能数量更重要。
- To C方向通常更看重用户敏感度、体验设计、产品吸引力、使用和留存。

### 5.5 用JD做人岗匹配

来源：亚慧01第710—726段；知乎02第338—356段。

教师需要掌握的JD分析顺序：

1. 这个岗位服务谁；
2. 要解决什么业务或用户问题；
3. AI在产品中承担什么任务；
4. 产品经理具体负责哪些环节；
5. 为什么要求某种行业或产品经历；
6. 要求掌握AI到什么深度；
7. 哪些要求是自己的已有资产；
8. 哪些差距需要通过学习或项目补齐。

## 六、来源使用与标注规则

后续制作02、03、PPT和讲义时，统一使用以下四种标注：

1. **参考课直接观点**：能够在第三部分找到明确课程和位置；
2. **基于参考课重新整理**：多个来源合并或为了教学而压缩，但没有改变原观点；
3. **本课程教学设计/案例假设**：课程结构、分析工具、练习、模拟案例等原创组织；
4. **待JD验证**：涉及当前岗位分类、具体职责、能力要求和市场情况，尚未用真实JD确认。

以下内容不得伪装成参考课程原话：三个核心问题、四方向教学地图、服务对象×业务目标×产品形态×交付方式、六类经验资产、方向判断卡、现场诊断和零基础三分法。

这些教学加工没有引入新的AI技术知识，作用是把已有参考内容组织成初级学员可以理解和执行的学习路径。

## 七、明确不采用或暂不采用的内容

| 原材料内容 | 处理决定 | 原因 |
|---|---|---|
| “AI岗位井喷”“高薪红利”“版本之子” | 不作为事实讲授 | 营销表达，缺少当前数据支持 |
| 年龄、职级和薪资的确定性结论 | 删除 | 个体、公司和市场差异很大，且时效性强 |
| “某方向占90%”“To C不赚钱”等判断 | 删除 | 参考材料未提供可靠、可复核的数据 |
| “按照这个方法大概率拿到Offer” | 删除 | 不能将个案经验转化为结果承诺 |
| 完整Prompt、RAG、Workflow、Agent技术讲解 | 移到后续课 | 超出本课岗位认知范围 |
| 完整六类能力模型和长期学习路线 | 暂不展开 | 容易让第一课重新膨胀成完整转型规划 |
| AI自动生成简历、行业报告和作品集的方法 | 移到项目或求职阶段 | 与本课学习目标不一致，也容易让学员绕过真实学习 |
| 具体产品的融资、估值和市场表现 | 开课前另行核验 | 高度时效，不能直接沿用录音观点 |

## 八、真实JD补充策略

当前项目旧版引用了少量百度岗位，但其中包含解决方案架构师等相邻岗位，且岗位有效性会变化。因此旧样本暂不直接进入新版课程。

真实JD不阻塞当前内容设计，但平台/能力、解决方案方向的具体岗位画像，以及所有市场变化判断，不能在JD核验前定稿。

最低准备8份，每个方向2份；条件允许时扩展到10—15份。最终课堂只展示3—4份差异明显的岗位摘要。

后续收集JD时，每份至少记录：

| 字段 | 记录内容 |
|---|---|
| 基础信息 | 公司、岗位名、城市、工作年限、发布日期、链接 |
| 服务对象 | 企业客户、内部员工、普通消费者或开发者 |
| 业务目标 | 增效、增收、体验、增长、风控或决策等 |
| AI任务 | 生成、问答、检索、预测、决策辅助、流程执行等 |
| 产品职责 | 调研、方案、平台、评测、交付、增长或运营等 |
| 背景要求 | 行业、To B/To C、平台、数据、技术协作等 |
| AI深度 | 只要求认知、要求项目经验，还是要求模型/算法背景 |
| 结果指标 | 效率、准确性、采用率、留存、收入、成本等 |
| 方向判断 | To B应用、To C应用、平台/能力或解决方案 |
| 学员匹配 | 哪类既有背景更容易切入，依据是什么 |

学员课后作业最低分析5份同方向JD；明确求职的学员建议分析10份。老师备课样本、课堂展示样本和学员作业数量是三个不同口径，不应混写。

最迟完成时间：逐页PPT定稿和试讲前。

## 九、现场转型方向诊断

### 9.1 教学定位

现场诊断是问题三“我的背景更适合优先验证哪个方向”的课堂应用，不是新增知识模块，也不是老师凭经验直接替学员决定职业方向。

每位学员统一输出：

1. 已有经验资产；
2. 优先验证方向；
3. 备选方向；
4. 判断依据；
5. 当前最大缺口；
6. 下一步验证动作。

### 9.2 课前准备

- 提前收集当前岗位、工作年限、所在行业、主要工作、代表项目、优势能力、AI基础、转型目标和客观限制；
- 获得学员公开分析的同意，必要时匿名；
- 优先选择3名背景差异明显的学员；
- 老师在课前完成初步分析，但课堂上仍要展示判断过程，不能只宣布答案。

### 9.3 课堂时间

- 标准方案：3人，每人8分钟，最后3分钟总结，共27分钟；
- 时间充足时：增加1—2名学员，每人只做2分钟快速判断；
- 不建议直接安排5人深度诊断，否则容易挤压岗位认知内容。

### 9.4 零基础处理原则

- **有产品经验、没有AI经验**：优先验证“原产品方向＋AI”，先补AI基础和AI项目证据；
- **没有产品经验、但有行业或职能经验**：优先验证“原行业/职能＋AI应用”或解决方案方向，同时补产品基本功；
- **产品、AI和行业积累都较弱**：暂不强行确定岗位，先选熟悉场景，完成产品基础、AI基础和一个小项目，再用JD验证方向。

现场表达必须使用“建议优先验证”，避免使用“你就适合”“一定能转”“一定能拿到Offer”等确定性承诺。
