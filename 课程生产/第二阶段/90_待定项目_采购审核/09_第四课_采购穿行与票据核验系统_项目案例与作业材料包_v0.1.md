# 第四课：采购穿行与票据核验系统｜项目案例与作业材料包

> 版本：v0.1｜2026-09-22  
> 用途：课堂规则推演、公共案例测试、个人项目作业和点评验收  
> 配套讲义：`08_第四课_采购穿行与票据核验系统_老师版完整讲义_v0.1.md`  
> 案例声明：本文所有企业、人员、供应商、单据和审核结果均为教学模拟，不代表真实企业数据、税务凭证或审计结论。

## 使用方法

课堂使用第一至第五部分完成材料关系、字段提取、规则核验和人工复核推演。学员课后复制第六部分模板，改造成自己的材料审核项目。

本版先提供结构化的“文本单据”和标准答案，便于统一讲解。后续可以依据本包生成 PDF 或图片版模拟单据，用于 OCR、视觉模型和工作流实测。在真实运行前，本文中的系统输出均属于预期结果。

## 一、公共项目背景与统一口径

### 1. 模拟业务

启明智造在 2026 年 8 月采购一批无线键盘。审核人员在 2026 年 9 月 15 日，对 ERP 采购记录、采购申请单、入库单和发票进行穿行核验。

系统需要回答：

1. 四类材料是否属于同一笔采购；
2. 供应商、物料、数量、金额和日期是否一致或合理；
3. 哪些字段不确定、哪些材料缺失、哪些规则确认存在差异；
4. 审核人员修改或确认后，是否留下完整记录。

### 2. 固定口径

| 项目 | 设定 |
|---|---|
| 企业 | 启明智造（教学模拟） |
| 购买方名称 | 启明智造有限公司 |
| 审核月份 | 2026 年 8 月 |
| 固定审核日 | 2026-09-15 |
| 物料 | K68 无线键盘 |
| 数量单位 | 件 |
| 币种 | 人民币 |
| 税价口径 | ERP 含税金额与发票价税合计比较 |
| 金额容差 | 绝对差不超过 0.01 元 |
| 未提供信息 | 记为未知，不能补造 |

### 3. 本轮材料范围

- ERP 采购记录；
- 采购申请单；
- 入库单；
- 增值税发票。

本包不提供真实发票验真、工商查询、银行流水、合同或付款审批数据。

## 二、字段字典与关联规则

### 1. 字段字典

| 字段名 | 中文名称 | 类型 | 来源 | 是否进入规则 |
|---|---|---|---|---|
| purchase_id | 采购单号 | 字符串 | ERP、申请单、入库单、发票备注可能出现 | 是 |
| buyer_name | 购买方 | 字符串 | ERP、申请单、发票 | 辅助 |
| supplier_name | 供应商 | 字符串 | 四类材料 | 是 |
| material_name | 物料名称 | 字符串 | 四类材料 | 辅助关联 |
| requested_qty | 申请数量 | 数值 | 采购申请单 | 是 |
| received_qty | 入库数量 | 数值 | 入库单 | 是 |
| invoiced_qty | 开票数量 | 数值 | 发票 | 是 |
| budget_amount | 预算金额 | 金额 | 采购申请单 | 本轮不与发票直接比较 |
| erp_gross_amount | ERP 含税金额 | 金额 | ERP | 是 |
| invoice_gross_amount | 发票价税合计 | 金额 | 发票 | 是 |
| request_date | 申请日期 | 日期 | 采购申请单 | 是 |
| receipt_date | 入库日期 | 日期 | 入库单 | 是 |
| invoice_date | 开票日期 | 日期 | 发票 | 是 |
| approval_status | 审批状态 | 枚举 | 采购申请单/审批数据 | 是 |

每个提取字段还应保存：原始文本、标准化值、文件编号、页码或区域、置信度、复核状态和是否被人工修改。

### 2. 关联规则

1. 存在采购单号时，标准化格式后精确关联；
2. 没有采购单号时，依据供应商、物料、金额和日期生成候选；
3. 只有一个候选也要展示关联依据；
4. 同时匹配两笔及以上业务时，不自动确认；
5. 没有匹配到预期材料时，标记材料缺失；
6. 材料缺失不等于业务违规，关联不确定不等于规则差异。

### 3. 核验规则

| 编号 | 名称 | 逻辑 | 字段不足时 |
|---|---|---|---|
| R01 | 供应商一致 | 四类材料的标准供应商主体一致 | `insufficient_data` |
| R02 | 入库量不超过申请量 | `received_qty <= requested_qty` | `insufficient_data` |
| R03 | 发票数量不超过入库量 | `invoiced_qty <= received_qty` | `insufficient_data` |
| R04 | 发票与 ERP 含税金额一致 | `abs(invoice_gross_amount - erp_gross_amount) <= 0.01` | `insufficient_data` |
| R05 | 时间顺序合理 | `request_date <= receipt_date` 且 `request_date <= invoice_date` | `insufficient_data` |
| R06 | 采购申请已审批 | `approval_status = approved` | `insufficient_data` |

规则结果允许：`passed`、`flagged`、`not_applicable`、`insufficient_data`、`error`。

案件状态允许：`passed`、`flagged`、`needs_review`、`missing_document`、`system_error`。

业务状态：已入库、待付款
```

### 2. 采购申请单

材料编号：PR-260802

申请部门：渠道销售部
供应商：上海恒远电子有限公司
物料名称：K68 无线键盘
申请数量：100 件
预算金额：60,000.00 元
申请日期：2026-08-06
审批状态：已审批
```

### 3. 入库单

```text
材料编号：GR-260802
采购单号：PO-2026-0802
供应商：上海恒远电子有限公司
物料名称：K68 无线键盘
入库数量：100 件
入库日期：2026-08-19
仓库确认：已确认
```

### 4. 发票

```text
材料编号：INV-260802
销售方：上海恒远电子有限公司
购买方：启明智造有限公司
货物名称：K68 无线键盘
数量：110 件
价税合计（小写）：¥62,150.00
开票日期：2026-08-21
备注：采购单 PO-2026-0802
```

### 5. 预期规则结果

| 规则 | 结果 | 说明 |
|---|---|---|
| R01 | passed | 供应商一致 |
| R02 | passed | 入库 100 件，不超过申请 100 件 |
| R03 | flagged | 发票 110 件，比入库 100 件多 10 件 |
| R04 | flagged | 发票金额比 ERP 金额高 5,650.00 元 |
| R05 | passed | 日期顺序符合本轮规则 |
| R06 | passed | 申请已审批 |

预期案件状态：`flagged`。

预期证据摘要：

```text
R03 数量差异
- 入库数量：100 件，来源 GR-260802 入库数量字段
- 发票数量：110 件，来源 INV-260802 数量字段
- 差异：10 件

R04 金额差异
- ERP 含税金额：56,500.00 元，来源 ERP-L19 含税金额列
- 发票价税合计：62,150.00 元，来源 INV-260802 价税合计区域
- 差异：5,650.00 元
```

正确结论：存在需要人工核实的数量和金额差异。

错误结论：供应商虚开发票、采购人员舞弊或企业存在财务造假。当前材料不足以支持这些定性。

### 6. 人工处理练习

让学员选择一种后续情况并设计处理：

- 情况 A：供应商确认发票开错，重新开票；
- 情况 B：仓库发现漏录一张补充入库单；
- 情况 C：ERP 尚未同步追加采购审批；
- 情况 D：无法解释差异，需要升级调查。

每种情况都应写清：补充什么证据、谁确认、是否重跑规则、怎样保留原结果。

## 五、案例三：字段和关联都需要人工确认

### 1. ERP 候选记录

```text
候选 A
采购单号：PO-2026-0803
供应商：上海恒远电子有限公司
物料：K68 无线键盘
数量：100 件
含税金额：56,500.00 元
采购日期：2026-08-22

候选 B
采购单号：PO-2026-0804
供应商：上海恒远电子有限公司
物料：K68 无线键盘
数量：100 件
含税金额：56,500.00 元
采购日期：2026-08-23
```

### 2. 采购申请单

```text
材料编号：PR-260803
采购单号：PO-2026-0803
供应商：上海恒远电子有限公司
物料名称：K68 无线键盘
申请数量：100 件
预算金额：60,000.00 元
申请日期：2026-08-22
审批状态：已审批
```

### 3. 入库单

```text
材料编号：GR-260803
采购单号：空白
供应商：上海恒远电子有限公司
物料名称：K68 无线键盘
入库数量：100 件
入库日期：2026-08-28
仓库批次：WH-0828-A
```

### 4. 发票识别结果

```text
材料编号：INV-260803
销售方：上海恒远电子有限公司
购买方：启明智造有限公司
货物名称：K68 无线键盘
数量：100 件
价税合计原文：扫描模糊，可见“56,?00.00”
模型候选值：56,500.00 元
字段置信度：0.54
开票日期：2026-08-29
备注：未填写采购单号
```

### 5. 系统第一轮正确输出

```text
发票金额：needs_review
原因：价税合计区域模糊，候选值置信度低

入库单关联：needs_review
原因：缺少采购单号，同时匹配 PO-2026-0803 和 PO-2026-0804

发票关联：needs_review
原因：缺少采购单号，关键字段不能产生唯一候选

R03：insufficient_data
R04：insufficient_data
案件状态：needs_review
```

系统不能在这一步输出 `passed` 或 `flagged`。

### 6. 人工复核设定

课堂推演时提供以下补充信息：

```text
审核人员查看原图，确认发票价税合计为56,500.00元。
仓库批次 WH-0828-A 的收货通知对应 PO-2026-0803。
```

人工操作：

1. 确认发票金额为 56,500.00 元；
2. 将入库单关联至 PO-2026-0803；
3. 将发票关联至 PO-2026-0803；
4. 保存修改人、时间、依据和原始候选；
5. 重新运行 R01 至 R06。

复核后预期结果：六条规则通过，案件状态更新为 `passed`，但审核轨迹中仍保留第一次的低置信度和多候选记录。

### 7. 审核留痕示例

| 时间 | 操作人 | 操作 | 修改前 | 修改后 | 依据 |
|---|---|---|---|---|---|
| 2026-09-15 14:20 | 审核员 A | 确认发票金额 | 候选 56,500 / 置信度 0.54 | 56,500.00 / 人工确认 | 发票原图价税合计区域 |
| 2026-09-15 14:25 | 审核员 A | 确认材料关联 | PO-2026-0803、PO-2026-0804 两个候选 | PO-2026-0803 | 收货通知与仓库批次 WH-0828-A |
| 2026-09-15 14:26 | 系统 | 重跑规则 | R03、R04 无法计算 | R01—R06 全部通过 | 已确认字段与关联 |

## 六、课堂互动题

### Q1：缺少入库单意味着什么

ERP 有采购记录，但当前材料包里没有入库单。

**A.** 货物一定没有入库。  
**B.** 当前审核材料缺少入库证据，需要补充或核实。  
**C.** 供应商一定没有发货。

参考答案：**B**。

### Q2：两个候选怎样处理

一张发票没有采购单号，同时匹配两笔同供应商、同金额采购。

**A.** 自动选择日期最近的一笔。  
**B.** 随机选择一笔。  
**C.** 展示候选和依据，由人工确认。

参考答案：**C**。

### Q3：金额模糊时能否执行规则

模型候选金额为 56,500 元，置信度 0.54。

**A.** 先当作正确值执行规则。  
**B.** 标记字段待确认，依赖该字段的规则暂不执行。  
**C.** 直接把案件判为金额异常。

参考答案：**B**。

### Q4：发票数量大于入库数量意味着什么

**A.** 已经证明供应商舞弊。  
**B.** 存在确定性数量差异，需要核实业务原因。  
**C.** OCR 一定识别错误。

参考答案：**B**。

### Q5：人工修正字段以后怎么办

**A.** 覆盖原值并直接结束。  
**B.** 保存前后值和依据，重跑受影响规则。  
**C.** 只在备注中写一下，不更新规则。

参考答案：**B**。

## 八、提交与验收标准

### 点评课前初版

提交：业务背景、流程、材料清单、字段字典、关联规则、至少 5 条核验规则、核心页面或 Demo、6 组材料，以及已有测试结果或具体卡点。

### 点评后最终版

需要补齐：

- 一条实际跑通的完整链路；
- 正常、确定性差异、不确定或缺失三类实际测试；
- 字段层、规则层和案件层结果；
- 一次人工修正和规则重跑；
- 一份审核留痕；
- 一个完成分析、修改和回归的 Bad Case；
- 3—5 分钟演示录屏。

### 不合格情形

- 只有单文档总结；
- 只有 OCR，没有业务核验；
- 让模型直接完成精确金额计算；
- 不保留证据位置；
- 把识别失败当作风险成立；
- 所有问题都显示“审核不通过”；
- 没有人工处理和审核留痕；
- 没有实际测试却声称系统已经达到业务效果。
