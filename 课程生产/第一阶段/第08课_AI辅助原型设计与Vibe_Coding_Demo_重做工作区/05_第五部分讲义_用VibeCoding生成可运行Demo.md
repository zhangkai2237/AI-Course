# 第八课第五部分讲义：用 Vibe Coding 生成可运行 Demo

> 建议时长：43 分钟  
> 本部分目标：把已经确认的 PRD、页面结构和状态设计，按可验证切片转化为可运行 Demo。

## 一、Vibe Coding 在本课中的定位

Vibe Coding 是快速实现产品方案的方式，不是把产品决策交给 AI。

产品经理必须控制四件事：

1. 输入依据：AI读取了哪些正式文件；
2. 实现范围：本轮只做什么；
3. 验收条件：怎样才算完成；
4. 修改边界：什么可以改、什么不能动。

核心句：

> AI负责生成和修改代码，产品经理负责范围、决策和验收。

---

## 二、为什么不要一次生成整个产品

一次性生成容易导致：

- 问题混在一起，难以定位；
- AI顺手改动已经确认的功能；
- 修改一个局部导致其他路径退化；
- 看起来完成，却无法说明每项规则是否生效。

正确方式是按可验证切片实现：

1. 建立商品数据和页面骨架；
2. 完成加入对比和底部对比栏；
3. 完成商品对比页；
4. 完成只看差异和全部参数；
5. 补充超限、跨类目、缺失和冲突；
6. 完成移动端适配和核心路径检查。

每个切片遵循：

```text
说明本轮目标
→ 指定依据与不可修改项
→ Codex实现
→ 启动并检查
→ 记录问题
→ 局部修改
→ 回归核心路径
```

## 三、首次生成 Demo 的 Prompt

```text
请读取当前项目中的以下正式材料：

1. 商品对比工具最终PRD；
2. 产品决策记录；
3. 用户任务与页面清单；
4. 核心用户流程；
5. 页面信息架构；
6. 页面状态表；
7. 低保真与核心页面评审记录；
8. 商品模拟数据。

请在demo目录中生成商品对比工具一期的可运行Demo。

技术要求：
- 使用原生HTML、CSS和JavaScript；
- 所有代码放在demo/index.html；
- 不使用外部框架，不安装依赖；
- 双击文件或启动本地静态服务即可运行；
- 使用本地模拟数据，不连接后端；
- 适配移动端浏览器。

实现范围：
- 商品选择页；
- 底部对比栏；
- 商品对比页；
- 只看差异和全部参数；
- 删除、替换和返回路径；
- 少于2个、达到4个、跨类目、参数缺失和参数冲突状态；
- 浏览器本地临时保存。

不得实现：
- AI推荐；
- 强制登录；
- 云端保存；
- 跨类目对比；
- 统一到手价；
- 无依据补全参数。

执行方式：
1. 先列出你读取到的依据、实现清单和验收清单；
2. 如发现冲突或缺失，停止并列出问题；
3. 得到确认后再生成demo/index.html；
4. 启动本地预览；
5. 按验收清单逐项测试；
6. 只修复明确发现的问题；
7. 输出已实现能力、模拟边界和未实现能力。
```

## 四、高质量局部修改指令

修改指令包含五项：

1. 当前问题；
2. 复现位置；
3. 期望结果；
4. 保持不变的内容；
5. 验收方式。

### 示例1：修复第5个商品仍能加入

```text
当前问题：用户已经选择4个商品后，点击第5个商品仍然加入成功。

复现位置：商品选择页，连续加入5个同类SKU。

期望结果：第5个商品不得加入；保留原有4个商品；页面说明最多对比4个，并提供管理已选商品的入口。

保持不变：不要修改商品数据、商品对比页布局、只看差异逻辑和已有4个商品的顺序。

验收：分别验证选择1个、2个、4个和第5个商品时的结果，并报告测试结果。
```

### 示例2：修复缺失参数被自动补齐

```text
当前问题：模拟数据中缺失的电池容量在对比页被显示为推测值。

期望结果：缺失值统一显示“暂无数据”，不得生成或推测数值。

保持不变：不要修改其他参数值、价格展示和页面布局。

验收：使用包含缺失参数的SKU进入对比页，确认显示“暂无数据”；再检查其他SKU参数未改变。
```

## 五、Demo 必须声明能力边界

Demo可以使用：

- 教学模拟数据；
- 简化的本地状态；
- 受控异常样例；
- 聚焦核心流程的页面范围。

Demo不可以：

- 假装接入真实商品数据；
- 把本地保存称为云端同步；
- 用写死结果证明推荐有效；
- 隐藏未实现功能；
- 用视觉完成度替代业务验证。

---

## 六、课堂实施节奏

- 5分钟：Codex读取依据并输出实现与验收清单；
- 12分钟：生成第一版 `demo/index.html`；
- 8分钟：运行核心路径，记录问题；
- 10分钟：完成两次局部修改；
- 5分钟：回归核心路径；
- 3分钟：记录能力边界与修改结果。

---

## 七、本部分课堂产出

- `demo/index.html`；
- 至少两条《Demo修改记录》；
- 《Demo能力边界说明》；
- 初步验收结果。

过渡串词：

> Demo已经能够运行，但“点了几下没报错”不等于完成。最后还要回到正式PRD和状态表，用稳定用例完成验收，并准备一条可重复的演示路径。
