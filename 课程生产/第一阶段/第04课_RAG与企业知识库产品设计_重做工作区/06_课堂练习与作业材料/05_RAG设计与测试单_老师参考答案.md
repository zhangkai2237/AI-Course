# 商家规则RAG设计与测试单｜老师参考答案

## 一、业务目标

当活动商家询问活动规则时，系统应从“商家活动规则知识库”找到当前有效、适用于该商家的规则片段，并以“简洁答案＋适用条件＋文档版本”的方式回答。

如果没有可靠依据，应明确说明当前知识库未找到答案，不使用通用常识补齐，并引导查询对应系统或人工确认。

## 二、使用RAG的理由

- 企业内部规则；
- 会发生版本更新；
- 用户问法多样；
- 需要核验回答依据。

不用RAG：

- 门店当天补贴消耗、订单明细：业务系统；
- 赔偿和处罚撤销：人工/受控流程；
- 模糊问题：先追问。

## 三、知识治理六字段

| 知识 | 来源 | 负责人 | 版本/生效时间 | 适用范围 | 权限 | 更新/下线 |
|---|---|---|---|---|---|---|
| 新客立减规则 | 正式活动规则 | 活动运营组 | V2；7月1日生效 | 华东已认证正常营业餐饮商家 | 商家和活动运营 | V2替代V1；V1不得进入有效检索 |
| 违规与申诉说明 | 正式申诉制度 | 活动风控组 | V1；7月1日生效 | 新客立减活动商家 | 商家、运营、风控 | 制度更新后审核替换 |

## 四、双链路

离线：

```text
知识采集
→ 解析清洗
→ 分块
→ 元数据
→ 向量化/索引
→ 知识库
```

在线：

```text
用户问题
→ 问题理解/改写
→ 选择知识源
→ 检索
→ 重排
→ 增强Prompt
→ 生成
→ 引用/兜底
```

## 五、RULE升级

```text
RULE
→ 检索商家规则知识库
→ 返回并排序候选片段
→ 判断依据状态
   ├─ 可靠：基于片段回答并显示来源
   ├─ 无依据：明确未找到，不补写
   └─ 冲突：提示冲突，转人工/知识负责人
```

## 六、回答规则

1. 只根据检索片段回答；
2. 保留日期、适用范围和前提；
3. 没有依据或存在冲突时不自行推断。

## 七、分段检查答案

重点抽查：

- “报名截止7月25日”与“履约至7月31日”不能混为同一含义；
- “仅华东区域餐饮商家适用”不能丢失；
- V1“已失效”和“V2替代”必须保留；
- 实时补贴查询边界应能单独被检索。

## 八、四步排查顺序

1. 看路由是否正确；
2. 看正确知识是否存在；
3. 看实际检索回了什么；
4. 看模型怎样使用依据。

## 九、点评原则

答案不要求和参考文本完全一致，优先检查：

- 是否误把实时数据放进RAG；
- 是否把“当前活动不适用”错误扩大成“所有活动都不适用”；
- 是否有版本和权限；
- 是否有无答案和冲突；
- 是否分开看检索与生成。
