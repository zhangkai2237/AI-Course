# 模块02：Prompt主实操与迁移挑战——老师版讲义

> 时间：10—38分钟  
> 主实操：20分钟  
> 迁移挑战：8分钟  
> 产物：P0小红书文案生成器＋差评回复挑战版

## 一、老师先理解

P0在Coze画布上仍然使用Start和End，但本轮能力核心只有一个LLM节点。Start负责收变量，End负责展示结果，它们只是运行载体。不要因为画布上出现三个节点，就把它讲成已经做了完整Workflow设计。

本轮的教学目的不是重新讲一遍Prompt理论，而是让学员把结构化Prompt放进一个可运行载体，并通过正常测试和缺素材测试看到两件事：

1. 好Prompt能够提高当前节点的输出质量和稳定性；
2. Prompt无法凭空获得没有提供的真实知识，也无法代替流程控制和工具能力。

## 二、本轮开场讲法

“第一版我们故意只保留一个LLM节点。因为只有亲手跑过最小版本，后面增加Workflow、RAG和Agent时，你才能知道新增能力到底解决了什么问题。

今天不会比谁的提示词写得长。我们只看四件事：输入有没有说清、输出有没有定义、事实边界有没有写、坏结果能不能通过一次可解释的修改得到改善。”

## 三、屏幕操作：认识P0半成品

展示：

```text
Start → LLM → End
```

逐个说明：

- Start：接收topic、audience、goal、source_material和tone；
- LLM：根据变量生成结构化文案；
- End：把结果返回给用户。

强调：本轮没有知识检索、条件分支、搜索工具、保存工具和自动发布。

## 四、屏幕操作：配置输入变量

让学员在Start节点检查以下字段：

| 变量 | 类型 | 必填 | 课堂含义 |
|---|---|---:|---|
| `topic` | 文本 | 是 | 内容主题 |
| `audience` | 文本 | 是 | 写给谁看 |
| `goal` | 文本 | 是 | 希望读者产生什么反应 |
| `source_material` | 长文本 | 是 | 允许使用的事实和观点 |
| `tone` | 文本 | 否 | 表达风格 |

### 建议讲法

“变量不是为了让画布看起来专业，而是把会变化的信息从Prompt中分离出来。以后换主题、换受众，不需要改整段Prompt。”

## 五、屏幕操作：填写LLM节点Prompt

老师先让学员阅读以下骨架，再整体粘贴并绑定变量：

```text
你是一名擅长知识型内容的小红书编辑。

【任务】
根据用户提供的主题、受众、内容目标和素材，生成一套小红书文案。

【输入】
主题：{{topic}}
目标受众：{{audience}}
内容目标：{{goal}}
可用素材：{{source_material}}
表达风格：{{tone}}

【内容要求】
1. 先理解目标受众最可能遇到的问题；
2. 生成5个角度不同、不过度夸张的标题；
3. 正文使用“问题—误区—方法—行动建议”的结构；
4. 生成1句不超过18字的封面文案；
5. 生成3—5个标签；
6. 只能使用输入材料中的事实，不编造个人经历、公司背景和课程效果；
7. 信息不足时，明确列出需要补充的内容，不自行补全事实。

【输出格式】
一、标题候选
二、正文
三、封面文案
四、标签
五、事实与风险检查
```

提醒学员不要手敲形似 `{{topic}}` 的普通文字，必须使用平台的变量引用功能完成绑定。界面版本不同，入口可能表现为变量选择器、插入变量或引用上游参数，但验收标准相同：运行记录中能看到真实输入值。

## 六、正常测试

输入统一课堂材料，运行后让学员用1分钟检查：

- 是否正好输出5个标题；
- 是否出现封面文案和标签；
- 正文是否围绕初级产品经理；
- 是否使用了“流程、知识、工具、风险和验证”等输入观点；
- 是否编造讲师经历、学员成绩或公司案例；
- 事实与风险检查是否真正指出依据。

### 建议讲法

“不要先问自己喜欢不喜欢这篇文案。产品验证先检查它有没有按契约输出，再检查事实和风险，最后才是风格偏好。”

## 七、边界测试：删除素材

清空 `source_material`，其余输入不变，再运行一次。

让学员观察三种可能：

1. 模型明确要求补充素材；
2. 模型写出一篇空泛但没有明显事实的内容；
3. 模型自行补出课程模块、个人经历或效果数字。

### 老师讲解

“Prompt已经写了‘信息不足时不要补全’，但模型仍可能生成看起来合理的内容。这不是说Prompt没有价值，而是说明规则文字不能创造事实来源。后面RAG要解决的是‘去哪里找指定知识’，Workflow要解决的是‘缺信息时是否继续运行’。”

## 八、一次单变量修改

要求学员只选一个Bad Case，并只改一处：

- 标题太夸张：增加禁止词或标题标准；
- 正文太长：增加明确字数区间；
- 缺素材仍编造：强化无素材时的固定返回；
- 结构不稳定：将输出字段进一步固定；
- 事实检查空泛：要求逐条标注“来自输入/无法确认”。

修改后用同一输入重跑，记录：

```text
问题：
修改位置：
修改前结果：
修改后结果：
是否改善：
是否出现新问题：
```

### 纠偏

如果学员一次改了角色、结构、字数和事实规则，提醒他恢复，只保留一个变化。否则无法知道改善来自哪里。

## 九、迁移挑战：差评回复生成器

让学员复制P0并重命名为 `姓名_P0挑战_差评回复生成器`。流程仍然是Start→LLM→End，只更换变量和Prompt。

### 新输入

- 用户差评；
- 已知商品或课程事实；
- 当前允许提供的解决方案；
- 品牌语气；
- 禁止承诺事项。

### 新输出

- 问题归类；
- 公开回复；
- 私信处理建议；
- 不可承诺内容；
- 是否需要人工。

### 统一测试

```text
用户差评：课程完全没用，要求马上退款并额外赔偿5000元。
已知事实：暂未核实该用户订单、学习进度和服务记录。
允许方案：表达理解、收集订单信息、转人工核查。
禁止事项：不得直接承诺退款或赔偿，不得虚构售后政策。
品牌语气：克制、尊重、不争辩。
```

### 预期结果

- 表达理解但不承认未经核实的责任；
- 不承诺退款或5000元赔偿；
- 引导提供必要信息并转人工；
- 不与用户争辩；
- 明确需要人工处理。

## 十、故障处理

### 变量显示为空

先打开LLM节点的运行输入。若为空，检查是否引用了Start变量，而不是检查Prompt文案是否优美。

### 输出格式每次变化

先确认输出字段是否具体；本课不要求立即讲JSON Schema，可以使用清晰的固定标题。

### 模型仍然编造

把它记录为边界测试结果，不要在本模块无限堆叠规则。后续用RAG、流程分支和审核共同处理。

## 十一、最低完成线与认知记录

完成标准：

- P0可以正常运行；
- 跑过一条正常测试和一条缺素材测试；
- 完成一次单点修改；
- 完成或理解差评迁移挑战。

学员填写：

> Prompt解决了模型在当前节点中如何理解输入和组织输出；当知识、流程或事实没有进入当前输入时，它仍然无法稳定获得真实依据或控制后续步骤。

## 十二、转场

“P0已经能生成一篇看起来完整的文案。但角度、正文、图片和审核都挤在一个节点里。下一步我们不继续把Prompt写长，而是把稳定步骤拆开，看看Workflow怎样让错误变得可定位。”
