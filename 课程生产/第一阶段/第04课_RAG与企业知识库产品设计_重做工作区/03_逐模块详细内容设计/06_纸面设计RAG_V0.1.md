# 06 纸面设计RAG V0.1（73-83分钟）

## 教学目标

让学员在打开平台前，先把业务边界、知识来源、问答链路和失败处理设计清楚。

## 练习背景

第03课的“邻里增长平台商家咨询分流助手”已经能够把咨询分为四类。本课只升级`RULE`分支。

平台准备了三份虚构材料：

1. 《新客立减活动规则V2》：当前有效；
2. 《活动违规与申诉说明》：当前有效；
3. 《新客立减活动规则V1_已失效》：旧版本。

## 学员填写任务

### 第一步：写清业务目标

补全一句话：

> 当商家询问________时，系统应从________中找到________，并以________方式回答；如果没有可靠依据，则________。

参考：

> 当商家询问活动规则时，系统应从商家规则知识库中找到当前有效且适用于该商家的规则片段，并以简洁答案加依据的方式回答；如果没有可靠依据，则说明未找到并引导人工确认。

### 第二步：定义允许进入的知识

填写：

- 当前允许使用的文档；
- 权威来源；
- 负责人；
- 当前版本；
- 适用范围；
- 权限；
- 更新/下线规则。

### 第三步：补全升级后的路径

```text
用户问题
→ 意图分类
→ RULE
→ __________
→ __________
→ 判断依据状态
   ├─ 可靠依据 → __________
   ├─ 没有依据 → __________
   └─ 资料冲突 → __________
```

参考答案：

```text
→ 检索商家规则知识库
→ 返回候选片段并重排
→ 判断依据状态
   ├─ 可靠依据 → 基于片段回答并展示来源
   ├─ 没有依据 → 明确无答案，不使用模型常识补齐
   └─ 资料冲突 → 提示版本冲突并转知识负责人/人工
```

### 第四步：写出三条回答规则

建议：

1. 只根据检索到的知识片段回答；
2. 必须保留时间、范围和前提条件；
3. 无可靠依据或资料冲突时，不自行推断。

### 第五步：准备五条测试

至少覆盖：

- 直接命中；
- 同义表达；
- 跨段条件；
- 无答案；
- 新旧版本冲突。

## 两人互查清单

互相检查：

- 是否把实时数据误放进知识库；
- 是否说明了当前有效版本；
- 是否定义无答案；
- 是否定义冲突处理；
- 是否要求展示或记录依据；
- 是否保留上一课的其他三条路径。

## 老师收口

强调：

> 平台搭建只是把这张纸面方案运行起来。如果纸面上没有定义“没找到怎么办、冲突怎么办”，工具不会替产品经理自动做出正确业务决策。
