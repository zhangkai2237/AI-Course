## 一、本模块的作用

本模块不再增加新知识，只完成三件事：

1. 把整节课收束成四个可以复述的结论；
2. 说明课后只交一份完整产物，而不是多份零散作业；
3. 让学员知道作业怎样才算合格。

### 时间原则

只有3分钟，老师不能在此处重新解释Token、六要素或技术边界。详细作业说明应提前放入学员讲义或作业模板，课堂只说明任务、最低要求和截止方式。

## 三、整节课只带走四个结论

### 结论1：大模型是生成，不是固定查询

> 大模型会依据当前上下文逐步生成后续Token，因此同一输入可能得到不同结果；一次Demo不能证明稳定。

### 结论2：上下文是有限的任务工作区

> 用户输入、内部指令、历史对话和补充材料都会占用上下文。产品经理要选择必要、可靠、结构清楚的信息，而不是无差别堆料。

### 结论3：好Prompt来自清楚的产品定义

> 先定义谁在什么时点需要什么结果、怎样算可用，再反推输入、规则和输出；Prompt不是脱离需求的文案技巧。

### 结论4：Prompt产品化是让产品承担复杂度

> 固定要求由产品承载，变化信息通过字段收集，已有信息由系统自动获取，高风险结果由用户确认。

## 四、课后作业：完成一份Prompt产品化设计单

### 4.1 作业任务

从自己真实工作中选择一个适合文本类大模型辅助的具体场景，完成《Prompt产品化设计单》V1.0。

优先选择：

- 已经存在明确人工流程；
- 有相对清楚的输入材料；
- 知道结果交给谁使用；
- 能找到一条真实脱敏样例或构造合理的虚构样例；
- 一次任务可以在几分钟到几十分钟内完成。

不建议选择：

- “做一个万能企业Agent”；
- “用AI提升公司效率”；
- “做一个全能客服”；
- 同时包含十几个流程的大型平台；
- 必须使用公司敏感数据才能完成的题目。

### 4.2 可选场景示例

- 用户访谈记录整理；
- 客服对话问题归因；
- 需求反馈分类；
- 营销文案草稿；
- 合同要点提取；
- 周报信息汇总；
- 招聘面试记录整理；
- 项目风险和行动项提取。

示例只用于帮助选题，不代表所有场景都天然适合大模型。学员仍需说明使用者、输入和结果。

## 五、《Prompt产品化设计单》提交结构

### 第一部分：场景

1. 场景名称；
2. 目标用户；
3. 使用时点；
4. 当前人工任务；
5. AI结果之后的下一步动作。

### 第二部分：目标输出与验收

| 目标输出 | 怎样算合格 | 高风险错误 |
|---|---|---|
|  |  |  |
|  |  |  |

### 第三部分：上下文清单

| 信息 | 类型：事实/背景/规则 | 支持哪项输出 | 必需/按需 |
|---|---|---|---|
|  |  |  |  |
|  |  |  |  |

### 第四部分：结构化Prompt

按需要填写：

- 角色与能力；
- 任务目标；
- 业务背景与输入材料；
- 规则与约束；
- 输出格式与验收标准；
- 示例与迭代要求。

不要求为了完整而强行写满六项，但每一段都应能说明用途。

### 第五部分：产品化拆分

#### A. 信息供给

| 信息或规则 | 产品固定/用户提供/系统获取 | 产品承载或交互方式 |
|---|---|---|
|  |  |  |
|  |  |  |

#### B. 风险处理

必做版至少填写1项；进阶版补齐主要风险字段和后续动作。

| 输出字段或后续动作 | 主要风险 | 普通展示/建议检查/必须确认 | 证据、权限和交互方式 |
|---|---|---|---|
|  |  |  |  |
|  |  |  |  |

### 第六部分：一次测试和Bad Case

至少完成：

1. 使用一条脱敏或虚构样例运行Prompt；
2. 保存输入、Prompt和输出；
3. 找到至少一条不满意结果；
4. 判断它首先属于任务、上下文、规则、输出，还是已超出单次Prompt；
5. 提出下一次最小修改，不要求完成正式评测。

### 第七部分：技术边界判断

用一句话判断：

> 当前问题主要用Prompt和上下文能否解决？是否已经涉及私有知识、多步骤流程或外部系统动作？

不要求在本次作业中设计RAG、Workflow或Agent。

## 六、作业最低验收标准

### 合格必须满足

- [ ] 场景具体到“谁在什么时点完成什么任务”；
- [ ] 至少定义2项目标输出和可检查标准；
- [ ] 至少列出3类必要上下文；
- [ ] Prompt中的主要要求能对应任务、风险或输出；
- [ ] 能区分产品固定、用户提供和系统获取；
- [ ] 至少为1项高风险结果设计建议检查或必须确认；
- [ ] 至少运行1条样例并找到1条Bad Case；
- [ ] 提出一个具体修正动作；
- [ ] 不提交真实敏感数据、个人隐私或公司机密。

### 不合格的典型情况

- 只有一段从网上复制的Prompt；
- 选题是“万能助手”，没有具体用户和任务；
- 输出标准只有“专业、准确、高质量”；
- 把所有资料全部放进上下文，无法说明用途；
- 只展示一次满意结果，没有Bad Case；
- 产品方案仍要求用户每次填写完整Prompt；
- 使用未经脱敏的客户、员工或公司数据。

## 七、完全零基础学员的替代任务

### 适用对象

- 当前没有正式工作场景；
- 无法接触可脱敏的业务材料；
- 对所在行业流程还不了解；
- 第一次尝试结构化Prompt。

### 替代选题

任选一个低风险、容易获得材料的任务：

1. 公开访谈或公开视频字幕整理；
2. 一篇公开产品测评的优缺点提取；
3. 虚构用户反馈分类；
4. 个人学习笔记整理和行动计划提取；
5. 使用模块07的销售案例，但必须重新设计一个不同的目标输出。

### 对零基础的最低要求

不要求画完整界面，只需完成：

- 一个明确使用者和时点；
- 两项输出及验收标准；
- 一版结构化Prompt；
- 产品固定、用户提供和系统获取各至少一项；
- 至少选择1项高风险结果，说明应建议检查还是必须确认；
- 一条Bad Case及修改。

### 不建议的替代方式

- 直接复制老师的销售案例参考答案；
- 让模型替自己生成整份作业后不做检查；
- 为了显得复杂，主动加入RAG、Agent和MCP名词。
