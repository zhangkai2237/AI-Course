> 版本：V1.0

## 一、课程定位

本课解决的不是“如何上传一个文件”，而是：

> 当AI的回答必须基于企业内部知识、需要持续更新并提供依据时，产品经理如何判断是否使用RAG，如何设计知识来源、处理链路、产品边界和最小测试。

与前后课程的增量关系：

- 第02课：一次模型调用如何使用上下文与Prompt；
- 第03课：多类问题如何通过Workflow走不同路径；
- **第04课：知识型问题如何先检索企业知识，再基于证据生成；**
- 第05课：模型如何在目标约束下选择并调用工具。

## 四、本课程教学重组（T）

以下框架是基于来源重新组织的教学方法，不是任何参考课程的逐字原话：

1. **RAG双链路图**
   - 离线建库：知识采集 → 解析清洗 → 分块 → 元数据 → 向量化/索引；
   - 在线问答：用户问题 → 问题处理 → 检索 → 重排 → 增强Prompt → 生成 → 引用/兜底。
2. **知识治理六字段**
   - 来源、负责人、版本/生效时间、适用范围、权限、更新/下线规则。
3. **四种失败状态**
   - 没找到、找错了、资料冲突、找到了但模型答错了。
4. **五条最小测试**
   - 3条正常命中、1条无答案、1条版本冲突。
5. **三层产品边界**
   - 知识型问题走RAG；
   - 实时事实走业务系统；
   - 高风险争议走人工。

## 五、教学案例（CASE）

### 邻里增长平台商家规则知识库

案例完全虚构，沿用第03课商家咨询分流助手。

计划准备三份教学文档：

1. 《新客立减活动规则V2》：当前有效规则；
2. 《活动违规与申诉说明》：投诉与申诉边界；
3. 《新客立减活动规则V1_已失效》：故意与V2形成版本冲突。

课堂只升级`RULE`路径：

`用户问题 → 意图分类 → RULE → 检索商家规则知识库 → 判断是否有可靠依据 → 带依据回答/提示冲突/无答案`

其他路径保持：

- `DATA`：提示查询业务系统，不编造实时数值；
- `COMPLAINT`：转人工，不承诺赔付；
- `OTHER`：追问澄清。

## 六、本课明确不讲

- Embedding数学推导、向量维度和相似度公式；
- 六种以上分块算法的工程细节；
- Graph RAG、知识图谱、复杂混合检索调参；
- 大规模向量数据库选型和性能压测；
- RAG评估指标的完整公式体系；
- 真实公司文档上传和生产权限接入；
- 微调的完整方案；
- Agent自主规划和工具调用。

## 七、来源风险与纠偏

1. 录音转写中的`reg`统一理解为`RAG`，`process/prom put`按上下文理解为`Prompt`。
2. 不使用“RAG一定解决幻觉”“知识库决定80%效果”“统一召回率应达到某个百分比”等绝对化表达。
3. 知乎技术先导课的操作路径有较高时效性，课程固定“操作目标”，不固定按钮名称。
4. 亚慧课程技术细节较多，本课只保留产品经理能用于决策、沟通和验收的部分。

## 八、结论

本课有充分来源支撑，并与第03课形成直接的可见增量：上一课解决“问题走哪条路”，本课解决“知识型问题到哪里找依据、怎样安全回答”。新增知乎技术先导课让课程能够同时覆盖概念、Coze操作和RAG接入Workflow，亚慧材料则补齐企业级链路、治理和问题定位。
