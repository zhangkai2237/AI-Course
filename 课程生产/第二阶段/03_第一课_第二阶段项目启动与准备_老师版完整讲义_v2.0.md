# 第一课｜第二阶段项目启动与准备

> 文档用途：第二阶段第一课老师版完整授课讲义。  
> 建议时长：约70—90分钟，根据课堂互动自然调整。  
> 本课定位：讲清第二阶段怎样学习、为什么选择三个公共项目，以及学员可以从自己的业务中准备哪些个人项目方向。  
> 本课不要求：正式选题、写PRD、画原型、选择模型或开发产品。

---

# 第一节：第二阶段怎样学习

> 建议时长：15—20分钟

## 一、为什么进入第二阶段

第一阶段已经分别学习了AI产品经理常用的知识和方法，包括大模型、Prompt、Workflow、RAG、Agent、需求分析、MVP、PRD、原型、评测、Bad Case、模型选择、成本和ROI。

这些内容解决的是“每个知识点是什么、可以怎样使用”。第二阶段要解决另一个问题：

> 面对一个不完整的业务问题，能否把这些知识连续地用起来，形成一个可以解释、可以验证、可以修改的AI产品方案？

因此，第二阶段不再按照RAG、Workflow或者Agent分别组织课程。每次先面对一个真实业务问题，再判断需要使用哪些能力。

例如，一个企业智能客服项目可能同时需要：

- 大模型理解用户问题；
- 知识库提供产品和制度信息；
- 业务接口查询订单、账户或服务状态；
- 规则判断权限和办理条件；
- 工作流推动业务办理；
- 人工处理高风险和特殊情况。

产品经理需要做的，是根据业务问题安排这些能力，而不是为了使用某项技术寻找项目。

## 二、公共项目和个人项目

第二阶段包含三个公共项目和三个个人项目。

公共项目由老师在课堂上完整拆解。它为全班提供共同的业务材料、分析过程和判断标准，让学员看到一个项目怎样从业务问题逐渐发展为产品方案、核心页面和评测方法。

个人项目由每位学员独立完成。学员需要把公共项目中学到的方法迁移到自己的行业、经历或熟悉的业务中，重新定义用户、流程、材料、规则、风险和产品范围。

公共项目提供参照，个人项目证明学员能够独立迁移方法。学员不能只替换项目名称、行业名称和页面文案，就把公共项目当成自己的项目。

## 三、一轮项目怎样推进

每一轮项目按照同一节奏推进：

1. 老师完整讲解一个公共项目；
2. 每位学员独立完成自己的项目V0.1；
3. 固定的4—5人小组进行互评；
4. 小组提出最需要老师讲解的典型问题；
5. 老师集中点评代表项目；
6. 每位学员根据问题修改自己的项目，形成V1.0。

可以把这套机制概括为：

> 老师讲公共项目，个人完成V0.1，小组互评，老师点评，个人修改为V1.0。

小组不共同完成一个项目，也不拆分任务共同提交。每个人始终拥有自己的选题、材料和最终成果。小组的作用是帮助成员提前发现问题，让老师的课堂点评能够覆盖更多共性问题。

## 四、十次课的整体安排

| 课次 | 主要内容 |
|---|---|
| 第1课 | 第二阶段启动与项目准备 |
| 第2课 | 公共项目一：企业智能客服与业务办理 |
| 第3课 | 个人项目一点评与修改 |
| 第4课 | 公共项目二：业务材料审核与风险核验 |
| 第5课 | 个人项目二点评与修改 |
| 第6课 | 公共项目三：专业研究与方案生成 |
| 第7课 | 个人项目三点评与修改 |
| 第8课 | 选择一个主项目继续深化 |
| 第9课 | 作品集、简历和项目讲述 |
| 第10课 | 项目路演、验收与阶段总结 |

公共项目课可以根据项目复杂度讲到三小时。点评课的重点不是给作业打分，而是公开展示一个项目怎样发现问题、怎样修改，以及不同业务背景下为什么会做出不同选择。

## 五、第二阶段的最终成果

每位学员最终完成：

- 三个独立的个人AI产品项目；
- 从中选择一个项目继续做深；
- 一套能够放进作品集和简历的项目材料；
- 一套能够在面试中讲清项目背景、关键判断和修改过程的表达。

三个项目都要形成相对完整的产品方案，包括业务背景、用户、流程、材料、AI与规则分工、MVP、核心页面、测试和修改记录。但不要求三个项目都开发成生产级系统。

更合理的成果结构是：

> 三个完整项目方案，其中一个项目拥有更扎实的验证、迭代和作品集表达。

# 第二节：三个公共项目的选择逻辑

> 建议时长：10—15分钟

## 一、什么样的项目适合作为公共项目

课堂可以先请学员选择：

> 下面哪一项最适合作为全班共同学习的公共项目？

- A. 使用当前最热门的技术
- B. 项目名称听起来足够先进
- C. 业务流程、材料和判断标准比较清楚
- D. 容易快速做出一个好看的演示

老师的判断是C。

公共项目要让不同背景的学员建立共同的分析标准，所以需要满足四个条件：

1. 对应真实而常见的业务问题；
2. 能自然组合多种AI产品能力；
3. 业务材料、判断过程和异常情况可以展示；
4. 能迁移成多个行业和岗位中的个人项目。

## 二、为什么不按技术方向选择项目

如果按技术组织项目，课程容易变成“做一个RAG项目”“做一个Workflow项目”“做一个Agent项目”。但真实工作通常不会先确定技术，再寻找问题。

同一个项目可能同时使用模型、知识库、业务接口、规则、工作流和人工处理。产品经理真正需要判断的是：

- 当前业务问题是什么；
- 哪种能力适合解决其中哪一步；
- 哪些工作不应该交给大模型；
- 产品怎样进入原有业务流程。

因此，三个公共项目按照业务问题选择，而不是按照技术名词分课。

## 三、三个项目覆盖的业务问题

| 公共项目 | 主要处理对象 | 主要目标 | 重点能力 |
|---|---|---|---|
| 企业智能客服与业务办理 | 人提出的问题和办理请求 | 回答问题并推动服务完成 | 对话理解、知识和业务系统连接、流程闭环 |
| 业务材料审核与风险核验 | 合同、票据、申请等业务材料 | 发现缺失、差异和风险 | 信息提取、规则核验、语义判断、人工复核 |
| 专业研究与方案生成 | 复杂任务和多来源资料 | 形成研究、简报或解决方案 | 任务拆解、资料组织、来源核实、专业审阅 |

三个项目分别从“人提出请求”“材料进入流程”和“专业人员接受复杂任务”三个入口切入，覆盖企业服务、运营与风险控制、销售咨询研究和管理等多类工作。

## 四、为什么没有单独设置C端公共项目

这不代表C端项目不重要。

公共项目需要全班能够共享基本材料、理解共同流程，并使用相对一致的标准进行点评。很多C端产品的成败高度依赖真实用户、流量、用户行为数据、增长实验、留存和长期运营。课堂无法获得这些条件时，项目很容易只剩下一个好看的页面或演示。

三个公共项目虽然以可讲清业务过程的企业场景为主，但并不排斥C端：

- 电商售后助手、课程服务助手、医疗服务助手都直接面向个人用户；
- 有真实C端经验、用户或数据的学员，可以选择C端个人项目；
- 评价标准仍然是业务是否真实、材料是否可得、结果是否能够判断，而不是项目属于B端还是C端。

这一节最后可以收束为：

> 公共项目按照业务问题选择，技术能力根据项目需要进行组合。

# 第三节：三个公共项目与个人项目方向

> 建议时长：30—40分钟

这一节不展开三个项目的完整PRD。重点是让学员理解它们为什么值得学习、能够应用到哪些工作，以及自己可以从哪里切入。

讲解前可以提醒学员关注两个问题：

- 哪一类工作与自己的经历最接近？
- 哪一类项目的材料是自己可能获得的？

## 一、企业智能客服与业务办理

### 1. 项目定位

这个项目建立一个面向客户、员工或合作伙伴的统一服务入口。它既要理解用户的问题，也要连接知识、业务数据和办理流程，必要时把特殊情况交给人工。

它比普通聊天机器人更复杂的地方在于：回答问题只是入口，最终还要解决身份和权限、业务查询、条件判断、系统操作、异常处理和人工责任。

### 2. 可以应用的业务范围

#### 面向消费者

- 电商售后服务助手：查询订单、解释退换货政策，并发起售后流程；
- 在线教育学员服务助手：处理课程咨询、请假、补课、延期和退款；
- 银行业务办理助手：解答账户和信用卡问题，完成部分业务引导；
- 保险理赔服务助手：判断理赔类型、说明材料并查询进度；
- 医疗服务助手：提供科室选择、预约、检查准备和复诊提醒；
- 本地生活服务助手：处理预约、改期、退款和会员权益；
- 旅游出行服务助手：处理订单、退改政策和行程变化。

#### 面向企业客户和合作伙伴

- 企业软件客户服务助手：解答产品问题、查询服务权限并创建工单；
- 制造业设备售后助手：根据设备型号和故障现象提供排查和维修安排；
- 经销商服务助手：查询价格、库存、订单和返利规则；
- 供应商协同助手：查询采购要求、交货计划和结算状态；
- 大客户服务助手：处理交付、续费、增购和服务升级。

#### 面向企业内部

- 员工人事服务助手：解答考勤、休假、薪酬和福利问题；
- 企业IT服务助手：处理账号、权限、软件、设备和网络问题；
- 财务共享服务助手：回答报销、发票、付款和预算问题；
- 采购服务助手：查询采购申请、订单和供应商状态；
- 行政服务助手：处理会议室、访客、办公用品和设备借用。

这一方向适合客服、运营、售后、销售支持、人事、行政、IT、财务等背景的学员。

## 二、业务材料审核与风险核验

### 1. 项目定位

这个项目处理企业业务流程中的合同、票据、申请表、资质证明和检测报告等材料。系统需要提取关键信息，对照业务规则进行检查，发现材料之间的差异和风险，并把不确定或高风险的问题交给人工。

它的复杂度来自多份材料之间的对应关系，以及确定性规则、语义判断和人工责任之间的边界。产品还要能够说明风险来自哪里，方便审核人员回到原文确认。

### 2. 可以应用的业务范围

#### 财务与费用

- 员工报销审核助手：核对发票、报销单、行程和费用制度；
- 企业付款材料核验助手：检查合同、订单、验收单和发票是否一致；
- 预算申请审核助手：核对预算科目、历史支出和审批要求。

#### 合同与法务

- 合同条款审核助手：检查付款、违约、交付和数据安全等风险；
- 合同履约检查助手：检查交付、验收和付款条件是否满足；
- 企业制度合规检查助手：判断申请或操作是否符合内部制度。

#### 采购与供应商

- 供应商准入审核助手：核验营业执照、资质和准入条件；
- 采购申请审核助手：检查预算、询价材料和供应商选择；
- 招投标文件检查助手：检查响应内容、资质和材料缺项。

#### 金融与保险

- 企业开户材料审核助手：检查企业身份、股权结构和经营证明；
- 贷款申请材料预审助手：核对收入、资产、负债和资金用途；
- 保险理赔材料审核助手：核对保单、事故证明和费用凭证。

#### 人事、行政和公共服务

- 招聘入职材料审核助手：检查身份、学历、经历和入职文件；
- 项目申报材料预审助手：对照申报指南检查资格和附件；
- 政府办事材料预审助手：提交前检查条件和材料完整性；
- 质量检测报告核验助手：检查检测项目、数值、结论和签章；
- 内容发布合规检查助手：检查广告和公开材料中的风险表述。

这一方向适合财务、法务、采购、风控、人事、政务、金融、保险和质量管理背景的学员。

## 三、专业研究与方案生成

### 1. 项目定位

这个项目服务于销售、售前、产品、咨询、研究和管理等知识工作。系统需要理解复杂任务，拆解需要回答的问题，组织不同来源的材料，识别信息缺口和冲突，并形成可以由专业人员继续修改的研究或方案初稿。

它比普通写作助手更强调研究过程：资料从哪里来、哪些内容可以确认、哪些还需要核实、方案中的承诺由谁负责。

### 2. 可以应用的业务范围

#### 销售与售前

- 客户需求分析助手：整理访谈、需求文件和历史沟通；
- 大客户拜访准备助手：汇总客户背景、业务动态和合作历史；
- 企业解决方案生成助手：结合客户需求、产品能力和行业案例形成方案；
- 招标需求分析助手：拆解资格要求、技术要求和评分标准；
- 投标响应助手：将招标要求映射到产品能力和证明材料。

#### 产品与运营

- 竞品研究助手：整理功能、价格、用户评价和市场动作；
- 产品机会分析助手：结合反馈、客服记录和业务数据寻找机会；
- 产品规划助手：把战略目标、用户问题和业务约束整理为规划；
- 用户研究分析助手：汇总访谈、问卷和反馈，提炼需求；
- 运营活动方案助手：根据目标、用户和历史活动形成方案。

#### 行业与管理

- 行业研究助手：整理市场、产业链、竞争格局、政策和趋势；
- 市场进入分析助手：研究新地区或新行业的需求、竞争和风险；
- 政策研究助手：分析政策适用对象、影响范围和企业行动；
- 经营分析助手：汇总经营数据和部门反馈，分析问题；
- 战略规划助手：整理外部环境、企业能力和业务目标。

#### 专业服务

- 咨询项目研究助手：围绕客户问题组织访谈、数据和外部资料；
- 投资研究助手：汇总公司、行业、财务和风险信息；
- 课程研发助手：根据学习目标和参考资料设计课程；
- 培训方案助手：分析组织需求和能力差距，形成培训计划；
- 技术选型研究助手：对比技术方案、供应商、成本和实施风险。

这一方向适合产品、运营、销售、售前、咨询、市场、战略、研究、培训和管理岗位的学员。

## 四、从公共项目发展为个人项目

公共项目提供方法和共同标准。个人项目至少需要根据自己的业务重新确定五件事：

- 用户：谁在使用；
- 场景：在什么情况下遇到什么问题；
- 流程：现在怎样完成；
- 材料：有哪些业务数据、文档、规则和样本；
- 范围：第一版准备解决到什么程度。

只改项目名称、行业和页面颜色，仍然是复制公共项目。用户、流程、材料、规则、异常情况和测试问题发生变化，项目才真正进入自己的业务。

## 五、课堂互动

问题一：你的工作更接近哪一类？

- A. 回答问题、提供服务或办理业务
- B. 检查材料、核对规则或发现风险
- C. 搜集信息、研究问题或输出方案
- D. 暂时无法归类

问题二：你更容易获得哪一类材料？

- A. 常见问题、服务规则和业务记录
- B. 合同、票据、申请表和审核标准
- C. 客户需求、研究资料、历史报告和方案模板
- D. 暂时不确定

问题三：在刚才的项目变种中，哪一个与你的经历最接近？如果没有，可以写出一个属于自己的变种。

这一课只记录两三个可能方向，不要求正式选题。

# 第四节：第一课课后准备

> 建议时长：5—8分钟

第一课后不需要确定最终项目，也不需要写PRD。每位学员只完成两项准备。

## 一、盘点三个候选场景

从自己的工作、行业经验或目标岗位中，找到三个真实业务场景。每个场景简单回答：

- 谁在使用；
- 需要完成什么事情；
- 现在怎样完成；
- 主要问题是什么；
