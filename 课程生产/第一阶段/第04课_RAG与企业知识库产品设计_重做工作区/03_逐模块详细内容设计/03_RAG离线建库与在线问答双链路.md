# 03 RAG离线建库与在线问答双链路（23-43分钟）

## 教学目标

让零基础学员看懂RAG全流程，并能说明某个问题发生在“建库阶段”还是“问答阶段”。

## 总体结构

RAG不是一条线，而是两条在检索点汇合的链路。

### 链路A：离线建库

```text
知识采集
→ 文档解析与清洗
→ 分块
→ 补充元数据
→ 向量化/建立索引
→ 可检索知识库
```

### 链路B：在线问答

```text
用户问题
→ 问题理解/改写
→ 选择知识源
→ 检索相关片段
→ 重排
→ 组装增强Prompt
→ 大模型生成
→ 引用、拒答或转人工
```

## 离线建库逐步解释

### 1. 知识采集

确定哪些材料允许进入知识库，例如制度、规则、FAQ、产品手册。

产品经理先回答：

- 谁会用；
- 要回答什么问题；
- 哪些文档是权威来源；
- 哪些内容不能进入。

### 2. 文档解析与清洗

PDF、Word、表格、网页和图片结构不同，需要先提取正文、标题、表格和必要的层级信息。

常见问题：

- 扫描PDF没有正确OCR；
- 页眉页脚被重复提取；
- 表格列关系丢失；
- 标题和正文混在一起；
- 失效说明没有被识别。

本课不讲解析算法，但要让学员知道“上传成功”不等于“内容解析正确”。

### 3. 分块

长文档会被切成若干可检索片段。片段需要：

- 能独立理解；
- 保留必要上下文；
- 不把条件和结论拆开；
- 不把不同主题混在同一块。

### 4. 元数据

除了正文，还应保存：

- 文档名称；
- 章节；
- 版本；
- 生效时间；
- 适用对象；
- 权限标签；
- 来源链接或文档ID。

元数据既帮助过滤和治理，也帮助最终引用。

### 5. 向量化与索引

课程只保留产品层解释：

> 系统把片段转换成便于比较语义关系的表示，并建立可快速查找的索引。

不需要推导向量维度或相似度公式。学员需要知道它让“不同说法、相近意思”有机会互相命中。

## 在线问答逐步解释

### 1. 问题理解/改写

用户问题可能模糊、带上下文或包含多个意图。系统可以先：

- 补全上下文；
- 抽取关键词和实体；
- 把口语问题改成更适合检索的表达。

这是可选优化，不是每个最小RAG都必须有。

### 2. 选择知识源

如果有多个知识库，需要判断去哪一个。例如活动规则、产品说明、申诉制度可能分别维护。

上一课Workflow可以先完成路由，本课不让RAG跨越全部业务边界。

### 3. 检索

从知识库中找回若干相关片段。检索结果是候选依据，不等于最终答案。

### 4. 重排

把更符合当前问题的片段放到前面，减少无关内容占用上下文。

### 5. 增强Prompt

系统把以下内容组合起来：

- 用户问题；
- 检索到的片段；
- 回答规则；
- 输出格式；
- 无依据时的处理方式。

### 6. 生成与产品处理

大模型基于检索内容组织答案，产品层再决定：

- 是否显示引用；
- 是否提示版本；
- 是否暴露冲突；
- 是否拒答；
- 是否转人工；
- 是否记录反馈。

## 一次问题定位演示

问题：“活动什么时候结束？”

四种结果：

1. 没检索到V2规则 → 检索或知识问题；
2. 检索到了V1，没有V2 → 版本/过滤问题；
3. 同时检索到V1和V2 → 冲突处理问题；
4. 检索到V2，但回答日期仍错误 → 生成问题。

用这个例子强调：

> 只看最终答案，无法知道应该改知识、改检索、改Prompt还是改产品策略。

## 产品经理需要掌握到什么程度

必须掌握：

- 每个环节的输入和输出；
- 哪些地方可能失败；
- 哪些结果需要记录；
- 如何设计样本验收；
- 何时找算法、数据、后端或运营协作。

不要求：

- 自己实现Embedding模型；
- 自己编写向量数据库；
- 推导检索公式；
- 调优全部算法参数。

## 衔接

理解流程后还不够。企业RAG最容易被忽略的并不是模型，而是“谁提供知识、哪个版本有效、谁能看”。
