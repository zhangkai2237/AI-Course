# 第八课第三部分讲义：先用低保真结构验证方案

> 建议时长：18 分钟  
> 本部分目标：把已经确认的用户任务、页面和流程，转换成可以评审的页面结构。

## 一、为什么不能直接进入高保真

第二部分已经回答了三个问题：用户要完成什么任务、需要哪些页面、怎样走完流程。

但页面里还有四个问题没有解决：

1. 信息放在哪里；
2. 用户先看到什么；
3. 核心操作是否容易发现；
4. 规则和异常在页面上如何被观察。

低保真原型就是用最低的视觉成本验证这些结构问题。

核心句：

> 低保真不是简陋的高保真，而是专门用来暴露结构问题的验证工具。

---

## 二、低保真阶段只检查四件事

### 1. 页面是否支持用户完成任务

商品选择页必须支持选择具体 SKU；底部对比栏必须让用户看见已选数量；商品对比页必须帮助用户识别差异。

### 2. 信息层级是否符合决策顺序

用户先确认比较的是哪些商品，再查看核心参数，最后根据需要展开全部参数。不能把全部信息同时堆在首屏。

### 3. 关键操作是否容易发现

加入对比、进入对比、只看差异、展开参数、删除和替换，都要有明确位置。

### 4. 规则是否有对应的页面证据

“最多4个”“参数缺失”“参数冲突”“价格有条件”等产品规则，必须在页面中找到提示、标记或操作反馈的位置。

低保真阶段暂不讨论：

- 品牌色和插画；
- 阴影、圆角和动效；
- 最终营销文案；
- 完整技术实现。

---

## 三、三个核心界面的信息架构

### 商品选择页

- 当前商品与具体 SKU；
- 加入对比入口；
- 已加入状态；
- 跨类目和数量上限提示；
- 返回或继续浏览入口。

### 底部对比栏

- 已选商品缩略信息；
- 当前数量；
- 删除入口；
- 进入对比按钮；
- 少于2个商品时的提示。

### 商品对比页

1. 返回入口与页面标题；
2. 商品固定区；
3. 活动价与优惠条件；
4. 核心参数、全部参数和只看差异；
5. 参数分组与参数值；
6. 缺失、冲突和来源说明；
7. 删除、替换与反馈入口。

页面信息架构的判断原则是：

> 先支持任务，再组织信息；先保证理解，再追求视觉完成度。

## 四、课堂演示：让 Codex 生成灰度低保真原型

本轮可以开始生成一个单文件 HTML，但只用于验证结构，不把它当作最终 Demo。

### Prompt 示例

```text
请读取以下正式材料：

1. 商品对比工具最终PRD；
2. 产品决策记录；
3. 用户任务与页面清单；
4. 核心用户流程；
5. 待确认交互决策。

请为商品对比工具一期生成一个灰度低保真原型。

交付要求：

- 使用原生HTML、CSS和JavaScript；
- 所有代码放在prototype/low-fi.html；
- 不使用外部框架，不安装依赖；
- 只实现商品选择页、底部对比栏和商品对比页；
- 使用灰度、线框和文字占位，不做品牌色、插画、阴影和复杂动效；
- 页面可以点击，用于验证核心流程；
- 使用本地模拟数据，不连接后端；
- 不得增加PRD没有确认的功能。

低保真原型必须表达：

1. 选择具体SKU并加入对比；
2. 已选商品和2至4个数量规则；
3. 进入商品对比页；
4. 核心参数、全部参数和只看差异；
5. 价格优惠条件；
6. 参数缺失与参数冲突的呈现位置；
7. 删除、替换和返回路径。

请先输出页面信息架构和你准备实现的交互，不要立即写代码。
如果发现材料冲突或缺失，请列出问题并停止，不要自行扩大范围。
我确认后，再生成prototype/low-fi.html并启动本地预览。
```

## 五、如何评审低保真原型

评审时不讨论“好不好看”，只回答四个问题：

1. 用户能否完成核心任务；
2. 关键操作是否容易找到；
3. 产品规则是否有页面证据；
4. 失败或返回后是否能继续操作。

建议记录格式：

| 页面或位置 | 结构问题 | 对用户的影响 | 修改要求 |
|---|---|---|---|
|  |  |  |  |

修改指令必须说明当前问题、期望结果和保持不变的内容，避免让 AI 重新生成整个原型。
