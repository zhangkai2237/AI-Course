## 1. 项目背景与问题定义

### 1.1 已确认事实

- 近30天手机详情页有684,000名去重访问用户，其中39.2%在同一天浏览过3个及以上不同手机SPU，即约268,128人存在多商品浏览行为。
- 多商品浏览用户平均发生6.8次详情页切换和4.4次列表页返回，但该行为不能直接等同于“用户一定在对比商品”。
- 21名受访者中，12人会使用截图、备忘录或多个标签页辅助比较；15人认为单纯罗列全部参数帮助有限；9人希望优先看到差异。
- 手机核心参数完整率约82%，全部参数完整率约71%；同义字段未统一、单位不统一、来源冲突等问题客观存在。
- 当前系统已有商品详情、价格、库存和参数接口，但没有专门的对比字段接口，也没有可直接使用的核心参数配置后台。

### 1.2 核心问题

普通换机用户在2—4款候选手机之间决策时，需要反复切换详情页、手工记录参数和优惠条件。信息分散、字段口径不一致以及价格条件复杂，使用户难以快速识别候选商品之间真正影响决策的差异。

### 1.3 证据边界

- 现有数据只能证明“多商品浏览和手工比较行为存在”，不能证明详情页切换是转化下降的唯一原因。
- 同日浏览3个以上SPU用户的转化数据不能直接用于推导商品对比工具一定提升转化。
- 因此一期的直接目标是提升比较任务的完成效率；加购和下单转化只作为观察指标，不作为确定性承诺。

## 2. 产品目标与成功标准

### 2.1 一期唯一主目标

帮助普通换机用户在一个页面内完成2—4款候选手机的结构化比较，优先识别价格、核心参数和缺失/冲突信息之间的差异，减少为完成比较而反复切换商品详情页的成本。

### 2.2 非目标

- 不替用户判断“哪款最好”或直接给出购买推荐；
- 不承诺统一计算个人最终到手价；
- 不解决企业采购、批量询价或5款以上商品比较；
- 不在一期解决全平台全部品类的字段标准化；
- 不以一期功能直接承诺提升成交转化。

### 2.3 指标体系

| 层级 | 指标 | 定义 | 用途 |
|---|---|---|---|
| 主指标 | 有效对比完成率 | 进入对比页且成功加载至少2个SKU后，触发“只看差异”“展开全部参数”“返回商品详情”或“去购买”任一有效行为的会话数 ÷ 成功加载至少2个SKU的对比会话数 | 判断用户是否完成了有效比较 |
| 过程指标 | 对比发起率 | 点击“开始对比”的去重用户数 ÷ 看到有效对比入口且满足可添加条件的去重用户数 | 判断入口与需求匹配度 |
| 效率指标 | 对比过程中详情/列表返回次数 | 从首次加入对比到退出对比会话期间的详情页和列表页返回次数 | 观察信息切换成本是否下降 |
| 质量指标 | 核心字段有效展示率 | 正常展示或明确展示“暂无数据/数据有冲突”的核心字段单元格数 ÷ 应展示核心字段单元格数 | 防止以隐藏问题换取表面完整 |
| 观察指标 | 对比后加购率 | 完成有效对比后24小时内加购任一被比较SKU的用户数 ÷ 有效对比用户数 | 仅观察，不作为一期主成败标准 |
| 观察指标 | 对比后下单转化率 | 完成有效对比后14天内购买任一被比较SKU的用户数 ÷ 有效对比用户数 | 需实验设计支持，不能直接归因 |

> 产品决策：课程Demo以功能验收和任务可完成性为成功标准，不虚构真实上线目标值。真实上线前，数据负责人须补充埋点基线、样本量和目标阈值。

### 2.4 第8课Demo通过标准

第8课Demo只有同时满足以下条件，才视为正确实现本PRD：

1. 本文18条验收用例全部通过；
2. “添加2款并开始对比”“只看差异”“删除/替换后本地恢复”三条主任务均可独立完成；
3. SKU重复、超过4款、参数缺失、缺货和价格条件至少各有一个可演示样例；
4. 页面不出现AI推荐、最佳商品结论、虚构到手价或跨设备保存暗示；
5. 所有本地模拟状态均明确标注，不让学员误认为真实接口已经接入。

## 3. 目标用户与核心场景

### 3.1 目标用户

一期核心用户为正在比较2—3款手机的普通个人消费者，典型特征包括：

- 已经形成候选商品，但对专业参数理解有限；
- 需要快速判断候选商品的主要差异；
- 关注活动价格，但不一定能理解优惠券、会员价和以旧换新的适用条件；
- 可能使用截图、备忘录或反复切换页面辅助比较。

### 3.2 核心用户故事

> 作为一名正在更换手机的普通消费者，我希望把2—4个具体配置的候选手机放在同一页面中，先看到价格和核心参数差异，再按需展开全部参数，以便在不反复切换详情页的情况下缩小选择范围。

### 3.3 核心任务链路

1. 用户在手机详情页选择具体SKU；
2. 点击“加入对比”，商品进入底部对比栏；
3. 用户点击“继续添加”，进入候选商品选择页并添加其他同类SKU；
4. 达到2个SKU后点击“开始对比”；
5. 系统默认展示核心参数并突出差异；
6. 用户可切换“只看差异”、展开全部参数、删除或替换商品；
7. 用户返回商品详情或前往购买。

## 4. 一期范围

### 4.1 范围内

| 维度 | 一期决策 |
|---|---|
| 品类 | 手机，仅允许同一三级类目内比较 |
| 终端 | 移动端H5；桌面端仅要求基本可访问，不做专项适配 |
| 主入口 | 手机详情页中，用户选择具体SKU后的“加入对比” |
| 添加候选 | 通过对比栏“继续添加”进入候选商品选择页 |
| 对比对象 | SKU，即具体配置与颜色的可购买商品 |
| 数量 | 最少2个、最多4个SKU |
| 登录 | 未登录即可使用 |
| 保存 | 同一浏览器本地临时保存24小时 |
| 默认视图 | 核心参数视图，差异项视觉突出 |
| 筛选 | 支持“只看差异” |
| 全部参数 | 支持按分组展开并按需加载 |
| 数据异常 | 明确展示缺失、冲突、更新时间和来源信息 |

### 4.2 范围外

- 跨三级类目比较；
- 5个及以上商品同时比较；
- AI推荐、自动生成购买结论或“最佳商品”标签；
- 账号云端保存、跨设备同步和历史对比管理；
- 分享链接、多人协作和导出；
- 企业采购、批量询价、发票与供货周期能力；
- 跨店铺Offer比较和个人专属到手价计算；
- 平板、电脑、家电等其他品类；
- 新建完整的类目参数配置后台。

## 6. 核心业务规则

### 6.1 对比对象与唯一性

1. 对比对象唯一键为`sku_id`。
2. 用户必须先选择具体规格后才能加入对比；仅有SPU、没有SKU时禁止加入。
3. 相同`sku_id`不得重复加入；再次添加时保持原列表不变并提示“该商品已在对比中”。
4. 同一`spu_id`下的不同SKU允许比较，商品列必须同时展示型号、配置和颜色，避免用户误认。
5. 一期比较的是平台统一SKU，不处理不同店铺Offer之间的同款比价。
6. 仅允许手机三级类目内比较；不满足条件时拒绝添加并说明原因。

### 6.2 数量规则

| 当前数量 | 行为 |
|---|---|
| 0个 | 对比栏不展示 |
| 1个 | 可继续添加；“开始对比”禁用，并提示“至少选择2款商品” |
| 2—3个 | 可开始对比，也可继续添加 |
| 4个 | 可开始对比；“继续添加”禁用并提示“最多比较4款商品” |
| 尝试添加第5个 | 不改变已有列表，提示先删除或替换商品 |

### 6.3 商品顺序

- 默认按加入顺序从左到右展示；
- 删除商品后，其余商品保持相对顺序；
- 一期不支持拖拽排序；
- 从对比页返回详情后再返回，对比顺序不变。

### 6.4 参数归一化与差异判断

1. 差异判断必须在字段名、单位和值完成标准化后进行。
2. 数值字段转换为统一单位后比较，例如重量统一为`g`、电池容量统一为`mAh`。
3. 枚举和文本字段使用标准值比较；仅文案大小写、空格或同义词差异不视为商品差异。
4. 同一字段的全部SKU值相同，标记为“相同”。
5. 至少两个有效值不同，标记为“差异”。
6. 部分SKU有值、部分SKU缺失，也标记为“差异”，缺失项显示“暂无数据”。
7. 全部SKU均缺失的字段不在核心参数视图展示；在全部参数视图中默认隐藏。
8. “只看差异”开启后，仅保留规则5或规则6命中的字段；商品基础信息和价格区始终保留。
9. 系统不得根据相邻字段、商品名称或AI推断缺失参数。

### 6.5 数据来源与冲突

显示值采用以下优先级：

1. 平台标准属性；
2. 品牌方结构化数据；
3. 商家填写数据；
4. 历史迁移数据。

当多个来源值不一致时：

- 按优先级展示当前值，并标记“数据有冲突”；
- 用户点击标记可查看数据来源与最近更新时间；
- 提供“反馈数据问题”入口；
- 不得静默选择来源，也不得由系统猜测正确值。

### 6.6 价格与优惠口径

1. 展示划线价`list_price_cny`、当前活动价`sale_price_cny`和优惠条件`promo_note`。
2. 活动价必须标注“活动价”，并展示数据更新时间。
3. 登录后才能确认的会员价、用户券、以旧换新补贴等，不纳入统一价格计算。
4. 不生成“到手价”字段；优惠条件存在时提示“实际价格以结算页及用户资格为准”。
5. 活动价缺失或失效时展示划线价，并提示“活动信息暂不可用”。
6. 价格接口部分失败时，其余参数继续展示；失败商品的价格单元格提供重试。
7. 去购买前如价格发生变化，以商品详情或结算页最新结果为准。

### 6.7 库存与商品状态

- 有货：允许加入、比较和去购买；
- 缺货：允许比较，显示“暂时缺货”，去购买按钮禁用；
- 下架：未加入时禁止新增；已在本地列表中的下架SKU保留商品列并标记“商品已下架”，允许删除或替换；
- 状态未知：显示“库存状态暂不可用”，允许查看参数但去购买前必须重新校验。

### 6.8 匿名本地保存

1. 保存内容仅包含SKU ID列表、加入顺序和最近更新时间，不保存账号、价格快照或个人信息。
2. 同一浏览器、同一站点下，刷新或关闭后24小时内重新打开可恢复候选列表。
3. 每次增删或替换商品后刷新保存时间；超过24小时自动清空。
4. 用户清理浏览器数据、使用无痕模式或禁用本地存储时，状态可能丢失；系统不得承诺恢复。
5. 登录前后的本地列表不自动上传、不跨设备同步，也不与账号历史合并。
6. 本地数据损坏或包含无效SKU时，忽略无效项并保留可恢复项，同时给出一次轻提示。

| 分组 | 字段 | 数据字段 | 展示规则 |

## 8. 功能需求

### FR-01 详情页加入对比

- 用户选择具体SKU后，“加入对比”按钮可用；
- 未选择完整规格时点击，定位规格选择区并提示先选择配置；
- 加入成功后按钮变为“已加入”，底部对比栏出现；
- 重复添加、跨类目、下架或超过上限时按业务规则处理。

### FR-02 对比栏管理

- 展示已选SKU的缩略图/占位图、型号和配置；
- 支持删除单个SKU；
- 支持“继续添加”；
- 根据数量控制“开始对比”的可用状态；
- 用户删除最后一个SKU后，对比栏关闭并清空本地状态。

### FR-03 候选商品选择

- 仅展示同一手机三级类目下的候选；
- 商品卡展示品牌型号、具体配置、活动价和库存状态；
- SKU规格未确定时必须先选择规格；
- 已加入商品展示“已加入”，不能重复添加；
- 达到4个后其他加入按钮禁用。

### FR-04 对比页核心视图

- 顶部固定展示2—4个商品列；
- 默认先展示商品基础信息、价格和核心参数；
- 差异单元格采用统一视觉标记，但不使用“更好/更差”结论；
- 商品名称过长时最多两行，并保证配置信息可识别；
- 移动端支持横向查看商品列，字段名区域保持可识别。

### FR-05 只看差异与全部参数

- “只看差异”默认关闭，用户状态在本次会话内保留；
- 开启后按6.4规则过滤字段；
- “全部参数”按分组展开并按需加载；
- 加载失败时保留核心参数，失败分组可单独重试。

### FR-06 删除与替换

- 对比页支持删除商品；
- 删除至1个时留在页面并显示“再添加1款即可对比”，差异视图不可用；
- “替换商品”打开候选选择页，选择成功后保持原列位置；
- 替换操作同样受类目、重复和数量规则约束。

### FR-07 数据异常呈现

- 缺失值统一显示“暂无数据”；
- 冲突值标注“数据有冲突”，可查看来源；
- 接口失败区分整页失败、单商品失败和单模块失败；
- 任何异常不得用推测值补齐。

### FR-08 数据问题反馈

- 入口位于冲突/缺失提示附近；
- 自动携带SKU ID和字段名；
- 问题类型包括：参数缺失、参数错误、价格异常、商品规格不一致、其他；
- 用户可补充不超过200字说明；
- 匿名用户可提交，不要求填写手机号等个人信息；
- 提交成功给出确认，失败保留填写内容并支持重试。

### FR-09 返回详情与去购买

- 点击商品头部可返回对应SKU详情页；
- 有货商品提供“查看商品/去购买”动作；
- 进入详情页前重新获取价格与库存，比较页数据不作为交易承诺；
- 缺货或下架商品不提供可用购买按钮。

## 9. 页面状态与异常处理

| 状态 | 触发条件 | 页面行为 |
|---|---|---|
| 初始态 | 无候选SKU | 不显示对比栏；详情页显示加入入口 |
| 单商品态 | 仅1个SKU | 显示继续添加；开始对比禁用 |
| 可对比态 | 2—3个SKU | 开始对比与继续添加均可用 |
| 满额态 | 4个SKU | 可开始对比；继续添加禁用 |
| 核心加载中 | 进入对比页 | 商品头和字段骨架屏；防止重复提交 |
| 全量成功 | 所有核心数据加载完成 | 正常展示并计算差异 |
| 单商品失败 | 某SKU接口失败 | 保留其他列，失败列显示重试与删除 |
| 价格失败 | 价格模块失败 | 参数继续展示；价格区显示重试 |
| 全部参数失败 | 懒加载失败 | 核心区不受影响；失败分组可重试 |
| 空差异态 | 开启只看差异后无差异字段 | 提示“当前字段暂无明显差异”，可关闭筛选 |
| 本地恢复态 | 24小时内读取到有效列表 | 恢复顺序；对失效SKU单独提示 |
| 整页失败 | 核心接口均不可用 | 显示错误说明、重试和返回入口 |

## 11. 非功能要求

### 11.1 性能

- 单次最多请求4个SKU；价格和核心参数允许并行请求；
- 首屏优先返回商品头、价格和核心参数；全部参数按需加载；
- 单模块失败不得拖垮整页；
- 避免因重复点击发起重复请求；
- 真实上线性能阈值需结合现有价格接口P95约320ms和聚合接口方案由技术评审确认。

### 11.2 可用性与无障碍

- 差异不能只依赖颜色表达，需同时使用文字、图标或底纹；
- 关键按钮需有明确禁用原因；
- 长商品名、长优惠文案和缺失字段不能破坏表格对齐；
- 移动端触控区域满足基本可点击性，横向滚动时字段归属清晰。

### 11.3 安全与合规

- 不宣称“最低价”“最佳”“最值得买”等无证据结论；
- 价格、促销和库存必须展示条件或更新时间；
- 匿名本地保存不存储个人信息；
- 数据反馈说明中如出现个人信息，真实上线前需按平台内容安全规则处理。

## 12. 验收标准

### AC-01 正常加入并开始对比

**Given** 用户在手机详情页已选择一个有效且有货的SKU  
**When** 用户点击“加入对比”，再添加另一个同类SKU并点击“开始对比”  
**Then** 系统进入对比页，按加入顺序展示2个SKU及核心参数。

### AC-02 未选择具体规格

**Given** 用户停留在手机SPU详情页但尚未选择完整规格  
**When** 用户点击“加入对比”  
**Then** 系统不添加商品，定位规格选择区域并提示先选择具体配置。

### AC-03 重复SKU

**Given** 某`sku_id`已在对比列表中  
**When** 用户再次添加同一`sku_id`  
**Then** 列表数量和顺序不变，并提示“该商品已在对比中”。

### AC-04 同SPU不同SKU

**Given** 列表中已有某型号的12GB+256GB SKU  
**When** 用户添加同一SPU下12GB+512GB SKU  
**Then** 系统允许加入，并在两列清楚展示不同配置与颜色。

### AC-05 不足2个商品

**Given** 对比栏仅有1个SKU  
**When** 用户查看“开始对比”按钮  
**Then** 按钮禁用，并提示至少再添加1款商品。

### AC-06 超过4个商品

**Given** 对比栏已有4个SKU  
**When** 用户尝试添加第5个SKU  
**Then** 系统拒绝添加，已有列表不变，并提示先删除或替换商品。

### AC-07 跨类目添加

**Given** 对比栏中已有手机SKU  
**When** 用户尝试添加非同一三级类目的商品  
**Then** 系统拒绝添加，并提示仅支持同类手机比较。

### AC-08 只看差异

**Given** 对比页同时存在相同字段、不同字段和有值/缺失字段  
**When** 用户开启“只看差异”  
**Then** 相同字段被隐藏，不同字段及有值/缺失字段保留，商品头和价格区仍展示。

### AC-09 参数缺失

**Given** 某SKU的充电功率无可信数据  
**When** 对比页展示充电功率行  
**Then** 该单元格显示“暂无数据”，系统不推测或补齐数值。

### AC-10 参数冲突

**Given** 某字段的平台标准值与商家填写值冲突  
**When** 用户查看该字段  
**Then** 页面按来源优先级展示当前值、标记“数据有冲突”，并可查看来源和反馈问题。

### AC-11 价格条件

**Given** 某SKU存在活动价和带资格限制的优惠说明  
**When** 页面展示价格  
**Then** 分别展示活动价、优惠条件和更新时间，不计算或宣称统一到手价。

### AC-12 价格接口失败

**Given** 核心参数成功但价格接口失败  
**When** 页面加载完成  
**Then** 参数区可正常使用，价格区显示失败说明和单独重试入口。

### AC-13 缺货与下架

**Given** 已加入列表的SKU变为缺货或下架  
**When** 用户重新打开对比页  
**Then** 系统保留可用参数，明确标记状态，禁用购买并支持删除或替换。

### AC-14 本地恢复

**Given** 匿名用户已选择3个SKU且距离最后操作未超过24小时  
**When** 用户在同一浏览器重新打开页面  
**Then** 系统按原顺序恢复3个SKU；登录状态变化不触发云端同步。

### AC-15 本地数据失效

**Given** 本地列表超过24小时或包含无效SKU  
**When** 页面读取本地状态  
**Then** 过期列表被清空；无效SKU被忽略，其他有效SKU仍可恢复。

### AC-16 单商品加载失败

**Given** 4个SKU中有1个基础信息请求失败  
**When** 对比页完成加载  
**Then** 其余3个SKU正常展示，失败列提供重试、删除和替换，不出现推测数据。

### AC-17 全部参数懒加载失败

**Given** 核心参数已加载成功  
**When** 用户展开全部参数但请求失败  
**Then** 核心参数保持可用，失败分组显示重试，不刷新或清空整页。

### AC-18 数据反馈

**Given** 用户在缺失或冲突字段点击“反馈数据问题”  
**When** 用户选择问题类型并提交  
**Then** 系统自动携带SKU与字段，成功后给出受理提示；失败时保留输入并允许重试。

## 13. 依赖、风险与上线前待确认

### 13.1 关键依赖

- 类目字段映射与核心参数清单可由配置或静态映射提供；
- 商品详情、价格、库存接口支持最多4个SKU的聚合调用；
- 参数元数据可返回来源、更新时间和冲突标识；
- 数据反馈有可接收的服务或工单入口；
- 埋点平台可串联匿名会话与后续加购/下单行为。

### 13.2 主要风险与应对

| 风险 | 影响 | 一期应对 |
|---|---|---|
| 核心参数缺失 | 用户误以为商品不具备该能力 | 显示“暂无数据”，不推测，提供反馈 |
| 多来源冲突 | 用户不信任对比结果 | 展示冲突、来源与更新时间 |
| 价格条件复杂 | 用户误解活动价为最终价 | 拆分价格与条件，增加结算页提示 |
| 4列移动端拥挤 | 阅读困难 | 核心字段优先、横向查看、全部参数懒加载 |
| 本地状态丢失 | 用户认为保存失效 | 明确“本地临时保存”及24小时边界 |
| 指标被错误归因 | 将转化变化全部归于工具 | 主看任务完成效率，转化仅观察并配合实验 |

### 13.3 真实上线前必须确认

以下事项不阻塞第8课原型与Demo，但阻塞真实产品上线：

1. 指标基线、目标值、实验分流、样本量和观察周期；
2. 核心参数映射的维护责任人与更新机制；
3. 价格、库存、反馈接口的真实字段、错误码与负责人；
4. 性能SLA、降级缓存策略和监控告警；
5. 活动价及优惠文案的业务与法务审核口径；
6. 匿名埋点、本地存储和反馈内容的数据合规评审；
7. 上线范围、灰度计划、回滚条件和客服说明。

## 14. 第8课Demo实现边界

为保证课程演示稳定，第8课可使用`08-商品样例数据_标准化.csv`生成纯前端HTML Demo，并模拟以下能力：

- 6个候选SKU中选择2—4个；
- 重复、上限、缺失字段、缺货与促销条件状态；
- 核心参数、只看差异和全部参数；
- 删除、替换、本地24小时保存与恢复；
- 数据反馈提交成功/失败的界面状态。

Demo中的价格更新时间、接口延迟、反馈提交和去购买均为本地模拟，不代表真实服务已经接入。Demo不得擅自增加AI推荐、最佳商品结论、账号同步或跨品类比较。

标准化CSV未直接提供但Demo必需的辅助字段，统一使用以下教学夹具，不得由生成工具自由发挥：

| 辅助字段 | Demo固定规则 |
|---|---|
| `category_id` | 6个正式商品样例固定为`phone`；另设1个`TEST_TABLET_001`非手机负向测试夹具，只用于验证跨类目拒绝，不进入正常商品列表 |
| `price_updated_at` | 使用Demo启动时生成的本地时间，并标注“模拟更新时间” |
| 商品图片 | 使用统一占位图或纯色设备示意，不抓取真实商品图 |
| 参数来源 | 默认标记为“课程标准化样例数据” |
| 冲突样例 | 可为一个字段注入两条模拟来源，但必须显示“模拟冲突” |
| 反馈结果 | 仅在前端模拟成功/失败，不向真实服务发送数据 |
