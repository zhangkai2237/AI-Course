# 06 纸面设计RAG V0.1｜老师版讲义（73-83分钟）

## 短休息后的开场

> 接下来先不打开工具。请先把知识从哪里来、怎么走、找不到怎么办写清楚。平台只能运行你的方案，不能替你补齐业务规则。

发放《RAG设计与测试单》和三份教学文档简介。

## 73-75分钟：讲清案例

沿用“邻里增长平台商家咨询分流助手”。强调全部为教学虚构。

三份材料：

1. 当前有效的《新客立减活动规则V2》；
2. 当前有效的《活动违规与申诉说明》；
3. 已失效的《新客立减活动规则V1》。

初始纸面设计先把V1标为不应进入当前有效检索范围，后面平台环节再故意导入制造冲突。

## 75-79分钟：学员个人填写

要求填四块：

### 业务目标

当什么用户问什么问题时，从哪里找什么依据，如何回答，找不到怎么办。

### 知识治理

至少填来源、负责人、版本、生效范围、权限和下线方式。

### 升级路径

```text
RULE
→ 检索指定知识库
→ 返回并排序候选片段
→ 判断依据状态
→ 回答/无答案/冲突
```

### 三条回答规则

建议答案：

1. 只根据检索片段回答；
2. 保留日期、范围和前提；
3. 没有依据或存在冲突时不自行推断。

老师巡视时先查边界，不先查术语。

## 79-81分钟：两人互查

互查问题：

- 有没有把实时门店数据放进知识库；
- 有没有当前有效版本；
- 有没有无答案；
- 有没有冲突策略；
- 有没有依据；
- 有没有误改其他三条Workflow路径。

## 81-83分钟：公布参考图

展示：

```text
RULE
→ 商家规则知识库
→ 检索候选片段
→ 有可靠依据？
   ├─ 是 → 基于依据回答并显示来源
   ├─ 否 → 明确未找到，不自由补全
   └─ 冲突 → 提示冲突并人工确认
```

强调：

> 真实系统里的“是否可靠”可能由阈值、过滤规则、模型判断和人工共同完成。本课用产品状态图表达，不假装一个条件节点就能解决全部问题。

## 老师巡视常见问题

**学员把“规则库”写成“所有公司资料”。**  
追问：目标用户会问哪些问题？每类问题由哪份权威资料回答？

**学员没有无答案。**  
追问：用户问了知识库没有的门店实时数据，系统会怎样？

**学员让模型判断新旧版本。**  
追问：模型依据什么获得业务授权？版本信息是否应该在建库时确定？
