# 模块02｜Agent最小运行循环

> 建议时长：12分钟  
> 核心问题：Agent是怎样根据结果继续行动的？

## 一、教学目的

让零基础学员看懂Agent的最小运行逻辑，但不进入ReAct论文、思维链或规划算法。

## 二、核心运行图

```text
接收目标
→ 判断当前缺少什么
→ 选择下一步行动
→ 调用知识或工具
→ 观察执行结果
→ 判断是否继续
→ 输出、确认、停止或转人工
```

循环部分：

```text
判断 → 行动 → 观察 → 再判断
```

## 三、六个运行要素

### 1. 目标

最终要完成什么，什么结果代表任务结束。

错误目标：

> 帮助商家经营得更好。

课堂目标：

> 基于指定门店和时间范围的经营数据，识别一个主要问题，查询适用规则并生成活动草稿；写入前必须确认。

### 2. 状态

Agent当前已经掌握的信息：

- 门店ID；
- 日期范围；
- 用户权限；
- 查询过的工具；
- 工具返回结果；
- 是否已经得到用户确认。

### 3. 判断

当前最合理的下一步：

- 缺参数就追问；
- 信息完整就查询；
- 新客下降就查新客规则；
- 数据不足就停止或请求扩大范围；
- 有冲突就转人工。

### 4. 工具

系统明确允许Agent使用的外部能力。

工具清单决定Agent“能做什么”，不是模型自己临时创造工具。

### 5. 观察

工具真实返回的结果，包括成功数据和错误状态。

Agent不能只接收“成功”，还需要读懂：

- 无数据；
- 无权限；
- 超时；
- 规则冲突；
- 写入失败。

### 6. 结束条件

- 任务完成；
- 等待用户确认；
- 用户拒绝确认；
- 工具连续失败；
- 结果冲突；
- 没有权限；
- 超出能力范围。

## 四、四类产品设计

将六个运行要素收敛成产品经理容易使用的四项：

| 产品设计项 | 需要回答 |
|---|---|
| 目标 | 最终交付什么 |
| 能力 | 可以调用哪些知识和工具 |
| 边界 | 哪些可自动、需确认或禁止 |
| 兜底 | 失败、冲突和越界时怎么办 |

## 五、案例走一轮

用户：

> 分析门店10086最近30天的新客表现。

运行过程：

```text
目标：判断新客表现并给出建议
→ 状态：门店和日期已知
→ 判断：需要查询经营数据
→ 行动：调用query_store_metrics
→ 观察：新客环比-25%，诊断标签为新客下降
→ 判断：需要查询当前新客活动规则
→ 行动：调用search_activity_rules
→ 观察：找到当前有效规则
→ 输出：生成建议；未获得写入确认，不创建草稿
```

## 六、为什么使用诊断标签

本课不让模型自由决定“-10%还是-20%算异常”。

模拟数据工具返回：

```text
diagnosis_label: new_customer_decline
diagnosis_reason: 环比下降25%，超过教学阈值20%
```

Agent负责选择下一步，业务阈值由工具或业务规则负责。

这体现：

> 确定性的业务判断尽量留在规则或系统中，模型负责处理需要语义理解和动态选择的部分。

## 七、教师动作

- 每讲一个要素，都回到同一轮案例；
- 不展示模型隐藏思维过程；
- 只展示工具选择、参数、返回状态和下一步行动；
- 强调“观察”包括失败结果。

## 八、学员动作

在纸上补全两个状态：

1. 如果工具返回`data_incomplete`，下一步是什么？
2. 如果规则工具返回`rule_conflict`，下一步是什么？

参考：

- 数据不足：请求扩大日期范围；
- 规则冲突：停止生成确定方案，提示冲突并转人工确认。

## 十、本模块验收

学员能够不看材料画出：

```text
目标 → 判断 → 工具 → 观察 → 继续/停止
```
