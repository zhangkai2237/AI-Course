## 一、老师先理解：现场诊断的价值和风险

现场分析最容易让学员感到课程“有针对性”，也是最容易产生误导的环节。

它的价值在于，老师可以把前面讲过的四方向地图、六类资产和三级证据真正用在一个人身上，让全班看到判断过程，而不只是记住框架名称。

它的风险在于：

- 信息只有几分钟，无法完整了解一个人的职业经历；
- 当前真实JD尚未补齐，尤其平台和解决方案方向仍待验证；
- 学员可能把老师的一句话当成确定的职业结论；
- 老师可能受到职业名称、表达能力或个人印象影响；
- 公开课堂可能涉及公司、项目、收入或个人限制等敏感信息；
- 为了追求现场效果，容易说出“你特别适合”“转型问题不大”等过度承诺。

因此，现场诊断必须遵守四条原则：

1. **只根据已提供的事实和证据判断**；
2. **只给优先验证方向，不给最终职业裁决**；
3. **只指出一个当前最大缺口和一组下一步动作**；
4. **明确说明仍需用真实JD和项目结果验证**。

老师的角色不是算命，也不是在8分钟内证明自己见多识广，而是示范一套可重复的判断方法。

以下内容不来自参考课程的固定模板：

## 三、课前准备：不要等上课才第一次了解学员

### 3.1 课前问卷

建议在开课前24—48小时收集。学员可以匿名，允许不填写收入、公司名称等非必要信息。

#### 基本背景

1. 当前岗位、工作年限和所在行业；
2. 日常最主要的三项工作；
3. 希望转AI产品的原因：内部转岗、外部求职、能力升级或其他；
4. 城市、行业、时间等客观限制。

#### 项目证据

5. 一个自己参与最深的项目；
6. 项目中自己具体负责什么；
7. 自己做过什么关键判断或取舍；
8. 最后产生了什么结果，如何判断。

#### 六类资产

9. 长期接触的用户或客户是谁；
10. 最熟悉的业务流程是什么；
11. 是否做过数据分析、指标设计或技术协作；
12. 是否做过客户访谈、方案、实施、培训、验收或复盘；
13. 使用过哪些AI工具，是否完成过AI项目。

#### 公开授权

14. 是否愿意在课堂公开分析；
15. 是否需要匿名；
16. 哪些信息不希望课堂展示。

如果必须控制问卷长度，可保留原内容设计中的13项，把公开授权合并在最后一项。这里拆成16项是为了老师备课更清晰。

### 3.2 选择哪三名学员

优先选择背景差异明显、能代表常见问题的三人，而不是只选表达最好或经历最亮眼的人。

推荐组合：

- 一名有产品经验、没有AI项目；
- 一名没有产品经验、但有明显行业或职能资产；
- 一名产品、AI和行业证据都较弱。

也可以根据实际班级调整，例如加入一名技术背景或一名客户交付背景学员。

不建议选择：

- 没有明确同意公开的学员；
- 当前正经历严重职业、心理或经济压力，公开讨论可能造成伤害的学员；
- 信息过少且课前无法补充的学员；
- 三人背景高度相似，无法让全班看到不同推导路径。

### 3.3 为什么不随机现场抽三个人

随机抽人虽然有互动感，但容易出现信息不足、隐私风险和时间失控。更稳妥的方式是课前自愿报名，老师提前选择并做初步分析。

若希望保留现场感，可以提前确定5名候选，课堂开始时从中选择3名；但所有候选都应完成问卷并同意公开。

### 3.4 教师课前分析卡

每名候选学员提前填写一张：

| 项目 | 教师记录 |
|---|---|
| 背景事实 | 岗位、行业、年限、主要职责、转型目标 |
| 强证据 | 自己承担关键责任，能讲清行动和结果的经历 |
| 中证据 | 深度参与但不是主要负责人的经历 |
| 弱证据或待确认 | 兴趣、自评、工具体验、信息不完整的经历 |
| 行业资产 | 证据和等级 |
| 用户资产 | 证据和等级 |
| 业务资产 | 证据和等级 |
| 产品资产 | 证据和等级 |
| 数据与技术协作资产 | 证据和等级 |
| 客户与项目交付资产 | 证据和等级 |
| 优先验证方向 | 初步方向＋依据 |
| 备选方向 | 初步方向＋待确认问题 |
| 暂不优先方向 | 证据明显不足的方向＋原因 |
| 当前最大缺口 | 只选一个 |
| JD验证任务 | 需要比较的岗位类型和数量 |
| 项目验证任务 | 利用既有背景完成的最小动作 |
| 现场必问 | 最多3个事实问题 |
| 隐私边界 | 不展示的公司、项目、收入或个人信息 |

### 3.5 课前准备的判断不是最终答案

老师可以提前形成假设，但不要在现场只寻找支持自己判断的信息。如果学员补充的新事实改变了结论，应明确说：

> 你刚补充的这段经历会改变我原来的判断，我们重新调整一下优先方向。

这本身就是很好的教学示范：结论应随证据更新。

## 四、现场布置与规则说明

### 4.1 休息结束后的开场话术（83:00—84:00）

> 接下来我们选3名同学做现场分析，每人8分钟。这里不是职业测评，也不会替任何人决定未来。我会根据他现在提供的经历，提取可以证明的资产，给出一个优先验证方向、一个备选方向、一个最大缺口，以及需要完成的JD和项目任务。
>
> 信息不充分时，我会明确说“不足以判断”。平台和解决方案方向还需要真实JD进一步验证。没有被点到的同学，也请对照三个案例修改自己的判断卡。

### 4.2 隐私说明

> 被分析的同学只需要讲与判断有关的信息。公司名称、项目数据、客户名称和收入都可以匿名；涉及内部机密时，只讲抽象流程和自己的责任，不讲具体数据或商业信息。

老师本人也不要通过追问引导学员披露敏感公司信息。例如，不问“你们公司具体是哪家、这个指标是多少”，可以问：

> 你可以不说公司名称，只说明这是企业内部流程还是消费者产品；结果可以不讲具体数值，只说有没有上线、验收或发生明显变化。

### 4.3 计时规则

- 每名学员严格8分钟；
- 第6分钟时老师必须进入“给建议”阶段；
- 第7分30秒开始收口；
- 如果事实仍然不足，不继续无限追问，输出“当前无法确认＋下一步补证据”；
- 三名学员结束后保留3分钟总结。

建议老师使用桌面计时器，并让助教在第5分钟和第7分钟提示。

## 五、现场诊断的统一判断逻辑

### 5.1 第一步：确认事实，不解释

先问具体经历：

- 服务谁；
- 熟悉什么流程；
- 做过什么项目；
- 自己负责什么；
- 做过什么判断；
- 最后有什么结果。

不要先问“你想做To B还是To C”，否则学员会围绕自己的偏好组织答案。

### 5.2 第二步：提取六类资产

把事实放入六类资产，并判断证据等级：

- 行业；
- 用户；
- 业务；
- 产品；
- 数据与技术协作；
- 客户与项目交付。

### 5.3 第三步：与四方向工作重点比较

- To B应用：企业流程、业务落地、多角色、权限、采用；
- To C应用：具体用户、体验、Aha Moment、使用和留存；
- 平台/能力：通用能力、系统抽象、复用和技术协作；
- 解决方案：客户问题、方案、PoC、交付边界和采用。

平台和解决方案的具体要求仍待JD验证，因此建议必须使用条件表达。

### 5.4 第四步：给出方向假设

必须同时说明：

- 为什么优先验证；
- 哪些资产支持判断；
- 哪些信息仍然不足；
- 为什么备选方向值得保留；
- 什么证据会让结论改变。

### 5.5 第五步：只指出一个最大缺口

最大缺口可以是：

- AI基础和能力边界；
- 产品基本功；
- 完整AI项目证据；
- 行业或用户理解；
- 数据与技术协作；
- 客户和项目交付；
- 真实岗位信息不足。

一次列出十项缺口会让学员无从行动，也掩盖真正优先级。

### 5.6 第六步：给出双验证任务

每次必须包含：

1. **JD任务**：分析哪一类岗位、至少多少份、重点核对什么；
2. **项目或学习任务**：利用已有背景完成什么小验证。

方向判断必须最终回到外部证据，而不是停在老师个人观点。

## 六、单人8分钟标准流程

### 第0:00—1:00｜复述背景并确认目标

老师用30秒复述：

> 我先确认一下：你目前在【行业】做【岗位】大约【年限】，主要负责【三项工作】。你想转AI产品主要是为了【转岗／求职／能力升级】。这个理解准确吗？

然后问：

> 今天你最希望我们帮你判断的，是优先方向，还是第一步怎么补证据？

如果学员开始长篇介绍，及时限定：

> 为了控制时间，请先补充一条你认为最关键的经历，其他信息我会追问。

### 第1:00—3:00｜追问最关键的事实证据

从下面问题中选择2—3个，不要全部问：

1. 你长期服务的用户或客户是谁？
2. 你最熟悉的一条业务流程是什么？
3. 在参与最深的项目里，你亲自做了什么决定？
4. 这个决定产生了什么结果，怎样判断？
5. 你是否用数据或指标做过判断？
6. 你与哪些技术角色协作，推动到什么程度？
7. 你是否承担过客户或内部业务方的方案、交付或验收？

追问原则：学员说标签，老师追事件；学员说“参与”，老师追具体责任；学员说“效果不错”，老师追判断依据。

### 第3:00—4:00｜当场提取资产

参考话术：

> 根据刚才的信息，我先提取三条比较明确的资产。第一是【资产＋证据】，属于强证据；第二是【资产＋证据】，目前是中证据；第三是【自评或浅层经历】，暂时只能算弱证据。

不要为了照顾情绪把每项都说成优势。也不要只说缺点，至少指出学员已经可以利用的一到两项真实资产。

### 第4:00—5:30｜给出优先方向和备选方向

统一句式：

> 基于你目前在【两到三类资产】中的证据，我建议优先验证【方向】，因为这个方向的工作更需要【对应工作重点】，与你做过的【具体经历】有交叉。
>
> 备选方向是【方向】，但目前还需要确认【信息或JD要求】。如果后续发现【条件】，这个方向的优先级可能会上升／下降。

如果信息不足，允许这样说：

> 现在还不足以在To B和To C之间做可靠判断。我们能确认的是，你需要先补【某类证据】；完成以后再比较方向。

### 第5:30—6:30｜指出一个最大缺口

参考话术：

> 你现在不是所有能力都要补。当前最影响方向成立的缺口是【一个缺口】。因为目标方向要求【工作】，但你现在只有【弱证据／没有项目证据】。

如果学员追问其他短板，可以说：

> 其他能力以后也要补，但第一步先解决这个，否则方向判断仍然没有依据。

### 第6:30—8:00｜给出JD与项目任务，并复述输出

#### JD任务句式

> 先找【5份】与【城市／年限／行业】接近的【岗位类型】JD，重点看【三项职责或要求】是否反复出现，并比较你现有证据。

#### 项目任务句式

> 同时利用你熟悉的【用户／业务流程】，完成【具体项目动作】。最低产出包括【用户、流程、问题、AI任务、人机分工、效果标准／访谈／Demo／反馈】。

#### 最终复述

> 所以你的V0.2是：优先验证【方向】，备选【方向】；依据是【两条证据】；最大缺口是【一项】；下一步完成【JD任务】和【项目任务】。这不是最终结论，完成任务后再调整。

## 八、三个模拟诊断样例

> 以下均为教学案例，不对应真实学员或公司。平台和解决方案方向仍需当前JD验证。

### 样例A：企业后台产品经理，没有AI项目

#### 背景

- 3年企业审批和后台系统产品经验；
- 熟悉流程、角色权限和研发协作；
- 主导过审批系统改版并完成上线；
- 使用过大模型工具，没有AI项目和评测经验；
- 希望转AI产品，但不确定应用还是平台。

#### 可追问

1. 审批改版中你做了什么关键判断？
2. 是否参与过跨系统接口和权限设计？
3. 有没有长期接触某类企业用户或业务流程？

#### 资产提取

- 产品资产强：主导需求、流程设计和上线；
- 数据与技术协作强：权限、接口和研发协作；
- 企业业务资产中等：熟悉一条审批流程；
- AI项目证据弱：只有工具体验。

#### 现场输出示例

> 根据你在企业流程、权限设计和研发协作上的强证据，我建议优先验证To B AI应用，备选AI平台/能力。To B应用能够直接利用你对企业流程和多角色的理解；平台方向可能利用你的系统和权限经验，但具体技术深度与职责还要看真实JD。
>
> 你当前最大的缺口不是传统产品基础，而是没有AI能力验证、效果评估和人机分工的项目证据。下一步分析5份企业效能、知识助手类JD，同时从熟悉的审批或知识查询流程中选一个节点，收集真实问题，完成AI任务、人机分工和效果标准设计。

#### 什么会改变判断

- 如果平台JD普遍要求其已有的系统抽象和技术经验，平台优先级可能上升；
- 如果学员实际更熟悉具体企业业务而缺少平台抽象，To B应用更合理；
- 如果目标城市几乎没有对应岗位，需要调整行业或方向范围。

### 样例B：制造业大客户销售，没有产品经历

#### 背景

- 5年制造业大客户销售；
- 熟悉客户决策、采购、方案沟通和内部协同；
- 参与过售前方案，但没有主导产品设计；
- 没有AI项目；
- 希望尽快转岗。

#### 可追问

1. 你最熟悉的销售流程中，哪个环节最耗时或容易失误？
2. 你做方案时负责业务分析、产品配置还是纯商务关系？
3. 是否参与过实施、验收或上线采用？

#### 资产提取

- 行业资产强：理解制造业客户和采购链路；
- 业务资产强：熟悉大客户销售流程；
- 客户与方案资产中到强：取决于是否主导需求和方案；
- 产品资产弱：缺少需求到上线的完整证据；
- AI项目证据弱。

#### 现场输出示例

> 你最明确的资产是制造业客户、采购决策和销售流程。建议优先验证AI解决方案，备选销售助手类To B AI应用，但这两个方向都要通过真实JD确认。
>
> 这里不是因为“销售就适合解决方案”，而是你确实做过客户分析和方案沟通。如果进一步发现你只负责商务关系、没有业务方案和交付责任，解决方案方向的证据会变弱。
>
> 当前最大缺口是把业务问题转化为产品方案的能力。下一步分析5份制造、销售或CRM方向的AI解决方案／To B产品JD，并围绕销售拜访准备、客户跟进或CRM录入选一个场景，完成用户—流程—问题—AI任务—验证标准的完整分析。

#### 什么会改变判断

- 如果学员有深度实施和验收经验，解决方案证据增强；
- 如果更擅长内部销售流程设计而不愿持续客户交付，To B应用可能更适合；
- 如果目标JD要求较强产品设计而学员没有证据，需要先补项目而非立即求职。

### 样例C：应届生，没有明确行业积累

#### 背景

- 刚毕业；
- 体验过多个AI工具；
- 做过课程作业，没有真实上线项目；
- 对To B、To C都感兴趣；
- 没有长期接触的行业。

#### 可追问

1. 过去有没有持续服务某类用户的社团、实习或课程项目？
2. 哪个项目真正接触过用户，而不是只完成作业？
3. 接下来一个月最容易接触哪类真实用户？

#### 资产提取

- AI工具体验弱证据；
- 产品资产弱：课程作业尚未证明真实用户和反馈；
- 行业和业务资产弱；
- 可能存在校园、学习或内容场景的初步用户资产，需追问。

#### 现场输出示例

> 当前证据不足以可靠判断你更适合To B还是To C，所以我不建议现在贴方向标签。你第一目标不是选对岗位，而是创造第一条真实证据。
>
> 选择一个能接触用户的校园、学习或生活场景，完成3—5次访谈、一个小型方案或Demo和一次真实反馈验证；同时分析对应方向5份JD。项目结束后，再看你在用户体验、企业流程还是技术系统上表现出更强证据。

#### 什么会改变判断

- 如果学员能持续接触个人学习用户并表现出用户和体验能力，可优先验证To C；
- 如果通过实习接触企业流程，可转向To B验证；
- 如果有真实开发者工具或系统项目，可增加平台方向研究，但仍需JD核验。

## 九、常见现场情形及处理方式

### 9.1 学员一直讲岗位名称，不讲具体工作

老师打断：

> 职位名称先放一边。请选一个你参与最深的项目，告诉我当时服务谁、你做了什么决定、结果怎样。

### 9.2 学员把团队成果全部说成自己的成果

老师追问：

> 这个结果是团队完成的。你本人承担哪一部分？哪个决定是你做的？

语气保持中性，不公开质疑诚信，只做责任拆分。

### 9.3 学员说“我沟通能力强”

老师追问：

> 请给一个具体场景：你需要推动谁，存在什么分歧，你采取了什么行动，最后怎样？

### 9.4 学员坚持想做与证据完全不同的方向

不要直接否定兴趣：

> 这个方向可以保留为探索目标，但目前你的证据主要集中在【资产】。如果你仍然想转向【目标方向】，下一步需要有意识地补【缺失证据】，再比较投入成本和JD要求。

### 9.5 学员要求老师直接说“能不能找到工作”

建议回答：

> 仅凭8分钟信息和未补齐的市场JD，我不能可靠判断录用结果。现在能做的是确认你有哪些资产、目标岗位需要什么，以及下一步怎样验证差距。

### 9.6 学员年龄、学历或城市限制明显

不要给出绝对结论。记录为客观约束，并转化为验证任务：

> 这个限制可能影响岗位范围，但需要用你所在城市和目标年限的真实JD验证，不能直接根据普遍印象判断。

### 9.7 学员情绪明显受挫

先区分“证据不足”和“能力没有价值”：

> 我说的是目前没有足够证据支持这个方向，不是说你没有能力。我们把下一步缩小到一个可以产生证据的动作。

如果涉及严重心理压力，不在公开课堂继续深入，建议课后私下沟通或寻求适当支持。

### 9.8 时间到了但信息仍然不足

按时收口：

> 当前可以确认的是【已有资产】；无法确认的是【方向问题】。你的下一步不是继续猜，而是补充【一类信息／项目证据】并分析【JD类型】。完成后再判断。

### 9.9 学员披露公司敏感信息

立即提醒并停止细节：

> 具体公司、客户和数据不用展开。请抽象成用户类型、业务流程和你的责任即可。

## 十、常见错误建议及修正

| 错误建议 | 为什么有问题 | 推荐表达 |
|---|---|---|
| 你性格外向，适合To C | 性格不能替代用户和产品证据 | 你有持续用户研究和增长证据，可优先验证To C |
| 你不懂技术，只能做运营 | 过度否定，也没有看岗位技术深度 | 先盘点已有业务资产，再用JD确认需要补到什么技术深度 |
| 现在Agent热门，你就做Agent | 追逐技术名词，没有用户、问题和岗位 | 先找AI任务在熟悉场景中的价值，再看对应岗位 |
| 你做销售，一定适合解决方案 | 职业名称不等于方案和交付证据 | 进一步确认客户分析、方案设计、PoC和交付深度 |
| 你做开发，一定适合平台 | 实现能力不等于平台产品判断 | 检查是否有通用能力抽象、平台用户和跨团队推动证据 |
| 你什么都不会，先学完所有课 | 没有创造证据的行动起点 | 先做一个熟悉小场景验证，边做边补最低知识 |
| 你过去经验很好，转型问题不大 | 忽略AI项目和JD门槛 | 过去资产可能降低部分成本，但仍需补AI证据并核对岗位 |
| 这个方向不适合你 | 结论过度且缺少可逆性 | 目前证据不足，暂不优先；如果补到某证据可重新评估 |

## 十一、三名学员结束后的3分钟总结（107:00—110:00）

> 若每人严格8分钟，则三人诊断为83:00—107:00，最后3分钟总结。

### 第1分钟：比较三个人的不同答案

参考话术：

> 三名同学得到的方向不同：有人优先利用产品和流程资产，有人优先利用行业与客户资产，也有人暂时不确定方向，先创造第一份证据。

### 第2分钟：强调相同判断过程

> 但过程完全相同：先确认事实，再提取六类资产；区分强、中、弱证据；形成优先和备选方向；最后用JD和项目验证。

展示流程：

> 事实 → 资产证据 → 方向假设 → 最大缺口 → JD验证＋项目验证

### 第3分钟：要求全员完成V0.2

> 没有被分析的同学，请对照三个案例，在自己的V0.1上补三项：第一，我还缺哪条事实才能判断；第二，我应该分析哪类JD；第三，我这周能完成什么验证动作。补完以后就是V0.2。

转入模块07：

> 接下来用6分钟把整节课收口，并说明怎样通过课后JD作业把V0.2升级成V1.0；116分钟后保留机动时间。

## 十二、如果现场时间失控怎么办

### 情况一：只剩19分钟

改为2名学员，每人8分钟＋3分钟总结。不要把3名都压成6分钟，否则事实追问和任务输出都会变得仓促。

### 情况二：只剩12分钟

选择1名最具代表性的学员，完成8分钟完整诊断；再用2分钟给出另一类背景的简短对照，2分钟总结。

### 情况三：候选学员信息不足

不要现场硬判。可以用三个模拟案例中的一个做示范，并让全班练习判断。

### 情况四：课堂互动特别多

把其他问题收集到课后答疑，不在单人8分钟里无限展开。老师可以说：

> 这个问题有价值，但不影响当前方向判断，我们先记录，课后统一回答。

### 情况五：时间允许增加1—2人

只能做“快速分析”，每人2—3分钟，输出一条已有资产、一个待验证方向和一个下一步动作；必须明确不是完整诊断。

## 十四、老师现场自检清单

### 课前

- [ ] 三名学员是否自愿并完成公开授权？
- [ ] 是否确认匿名和敏感信息边界？
- [ ] 三名学员背景是否具有差异？
- [ ] 是否提前填写教师分析卡？
- [ ] 每人是否只准备最多3个关键追问？
- [ ] 是否准备计时器和时间提醒？

### 每名学员诊断中

- [ ] 我是否先确认事实，而不是先给方向？
- [ ] 我是否追问了本人责任、行动和结果？
- [ ] 我是否区分了强、中、弱证据？
- [ ] 我是否说清方向推导依据？
- [ ] 我是否明确了信息不足和可能改变结论的证据？
- [ ] 我是否只指出一个最大缺口？
- [ ] 我是否给出JD任务和项目任务？
- [ ] 我是否避免了性格、年龄和职业名称的机械判断？
- [ ] 我是否控制在8分钟内？

### 全部结束后

- [ ] 我是否总结了三人不同答案背后的相同过程？
- [ ] 我是否要求未被分析的学员也完成V0.2？
- [ ] 我是否再次说明结果是方向假设，而非就业结论？
- [ ] 我是否自然转入课后JD验证和V1.0？

如果这些项目能够做到，现场诊断才真正服务于教学。它的专业感不来自老师迅速给出一个漂亮答案，而来自结论有证据、有边界、能被后续行动检验。
