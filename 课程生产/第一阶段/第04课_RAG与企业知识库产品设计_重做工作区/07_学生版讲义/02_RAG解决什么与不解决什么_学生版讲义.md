# 02 RAG解决什么与不解决什么

## RAG的定义

RAG是Retrieval-Augmented Generation，中文为“检索增强生成”。

基本过程：

> 用户提问后，系统先从指定知识源中检索相关内容，再把用户问题和检索内容一起交给大模型生成答案。

可以先用“开卷考试”理解：

- 没有RAG：模型主要根据已有训练知识和当前Prompt回答；
- 使用RAG：模型先从指定资料中找到可能相关的依据，再回答。

但真实产品还需要处理版本、权限、无答案、冲突和引用。

## 适合RAG的场景

### 企业内部知识

- 活动规则；
- 产品手册；
- 公司制度；
- 售后政策；
- 内部FAQ；
- 项目经验。

### 需要持续更新的知识

规则和资料可以在模型不重新训练的情况下更新，但更新、审核和旧版下线仍需要治理。

### 用户表达多样

文档写“报名截止时间”，用户可能问“月底还能参加吗”。语义检索尝试根据意思找到相关内容。

### 需要依据的回答

答案可以关联文档、章节、版本和生效时间，方便核验。

## 不适合只靠RAG的问题

| 问题类型 | 示例 | 更适合的能力 |
|---|---|---|
| 一次生成 | 把一段话改得更简洁 | Prompt |
| 实时事实 | 今天用了多少补贴 | 业务系统/API |
| 精准个体查询 | 我的订单到哪里了 | 业务系统/API |
| 高风险裁决 | 是否赔偿、是否撤销处罚 | 人工/受控流程 |

## RAG与幻觉

RAG能为模型提供更可靠的外部依据，从而减少无依据生成，并让回答更容易核验。

但它不能消除幻觉，因为：

- 知识可能错误或过期；
- 检索可能没找到或找错；
- 模型可能没有忠实使用片段；
- 产品可能没有正确处理冲突。
