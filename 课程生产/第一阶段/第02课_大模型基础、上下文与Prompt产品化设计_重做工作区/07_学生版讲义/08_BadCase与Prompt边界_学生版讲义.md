# 模块08：Bad Case初筛与Prompt边界

> 课堂时间：108—114分钟  
> 本模块任务：判断问题首先发生在哪里，以及是否超出单次Prompt优化  
> 课堂产出：一条“问题类型＋验证动作＋后续方向”的判断

## 一、为什么不能一直增加Prompt

模块07通过补充规则和输出要求改善了结果，但不能由此得出：

> 只要继续把Prompt写得更长、更复杂，就能解决所有问题。

以下问题不能只靠改措辞解决：

- 模型没有获得企业最新知识；
- 原始录音或转写本身错误；
- 任务包含多个稳定步骤和条件分支；
- 需要查询、写入或发送等外部动作；
- 权限、安全或产品交互存在问题；
- 模型能力持续达不到要求。

所以第一步是：

> 先判断问题类型，再决定优先验证什么。

## 二、四类Prompt相关问题

这四类只是初学者使用的第一层初筛，不是完整根因体系。

### 1. 任务问题

识别信号：

- 不清楚服务谁；
- 同时要求多个互相竞争的任务；
- 只说分析一下、整理得专业；
- 不知道任务做到哪里结束。

优先验证：

- 固定首要用户和时点；
- 收敛为一个任务闭环；
- 明确目标输出；
- 明确不需要完成什么。

### 2. 上下文问题

识别信号：

- 缺少完成任务所需事实；
- 材料没有来源、时间或说话人；
- 输入大量无关、过期或冲突信息；
- 不知道哪个版本可信。

优先验证：

- 补充必要事实；
- 标明来源、时间和角色；
- 删除无关材料；
- 为冲突信息规定优先级或要求确认。

### 3. 规则与约束问题

识别信号：

- 把推测写成事实；
- 信息不足时自行补齐；
- 不区分已确认、讨论中和待确认；
- 没有说明高风险内容怎样处理。

优先验证：

- 规定事实依据；
- 明确缺失信息处理；
- 定义确定性状态；
- 要求关键结论附证据；
- 对日期、金额和承诺保留人工确认。

### 4. 输出问题

识别信号：

- 内容完整但不能进入后续流程；
- 缺少字段、负责人、时间或状态；
- 适合阅读但不适合检查；
- 用户无法定位原文或修改结果。

优先验证：

- 按后续用途定义字段；
- 明确验收标准；
- 提供证据和状态；
- 设计编辑、确认和写入动作。

## 三、分类可以交叉

一个Bad Case可能同时涉及多类问题。

例如行动项没有负责人：

- 原文已经有负责人，但模型漏掉：可能是输出或规则问题；
- 原文根本没有负责人：是上下文中的事实缺失；
- Prompt没有要求行动项：是任务或输出定义问题。

分类的目的不是争论唯一标签，而是决定：

> 第一件最值得验证的事情是什么？

## 四、Prompt与其他机制的边界

| 主要问题 | 优先考虑 | 最低理解 |
|---|---|---|
| 任务、输入、规则或输出没说清 | Prompt和上下文 | 先把本次任务说明清楚 |
| 缺企业私有、最新或大量知识 | 知识检索或查询 | 先找到相关知识，再提供给模型 |
| 多个稳定步骤、分支和检查 | Workflow | 把复杂任务拆成可控步骤 |
| 查询系统、创建任务、写CRM或发消息 | 工具调用和外部系统连接 | 执行动作需要权限、校验和确认 |
| 原始录音或转写错误 | 数据和上游能力 | Prompt不能恢复未正确记录的事实 |
| 以上清楚后仍持续不达标 | 模型、方案或场景评估 | 不要无限堆Prompt |

## 五、本课只做到“识别下一步方向”

本课不要求学会RAG、Workflow、Agent、工具调用或MCP，也不要求进行技术选型。只需要判断问题是否出现以下信号：

- 缺少企业私有、最新或大量知识；
- 存在多个稳定步骤和条件分支；
- 需要查询、写入、发送或创建任务；
- 原始数据或转写已经错误；
- Prompt和上下文清楚后仍持续不达标。

出现这些信号时，正确动作不是立刻说“上Agent”或“做RAG”，而是记录：

> 这个问题可能已经超出单次Prompt优化，下一步需要验证________。

具体产品形态和技术机制会在后续课程展开。

## 六、不能忽略的其他问题

四类初筛之外，还可能有：

- 原始数据或转写错误；
- 模型能力不足；
- 工具或接口失败；
- 权限和安全问题；
- 产品交互误导；
- 测试样本覆盖不足。

如果任务、上下文、规则和输出都清楚，多条代表性样本仍持续不达标，就需要评估模型、数据、方案或场景本身。

## 七、课堂练习

选择一条问题，完成：

> 这条问题首先属于________，我会先验证________；如果仍不能解决，再考虑________。

可选：

- 可能的试点范围被写成确定计划；
- 条件估计被写成正式工期；
- 行动项没有负责人和日期；
- 最新安全制度没有提供；
- 确认后的行动项无法写入CRM。

不能只写“优化Prompt”。

## 八、常见误区

### 缺知识就一定使用RAG

不一定，要看知识规模、更新频率、权限和任务。

### 多步骤就一定使用Agent

不一定，规则清楚、顺序固定时可能更适合Workflow。

### 工具调用成功就代表业务正确

不代表，还要检查参数、权限、确认和失败处理。

### 模型能力不够就继续增加Prompt

当任务等要素已经清楚仍不达标，应评估模型、数据、方案或场景。

这些名词在本课只用于提醒“可能需要其他机制”，不要求学员解释其完整定义。

## 九、先记住

1. 先区分任务、上下文、规则和输出问题；
2. 四类只是第一层初筛；
3. 缺知识、多步骤和外部执行可能需要不同机制，但本课不做选型；
4. 原始数据错误不是Prompt可以恢复的；
5. 技术名词不是升级路线，问题类型才是方案起点。
