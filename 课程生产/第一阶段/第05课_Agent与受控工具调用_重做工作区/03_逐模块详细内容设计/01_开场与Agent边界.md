# 模块01｜开场与Agent边界

> 建议时长：15分钟  
> 核心问题：有了Workflow和RAG，为什么还需要Agent？

## 一、教学目的

本模块不从定义开始，而是让学员先看到“下一步依赖动态结果”时，固定流程为什么会变得难维护。

学员需要形成的第一个判断：

> 路径稳定、规则明确时优先Workflow；只有下一步确实依赖当前状态和工具结果时，才考虑Agent。

## 二、承接前课

用一张递进图快速回顾：

```text
Prompt：完成一次生成或判断
Workflow：按预设步骤执行
RAG：取得企业知识依据
Agent：根据当前状态受控选择下一步
```

必须补充：

- Agent内部仍然会使用Prompt；
- Agent可以调用RAG；
- Agent可以把一条Workflow当作工具；
- Agent不是对前三种能力的替代。

## 三、开场任务

向学员展示需求：

> 帮我分析某家门店最近的经营情况。如果新客表现不好，查询适合的活动规则，并生成一份活动方案草稿。

请学员用2分钟回答：

1. 完成任务需要哪些步骤？
2. 每家门店都会走相同步骤吗？
3. 哪一步必须依赖前一步结果？
4. 哪一步可以提前写死？

## 四、先画固定Workflow

第一版流程：

```text
输入门店
→ 查询经营数据
→ 查询活动规则
→ 生成活动方案
→ 创建活动草稿
```

老师继续补充状态：

- 新客下降：需要查询新客活动；
- 新客正常但补贴异常：不应该继续推荐新客活动；
- 数据不足：应该追问是否扩大日期范围；
- 用户无写入权限：只能给建议；
- 规则冲突：不能继续创建草稿；
- 不存在经营异常：应该停止，而不是为了完成流程强行创建活动。

让学员观察：Workflow可以继续增加条件分支，但路径和维护复杂度会持续上升。

## 五、引出Agent

课堂定义：

> Agent是围绕目标，根据当前信息和工具结果，在产品规定的工具、权限和停止条件内选择下一步行动的系统。

这里使用“受控选择”而不是“自主完成一切”。

## 六、Chatbot、Workflow与Agent

只使用一个判断维度：

> 下一步主要由谁决定？

| 机制 | 下一步主要由谁决定 | 适用情况 |
|---|---|---|
| Chatbot | 用户决定下一轮问什么 | 问答、内容生成、对话 |
| Workflow | 产品提前规定 | 稳定步骤、确定规则、强可控 |
| Agent | 模型在约束内判断 | 下一步依赖动态结果和多个工具 |

Multi-Agent只在本课末尾出现，不在开场展开。

## 七、课堂判断题

请学员快速判断：

1. 上传发票→OCR→字段校验→人工复核：Workflow；
2. 查询员工休假制度：RAG；
3. 根据调研目标自主选择搜索、阅读和整理工具：Agent候选；
4. 把一段文案改得更简洁：Prompt；
5. 查询门店今日经营数据：数据工具，不因使用聊天界面就变成Agent。

## 八、教师动作

- 不要把Agent描述成“更高级的Workflow”；
- 对学员提出的复杂场景，追问“下一步为什么不能提前定义”；
- 如果学员回答“分支多就是Agent”，纠正为“分支多只是信号，关键是下一步是否依赖动态状态且难以穷举”。

## 九、学员产出

在设计表顶部填写：

- 当前任务；
- 固定路径能否完成；
- 哪一步需要动态判断；
- 暂时选择Workflow还是Agent；
- 判断依据。

## 十、来源与边界

- 主来源：A1 05:03-06:45；A2 01:08-03:28；A5 P81-P185。
- 课程加工：“谁决定下一步”对比表、商家经营案例。
- 本模块不展开规划算法、长期记忆和Multi-Agent。

## 十一、本模块验收

学员能够用一句话说明：

> 我选择Agent，不是因为任务看起来复杂，而是因为下一步需要根据工具结果动态决定。
