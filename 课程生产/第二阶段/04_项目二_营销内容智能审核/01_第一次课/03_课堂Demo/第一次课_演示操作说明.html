仅第一次课 · 课堂演示操作说明 v1.0

从一篇文案，走完三个审核环节

配合第三、五、六、七节使用。原型可本地离线打开，数据保存在当前浏览器，可随时重置与导出演示记录。

全部品牌、数据、角色与处理均为教学模拟。检查由预设脚本生成，没有接入真实模型、业务接口、身份认证或发布系统。自由文本超出演示覆盖时提示范围不足。课堂原型不能用于真实审核放行。

打开课堂原型 →　打开完整讲义 →

演示前准备

  1. 用桌面浏览器打开原型，建议1366×900或更大窗口，投屏时可适当缩放。
  2. 左下角“课堂演示控制”可载入四个预设场景；载入会清空当前演示进度，先按需导出记录。
  3. 右上角切换角色：小周为作者，小林为审核人员，小陈为内容负责人，小许为活动负责人。切换是课堂扮演，不是真实认证。
  4. 演示结果由明确的模板脚本决定，判断模型质量的内容继续使用讲义中的人工参考与验证安排。

A 作者自检：原句、依据和修改

  1. 控制面板载入“01 作者自检”，点击“运行自检”。
  2. 展开价格、65℃、赠品、避障与配送问题的依据，点击“定位原句”。
  3. 载入“只改一部分”，点击“保存为新版本”，再运行自检。价格条件仍不完整。
  4. 填写待确认说明，正式提交本版。保留问题进入人工流程，不等于自动批准。

课堂追问：作者具体知道要改什么了吗？报告来自哪个正文和依据版本？

B 正式审核：退回、修改、复核

  1. 沿A继续，或载入“02 正式复核”。右上角切换“小林”。
  2. 打开任务，对价格提示“确认问题”，填写理由后“退回作者修改”。
  3. 切换“小周”，进入作者稿件，载入“条件完整稿”，保存、自检、正式提交。
  4. 切换“小林”，打开最新任务，核对后点击“复核并通过”，填写结论。旧任务、旧正文和意见保留。
  5. 观察“检查完成”与“审核通过”分开，作者角色不能执行正式通过。

课堂追问：通过的是哪个版本？后续编辑会不会悄悄改变被批准正文？

C 巡检：从权益变化跟踪到实际更新

  1. 控制面板载入“03 权益变化巡检”，这会建立名额用完事件和六篇教学内容。
  2. 默认选择C01、C03、C05。点击“发起批量巡检”；C06范围待核会单独保留。
  3. C01“认领处理”，再“创建修订稿（转作者）”。此操作进入修订正文，不代表实际使用已更新。
  4. 作者自检、正式提交；审核人员复核通过。之后切换“小陈”，返回巡检批次。
  5. 对C01“确认实际更新”，记录已核实位置与版本，才关闭这项问题。
  6. C06点击“确认仍在使用并补查”，填写确认理由。补查后若有问题，按相同流程认领、修订、复核与登记更新。不能跳过范围待核后宣称全部完成。

课堂追问：检查运行结束、修订稿通过、实际使用更新分别发生在什么时候？原审核通过记录为何保留？

D 异常演示

缺资料

作者场景中，在控制面板选择“活动资料不可用”，再运行检查。观察部分范围未完成。恢复“正常预设检查”后重查提交，旧失败记录仍保留。

部分检查超时与人工补核

选择“功能检查超时”，运行后提交。审核人员可对当前版本“记录人工补核”，说明范围及依据。原机器失败保留；其他成立的业务问题仍需处理。建议先使用条件完整稿观察失败项与业务问题的区别。

旧版本结果返回

载入“04 版本变化”，先运行自检，在4.3秒延迟内载入另一份稿件并保存新版本。旧结果返回后应关联旧版本，不能直接作为当前稿件结果。再检查当前版本，比较两份记录。

原文位置校验失败

控制面板选择对应异常，再运行检查。结果标为未可靠完成，无法直接定位不存在的引文。人工补核要有独立记录。

自由文本

将模板改为未预设的自由文案并保存、检查。系统明确提示演示范围不足，不以空结果表示整篇无问题。

课堂暂停点

讲义位置适合演示的内容
第三节A、B、C的业务顺序，先讲角色与责任。
第四、五节A中原句与依据，说明审核点和能力分工；不把脚本结果当模型能力。
第六节B、C及D中的版本、状态、权限与异常承接。
第七节导出记录，讨论下一轮实际试用应采集什么。原型没有提供真实节省时间或准确率。

保存与范围说明

刷新通常会保留本地演示记录，浏览器禁用本地存储时仅能在当前页面会话使用。控制面板可重置或导出JSON。所有数据均在本地，不上传外部服务。不同浏览器、文件路径或本地预览地址的数据可能不共享。

原型是课堂流程教具，固定P1与本次活动，未实现真实登录、模型推理、平台发布、库存查询及完整规则配置。正式实施仍需真实资料、接口、权限与业务验证。
