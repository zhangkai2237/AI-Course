# 03 RAG的两条链路

RAG包含两条不同时间发生的链路。

## 离线建库

通常在用户提问前完成：

```text
知识采集
→ 文档解析与清洗
→ 分块
→ 补充元数据
→ 向量化/建立索引
→ 可检索知识库
```

### 知识采集

从目标问题反推权威材料，不是把组织里的所有文件全部上传。

### 解析与清洗

把PDF、Word、表格、网页或图片处理为系统可使用的内容。

需要检查：

- 扫描文字是否识别；
- 表格关系是否丢失；
- 页眉页脚是否成为噪音；
- “已失效”等标记是否保留。

### 分块

把长文档切成可检索片段。片段需要尽量保留完整的条件、结论和必要上下文。

### 元数据

正文之外的信息，例如文档名、版本、生效时间、适用范围、权限和来源。

### 向量化与索引

系统将文本转换成便于比较语义关系的表示，并建立快速查找结构。产品经理需要理解用途，不要求推导数学。

## 在线问答

收到用户问题后发生：

```text
用户问题
→ 问题理解/改写
→ 选择知识源
→ 检索
→ 重排
→ 增强Prompt
→ 生成
→ 引用、拒答或转人工
```

### 检索

找到一批可能相关的候选片段。候选片段不是最终答案。

### 重排

把更符合当前问题的片段排在前面，减少无关内容干扰。

### 增强Prompt

将用户问题、检索片段、回答规则和输出格式组合后交给模型。

### 生成和产品处理

模型组织答案，产品决定引用、无答案、冲突、权限和人工处理方式。

## 问题定位

| 现象 | 可能发生的位置 |
|---|---|
| 正确规则根本不存在 | 知识采集/更新 |
| 文档有规则但片段不完整 | 解析/分块 |
| 找到旧版、没找到新版 | 检索/版本过滤 |
| 找对片段但答案错误 | Prompt/生成 |
