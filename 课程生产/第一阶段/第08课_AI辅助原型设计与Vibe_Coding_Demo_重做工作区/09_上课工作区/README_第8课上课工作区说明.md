# 第8课上课工作区说明

> 课程：第8课｜AI辅助原型设计与 Vibe Coding Demo  
> 工作区用途：把第7课正式输入、第8课课堂生成产物、课堂记录集中到一个目录，避免上课时跨多个目录找文件。  
> 使用原则：`00_第七课正式输入` 作为只读基线；所有课堂生成、修改、验收都放在 `01_课堂生成产物` 和 `02_课堂记录`。

---

## 一、为什么要单独建这个工作区

第8课承接第7课，但第8课不应该重新做需求分析，也不应该让AI重新读取大量原始访谈、客服反馈、竞品观察等噪声材料。

第8课的核心任务是：

```text
读取第7课正式PRD和产品决策
→ 提取用户任务、页面、流程和状态
→ 生成低保真原型
→ 生成可演示界面
→ 生成可运行Demo
→ 局部修改与验收
```

所以本工作区只集中第8课真正需要的正式输入和备用依据。

## 四、上课前是否要真实生成一遍Demo

建议：必须真实生成一遍，而且不止生成最终Demo。

原因有三点：

1. 第8课是实操课，不是纯理论课。学生会期待看到PRD如何一步步变成原型和可运行Demo。
2. Vibe Coding现场生成存在不确定性。工具、路径、依赖、浏览器预览、代码质量都可能临场出问题。
3. 这节课的教学重点正是“过程控制”。如果你课前没有跑过全链路，就很难判断现场AI生成结果是正常偏差、产品越界，还是技术故障。

课前至少要生成并验证四类备份：

- 错误Demo：用于第一部分让学员找错；
- 低保真原型：用于讲“先结构、后视觉”；
- 可演示界面：用于讲页面状态和反馈；
- 最终Demo：用于讲Vibe Coding、局部修改、验收和第9课交接。

课堂上可以选择“现场重新生成”或“打开课前备份演示”，但课前必须已经有一套可运行版本兜底。

## 五、课堂使用建议

### 推荐方式

1. 上课时让Codex打开本工作区，而不是打开第7课原始目录。
2. Prompt里优先引用本工作区路径。
3. `00_第七课正式输入` 不修改，只读取。
4. 所有生成文件写入 `01_课堂生成产物`。
5. 课堂临时发现的问题、学员反馈、手动决策写入 `02_课堂记录`。

### 不建议

- 不建议在第8课现场重新读取第7课全部原始需求素材；
- 不建议现场覆盖第7课正式PRD；
- 不建议为了让Demo更好看而新增第7课没有确认的功能；
- 不建议让AI一次性生成完整Demo后直接讲结果。

---

## 六、第8课关键边界速查

第8课所有原型和Demo必须遵守以下边界：

- 一期只做手机三级类目；
- 对比对象是具体SKU；
- 最少2个、最多4个商品；
- 未登录可使用；
- 只做本地临时保存，不做云端保存；
- 展示活动价与优惠条件，不承诺统一到手价；
- 参数缺失显示“暂无数据”，不得推测；
- 参数冲突展示来源和反馈入口；
- 一期不做AI推荐最佳商品；
- 不做跨品类对比。
