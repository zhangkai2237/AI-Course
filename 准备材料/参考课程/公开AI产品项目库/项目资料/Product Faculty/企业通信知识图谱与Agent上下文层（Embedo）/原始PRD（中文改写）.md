# Embedo / Ambito 产品需求文档（中文改写）

> 来源：英文 `原始PRD.xlsx` 与 `原始PRD.csv`。本文按中文 PRD 结构重组。

## 1. 产品定义

Embedo / Ambito 是企业通信上下文平台。系统接入会议、邮件、日历和企业聊天，提取结构化组织实体，构建带权限和来源的知识图谱，并同时服务人类工作台与 MCP 兼容 Agent。

## 2. 问题背景

组织中的决策、承诺和例外大量存在于非结构化沟通中。传统知识库主要保存正式文档，难以回答“谁承诺了什么”“这个项目为何停滞”“上次与该客户做了什么决定”。企业 Agent 因此容易给出泛化或幻觉答案。

## 3. 用户与价值

### 人类用户

跨团队协调密集、需要对后续结果负责的知识工作者。他们希望被动获取到期事项、停滞项目、无人负责承诺和利益相关者沟通提醒。

### Agent 用户

企业内部 Agent 通过 MCP 查询权限范围内的决策、承诺、项目和来源片段，用于执行更可靠的工作流。

### 购买者

正在部署企业 AI Agent、建设组织知识基础设施或希望提升跨团队协同可见性的企业。

## 4. 产品目标

- 持续把沟通转化为结构化组织上下文；
- 让每个实体能够追溯到逐字来源；
- 自动发现承诺、决策、开放问题和项目停滞；
- 为人类和 Agent 提供同一上下文层；
- 严格保证用户、团队和租户之间的权限隔离。

## 5. 核心功能

### F1 多来源接入

接入 Zoom/Teams 会议、邮件、日历和 Slack/Teams 消息，对不同格式做标准化。

### F2 重要性判断与结构化提取

先判断沟通是否重要，再提取决策、承诺、行动项、开放问题、人员、项目和时间信息。每项实体保存置信度和逐字来源片段。

### F3 项目聚类与状态信号

自动将相关实体聚类为项目，识别长期未更新、无人负责或可能失约的承诺，并通过 Slack 等渠道提醒。

### F4 人类工作台

仪表盘显示当天会议、到期事项、停滞项目和近期利益相关者沟通。Ask Ambito 支持跨来源问题，并展示引用。

### F5 MCP 上下文服务

企业 Agent 携带用户身份和 OAuth 范围调用 MCP。服务在检索阶段过滤实体，只返回用户有权访问的上下文和来源片段。

### F6 部署与企业控制

考虑 SaaS、BYOK 和 VPC 部署，支持企业模型、密钥和数据边界要求。

## 6. 数据模型

- 原始材料：对象存储；
- 结构化实体：PostgreSQL；
- 语义检索：pgvector；
- 实体字段：类型、主体、责任人、时间、状态、置信度、source_id、逐字片段和权限范围；
- 权限层级：个人、团队、组织和租户；
- 服务：Python/FastAPI、Next.js、FastMCP、Supabase。

## 7. 模型分层

- Haiku：重要性和主题分类、轻量查询理解；
- Sonnet：决策、承诺等实体提取，项目聚类和综合；
- Opus：只处理低置信度或高复杂度升级案例；
- 确定性 Python：路由、权限、Schema 和流程控制；
- MVP 不做微调，优先使用提示词、评测和人工反馈。

## 8. 权限与安全要求

- 所有查询必须携带身份和授权范围；
- 权限过滤必须在数据检索时执行；
- 不直接向 Agent 返回整段原始会议或邮件；
- 不同租户之间的任何越权都为阻断级缺陷；
- 保存访问与来源审计记录；
- 结构、权限和 Schema 测试必须 100% 通过。

## 9. 成功指标与评测

### 质量指标

- 承诺召回率；
- 责任人归属准确性；
- 来源片段忠实度；
- 项目聚类和停滞识别质量；
- Ask Ambito 答案的引用支持率；
- MCP 权限正确率。

### 系统指标

- MCP 查询 P95 目标低于 500 毫秒；
- 解析有效率；
- 低置信度升级率和升级收益；
- 连接器成功率和数据新鲜度。

公开材料的小样本结果包括：结构解析有效率 100%；来源片段 48/50 正确；提取器 8 个来源中 7 个通过；承诺解决判断 35/35 正确。上述结果用于验证框架，不能替代企业规模压力测试。

## 10. 风险与待验证假设

- 用户是否愿意持续授权系统分析沟通；
- 自动归责与停滞提醒是否会产生组织摩擦；
- 不同连接器的权限模型能否统一；
- MCP 延迟目标在复杂权限过滤下是否可达；
- 上下文层是否能显著改善下游 Agent 的任务成功率。
